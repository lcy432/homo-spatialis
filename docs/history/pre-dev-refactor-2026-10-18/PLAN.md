## 0. 如何使用本计划

### 0.1 文件冲突与权限

完整规则见 [README 文件分工](README.md#governance)，本文作执行摘要：

1. 所有者最新明确决定优先；README 管愿景和范围，PLAN 管工程事实与顺序。
2. 已吸收的 DECISIONS 管具体数值契约；旧 CLAUDE／迁移文档中冲突的范围、进度和主规格，以 README 与本文列出的替换为准。
3. 历史 MEMOS／runs 是证据，不因新目标而改写 PASS/FAIL、运行口径或协议。
4. 配置文件决定**现在运行会做什么**，不能拿文档的新目标假装配置已经更新。差异先入账，在对应代码任务中修。
5. README 与 PLAN 之间若出现未解决冲突，暂停受影响部分，写明具体分歧；不能默选对自己最方便的版本。

生活模型各轮的文档分工：[docs/design/](docs/design/README.md) 集中长期技术说明，history/ 存阶段备忘，prompts/ 存执行任务；旧生活备忘已归档并保留原路径入口，研究 MEMOS 原地保留。`DECISIONS/` 记有效规则，README 记稳定说明，本文记工程状态，`runs/` 存运行证据（未提交时附 dirty 状态与输入、代码指纹）；解释文档和新日期不自动覆盖有效 ADR，上面的冲突处理顺序不变。

继续保留密钥保护、答案隔离、可追溯数值、计价一致和单一经济公式。修改 `src/econ/` 需要对应授权。本轮文档编辑不授权改代码、改配置、重跑、覆盖产物或修改其他文件。

### 0.2 状态词

| 状态 | 含义 |
|---|---|
| 已实现 | 函数／模块有代码及相应检查 |
| 已接入口 | 当前主命令实际消费该模块 |
| 有运行证据 | 有对应设计与版本的落盘结果 |
| 待实现／待接线 | 目标存在，但代码或调用链尚缺 |
| `pending_input` | 缺真实输入；不能用合成数据伪装满足 |
| `pending_computation` | 输入已有但计算／有效重复不足 |
| 设计不匹配 | 输入、抽样、噪声、协议等不一致；即使跑完也不能合并解释 |

旧材料中的“完成”必须说明完成的是哪一层。测试通过也不等于研究结论成立。

### 0.3 参数与假设登记（2026-10-08 起）

每轮新增或改变环境、数据映射、评价或代理认知规则，必须同轮更新[参数与假设目录](docs/design/parameter-assumption-register.md)，遵循 [ADR0022](DECISIONS/0022-parameter-register-and-e1-5-scope.md)。开工时查相关 ID；收尾列出改变的参数/规则、依据和仍未标定项，保存实际实验配置与版本。合成例值、用户输入、估计输出和数值精度分开；没有代码字段的未来条目标待实现。此次仅建立文档规则，没有新增校准程序或改变任何配置。

### 3.2 E2 的实现边界和验收

预计涉及 M4、输入／反馈类型、年度环境接口、配置和日志，具体文件在 E1 后列出。不要重写 M2 核心、自行添加迁移或复杂社交。

最小循环：

> 演进后的当年城市 + 上年实际状态 → 安全观察 → LLM 行动 → 校验执行 → 账目和内部评分 → 安全反馈 → 下一年。

验收至少覆盖：

- **动作有效：** 改变一个允许动作，账目或后续状态按规则改变；仅改理由文字不改变结算。
- **同源结算：** 观察、执行、评分使用同一年度数据和实际动作。`score(year=...)` 目前只是年标签，必须通过 `advance/with_record` 或新接口真正推进。
- **参数传递：** 若储蓄率属于动作，必须传入结算和评分，不能误用默认零。
- **状态延续：** 第二年读到第一年的真实结果，第三年同理。
- **信息隔离：** 代理看不到效用、最优城和研究答案；对嵌套结构也检查。
- **可重放：** 保存动作后，不再调用 LLM 也能重建账目与得分。
- **可审计平均：** 先完整计算每个分身分数，再按同城聚合；记录有效数、失败、离散度。
- **预算与失败：** 有限重试、超额停止、保留 partial；不悄悄丢弃低分／失败副本。
- **报告范围：** 若只支持很少动作或确定环境，明确说明，不能称完整人生模型。

先用合成小设计和模拟适配器检查执行链，再按已批准预算做少量真实调用。只通过 mock 不能声称真实模型闭环已验证。

**下个独立任务可采用的节约路线：**

1. 将 R_fit、R_post、R_moment 的配置和产物元数据分清，并确认实际入口使用；只加工具不算完成。
2. 在用户接受的 0.01–0.05 范围内，先提出如 0.05 的探索档，写明用途、版本与下游稳定性要求。表中 R=3000–5000 可作候选，不是已认证设置。
3. 复用缓存参数，在少量代表条件上比较后验变化是否改变偏好组判断、投影、斜率或窗口；规则先定、结果后看。
4. 需要低 R bootstrap 省时，先用少量同索引重复作配对验证；不能假设它天然保守。
5. 有实质信号且本地资源不足，再评估云算力用于高 R 重拟合和正式重复。不能用多租服务器弥补未定义的评分或错误接线。

这不是 E0 的补跑清单，也不是 E2 生活闭环的前置要求。

### 4.3 R2：需要正式回收报告时补接线

- 真实匹配／打乱选择、同题重复数据、模型与场景身份的输入校验。
- P10 抽样计划、实际层人数、权重、S 的真值矩进入入口和产物。
- 逐人表、人口报告、层内报告与跨层报告分别输出。
- 真实重复子集校准 σ；同题重复不算新的独立选择集。
- 实际抽样、N/T/J、世界、噪声、拟合规格、积分设置和协议全匹配才复用地板。
- 正式协议检查与复用签名要真正进入消费者路径；缓存缺失不能静默重拟合。
- 新参数只在实现后写成可执行命令；目前不存在 `p8_formal.yaml`。

### 4.4 R3：正式方向指标与不确定性

先具备真实输入和匹配设计，再做有效 B≥200 的联合流程。各臂在同一次人设块抽样下重算必要中心、分母、路径与指标。

必须分清：固定／重标定 σ、单点／全 t、总体／层内、逐点区间／同时置信带。当前单点两臂窗口不代表全部完成。

门二的 0.8、1.96、0.5 是设计规则，不是定理；正式使用前将选定值与用途写入新配置。门三报告可检测效应和条件结果，“不显著”不能变成“没有依赖”。阈值和对称判据不随结果改变。

### 4.5 已知技术欠账

这些要保持可见，但不在 E0 扩成大修：

| 欠账 | 何时处理 |
|---|---|
| ALR ±40 裁剪及与似然／梯度的一致性风险 | 使用极端坐标或修改估计器时；报告实际触发 |
| 多起点按未抛异常结果的似然选解，不等于全部已收敛 | 正式回收报告前核对有限性／收敛筛查，保留诊断 |
| 画像生成入口 seed/config 溯源参数未传齐 | E2 使用冻结画像前 |
| 货币损失两端语义范围校验不完整 | 正式 V2 金额报告前，取得 econ 修改授权 |
| 精度脚本预算不含全部参照与尾部工作 | 下一次数值任务前，不能称现参数为整任务硬上限 |
| 若干诊断脚本重复构造数据 | 有实际维护需要时抽公共数据构造；保留独立数学交叉核验 |
| 历史文档／代码注释引用旧节号 | 用 README 迁移表阅读；后续针对性同步 |
| 真值标度与职业工资尚属简化 | E3 实际数据接入及 V3 模型验证 |

## 6. 预算与工作纪律

### 6.1 先算规模，再调用

固定城市三年的基础年度调用数约为：

$$
N_{\mathrm{users}}\times C_{\mathrm{cities}}\times B_{\mathrm{copies}}\times3
\times K_{\mathrm{calls\ per\ year}}.
$$

另加画像生成、有限重试和研究重复。比如 1 个用户、4 城、每城 3 个分身、每年 1 次调用是 36 次年度调用；只是规模例子，不是冻结设计或已批准预算。

输入／输出 token 与价格按实际模型另算，不沿用旧“数十美元跑完”估价。CPU 积分、拟合和 bootstrap 也单独估墙钟和内存。先小后大，结果有价值再租云资源。

### 6.2 每次运行保存什么

代码提交、未提交改动标识、数据／配置指纹、人设／场景 ID、协议版本、模型版本与设置、seed、各类 R、重复数、有效数、失败原因、调用与计算耗时、结果路径。

长任务按批保存 partial，预算从参照计算前开始，包含尾部报告。估计超预算时先缩小或提出新预算；不能无声启动另一轮拟合。

### 6.3 变更应与问题相称

- 一次任务一个清楚验收对象，先检查是否已有可复用实现。
- 修改公式、信息条件、抽样或评分协议，都要记录版本及受影响产物。
- 不覆盖不同协议结果；旧结果保持原标签，必要时追加适用范围说明。
- 测试选能发现实际错误的检查，不以新增测试数量表示进度。
- 大规模运行不为文档编辑或小修复默认启动。
- 文档、代码与结果的“已完成”陈述都要有对应证据。
