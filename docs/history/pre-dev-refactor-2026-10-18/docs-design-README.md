## 以后怎样放

- 持续更新的技术说明放本目录，按模块/机制命名，不为每一轮复制整篇。
- 阶段设计讨论与回顾放 history/，以日期命名；保留当时结论，更正追加指针。
- 可复用的执行 prompt 放 prompts/，写清对应设计和本轮范围。
- [DECISIONS](../../DECISIONS/) 保留正式技术裁决；[runs](../../runs/) 保留运行证据，不搬进教程。
- 已有 [MEMOS](../../MEMOS/) 中的 P8/P9/P10 研究与代码审核记录是历史研究证据，原地保留。未来如写这些模块的长期技术详解，也放本目录并链接旧证据。
- 原生活设计备忘已归入 history/，旧 MEMOS 路径保留迁移入口，兼容旧链接。

## 效力和阅读顺序

先读 [README](../../README.md) 的愿景，再读 [PLAN](../../PLAN.md) 的工程状态，需要细节时查本目录和有效 ADR。所有者最新明确决定优先；说明文档不是另一套公式实现，不凭日期覆盖 ADR，也不把待实现设计当成运行事实。

每篇说明都要回答：做什么、如何计算、数据从哪来、代码在哪、怎样验证、省略了什么、哪些偏好的人受影响。更新参数或规则时同步代码、ADR、状态与证据链接；无关历史结果不改写。

每次改变模型参数、结构假设、资料映射或代理认知条件，同轮更新参数目录的相关 ID。目录是跨模块导航，不再复制出第二套运行配置；未来研究结果回到同一条目，保留旧版本和证据。尚未实现的 V2 设想只登记含义与待定项，不为占位填数值。
