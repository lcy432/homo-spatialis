# 下一轮：积分精度检查方案

**本轮不执行。** 这里只把指标、容差与预算定下来，免得到时候一边跑一边定判据。

起因见 `MEMOS/2026-09-16-p9-recovery-estimator.md` 订正九：3.1 的换坐标恒等式
对**任意** draws 数都成立（`a' = T·a` 是逐点线性变换，R=1 也成立），所以它
**证明不了** 200 draws 的积分精度够用。那件事至今**未验证**。

---

## 一、必须分开的两件事

混在一起问"200 draws 够不够"会得到一个没法用的答案，因为两条路径的成本差两个
量级。

| | 甲：固定参数下的后验积分 | 乙：更高 draws 下重估参数 |
|---|---|---|
| 问什么 | 参数钉死时，R 个点够不够积出 `E[w\|choices]` 与总体矩 | 换 R 会不会把优化落到另一个解 |
| 要跑什么 | 目标函数/后验求值，**不优化** | 完整四起点拟合 |
| 单次成本 | 秒级 | 约 900s |
| 本仓库现状 | 有缓存参数，可直接做 | 要新拟合 |

**先做甲。** 若甲显示 200 draws 下矩与后验已经稳定，乙的优先级大幅下降——那时
剩下的问题只是"似然绝对水平不可跨 R 比较"，而那一条已经记录在案且已被遵守
（公共随机数，同批 draws 内比较）。

## 二、甲：固定参数下的积分精度

**用缓存参数，不新拟合。** `runs/2026-09-16-p9-evidence/minimal-numerical-check.json`
里的 material 解就是参数；`check_base_change.py --cache` 已经能在几秒内加载并
校验它。

**指标**（三个，都是本项目真正要报的量）：

```
M1  总体权重均值      max_k |E[w_k]^(R) − E[w_k]^(R*)|
M2  总体权重协方差    ‖Σ_w^(R) − Σ_w^(R*)‖_F / ‖Σ_w^(R*)‖_F
M3  个体后验          max_i max_k |E[w_ik|y]^(R) − E[w_ik|y]^(R*)|
```

`R* = 12800` 作参照点。**参照点不是真值**，所以还要第二条腿：

```
M4  蒙特卡洛标准误    对每个 R，用 8 组独立旋转的 Halton 序列重算 M1–M3，
                      报组间标准差
```

M4 是关键——只比 `R` 与 `R*` 会把"两者碰巧接近"读成"都收敛了"。独立重抽给出
的是**这个量自己的**模拟误差。

**R 网格**：`{50, 100, 200, 400, 800, 1600, 3200}`，外加 `R* = 12800`。
加 50 与 100 是为了看出趋势——只从 200 起步，曲线太短，判断不了 200 处在
平台上还是斜坡上。

**事先定死的容差**（相对于本项目要报的精度）：

| 指标 | 容差 | 理由 |
|---|---|---|
| M1 | 2e−3 | 权重是 O(0.1) 量，报到千分位；再细无意义 |
| M2 | 1e−2 | 协方差比是主证据，但它本身要报到百分位 |
| M3 | 5e−3 | 个体后验喂给 `d_i`，而 `d` 的量级是 O(0.3) |

**判据**：R=200 的 M1–M3 全部在容差内、且 M4 给出的模拟标准误小于对应容差的
一半 → 200 draws 对矩与个体后验够用，记为已验证。任一项不过 → 报出最小满足
容差的 R，**不自动改默认值**（改默认是独立的工程决定，且会让所有历史结果
不可比）。

**预算**：7+1 个 R × 8 组旋转 × 一次后验求值。最大的那档（12800×8）约等于
64 次 200-draw 求值，单核**几分钟**。这是本方案先做甲的全部理由。

## 三、乙：更高 draws 下重估参数

**只在甲不过、或甲过了但仍想确认优化落点时做。**

设计：`R ∈ {200, 800, 3200}`，每档跑完整四起点 `fit_research`，比较

```
L1  选中解的 μ_a、Σ_a（搬到同一坐标后比）
L2  权重空间的矩（与甲的 M1/M2 同口径）
L3  起点极差 loglik_spread —— R 变大时它应当变小；不变说明是真多峰，
    而不是模拟噪声造出来的假峰
```

**不比跨 R 的似然绝对值**（`DECISIONS/0013` 第四节：200→800 移动约 33 个单位，
跨 R 不可比）。

**预算**：3 档 × 4 起点 × 约 900s ≈ **3 单核小时**，3200 draws 那档会更贵
（求值成本随 R 线性），估 **6–10 单核小时**。跑之前要明确批准。

## 四、不在本方案里的

- 不改 `n_draws` 的默认值。
- 不改估计器数学、不加正则项。
- 不重跑 baseline、门一、bootstrap。
- 甲乙都**不消耗大模型调用**。
