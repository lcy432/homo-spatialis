## 1. 用户能做什么

用户故事（合成人物；结果是本地离线 mock 规划器跑出来的，不代表模型能力，也不排名真实城市）：

1. 小林打开专属链接 `/invite#token=…`。页面在任何渲染之前读出秘密、立刻从地址栏与历史里抹掉，再用同源 JSON 换会话；
   首页显示“启动模拟的机会：共 3 次；已开始 0，已预留 0，还能用 3”。
2. “开始之前”页选显示语言、模型输入与输出语言、外观（默认稿纸）。点“开始填写”才新建服务器草稿：编号与修订号由服务器给，
   城市按规则预选全部 6 座，其余未答。
3. 第 1 步清除选择、只留西雅图与芝加哥（地图上点美国只筛选列表，不替小林选城）。第 2 步在职业目录里搜“文员”，结果只有
   “办公室文员”（名称与职责），点一下就选中，搜索框里的字不保存；年龄 35、现金 3000（2024 年美元）；最高学历选“高中”，
   职业证书点“没有证书”；文员没有开局经验要求，所以不问经验。
4. 第 3 步独立评分：六个方面起初都是“未答”，饼图是空的。小林给六项分别打 80/40/40/20/10/10（不必凑 100；原始合计 200），
   饼图临时显示 40/20/20/10/5/5 并标明是临时预览；改一项不改别的项。用方向键把安全从 40 推到 45 是一条撤销记录，撤销一次回到 40。
   物质内部打 25/25/30/20。想“同等重视”就点一下，每项设成 50（六维每项权重 50/3）。
5. 第 4 步：健康三题（一题暂不确定）；兴趣面板点“音乐”；口味面板搜“川菜”只找到“中餐”，并显示 E3 的说明（本版不区分地方菜），
   小林点“中餐”。没有硬要求、属性偏好或文字解释的板块；补充说明照旧可写（只供分身参考）。
6. 第 5 步左右对照“我填的”与“系统将采用的理解”：目录职业的名称与职责、按学历换算出的资格与理由（“高中毕业或同等学历”满足文员的
   开局要求）、六维的原始评分（合计 200）与 E3 换算的精确权重（合计 100）、面板里选的类别；知悉项的说明来自服务的显示信封，逐项知悉后
   确认画像。
7. 确认之后是本次设置：每城 1 个分身、3 年、停机上限保持默认 20 元（“到了就停下的上限，不是预计费用”）；页面按这些选项取一份只读的
   设置预览（范围说明、必要知悉项、此刻能否开始），小林勾选知悉项、点一次“确认并开始”。双击也只发一次；回复丢了就用同一个键找回。
   之后在同一个等待页看进度条与一句话：后台检查 → 排队 → 生活模拟（“已结算 3/6 个分身年度”）→ 完成；检查通过后服务自动开始，
   页面不再问第二次。小林中途离开再回来，仍是同一次运行。运行结束后首页显示“已开始 1，还能用 2”。
8. 结果先给本轮城市比较（每城 C / E / M、均值与分母、模拟缺失范围、比较方向），再进单城详情（J、L、V 并排解释，资料性质、目录
   覆盖、这次运行的范围说明），最后看某个分身逐年的生活记录。

## 2. 结构

```text
web/src/
  contract/   生成的类型（34 份消息）、Ajv 校验、样例读取（只给测试与开发画廊）、待 E3 的临时文字
  api/        HTTP 客户端（同源、CSRF、发送前后校验、身份代次）、各接口、会话与身份、查询与轮询（含显示信封）
  display/    显示附层：按位置取文字的纯函数（fields.ts）；页面作用域（scope.tsx：按字段位置 + 来源核对取译文、知悉项、作答状态、
              实际显示的缺译数）；各对象里常用位置的拼法（pointers.ts）；纯文本名称（names.ts）
  draft/      状态更新函数（四种答案状态、独立评分、按手势的撤销、目录职业、资格、面板）、自动保存、目录搜索（catalog.ts）、审阅、
              一次“确认并开始”的本地找回记录（startRecord.ts）
  i18n/       i18next：界面字典 zh / en（键由类型强制一致）；E3 业务文字的显示（<Zh> 在显示作用域里取英文，缺译标“未翻译”）
  ui/ prefs   外观（稿纸 / 地球）与本机偏好（只存显示语言与外观）
  geo/ view   底图加载；结果展示模型与 J 色阶（纯函数）
  components/ 独立评分控件（Allocator）、职业目录（CatalogPicker）、多选面板（ChoicePanel）、本次设置与一次开始（StartPanel）、城市列表、
              平面地图、地球、运行前检查、进度、比较图、年度记录……
  pages/      会话、首页、开局设置、五个填写步骤、运行意图、结果三层、我的运行、设置与删除
```

* 一套业务状态，两种外观：外观只换颜色变量与地图渲染器；页面、答案、选择、运行与结果只有一份，切换不保存、不提交。
* TanStack Query 管服务快照（键带身份代次）；状态更新函数管还没保存的编辑与撤销；服务修订号不当本地编辑计数。
* 展示模型只组织公共事实，不算新的分数、缺失范围、资格或恢复条件；数字一律显示 E3 给的 `display`，精确值只用来定位。

## 3. 契约与版本

* 类型由 `npm run contract:gen` 从 `contracts/product/v3/`（`e3a-product-schema-v3.5`，36 份；问卷 `e3a-questionnaire-v0.5-draft`、
  转换 `e3a-conversion-v4`；服务 API `e3c-service-api-v1.4`，显示附层 `e3-display-v2`）生成；`npm run contract:check` 在
  `test` 与 `build` 之前执行，哈希或生成结果对不上就失败。Ajv（2020）不填默认值、不转类型、不删字段：请求不合结构就不发，回复不合
  结构就不用（页面显示“结构不符”），不“修成能用”。
* 别名 `@contracts` 默认指向仓库的 `contracts/product/v3/`。几个会话共用工作区时，别的会话可能已经改了 schema 却还没提交：
  `E5_CONTRACTS_DIR` 可以指向只含已提交代码的工作树，让页面、核对与服务说同一个版本（浏览器测试同时设 `E5_SERVICE_REPO`）。

## 4. 会话与身份

* 秘密只在内存里交给 `POST /api/v1/session` 一次；会话在 HttpOnly Cookie，CSRF token 只放内存（刷新后 `GET /session` 取回）。
  修改请求带 `X-CSRF-Token`；查询与换会话不带。
* 身份代次：换邀请、退出、401、删除全部都先把代次加一、取消在途查询、清空缓存，再加载新内容。HTTP 层记下请求发出时的代次，
  回复到达时代次变了就丢弃（不会闪现上一个人的内容）。401 时私有页面锁住，提示重新打开专属链接。
* 浏览器存储只放显示语言与外观；E5-A 留在标签页里的 v2 样例答案启动时清掉，不并入服务身份。
* 退出只有服务确认了才算（204，或 401 = 服务那边已经没有会话）。请求没送到或回执丢了，页面进入“退出还没有得到确认”：私有页面先藏起来，
  不说已经退出，给“再试一次退出”与“重新检查”（独立核查 F1）。再试时服务回答 401 就是退出成功——上一次其实已经处理了。
* 首页每次显示都重新读会话视图，开局新建草稿后也刷新一次：站内回首页立刻有“继续填写”，不靠整页刷新（F2）。

## 5. 草稿与自动保存

* 停手 1.5 秒才保存；同一时间只有一个保存请求；保存期间又改了，存完用新修订号再存。发送时 `expected_revision` 与
  `draft.revision` 都写服务器当时的修订号（服务要求两者相同），服务器存下后加一。
* 409：先读服务器那一版。内容与本地相同（上一次回复丢了）就直接采用；不同就停在“冲突”，不再自动保存，由用户选“改用服务器的版本”
  或“把我这里的内容存成新的一版”——不会最后写入者自动获胜。429 按服务给的秒数再试；断网按 5、10、20、30 秒退避再试。
* 每个身份的修改请求限每分钟 60 次：停手再存加上审阅只在“已保存”时请求，正常填写远低于这个数。离开页面前还有没保存的改动会提醒。
* 未答 = 没有这一项；明确 0 = `provided "0"`；无所谓 = `indifferent`；暂不确定 = `unsure`。健康题没选就是未答（不预选任何一项）。
* 职业按 `capabilities.input_catalog` 直接选（交接单第 14 节）：分组索引（桌面是列表、手机是下拉）+ 关键词搜索（E3 的
  `catalog_search_nfkc_casefold_all_terms_v1`：NFKC、不分大小写、按空白切词、每个词都要命中某个搜索词；`web/src/draft/catalog.ts`
  是同一规则的页面实现，`tests/catalog.test.ts` 对照交接单的表）+ 直接点选；提交 `{mode: "catalog", selected_candidate, catalog_version,
  catalog_fingerprint}`，`raw_text` 为空，搜索词不保存。没有结果时显示 E3 的 `search.no_match`（支持范围）与“清除筛选”，从不自动换职业。
  换职业只换职业与经验题，学历、证书与其他事实不动；为上一个职业填的经验条目列出来由用户去留。文字描述（`mode: "text"`）只在资料包没有
  目录时出现（兼容）。
* 资格：最高学历单选（含“暂不确定”“未答”）；证书多选（勾选、带可移除的标签；“没有证书”= `provided` + 空表，与未答分开）；相关经验只在
  选中职业的 `experience_question` 不为空时问，按 E3 的 `related` 职业逐个填整年数。页面不换算资格：审阅页显示 E3 的 `review.qualifications`
  （来源、换算出的资格与理由、开局要求是否满足、还要问的经验题）。
* 六维与物质是独立评分（`ratings_normalized_v1`，DECISIONS/0047；`web/src/components/Allocator.tsx`）：每项一根 0–100 的滑块加数字精调
  （步长、小数位、同等重视的分值读 `capabilities.points.ratings`），互不影响、不必凑 100；拖动只改当前项的原始评分，其他项逐项不变
  （独立核查 E5-R6 的旧“来源 / 池 / 转移”入口与隐藏提交逻辑全部删除，按已批准的新交互替换解决）。初始不预填：滑块停在 0 仍是“未答”，
  用户拖动、输入数字或点“记为 0”才是明确的 0；无所谓 / 暂不确定保留状态不转数值。饼图是**临时预览**：权重 = 100 × 评分 ÷ 本组已答
  评分之和（精确分数），只画已答的项并列出未答项，已答全是 0 时没有可用比例；正式权重以 E3 审阅为准（`lines[].exact`），显示的四舍五入
  不回写。“同等重视”是用户主动把本组每项设成 50（会替换已有答案时先说明，可撤销）。一次指针手势（按下 → 拖动 → 松开）一条撤销记录，
  中途只本地预览、松手才写进草稿；下一次手势是新记录（E5-R5）；连续方向键按同一编辑序列合并，失焦结束。写法不对的数字（超过 100、
  分数、太多小数）原样保留并提示，不悄悄截断。物质父项明确为 0 时四项收起、标为不适用，草稿里的四项答案原样留着，父项改回正数就找回；
  父项未答不等于父项 0。
* 兴趣与口味是两块可选的多选面板（`ChoicePanel`，条目与分组来自 `input_catalog.leisure / taste`）：点选即选、再点取消，有数量与标签；
  条目 ≥ 10 个时显示 E3 的分组索引与搜索框（搜索只筛选，不改答案），命中的 `search_notes` 显示出来（“川菜”→ 只有“中餐”+ 说明）。
  一个都不选就是未答；“暂不确定”“没有固定爱好 / 没有口味偏好”“随当地体验”收在“其他情况”里，与已选类别互斥——切换时先说清会清空哪几项。
  没有“用文字描述”的入口。
* 硬要求与属性偏好不再出现：新草稿这两项是空表，没有默认通勤上限；没有隐藏控件再提交旧值。
* 只适配当前问卷（所有者 2026-10-26 决定删除草稿迁移）：`meta` 的共享结构 / 问卷 / 转换版本与能力清单不一致的草稿不进编辑器，
  `DraftRoute` 只显示“这份草稿是旧版本问卷填的，请新开一份”（写明两个问卷版本）与新开 / 回首页两个入口；页面不改写任何版本字段、
  不迁移、不把旧答案抄进新控件，也没有旧的百分比分配（manual / equal_split）控件。审阅里的 `version_changed` 同样只提示新开一份。
  已确认的画像、已开始的运行与历史结果不受影响：按原身份与绑定的显示资源读，停下的旧运行照常恢复。

## 6. 确认、本次设置、一次“确认并开始”与等待页

* 审阅的永远是服务器上已保存的那一版；改过答案，旧审阅与旧确认都失效（确认画像绑定的修订号对不上就不再显示本次设置）。
* 本次设置（`web/src/components/StartPanel.tsx`，DECISIONS/0048）：选项范围只读 `SessionView.rules.options`，省略就用服务默认值，城市来自
  确认画像不另传。按当前选项取一份只读的设置预览（`POST /run-start-preview`：不排队、不占次数、不调用模型）：有效设置、规划器与停机上限
  （不叫预计费用）、范围说明、必要知悉项、同意身份 `consent_fingerprint`、此刻能否开始（`start_allowed = false` 时没有可点的开始按钮，
  只显示正式原因）。选项一变就取新预览，旧勾选随同意身份一起清掉；换语言只换文字（同一份回复自带中英），同意身份不变。
* 一次“确认并开始”：勾选全部知悉项后点一次，`POST /run-intents` 带 `start = {start_when_ready, consent_fingerprint, acknowledged, accept,
  idempotency_key}`。发请求**之前**把键与原始请求存进本地记录（`draft/startRecord.ts`，按确认画像编号隔离，只存找回所需内容；换身份、
  退出、删除全部内容时清掉）；回复丢了（断线、关页、刷新）就重发**同一个请求、同一个键**找回同一个意图——不猜列表里最新一项、不换新键。
  服务明确拒绝（`start_consent_stale` → 重新取预览再确认；`start_acknowledgement_missing`；付费关着、次数用完、意图冲突）时什么都没建，
  记录作废；`idempotency_conflict` 照实显示，不自动换键绕过（只能明确作废本地记录）。连点在途时不再发送。
* 之后页面只读：服务检查通过后按授权自动开始，页面不发 `submit`、不恢复、不重开；没有第二个开始按钮。没有授权的意图（`start = null`，
  旧客户端留下的）只提示取消后用新流程重新确认并开始；页面不再提供第二次确认。
  授权作废（`start.state = void`）时显示原因（`void_reason`）与服务的说明；`allowed_actions` 含 `start_again` 才重新取预览、用户再确认一次
  （新键）。取消、恢复、删除都在对话框里确认、只按 `allowed_actions`，不自动重试。
* 等待页（`pages/IntentPage.tsx`，DECISIONS/0049）照服务的 `progress_summary` 画：阶段标签、一句当前状态（新句覆盖旧句，不累积历史）、
  依据记录的时间；`mode = indeterminate`（检查、排队、整理）是往复的不定长条，`clone_years` 按已结算 / 计划的分身年度数（“已结算 18/72
  个分身年度”），`finished` 只在结果真的可读时；不按调用次数、不按时钟增长。`needs_attention`、取消、删除、过期时停止“仍在忙”的动画，
  显示原因与下一步；断线时保留最后一份摘要与它的时间并说明不能刷新，不当成完成。`deletion.state` 区分删除中与已删除；流程结束但结果读不到
  不算完成。保留“查看本次输入与设置”（设置、运行前检查、公开进度）与“离开，稍后回来查看”；没有后端支持的暂停按钮。
* `checking / queued / running / deleting` 时每 3 秒只读查询一次，页面在后台不查询；断线按退避，429 按服务的秒数。结果的查询键带意图的
  `updated_at`：恢复后出了新结果、删除或过期都会重新读。
* 三种钱分开写：模拟现金（用户的开局资金）、停机上限（`max_cost`，到了就停）、启动机会（次数）。费用分已核算、用量不确定、在途预留，
  缺项写“未知”不写 0；规划候选数与服务尝试数分开。
* 期限照服务：`expires_at` 是**现在适用**的截止时间，旁边写 `expiry_basis`（从最后一次有效操作起算 / 结果从首次结束起算 /
  运行自身的期限 / 服务没有给出依据）；没有截止时间就写没有，不用 updated_at 加 30 天硬算。确认成功后显示画像摘要
  （首次确认时间、保存到），并写明重复确认不延长、画像到期不影响已经准备好的模拟（`GET /profiles`、`/profiles/{id}` 已接入 API 层）。
* 预览与检查不扣次数；检查通过才按服务事务预留，首次进入 E1 才使用。页面只展示 `quota`，不自己扣减或回填。
* 取消 / 恢复 / 删除仍只看 `allowed_actions`；被拒（例如 `cancel_not_allowed`）时显示服务的三句话并重新读意图，按钮随之变化。

## 7. 结果三层

* **城市比较**：每城一张卡（C / E / M 组成条、均值与分母、E3 的标题句）；比较图里圆点是完整者的平均 J（分母 C），横条是模拟缺失范围
  （分母 C + M）。横条不是误差条或置信区间，均值可以落在它外面——例如 1 个完整分身 J = 0.3、1 个缺失分身的已知月份给出下界 0.6、
  上界 0.8，城市范围 = [(0.3 + 0.6) / 2, (0.3 + 0.8) / 2] = [0.45, 0.55]，均值 0.3 在外面，两者各按公共值定位。数值表是等价的文字版本。
  城市顺序照服务给的顺序；不写“最佳城市”，比较只用 `comparisons` 的方向。
* **J 色阶（所有者 2026-10-24 决定）**：差距小时适度放大，但不放大成“第一名满分、最后一名零分”。本轮所有城市（所有国家共用）的最低
  a、最高 b，窗口宽 w = min(1, max(0.02, 2 × (b − a)))，以 (a + b) / 2 为中心，超出 [0, 1] 就平移回来。最新六城样例 104：a = 0.5141（休斯敦）、
  b = 0.5881（芝加哥）→ w = 0.148，窗口 [0.4771, 0.6251]，两端城市落在色阶的 25% 与 75%。差距小于 0.01 时窗口固定宽 0.02：本地 mock
  主闭环的西雅图 0.5602、芝加哥 0.5643 落在 40% 与 60%，看得出高低又不画成两个极端；差 0.0002 只差 1%，就画成同一个颜色。
  下限起初取 0.08，截图里差 0.004 的两城几乎同色，不符合“不要完全一个色”，改成 0.02。图例写明窗口两端，不代表 0 分或满分。
  比较图刻度的小数位按步长定（步长 0.0025 写四位），不出现重复的刻度标签。
  C = 0、未生成的城市不上色（中性符号与文字）；含 M 但有均值的城市保留均值颜色，另标缺失人数。
  注意：E3C 设计稿（[e3c-display-and-service-handoff](e3c-display-and-service-handoff.md) 第 5 节）写的是固定 [0, 1]、不按六城最小 / 最大拉伸；
  界面这里按所有者的决定做，分歧已在交付报告里列出。
* **单城详情**：J、L、V 并排（不画 L + V = J 的堆叠），C / E / M 与缺失原因、硬要求核验（未核验 ≠ 满足）、这座城的说明与比较；资料性质
  （观测 / 推导 / 估计 / 合成设定的条数、登记的模型设定、共同背景、通勤方式、税、构建计数——条数不是“真实性百分比”）、选项目录覆盖、
  这次运行绑定的那份运行前检查的范围说明（指纹对不上就写“读不到”，不用别的检查替代）。
* **分身年度记录**：年初 / 年末现金与年度已支付总额（年度合计，不是月度流水）；工作、住房、住处片区（片区典型通勤与实际通勤分开写）、
  逐月通勤（“每月通勤费”）、用车权、食品、耐用品（买到 / 在用 / 到期 / 剩余）、设备与服务、日常支持（计划 / 获得 / 没获得）、消费篮子
  （“0” 与 “—” 分开）、活动、没成交的购买、设备故障、健康与家务的逐月条带、税。全部是公开事实，不写心理活动或因果解释；模型的计划理由
  本版没有公开，单独留一栏说明。
* 月份条带（F3）按公开的月份列表细分：已获得 / 已安排但没获得 / 没有安排 / 没有生活 / 记录不足；设备条带说在用 / 不在用。
  例子：全年都生活、只在 7–12 月安排清洁、7 月没获得——1–6 月是“没有安排”，7 月是“已安排、没获得”，8–12 月“已获得”；
  年中第 8 个月结束生活的，9–12 月才是“没有生活”。两个列表都没有的月份是“记录不足”，不补零。
* 比较图的模拟缺失范围没有最小宽度（F4）：两端严格按公共值定位，上下界相等就是精确位置上的一道竖线；扩大的只是鼠标悬停区域。

## 9. 两种外观与地图

* 英文字体固定（所有者 2026-10-26 选定，只定英文；中文仍用系统字体，另议）。字体文件经 `@fontsource` 随包打包（latin 子集），不走网络。三档各司其职：
  大字 `--font-display` 只给页面 h1 与页眉品牌，是艺术字，同一页最多三处，不得用于 h2 以下、按钮、表格或正文；中字 `--font-heading` 给 h2–h4；
  小字 `--font-body` / `--font-label` / `--font-num` 给正文、标签与数字。稿纸：Great Vibes / EB Garamond / EB Garamond；
  地球：Rajdhani 600 / Space Grotesk 600 / IBM Plex Sans 与 IBM Plex Mono。对照页上的候选（Dancing Script、Pinyon Script、Exo 2、Sora 等）没有采用。
* 稿纸：暖白方格纸背景、石墨线、少量彩铅色；手写感只给标题（中文用系统楷体，英文用打包的 Great Vibes，OFL 许可）。纸纹只在页面背景，
  不加在地图、图表或数据点上。地球：深蓝灰面板、克制的青色。

  挪进小框）。铅笔感来自双层描边与纹理，不移动顶点。
* 地球：react-globe.gl（three.js），按需加载；拖动旋转、缩放、不自动旋转；减少动态效果时视角直接到位；“回到全球视角 / 转到所选国家”。

  没有 WebGL 或加载失败就说明原因、退回平面地图。
* 底图：Natural Earth 1:10m 国界（公有领域），中文界面用中国立场版、英文界面用默认版，`web/scripts/build-basemap.mjs` 简化成约 290 KB，

  （中文版的 ESB）会被 d3 读成“除它以外的整个地球”，生成时把它的环倒过来；`web/tests/basemap.test.ts` 检查两版都没有比半个地球还大的多边形。
* 城市点来自 E3 的地理显示清单 `GET /api/v1/display/geography?pack_fingerprint=…`（`web/src/geo/anchors.ts`）：输入按能力清单的资料包读，
  输出按**这次结果自己的**资料包指纹读；只给 `anchor_status = available` 的城市画点，按 `city_ref` 配对（编号自带地理方案与版本），
  unknown / not_applicable（合成城市）/ 清单里没有的城市列出原因、不猜位置。六城的点是 Census 都会区内部点（代表点，不是住处或市中心），
  平面地图与地球用同一个锚点，标签用清单里当前语言的短名。历史结果先读这份结果的显示信封，把它 `resource_version`（结果生成时绑定的
  显示资源版本）传给地理清单，并在图例旁写明版本；版本为空、信封读不到或还没读到时**不发任何地理请求**（省略版本读到的是当前登记的版本，
  不是历史版本；交接单第 19 节），页面写“这份结果没有绑定的历史显示版本”、不画城市点、不用当前锚点兜底，底图、列表与表格照常（E5-R4）；
