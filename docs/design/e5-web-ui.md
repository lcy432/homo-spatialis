## 1. 用户能做什么

用户故事（合成人物；结果是本地离线 mock 规划器跑出来的，不代表模型能力，也不排名真实城市）：

1. 小林打开专属链接 `/invite#token=…`。页面在任何渲染之前读出秘密、立刻从地址栏与历史里抹掉，再用同源 JSON 换会话；
   首页显示“启动模拟的机会：共 3 次；已开始 0，已预留 0，还能用 3”。
2. “开始之前”页选显示语言、模型输入与输出语言、外观（默认稿纸）。点“开始填写”才新建服务器草稿：编号与修订号由服务器给，
   城市按规则预选全部 6 座，其余未答。
3. 第 1 步清除选择、只留西雅图与芝加哥（地图上点美国只筛选列表，不替小林选城）。第 2 步写“我在写字楼做全职文员……”，停手后
   服务审阅已保存的那一版，给出候选“办公室文员”，小林点“就是这个”；年龄 35、现金 3000（2024 年美元），确认持有高中学历。
4. 第 3 步主动均分：每项显示 16.7（精确 50/3）。把安全改成 20，页面先问要不要改成手动分配，然后显示“多出 3.3 分（精确值
   10/3）”：5 × 50/3 + 20 = 310/3，减 100 是 10/3；拿显示值算会错成 16.7 × 5 + 20 − 100 = 3.5。小林点“从哪一项减”选物质，
   物质变成 40/3，“已分完”。物质内部再均分，每项 25。
5. 第 4 步：健康三题（一题暂不确定）；兴趣写“喜欢音乐”、口味写“喜欢川菜”，从服务给的候选里主动勾选（真实资料包把川菜归到
   “中餐”）；通勤上限 60 分钟。
6. 第 5 步左右对照“我填的”与“系统将采用的理解”（合计精确 100、物质 40/3），逐项知悉后确认画像；选每城 1 个分身、3 年，停机上限
   保持默认 20 元（页面写明“到了就停下的上限，不是预计费用”）。准备模拟不扣次数。
7. 运行前检查约一两分钟，通过后在等小林确认：勾选“我知道这次的范围、限制与停机上限”，点“确认开始”。双击也只发一次；断线时
   不自动重发，页面先查询，再点用同一个键。运行结束后首页显示“已开始 1，还能用 2”。
8. 结果先给本轮城市比较（每城 C / E / M、均值与分母、模拟缺失范围、比较方向），再进单城详情（J、L、V 并排解释，资料性质、目录
   覆盖、这次运行的范围说明），最后看某个分身逐年的生活记录。

## 2. 结构

```text
web/src/
  contract/   生成的类型（28 份消息）、Ajv 校验、样例读取（只给测试与开发画廊）、待 E3 的临时文字
  api/        HTTP 客户端（同源、CSRF、发送前后校验、身份代次）、各接口、会话与身份、查询与轮询
  draft/      状态更新函数（四种答案状态、精确分数、撤销）、自动保存、草稿编辑器、字段 → 步骤、审阅
  i18n/       i18next：界面字典 zh / en（键由类型强制一致）；E3 业务文字的显示（英文界面里标明中文原文）
  ui/ prefs   外观（稿纸 / 地球）与本机偏好（只存显示语言与外观）
  geo/ view   底图加载；结果展示模型与 J 色阶（纯函数）
  components/ 分配器、城市列表、平面地图、地球、运行前检查、进度、比较图、年度记录……
  pages/      会话、首页、开局设置、五个填写步骤、运行意图、结果三层、我的运行、设置与删除
```

* 一套业务状态，两种外观：外观只换颜色变量与地图渲染器；页面、答案、选择、运行与结果只有一份，切换不保存、不提交。
* TanStack Query 管服务快照（键带身份代次）；状态更新函数管还没保存的编辑与撤销；服务修订号不当本地编辑计数。
* 展示模型只组织公共事实，不算新的分数、缺失范围、资格或恢复条件；数字一律显示 E3 给的 `display`，精确值只用来定位。

## 3. 契约与版本

* 类型由 `npm run contract:gen` 从 `contracts/product/v3/`（`e3a-product-schema-v3.3`，28 份）生成；`npm run contract:check` 在
  `test` 与 `build` 之前执行，哈希或生成结果对不上就失败。Ajv（2020）不填默认值、不转类型、不删字段：请求不合结构就不发，回复不合
  结构就不用（页面显示“结构不符”），不“修成能用”。
* 别名 `@contracts` 默认指向仓库的 `contracts/product/v3/`。几个会话共用工作区时，别的会话可能已经改了 schema 却还没提交：
  `E5_CONTRACTS_DIR` 可以指向只含已提交代码的工作树，让页面、核对与服务说同一个版本（浏览器测试同时设 `E5_SERVICE_REPO`）。

## 4. 会话与身份

* 秘密只在内存里交给 `POST /api/v1/session` 一次；会话在 HttpOnly Cookie，CSRF token 只放内存（刷新后 `GET /session` 取回）。
  修改请求带 `X-CSRF-Token`；查询与换会话不带。
* 身份代次：换邀请、退出、401、删除全部都先把代次加一、取消在途查询、清空缓存，再加载新内容。HTTP 层记下请求发出时的代次，
  回复到达时代次变了就丢弃（不会闪现上一个人的内容）。401 时私有页面锁住，提示重新打开专属链接。
* 浏览器存储只放显示语言与外观；E5-A 留在标签页里的 v2 样例答案启动时清掉，不并入服务身份。
* 退出只有服务确认了才算（204，或 401 = 服务那边已经没有会话）。请求没送到或回执丢了，页面进入“退出还没有得到确认”：私有页面先藏起来，
  不说已经退出，给“再试一次退出”与“重新检查”（独立核查 F1）。再试时服务回答 401 就是退出成功——上一次其实已经处理了。
* 首页每次显示都重新读会话视图，开局新建草稿后也刷新一次：站内回首页立刻有“继续填写”，不靠整页刷新（F2）。

## 5. 草稿与自动保存

* 停手 1.5 秒才保存；同一时间只有一个保存请求；保存期间又改了，存完用新修订号再存。发送时 `expected_revision` 与
  `draft.revision` 都写服务器当时的修订号（服务要求两者相同），服务器存下后加一。
* 409：先读服务器那一版。内容与本地相同（上一次回复丢了）就直接采用；不同就停在“冲突”，不再自动保存，由用户选“改用服务器的版本”
  或“把我这里的内容存成新的一版”——不会最后写入者自动获胜。429 按服务给的秒数再试；断网按 5、10、20、30 秒退避再试。
* 每个身份的修改请求限每分钟 60 次：停手再存加上审阅只在“已保存”时请求，正常填写远低于这个数。离开页面前还有没保存的改动会提醒。
* 未答 = 没有这一项；明确 0 = `provided "0"`；无所谓 = `indifferent`；暂不确定 = `unsure`。健康题没选就是未答（不预选任何一项）。
  兴趣与口味写了文字就是“用文字描述”，候选要用户主动勾选；换成别的作答状态时原文保留、类别不再带着。
* 问卷或词表换了版本：审阅给出 `version_changed`，用户读过新说明、勾选“已按新说明重新确认”之后，才把草稿的版本信息换成当前版本
  （唯一会改 meta 的动作）；不会悄悄改版本头。

## 6. 确认、准备、提交与轮询

* 审阅的永远是服务器上已保存的那一版；改过答案，旧审阅与旧确认都失效（确认画像绑定的修订号对不上就不再显示“准备模拟”）。
* 运行选项的范围只读 `SessionView.rules.options`；省略就用服务默认值；城市来自确认画像，不另传。`RunIntentView.settings` 是这次保存
  的有效设置，页面照它显示。
* 按钮只看 `allowed_actions`，`waiting_for` 说明在等谁。确认开始：一次明确点击生成一个幂等键，绑定这份检查的 `confirm_with`；在途时
  不能再点；超时或断线先查询；检查换了（`preflight_stale`）要重新阅读、再次确认、换新键。取消、恢复、删除都在对话框里确认，不自动重试。
* `checking / queued / running / deleting` 时每 3 秒只读查询一次，页面在后台不查询；断线按退避，429 按服务的秒数。结果的查询键带意图的
  `updated_at`：恢复后出了新结果、删除或过期都会重新读。
* 三种钱分开写：模拟现金（用户的开局资金）、停机上限（`max_cost`，到了就停）、启动机会（次数）。费用分已核算、用量不确定、在途预留，
  缺项写“未知”不写 0；规划候选数与服务尝试数分开。
* 期限照服务：`expires_at` 是**现在适用**的截止时间，旁边写 `expiry_basis`（从最后一次有效操作起算 / 结果从首次结束起算 /
  运行自身的期限 / 服务没有给出依据）；没有截止时间就写没有，不用 updated_at 加 30 天硬算。确认成功后显示画像摘要
  （首次确认时间、保存到），并写明重复确认不延长、画像到期不影响已经准备好的模拟（`GET /profiles`、`/profiles/{id}` 已接入 API 层）。
* 取消 / 恢复 / 删除仍只看 `allowed_actions`；被拒（例如 `cancel_not_allowed`）时显示服务的三句话并重新读意图，按钮随之变化。

## 7. 结果三层

* **城市比较**：每城一张卡（C / E / M 组成条、均值与分母、E3 的标题句）；比较图里圆点是完整者的平均 J（分母 C），横条是模拟缺失范围
  （分母 C + M）。横条不是误差条或置信区间，均值可以落在它外面——例如 1 个完整分身 J = 0.3、1 个缺失分身的已知月份给出下界 0.6、
  上界 0.8，城市范围 = [(0.3 + 0.6) / 2, (0.3 + 0.8) / 2] = [0.45, 0.55]，均值 0.3 在外面，两者各按公共值定位。数值表是等价的文字版本。
  城市顺序照服务给的顺序；不写“最佳城市”，比较只用 `comparisons` 的方向。
* **J 色阶（所有者 2026-10-24 决定）**：差距小时适度放大，但不放大成“第一名满分、最后一名零分”。本轮所有城市（所有国家共用）的最低
  a、最高 b，窗口宽 w = min(1, max(0.02, 2 × (b − a)))，以 (a + b) / 2 为中心，超出 [0, 1] 就平移回来。最新六城样例 104：a = 0.5141（休斯敦）、
  b = 0.5881（芝加哥）→ w = 0.148，窗口 [0.4771, 0.6251]，两端城市落在色阶的 25% 与 75%。差距小于 0.01 时窗口固定宽 0.02：本地 mock
  主闭环的西雅图 0.5602、芝加哥 0.5643 落在 40% 与 60%，看得出高低又不画成两个极端；差 0.0002 只差 1%，就画成同一个颜色。
  下限起初取 0.08，截图里差 0.004 的两城几乎同色，不符合“不要完全一个色”，改成 0.02。图例写明窗口两端，不代表 0 分或满分。
  比较图刻度的小数位按步长定（步长 0.0025 写四位），不出现重复的刻度标签。
  C = 0、未生成的城市不上色（中性符号与文字）；含 M 但有均值的城市保留均值颜色，另标缺失人数。
  注意：E3C 设计稿（[e3c-display-and-service-handoff](e3c-display-and-service-handoff.md) 第 5 节）写的是固定 [0, 1]、不按六城最小 / 最大拉伸；
  界面这里按所有者的决定做，分歧已在交付报告里列出。
* **单城详情**：J、L、V 并排（不画 L + V = J 的堆叠），C / E / M 与缺失原因、硬要求核验（未核验 ≠ 满足）、这座城的说明与比较；资料性质
  （观测 / 推导 / 估计 / 合成设定的条数、登记的模型设定、共同背景、通勤方式、税、构建计数——条数不是“真实性百分比”）、选项目录覆盖、
  这次运行绑定的那份运行前检查的范围说明（指纹对不上就写“读不到”，不用别的检查替代）。
* **分身年度记录**：年初 / 年末现金与年度已支付总额（年度合计，不是月度流水）；工作、住房、住处片区（片区典型通勤与实际通勤分开写）、
  逐月通勤（“每月通勤费”）、用车权、食品、耐用品（买到 / 在用 / 到期 / 剩余）、设备与服务、日常支持（计划 / 获得 / 没获得）、消费篮子
  （“0” 与 “—” 分开）、活动、没成交的购买、设备故障、健康与家务的逐月条带、税。全部是公开事实，不写心理活动或因果解释；模型的计划理由
  本版没有公开，单独留一栏说明。
* 月份条带（F3）按公开的月份列表细分：已获得 / 已安排但没获得 / 没有安排 / 没有生活 / 记录不足；设备条带说在用 / 不在用。
  例子：全年都生活、只在 7–12 月安排清洁、7 月没获得——1–6 月是“没有安排”，7 月是“已安排、没获得”，8–12 月“已获得”；
  年中第 8 个月结束生活的，9–12 月才是“没有生活”。两个列表都没有的月份是“记录不足”，不补零。
* 比较图的模拟缺失范围没有最小宽度（F4）：两端严格按公共值定位，上下界相等就是精确位置上的一道竖线；扩大的只是鼠标悬停区域。

## 8. 双语

* 界面自己的文字在 `i18n/zh.ts`、`en.ts`（键一一对应，插值变量相同，由测试检查）。第一次进入按浏览器语言选，之后记住；顶部随时切换。
* E3 的业务文字（`*_zh`、标签、说明）原样显示；英文界面里标上 `lang="zh-CN"`，整块开头写一次“这一部分有服务提供的中文原文”。
  E3 的显示附层（`GET /api/v1/display`）交付后，只换 `i18n/biz.tsx` 的取值方式，页面不用改。
* 模型输入与输出语言是开局选项，写进 `occupation.language`；规划模型的语言目前没有字段（交接单第 12 节第 5 条）。
* 显示附层（`GET /api/v1/display`，e3-display-v1）的 API 层与纯函数已经就位（`web/src/display/fields.ts`：按 JSON Pointer 取译文，
  provided 用译文、missing 显示原文并带原因；中文信封的文字逐字等于 source 里的原文；查询键带语言与对象版本）。页面还没有改成
  按位置取文字：E3C 独立核查的三个显示缺陷（资源损坏破坏业务回复、同名实体串绑定、历史对象被当前译文覆盖）修复并复核之后再接，
  不用中文反查、不拿当前版本冒充历史版本。

## 9. 两种外观与地图

* 稿纸：暖白方格纸背景、石墨线、少量彩铅色；手写感只给标题（中文用系统楷体，英文用 Patrick Hand，OFL 许可）。纸纹只在页面背景，
  不加在地图、图表或数据点上。地球：深蓝灰面板、克制的青色。
* 平面地图：世界图用等面积的 Equal Earth；国家图用以该国为中心的圆锥等面积投影，范围取面积最大的那块陆地（不把阿拉斯加、夏威夷
  挪进小框）。铅笔感来自双层描边与纹理，不移动顶点。
* 地球：react-globe.gl（three.js），按需加载；拖动旋转、缩放、不自动旋转；减少动态效果时视角直接到位；“回到全球视角 / 转到所选国家”。
  总览视角对准现在能选的国家（各国大陆部分质心在球面上的平均方向，高度 1.9 个地球半径，仍看得到整个球面）；这些国家分散在地球两侧、
  平均方向没有意义（平均向量长度不到 0.5）时退回固定的大西洋视角。本资料包只有美国，所以打开就对着美国。
  没有 WebGL 或加载失败就说明原因、退回平面地图。
* 底图：Natural Earth 1:10m 国界（公有领域），中文界面用中国立场版、英文界面用默认版，`web/scripts/build-basemap.mjs` 简化成约 290 KB，
  来源与校验值在 `web/public/geo/SOURCES.md`；地球纹理是 NASA Blue Marble Next Generation（公有领域）。简化之后绕行方向反了的小多边形
  （中文版的 ESB）会被 d3 读成“除它以外的整个地球”，生成时把它的环倒过来；`web/tests/basemap.test.ts` 检查两版都没有比半个地球还大的多边形。
* 城市点来自 E3 的地理显示清单 `GET /api/v1/display/geography?pack_fingerprint=…`（`web/src/geo/anchors.ts`）：输入按能力清单的资料包读，
  输出按**这次结果自己的**资料包指纹读；只给 `anchor_status = available` 的城市画点，按 `city_ref` 配对（编号自带地理方案与版本），
  unknown / not_applicable（合成城市）/ 清单里没有的城市列出原因、不猜位置。六城的点是 Census 都会区内部点（代表点，不是住处或市中心），
  平面地图与地球用同一个锚点，标签用清单里当前语言的短名。历史结果不传“当前碰巧登记”的资源版本：等 E3C 修好历史对象的版本绑定
  再传它绑定的版本；明确请求的版本不存在时服务 404、不回退，页面就不画点。
* 版面（所有者 2026-10-25 的审美反馈）。稿纸不再模仿纸的材质，而是照搬印刷表格与旧式统计报告的排版：衬线正文、章节编号、
  上粗下细的分段线、只有横线的表格、小号带字距的标签；填写框是一道横线，填进去的字用手写体（中文楷体、英文 Patrick Hand），
  勾选框是印好的方框、勾是笔迹；朱砂色只用来盖章（“已分完”）与标记当前步骤。地图是输入页与结果页的视觉重心：占满正文宽度，
  只有一个能选的国家时默认放大到该国（可回到世界图），城市点带名称标签。地球模式里地球铺满整块舞台，其余内容收进右侧可收起的
  半透明面板（窄屏从底部升起；收起只是 inert + aria-hidden，不卸载内容），面板、按钮与输入框都是薄面板与发丝线，
  地球上同时画点与城市名。小动画：勾选的笔迹、刚改过的行的淡笔痕、“已选 n 座”的数字跳动、比较图的横条长出与圆点弹出、
  月历条带依次浮现、翻页淡入；系统要求减少动态效果时全部关闭。

## 10. 怎样检查

* `npm test`：契约核对 + 单元与组件测试（状态更新函数、自动保存、HTTP 客户端、色阶、结果展示模型、双语字典、比较图、年度记录、
  分配器、平面地图、锚点解析（样例 123 / 124 / 125）、显示附层读法（样例 105 / 106 / 122 / 92 / 68）、月份状态与零宽范围）。
  `tests/draft-fixtures.test.ts` 从服务新建的草稿（样例 62）起步、经页面的状态更新函数生成 4 份草稿样本，
  接入层的 `tests/product/test_web_drafts.py` 核对 E3 读到的答案状态。
* `npm run test:e2e`：Playwright 起一套隔离的本地 E3C 服务（127.0.0.1:8775，离线 mock，数据目录每次清空，来源
  `http://localhost:5180`，Origin / CSRF / 限流都是默认值）与 Vite（5180），走主闭环、会话与身份、草稿冲突与键盘、地球与无 WebGL、
  手机 360×740；退出遇到断网的三种情形、新建草稿后回首页、地图上点城市点与列表同步；截图与可访问性报告写进本机 `runs/web-e2e/`。
  主闭环一次约 5–7 分钟。测试浏览器的地球用软件 WebGL，
  页面图块用 CPU 栅格化：软件 GPU 也拿去栅格化页面时，带大地图的页面整页截图会随机缺块（2026-10-24 用 5 个结果样例对比：4 个缺块
  对 0 个），页面本身没有问题。
* 可访问性：每个关键页面跑 axe，致命、严重、中等问题都要是 0。表格里的数字不断行（正文允许任意位置断行，表格不继承），放不下就在
  外框里横向滚动，外框可以用键盘聚焦（带名称的区域）；标题层级不跳级；截图在中文 / 英文 × 稿纸 / 地球四种组合下逐页人工查看。
