# E1-3 设计备忘：探索月度评分与 E1-2 收尾

**这是思考与审核过程的备忘，本身不具有覆盖正式规则的效力。** 本轮有效的规则写在
[ADR0018](../../../DECISIONS/0018-life-exploratory-monthly-scoring.md)；两者不一致时以 ADR 为准，新日期的
备忘不自动覆盖有效 ADR，所有者的明确决定优先。本文是草案，可以更新；归档之后不改写原有结论，
只追加更正或替代指针。

## 一、本轮回答什么问题

给定一个分身已经结算好的一年（E1-2 的月度账目与实际执行记录），逐月回答：

1. 他这个月实际享受了什么（住的、吃的、用的、发生的）？
2. 各分项、各维度的满足感是多少，依据是哪条记录、哪个参数？
3. 哪些硬要求没满足，在哪几个月？
4. 什么时候不能给总分（缺数据、出局），为什么？

**不回答**：哪座城更好（不排序）、三年综合分、出局之后怎么算、折现与期末价值、真实城市的幸福水平。

## 二、采用与未采用的方案

| 问题 | 采用 | 未采用及理由 |
|---|---|---|
| 评分对象 | 实际执行记录（`ItemExecution` / `HoldingService`） | 按计划或理由评分：计划可能失败、理由不可核对 |
| 函数形式 | z = b + Σηx，s = min(c, z/(z+τ))：有界、单调、递减、可手算 | 旧对数效用：假设消费已最优分配，评价不了任意实际安排；线性：没有递减；分城 z-score：各城尺子不同 |
| 锚点 | τ 只在规格里，城市条件没有这个字段 | 按城市调 τ 或把本城最好条件归一成满分：同一个分数在不同城市含义不同 |
| 价格 | 从不进入评分；条件从规格读 | 用房租代表住房质量：贵就是好，等于重复奖励花钱 |
| 年度汇总 | 先逐月评分再平均，十二个月都可评分才有年均 | 先平均条件再套函数：半年共享办公会被算成 0.714 而不是 0.65 |
| 年付服务与耐用品 | 只从 `HoldingService` 读服务月 | 两处都读：同一次服务计两次；成交时奖励：同一笔钱既算购买又算使用 |
| 替代满足 | `any`：同一需求多处满足只计一次 | 简单相加：两居室加共享办公把"有工作间"算两次 |
| 使用 | 新样例把"年卡＋每月 8 次"声明成行为方案 | 把没有使用安排的年卡自动算成健身收益；静默改写 E1-2 样例的年卡含义 |
| 缺失 | 正权重缺失 → 该月不完整；零权重缺失不阻断 | 补零（缺数据被当成条件最差）；逐城删缺失需求再重新归一化（城市间权重不同）；50% 门槛（早期讨论值，没有依据，不设默认） |
| 降级 | 按实际得到的方案评分 | 额外的"失望分"：同一次条件下降被计两次 |
| 出局 | 出局当月与之后单列状态，没有年均 | 填零；忽略空值后平均（出局年份看起来像一个正常年份） |
| 产品偏好 | 只认明确数值：七维点数 / 100、物质细项点数 / 100；不够就报信息不足 | low/medium/high → 1/2/3；从自由文字推数值；补均匀权重；借用研究真值 |
| 硬要求 | 结构化条件词表 + 每月检验，单独报告 | 解析描述文字；用其他维度高分抵消；未满足就扣分或出局 |
| 旧城市属性 | 本轮不复用 | 未核对方向、单位与标度版本的映射，直接再缩放会把已缩放的指标再缩一次 |
| 最低方案矛盾 | 加载与结算报数据错误 | 让评分或结算自动替分身找更便宜的房子 |

## 三、探索假设与限制

* 参数全部是为了手算方便而取整的合成设定（ADR0018 第三节），不是经验估计。
* 使用假设：只有声明了使用安排（`visits_per_month`）的服务才产生锻炼收益；时间按声明次数计。
* 安全、医疗、机会、环境、通勤五维当前只有城市基础条件，没有行动改善机制；物质四个细项与休闲
  可以由行动改善。
* 没有项目之间的交互、享乐适应、负向作用、时间与精力约束。
* 硬要求的条件词表很小（类别、≥、≤、相等），范围只有"每个月"。

## 四、E1-2 收尾

**问题与复现。** 审核给出的情形：最低住房 900、最低食品 400，另一套合格可得的住房 500；分身现金
1,000，选 500 + 400。修复前：加载检查通过，结算返回 `exited`（第 1 月，1,000 < 1,300）。修复后：
加载器把它列进 `settlement_problems`，结算返回 `data_error`，消息点名 `a11.housing.room`。复现测试先
写、先跑出失败，再修复（`tests/life/test_settlement_closure.py` 的前三条在修复前失败）。

**修复。** `ledger.minimum_living_problems` 增加逐月比较：别的合格、可得项在某个月比最低方案便宜 →
矛盾；带资格限制的更便宜合格项 → 不支持的配置。计费换算抽到 `common/life_billing.py`，加载器与结算
共用。

**税表表述。** "旧税表按空间平减美元校准、必然套错"改成"计价口径尚未核查、旧接口缺少验证，本轮
暂不接入"（ADR0017 第七节已加订正说明）。

**依赖与 `plan_infeasible`。** 保留 econ 复用 ledger 检查的安排；E1-4 再把加载与可行性规则分清。
`plan_infeasible` 是整份计划试算失败、不提交账目，不是生活之后回滚时间；LLM 试算诊断与重试属于 E1-7。

## 五、尚未决定的问题与所属轮次

* E1-4：时间与精力（休闲的时间来源、省时如何计入且不与休闲重复）；规则模块职责；满足感反馈。
* E1-5：培训收益；参加培训的当月体验是否计入机会维；职业发展；长期目标；风险。
* E1-6：折现、终值、出局与剩余期间计分、跨分身聚合、共同子集比较与允许缺失的权重。
* E1-7：年度试算与重试、可见信息、真实 LLM 接线。
* 产品输入：序数消费偏好怎样得到明确数值。
* V2 前：真实税表、跨国数据、旧城市属性到新单位的映射。
* 正式评分：`score_mapping` 与 `material_preference_aggregation` 的裁决与参数标定来源。
