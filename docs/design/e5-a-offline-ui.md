# E5-A 技术说明：离线界面原型

> **存档（2026-10-24）**：网页已改接 E3C 服务、读共享结构 v3.3，样例适配器与本标签页存储已删除；现行说明见 [e5-web-ui](e5-web-ui.md)。下面是 E5-A 离线原型当时的设计，不再维护。

更新：2026-10-19（本地时区 UTC−7）。设计决定见 [ADR0036](../../DECISIONS/0036-e5a-offline-ui.md)，运行方法见 [网页指南](../../web/README.zh-CN.md)，
状态见 [docs/INDEX.md](../INDEX.md)（界面层 ui-01）。

界面读的全部是接入层的合成公共样例与 mock 规划器的结果，没有接任何服务。共享语义以 [E3/E5 共享约定](e3-e5-product-contract.md)与
[contracts/product/v2](../../contracts/product/v2/README.md) 为准，本文只讲界面怎样消费它们。

## 1. 用户能做什么

一个合成用户故事（样例 02–10，数字可以手算）：小林 35 岁，在写字楼做文员，想比较合成城 K51 与 M52。

1. 第 1 步先读“这是怎样的模拟”，点“载入样例用户 u501 的答案”（也可以从空白开始）。页面顶部一直有“合成样例……不是真实城市，也不是推荐”。
2. 第 2 步的分配器显示 物质 30、安全 20、发展 20、休闲 10、环境 10、交通 10 与“已分完”；物质内部 30 / 30 / 40，旁边写“这里分的是重要性，不是每月怎样花钱”。
3. 第 3 步：健康三题（一题暂不确定）、补充文字、通勤上限 60 分钟。
4. 第 4 步：先是“你的答案”回显，再是 E3 的审阅（每项的用途与支持状态），勾选“这是从健康、没有已有物品开始的简化情景”后点“确认我的信息”，
   再看运行前说明（三种能力、每城 1 个分身 3 年、离线 mock、费用 0），点“查看样例运行”。
5. 进度页显示两个分身都“正常生活完 N 年”，结果页写“1 个完成且可评价分身的平均 J：0.6078 / 0.6145”，分母句子、缺失范围与比较原文都在；分身故事页里看得到
   K51 第 1 年花 1,440 买设备包、每月仍做 4 + 6 = 10 小时家务，M52 每月花 108 请人上门、只做 2 + 2 = 4 小时，所以 M52 存款少 2,448 而 J 略高——页面不把这一点差距写成推荐。

自由填写的人：四步都能填、能撤销、能返回修改，刷新还在；第 4 步只显示“你填写内容的回显，不是系统的理解”，可以导出草稿（JSON），也可以“用样例继续看后面的流程”。

## 2. 结构

```text
页面（pages/、components/）
  └─ 只依赖 ProductApi（api/types.ts）：capabilities / review / confirm / preflight / submit / progress / result
        ├─ SampleAdapter（E5-A）：按场景原样返回 contracts/product/v2/samples/ 的样例；只模拟网络
        └─ HttpAdapter（E5-B）：空壳，接 E3-C
草稿（draft/）：UserInputDraft + 撤销记录，只存本标签页
流程（flow/）：确认画像、预检查、知悉项、幂等键、提交过的运行，只存本标签页
契约（contract/）：生成的类型、Ajv 校验、样例与 schema 的读取、待 E3 的临时显示文字
```

| 目录 | 做什么 | 不做什么 |
|---|---|---|
| `web/scripts/` | 生成类型、核对共享结构 | 不改 `contracts/` |
| `web/src/contract/` | 类型（生成）、校验、样例读取 | 不手写业务字段 |
| `web/src/api/` | 业务访问层、样例场景、网络模拟 | 不做职业匹配、金额换算、审阅、C / E / M |
| `web/src/draft/` | 草稿状态、撤销、精确分数辅助 | 正式合计以 E3 审阅为准 |
| `web/src/pages/`、`components/` | 四步填写、确认、进度、结果、分身故事、样例面板 | 不重算 J、均值、比例或范围 |

## 3. 契约怎样进来、变了怎样发现

* 类型由 `npm run contract:gen` 从 13 份 schema 生成：合成一份（同名定义必须逐字相同），去掉嵌套字段的 `title` 之后交给 json-schema-to-typescript。
* `npm run contract:check`：哈希与 `index.json` 一致、没有未登记的 schema、生成的类型是最新的；`build` 与 `test` 之前自动执行。E3 改了字段，这一步就失败，提示先重新生成、再检查用到这些字段的页面；
  TypeScript 会在用到旧字段的组件处报错。
* 运行时 Ajv（2020 版本类）校验适配器的每份输入与回复；不开 `useDefaults`、`coerceTypes`、`removeAdditional`。
* E3 重新生成样例时，运行编号与指纹都会变。场景表（`web/src/api/scenarios.ts`）只写样例编号，运行编号在载入时从样例里读；同一个运行的几份样例
  编号不一致就直接报错。`npm test` 另外核对每个场景、每份接受提交的回执都连得到进度或结果样例，浏览器端测试也从样例文件读编号。

## 4. 草稿与答案状态

| 用户做了什么 | 草稿里记成什么 | 界面显示 |
|---|---|---|
| 没填休闲 | `entries` 里没有 `leisure` | “还没有分配” |
| 物质填 0 | `{state: "provided", value_text: "0"}` | 0；物质内部折叠成“不适用” |
| 环境选“无所谓” | `{state: "indifferent"}` | “无所谓：这一项还没有分数；运行前需要给一个数（可以是 0）” |
| 健康题选“暂不确定” | `{choice: "unsure"}` | 暂不确定 |
| 健康题“先跳过” | `{choice: null}` | 未答 |
| 点“平均分配” | `{mode: "equal_split", entries: {}}` | 每项 16.7（精确 50/3） |
| 均分之后把安全改成 20（同意改成手动） | `mode: "manual"`，安全 `"20"`，其余 `"50/3"` | “多出 3.3 分（精确值 10/3）” |
| 从物质减去多出的部分 | 物质 `"40/3"` | “已分完” |
| 现金写“3000,50” | `amount_text: "3000,50"` | 原样保留，提示写法规则 |

“多出 3.3 分”是这样来的：5 × 50/3 + 20 = 310/3，减去 100 是 10/3 ≈ 3.33。如果拿显示值 16.7 去算，16.7 × 5 + 20 − 100 = 3.5，就错了；所以计数用精确分数，显示值只供阅读。

撤销以一次操作为一步；`revision` 只增不减（撤销也换新编号）。

## 5. 确认、提交与断线

* 确认画像与预检查各自记下对应的草稿编号与版本；之后改了答案就失效，运行按钮不再出现。
* 点“查看样例运行”时，这份预检查还没有幂等键就先生成并存进本标签页，再发送；提交返回之前不能再触发新的提交。
* 断网：提交没有送达，页面写“网络断了，提交没有完成”；再点用同一个键。回执丢失：提交已送达但回执丢了，再点用同一个键，得到“重复提交、同一个运行”（样例 08）。
* 刷新进度页：网址里带 run_id，只查询，不重新提交。

## 6. 以后怎样接真实服务（ui-02）

接入层的 LangGraph 外层流程原型（intake-04，[说明](langgraph-product-workflow.md)第 5、11 节）已经把“预检查 → 等用户确认 → 幂等登记 →
启动或恢复生活引擎 → 交付结果”串起来。界面只调用 E3-C 包在它外面的服务、读它的公开视图，不读 checkpoint、内部图状态或 E1 文件。
页面上的动作与流程操作的对应：

| 页面上的动作 | 流程操作（经 E3-C 服务） | 界面显示什么 |
|---|---|---|
| “确认我的信息”之后 | `start`：带已确认画像与幂等键；同一次“开始”的重复点击用同一个键 | 流程停在等用户确认（`waiting_for = confirmation`），显示公开视图里原样转交的 ProductPreflight（`preflight.public`） |
| “开始运行” | `confirm`：原样带回 `confirm_with`（用户看到的那份检查的身份） | 检查已经不是最新的，就显示新的检查，不开跑 |
| 回去改了答案 | 重新确认画像，再 `revise` | 旧检查作废 |
| 进度页 | `status`；断线重连只查询 | 流程阶段（`stage_zh`、`waiting_for`）与 E3 的 RunProgress 分开显示；`needs_attention` 时显示 `attention` 的中文说明与审计编号，不提供“自动重试” |
| 结果页 | `status` 到 `delivered` | E3 的 ProductResult，按本文第 1、4 节的规则呈现；“已交付”不等于每个分身都正常完成 |

要改的地方：

1. **业务访问层的接口**：现在的 `ProductApi`（`web/src/api/types.ts`）按 E3 的消息分成 review / confirm / preflight / submit / progress / result。接流程之后，
   预检查由 `start` 产生，“开始运行”变成带 `confirm_with` 的确认，幂等键要在 `start` 之前生成（现在是点“查看样例运行”时才生成），界面不再直接发
   `RunSubmission`。页面消费的仍是同一套共享消息，样例适配器跟着改成同样的接口。
2. **公开视图要先进共享结构**：流程阶段、在等谁、待处理事项现在只在流程原型里定义，还不在 `contracts/product/` 里（需求 B8）。E3 收进去之前，
   界面不接一份没有 schema 的 JSON。
3. **恢复与处理由维护者发起**（`resume`、`resolve`）；界面只显示“需要处理”与审计编号（需求 B3）。
4. 托管时由 E3-C 的 Python 服务同时提供 `/api` 与构建好的页面（同一个网址），不需要 Node 服务器。

## 8. 省略了什么，影响谁

* **用户自己的答案得不到系统审阅或结果**：要等 E5-B 接上 E3-C。参加使用观察的人，第 4 步之后看的是样例用户的结果。
* **资格题不会自动展开**：契约里还没有机器可读的触发条件（需求 A6），先放在第 1 步的折叠区。
* **没有恢复按钮、没有“我的运行”、没有登录**：E5-B / E5-C。
* **确认页在手机上很长**：审阅、知悉、确认画像与预检查都在一页；使用观察时看用户会不会迷路，再决定要不要折叠或拆页。
* **模型理由不展示**：契约里还没有带归属的字段（需求 B7）。

## 9. 怎样检查

* `npm test`（在 `web/` 里）：先核对共享结构（哈希与生成的类型），再跑单元与组件测试（精确分数、草稿状态、分配器、样例适配器、结果与进度组件）。
* `npm run test:e2e`：手机 360×740 与桌面 1280×800 各跑一遍，包括只用键盘走完正常闭环、断网与回执丢失、各样例场景、可访问性扫描；截图、导出的草稿与
  扫描报告写在本机运行记录（运行输出，每次覆盖）。
* **界面与接入层对同一份草稿的理解**：`web/tests/draft-fixtures.test.ts` 用页面同一个状态更新函数、按页面操作生成 4 份草稿样本，存在
  `web/tests/fixtures/drafts/`；`tests/product/test_web_drafts.py` 把它们交给 E3 的 `review_draft`，核对未答、0、无所谓、暂不确定、均分之后多出的
  10/3 与金额写法。任何一边改了理解，这两个测试之一就会失败；有意的改动之后用 `UPDATE_DRAFT_FIXTURES=1` 重新生成样本。
  样本按接入层当前的公共结构生成（能力清单取 `contracts/product/v3` 的样例 01，按 v3 的草稿结构校验）；页面本身还读 v2 的样例，界面改接 v3
  之后改回用页面自己的样例与校验。这 4 份草稿只用到六维、健康题与现金，这几处 v3 与 v2 相同。
