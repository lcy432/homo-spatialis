# E3B 六城真实生活资料包：组装、冻结与产品链

本说明讲六城资料包怎样从三块冻结资料组装成 E1 能跑的输入，以及怎样走产品链。引擎机制的决定见
[ADR0042](../../DECISIONS/0042-e3b-real-life-pack.md)；通勤资料见 [e3b-commute-data](e3b-commute-data.md)，食品、服务、设备、活动
与职业见 [e3b-items-data](e3b-items-data.md)；官方税规则见 `configs/intake/tax_us_2024.yaml`；所有设定与映射登记在
[参数与假设目录](parameter-assumption-register.md)（SC-26–SC-28、AC-14、AC-15、AG-24、PI-28–PI-49）。

## 1. 城市与范围

CBSA 2023 的六个都会区：纽约 35620、洛杉矶 31080、旧金山 41860、芝加哥 16980、休斯敦 26420、西雅图 42660（旧金山不含圣何塞）。
住房与岗位按**税的支持范围**裁剪：纽约只留纽约市五个县的居民、工作地在纽约州；芝加哥只留伊利诺伊州部分；其余四城整个都会区都在
一个州里。支持的人：单身、只有工资收入、标准扣除；40 个职业（SOC 2018）。

## 2. 构建（离线）

```
uv run python scripts/life_pack_us.py check-tax     # 官方税规则：摘句逐字在缓存网页里、每个数在摘句里
uv run python scripts/life_pack_us.py check-safety  # 都会区犯罪资料：每城的数、覆盖、与模拟居住范围的关系与安全背景（缺资料时先 fetch-safety）
uv run python scripts/life_pack_commute.py ...      # 通勤资料（另见 e3b-commute-data）
uv run python scripts/life_pack_items.py ...        # 生活机会与职业（另见 e3b-items-data）
uv run python scripts/life_pack_us.py build         # 组装、冻结到 data/frozen/life/us-v1/pack/，并生成 configs/product/e3b_us_v1_pack.yaml
```

`build` 读 intake-02 的冻结库（只在本机）、原始文件缓存与两份冻结资料，写四份文件与报告：

| 文件 | 内容 |
|---|---|
| `life_input.json` | 协议（生活规则沿用产品样例；协议身份 `life-v1-e3b-us`，能力词表换成真实资料包的，设备故障来源写定）、六座城的目录（住房、片区、通勤关系、用车权、食品、服务、设备、装备、活动、培训、岗位、年度菜单、最低生活、治疗）、官方税 |
| `scoring.json` | 评分规格原样（绑定 E3B 协议；内容身份不含协议编号，仍是 `180fd938…`，反馈政策照样钉住它），比较组 `group.e3b-us-v1`，按登记规则写的城市条件（安全、环境按片区写同一个城市值） |
| `evaluation.json` | 期末参考生活 `eval.e3b-us.main`（槽位按真实目录绑定，PI-47） |
| `city_facts.json` | 代理可见的城市背景指数（安全来自都会区犯罪统计，环境、发展来自资料，休闲是共同先验；b = 0.5 × 指数），外加暴力犯罪率、财产犯罪率与治安资料覆盖范围三条可读事实（不带换算参数） |
| `report.json` | 每城计数、排除原因、背景数值、安全资料（每城的数、率、覆盖、与模拟居住范围的关系）与全国参照、三份犯罪原始文件与四份输出文件的 SHA-256 |

每条来源的 `geography_scope` 写比较组的口径（加载器要求各城同一粒度），具体的 PUMA 或都会区写进来源的 inputs。

## 4. 安全与休闲背景（所有者 2026-10-23）

**安全**：每个都会区一个背景值，城内所有居住片区共用（评分条件按片区写同一个值）。它表示这个都会区的治安情况对生活里安全考虑的影响，**不是**个人遭遇犯罪或伤亡的概率：不建犯罪事件、不抽伤亡，不影响现金、疾病或出局，同城搬家不改安全，也不说哪种出行方式更安全。

资料（PI-49，`fetch-safety` 获取、`check-safety` 离线列出）与换算（PI-45 `fbi_relative_rate_v1`）：

    暴力率、财产率 = 案件数 × 100,000 / 人口（几个县先加数与人口再算率，不平均各县的率）
    r = 0.5 × 暴力率 / 全国暴力率 + 0.5 × 财产率 / 全国财产率
    安全指数 = min(10, 6 / r)，取到 0.001；评分条件 b = 指数 / 2；安全分 s = b / (b + 3)（τ = 3，上限 0.9）

| 城市 | 资料 | 覆盖 | 人口 | 暴力率 | 财产率 | r | 指数 | b | 安全分 s |
|---|---|---|---|---|---|---|---|---|---|
| 纽约 | 纽约州 DCJS 2024 县合计（各机构实际报告的汇总，缺报不补）+ PEP 2024 县人口 | 都会区的纽约州部分：10 个县，都会区人口的 64.5%；不含新泽西、宾州；模拟居住的纽约市五区都在内 | 12,859,419 | 500.17 | 1,818.50 | 1.2130 | 4.946 | 2.473 | 0.452 |
| 洛杉矶 | FBI 表 6 估计总数 | 整个都会区；实际报告覆盖 99.2% 人口 | 12,883,860 | 519.30 | 1,955.71 | 1.2786 | 4.693 | 2.3465 | 0.439 |
| 旧金山 | FBI 表 6 实际报告合计 | 整个都会区（不含圣何塞）；全部机构报告 | 4,585,588 | 546.30 | 3,140.88 | 1.6529 | 3.630 | 1.815 | 0.377 |
| 芝加哥 | FBI 表 6 估计总数 | 整个都会区，含 4 个印第安纳州县（模拟居住只在伊利诺伊州部分）；实际报告覆盖 96.7% | 9,373,214 | 269.76 | 1,791.90 | 0.8846 | 6.783 | 3.3915 | 0.531 |
| 休斯敦 | FBI 表 6 估计总数 | 整个都会区；99.9% | 7,713,658 | 563.92 | 2,546.12 | 1.5085 | 3.978 | 1.989 | 0.399 |
| 西雅图 | FBI 表 6 估计总数 | 整个都会区；99.8% | 4,110,067 | 385.49 | 2,971.53 | 1.3809 | 4.345 | 2.1725 | 0.420 |
| 全国参照 | FBI 表 1（2024） | 全美 | 340,110,988 | 359.10 | 1,760.13 | 1 | 6 | 3 | 0.5 |

手算（休斯敦）：暴力率 43,499 × 100,000 / 7,713,658 = 563.92，是全国的 1.5704 倍；财产率 196,399 × 100,000 / 7,713,658 = 2,546.12，是全国的 1.4466 倍；r = 0.5 × 1.5704 + 0.5 × 1.4466 = 1.5085；指数 = 6 / 1.5085 = 3.978；b = 1.989；s = 1.989 / 4.989 = 0.399（原来的共同先验是 3 / 6 = 0.5）。

要点：全国平均对应指数 6、b = 3，与原来的共同先验相同；犯罪率更高的城市指数更低；每城只和固定的全国参照比，不按六城最高、最低拉伸，改一城的资料不改别城；资料缺失报未知，不当零犯罪，也不用六城平均填补。代理在城市事实里看到治安指数、暴力与财产犯罪率和资料覆盖范围（如“都会区的纽约州部分（约 2/3 人口，含纽约市五区）”“整个都会区（含本模拟不居住的外州部分）”），看不到权重、全国参照或换算。

**休闲**：六城共同背景 b 从 4 降到 1（τ = 12）。没有参加活动的月份，休闲分由 4/16 = 0.25 变成 1/13 ≈ 0.077；同一个月参加 2 小时、兴趣匹配的活动（折 3 小时）由 7/19 ≈ 0.368 变成 4/16 = 0.25。活动的参与小时、兴趣加成与用户权重都不变，结算与参与记录一字不差（`tests/life/test_e3b_engine.py` 的两个隔离测试）。

## 5. 产品链

`configs/product/e3b_us_v1_pack.yaml`（状态 `real_data_frozen`）沿用 E3-A 的问卷与词表，换上六城、40 个职业、真实能力与菜系。编译
（`src/product/compile.py`）：没有声明便利候选时保留真实的设备与服务；开局岗位取确认职业的中位工资档；重复序号轮流分到两个环境重复。
职业要求的学历要用户明确确认，自由文字不授予（预检查报“与你职业对应的岗位要求 edu_at_least_hs”）。

```
uv run python scripts/run_product_full.py --out runs/<目录> --mock --pack configs/product/e3b_us_v1_pack.yaml --abilities edu_at_least_hs
uv run python scripts/product_workflow.py --services e3 --e3-workspace <目录>/ws e3-seed --example e3b_normal   # LangGraph：e3b_normal / e3b_mixed / e3b_exit / e3b_paused
```

## 6. 运行结果（mock 规划器，合成人物；本机运行，`runs/` 不进仓库）

* 2026-10-23 调整后（构建 `7abf315c…`，菜单重抽）全规模 mock，6 城 × 4 分身 × 3 年，真实模型调用 0 次：纽约、洛杉矶、芝加哥、休斯敦各 4/4 完整；西雅图 4 个分身都过完三年，但参考生活的固定住房（最便宜住房、居民通勤最短片区的一卧中档）从岗位片区出发都超过 60 分钟通勤上限，估值不完整（0/4）；旧金山 2 个分身估值不完整、2 个第 1 年规划停止（第二个环境重复的菜单里没有不用车能到岗的住房，没有公交资料）。完整分身的平均 J：纽约 0.5443、洛杉矶 0.5022、芝加哥 0.5588、休斯敦 0.5095。零调用重放：年度绑定、评价与城市报告逐项相同。调整前的运行按自己存档的资料快照重放，也逐项相同（存档的城市事实里没有犯罪率），没有悄悄换用新资料。
* 前后两次运行的城市平均 J 混合了三件事：安全换成都会区值、休闲降到 1、菜单重抽；不能拿差值看安全或休闲各自的作用。
* 以下是调整前（构建 `39240c28…`）的结果：全规模 mock 72 个年度全部过完，规划调用 72 次、真实模型调用 0 次；零调用重放逐项相同。
* LangGraph：e3b_normal（文员）交付，五城 4/4 完整，旧金山 0/4（估值不完整，见下）；e3b_mixed（售货员，第 1 年 1 月大病、旧金山一个
  分身规划格式错误）：两个确认的生活出局（旧金山、西雅图）、一个规划停止（模拟问题）、其余完整；e3b_exit（快餐柜台，现金 300、大病）：
  每城一个生活出局；e3b_paused（芝加哥一个分身程序异常）：批次暂停、照实投影；中断恢复（第 30 次规划调用时进程崩溃）后交付的分身类别、
  J 与城市平均和不中断的运行完全相同。
* 旧金山的分身都能过完三年（mock 选了能步行或骑车到岗的住处），但参考生活的固定住房槽位到不了岗位或超过 60 分钟通勤上限，估值不完整：
  这是公交资料缺失的直接后果，报模拟问题，不填 0。

## 8. 没做与限制

旧金山公交票价；芝加哥公园真实活动；四城没有培训；博物馆价格；安全只有都会区级报案统计（纽约缺新泽西与宾州部分，芝加哥含不模拟居住的印第安纳州部分，纽约与其他五城口径不完全相同），换算权重与尺度没有做敏感性检查；休闲背景是共同先验；参考生活的住房槽位不看岗位在哪（西雅图估值不完整）；治疗价格是共同假设；停车费、按距离票价、
多人家庭、非工资收入、税收抵免；岗位按大类放在同一就业片区；真实大语言模型会不会合理选择没有验证。
