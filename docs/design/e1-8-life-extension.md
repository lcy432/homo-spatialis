# 生活扩展：完整食品方案、个人消费与享受、装备与爱好（E1 + E3）

裁决见 [ADR0041](../../DECISIONS/0041-life-extension-food-enjoyment-hobbies.md)；参数见[参数与假设目录](parameter-assumption-register.md) SC-21–SC-25、PI-26–PI-27、EV-19、AG-04、AG-17、AG-23。所有数值都是合成探索设定，不能据此排序真实城市。

## 1. 做什么

分身在合成世界里多了三种生活：

* **吃饭是一个月的完整方案**：例如“每周 17 顿自己做（10 顿新鲜）+ 4 顿意式外食”。月费、做饭与外食时间、饮食评分都读同一份方案。
* **个人消费与享受**：舒适椅、坐垫这类居家舒适用品（在用就有），按摩这类享受型服务（按实际次数）。
* **装备与爱好**：吉他提供“能弹吉他”的能力，练琴是一次活动；网球套餐自带球拍，只对这一次有效。

不变的老规则：偏好不是开支比例；贵不等于更好；买不起不等于不喜欢；花钱、成交与持有本身不加分；“没发生”“资料未知”“模型不支持”分开报。

## 2. 数据形状（`src/common/life_contracts.py`）

| 事实 | 字段 | 检查 |
|---|---|---|
| `FoodPlanFacts` | 是否覆盖一个月基本饮食、每周餐数、各部分（自己做 / 外食 / 外送、餐数、新鲜餐数、菜系）、做饭小时、外食小时 | 可得的方案必须是完整方案；做饭 + 外食小时 = 资源账小时 |
| `EnjoymentProvision` | 功能、方式（`passive_service_month` 在用即有 / `service_units` 每月份数） | 耐用品只能是在用即有；功能要在词表里 |
| `EquipmentFacts` | 提供的能力 | 只能挂在耐用品上；能力要在词表里 |
| `ActivityFacts` | 主类别、标签、参与小时、准备往返小时、需要的能力、套餐本次提供的能力 | 参与 + 准备往返 = 每次资源小时；代替正餐的套餐拒绝 |
| `ActionItem.months` | 一项体验在不连续的几个月参加 | 严格递增；不另造编号、不去掉唯一性检查 |
| `ParticipationRecord` | 每项活动每个请求月一条：完成 / 暂停 / 没能进行、次数、参与与往返小时、用到的装备、套餐能力、原因 | 时间账、评分与记忆都读它 |

## 3. 钱、一次参与和一件装备怎样流动

**结算顺序**（`src/econ/life_settlement.py`）：每月先付住房与食品（最低生活检查只检查、不另扣），再按计划顺序执行其他行动；**需要持有能力的活动**推到当月一次性购买之后。所以“吉他排在练琴后面”与“吉他排在前面”结果相同（同一支付优先级下与 JSON 位置无关）。

一把吉他（K51，240，寿命 3 年 = 36 个月）的一生：

1. 第 2 月买下：扣 240，生成持有物，当月生效；
2. 第 2 月练琴 2 次：`_capabilities_now` 查有效持有物（不扣寿命），找到“能弹吉他”，记一条参与：完成、2 次、4 参与小时、用到 `k51.durable.guitar`；资源账记 4 小时；
3. 寿命只按服务月扣：第 2–12 月共 11 个月，年末剩 25 个月，跨年不重置；
4. 买失败、病中按应急安排取消、下一年才生效、已到期：都没有能力，这个月的练琴记“没能进行”，不收费、没有小时、不计分；
5. 到期之后可以在晚于到期的月份再买一把（两段服务月不重叠）；还在服务期内再买同一件仍然拒绝。

网球套餐：活动自带“能打网球”，这一次就能打；不生成持有物，下一年想自带球拍去打就没有能力。

## 4. 评分（`src/econ/life_scoring.py`，评分版本 `e1-life-v1`）

物质 M = Σ 物质权重 × 四项分数（居住空间、饮食生活、日常生活便利、个人消费与享受）；B 与 S = (1 − γ)B + γH 不变。每项 s = min(c, z/(z + τ))。

| 分项 | z | 手算 |
|---|---|---|
| 饮食生活 | 1 × 每周新鲜餐 + 0.5 × 每周合口味餐（τ 7） | 基本方案 3 顿新鲜 → 0.3；川味家常（21 顿全川菜、10 顿新鲜）对确认川菜的人 → 20.5/27.5；家常加意式外食（新鲜 14） → 14/21 |
| 个人消费与享受 | Σ η_f v_f：居家舒适在用 1.5，放松护理每次 1.0（τ 3） | 舒适椅 1.5，椅 + 坐垫仍 1.5，椅 + 每月 2 次按摩 3.5 → 3.5/6.5 |
| 休闲 | 城市背景 4 + 参与小时 ×（1 + 0.5 × 主类别匹配）（τ 12） | 合唱 2 小时：确认音乐的人 7/19，中性 6/18；没有活动的月份两人相同 |

价格、档次、外食次数不是输入；外食只在饮食项计分，烹饪课只在休闲项计分；纯装备没有享受功能；同一参与拆成几条记录得分不变；次要标签不再乘。

## 5. 期末参考生活（`src/econ/life_terminal_value.py`，评价版本 `e1-life-evaluation-v3`）

每个模板每月安排 4 次音乐练习，按**能力**使用期末持有物（任何在服务期内、能弹吉他的都算，商店现在卖不卖不影响）：

* 持有物覆盖整个 12 个月 → 照用；
* 只剩 r 个月 → 前 r 个月照用，之后基本模板停止、较舒适模板在第 r + 1 个月换一把；
* 没有这项能力 → 不买、不安排。

较舒适模板另有每月一次按摩；期末在用的舒适用品照常提供功能。模板没用到的期末能力写进“未估值”的范围缺口。两座城同一套槽位与模板；L/V/J 公式不变，购买价不进估值。

## 6. 信息隔离（`src/agentlayer/life_views.py`）

代理看到：食品方案的组成与小时、享受的功能与份数、装备能力、活动的类别与小时及需要的能力（逐字段复制，不带审计用的说明文字），确认的兴趣与口味与本版未支持的原文（新许可 `show_interests`，没有默认值），上一年的参与事实（反馈与记忆 `e1-life-memory-v2`）。

代理看不到：评分规则编号、η、κ、τ、锚点、匹配结果、参考方案与参考分、评价模板编号、未来事件。空字段（没有工资、没有资格标签……）不序列化：键不出现就是“没有”；价格的 `null` 仍表示没有报价。这样产品样例最大一份离线请求约 61,894 token，低于所有者设定的 64,000。

## 7. 接入层（E3）

* 物质四项（词表 `e3a-vocabulary-v2`）；公共结构 `e3a-product-schema-v3`，旧确认重新审阅。
* 兴趣与口味（`src/product/interests.py`）：文字按资料包别名切片成候选，有歧义的列出、没认出的原样保留；**选中**才进入画像；只有文字没有选中时审阅阻断。作答状态分开：未答 / 暂不确定 / 没有固定爱好（没有偏好）/ 通用评价 / 确认。品牌只留存。
* 生活扩展候选的编译检查（`src/product/life_items.py`，`e3-life-item-compiler-v1`）：只用 E1 契约与词表判定能不能编进 E1——可执行 / 拒绝（缺做饭时间、带日期或年龄限制、代替正餐、寿命不明）/ 本版未支持 / 资料未知；不补任何数值；编译结果有自己的内容身份。

## 9. 省略了什么、影响谁

* 真实资料（intake-02）没有做饭时间、每周新鲜餐数、活动参与时间与无日期的活动，相应机会不能编进 E1；本轮只在合成样例上可执行。
* 菜系与兴趣只有很小的合成词表；说法不在别名里的人得到“没认出”。
* 匹配系数是统一的模型假设，不是对个人的测量；真实模型会不会据此安排生活没有验证。
* 期末模板只覆盖“音乐练习”这一种装备活动；球拍等其他能力报范围缺口。
