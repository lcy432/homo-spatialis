**六维日常生活偏好合计 100 分，加独立的健康风险应对回答。健康回答不占这 100 分，也不是第七个评分权重。**

**一、目标：让用户答案真正进入已有生活引擎，同时保持最初的实验设想。**

项目的直观设想是：把代表同一个人的多个分身放到不同城市，每个分身固定在所在城市生活三个年度。规划器根据用户偏好、当地机会和实际状态选择行动；环境检查行动、按月算账、更新状态并评分；最后比较同一用户在各城市的生活结果。

本轮必须保留以下分工：

- 用户决定自己重视什么，E3 解释、校验并取得确认。
- 分身选择怎样生活，不能由 E3 预先固定消费比例或替它求出“最优人生”。
- E1 决定行动是否可行、实际赚花多少钱、病情怎样变化及怎样评价。
- E3 从 E1 结果生成公开投影，E5 负责展示。
- 不用静态效用排序、固定消费篮子、softmax 或最终评议 LLM 替代这条生活链。
- 产品中的用户陈述不是人的完整心理真值；研究中注入的偏好真值保持独立。
- 本轮用 mock／可控离线规划器验证接线，不声称已经检验真实 LLM 的偏好理解或真实城市推荐能力。

最终必须实际贯通：

**原始答案 → 可读确认 → 已确认画像 → 标准初态及 E1 输入 → 现有检查与冻结 → 三年离线生活 → E1 评价和汇总 → 产品结果。**

至少包含同一用户跨两座合成城市的完整闭环。样例规模不代表未来产品的城市数量上限。

**模块 B：原始答案、确认画像和精确偏好。**

原始答案、候选解释和已确认画像分层保存。后续修改相关答案，应使旧确认和预检查身份失效。内容指纹用于核对内容，不代替线上认证与授权。

输入包括：

- 候选城市的稳定身份；
- 职业原文、语言、确认职责、职业概念和分类映射；
- 年龄、可用现金、币种、金额时期及口径；
- 六维与物质细项；
- 独立健康回答；
- 可选文字、属性偏好、已确认资格和受支持的硬要求。

状态至少分开：

- 答案：未答、已提供、明确无所谓、暂不确定。明确 0 是已提供的数值。
- 支持：支持、部分支持、未支持。
- 确认：待确认、已确认、修改后失效。
- 用途：规划、初态／资格、评分、仅留存；必要时另标执行是否保障。

六维键为：

`material / safety / opportunity / leisure / environment / commute`

物质键为：

`housing_space / fresh_food / daily_convenience`

落实以下规则：

1. 六维合计 100；物质父项为正时，三细项也须有有效的合计 100 分配。
2. 物质父项明确为 0 可以跳过细分，记录为不适用，不伪造三个回答。
3. 不预填数值、人格套餐，不自动按比例扣减其他项。
4. 主动均分才生成平均值，不把“无所谓”自动换成 0 或均分。
5. 手工输入先按精确十进制解析；确认结果使用统一的精确分数表示，例如 `"50/3"`，并规定规范化方式。
6. 六维均分每项 `50/3`，物质均分每项 `100/3`；不能给排列靠前的项目多分。
7. 显示文本与计算值分开，显示舍入不回流计算。E5 不承担凑和与业务归一化。
8. 正权重缺资料或支持时明确报告，不静默删除并重分配。
9. 各维含义、参考改善范围、当前覆盖统一由 E3 提供；不能逐城重新标定用户权重。
10. 便利权重表达减少杂务的相对重要性，不是预算、愿付金额或必须购买的指令。设备和人工服务不各设一份必填偏好。

健康问卷使用以下三道有版本的占位题，状态标为暂定文案，不宣称量表已验证：

共同提示：“假设基本生活已有保障，判断下面的选择是否符合你。没有正确答案。”

- “一种安排能多赚一点钱，但生病、需要休息几天的可能也更高。我愿意选择它。”
- “为了应对可能发生的健康开支，我愿意推迟一次想要、但并不急需的消费，先留一笔钱。”
- “健康风险的信息还不清楚时，我愿意先放弃眼前的一点收益，等了解清楚再决定。”

选项：“符合我／不符合我／无明显倾向／暂不确定”，无预选；未答另存。

保留题目版本、题目 ID、答案状态、选项及对应含义。不计算总健康分，不推断患病概率、疼痛权重、疗效、愿付金额或拒绝治疗。未答与不确定可以保留，但观察中必须准确说明没有相应明确指令。

职业匹配首轮采用现有目录和受控词表，实际实现明确、歧义、未知路径。用户确认少量可读候选，不填职业代码。内部保留国家、分类体系、版本、代码及依据。职业、资格和城市岗位分别记录，不从职称自动授予证书。本轮是目录岗位下的生活情境，不新增招聘概率。

自由文字沿用 2,000 字符限制，明确报超限，不静默截断。不调用 LLM 提取，不沿用旧文本自动调分逻辑。若有规则产生候选结构化解释，也必须确认后才能生效。

品牌、菜系、制作方式、档次、服务质量和上门顾虑保留原文与支持状态，不偷偷挪入已有权重。若用户确认“不让陌生人进家”等为不可妥协要求，而当前无执行保障，应明确报告不支持，不能伪称现有硬要求检查已经能拦截。

保留未来访谈的来源与证据引用接口：

**访谈记录 → 候选解释 → 确认画像 → 同一编译器。**

本轮仅支持表单入口，不实现访谈，也不将 MBTI、塔罗等标签自动映射成数值或事实。

- 模拟失败不写成生活出局；服务或预算暂停尚无报告时显示未生成，不擅自生成分类。

- 用户结果不能原样回灌仍在生活中的 agent。
- 不新增排序规则、最低完成比例或现实推荐结论。

公开样例只用合成人物，不将真实个人输入、原始模型回复、内部路径或密钥默认放入产品响应和公开仓库。
