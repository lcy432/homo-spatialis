## 3. 七类问题：复现、修复与验收

以下行号对应审核基线，以当前代码为准。本节E5-R1–R7与E3审核的“R1旧画像兼容”不是同一编号。

### E5-R1：未完成的“有经验”被保存成“没有经验”

**复现：** 新建草稿，目录选餐厅厨师；点“有相关经验”，不填年数，等待保存，刷新。当前变成“没有相关经验”。定位 `web/src/pages/draft/Steps.tsx` 的 `ExperienceQuestion`，基线约198行：has派发了 `experience/state = none`，只靠局部 `wantsEntries` 保持外观。

**修复：** 未填写足以形成业务答案的年数时，业务保持未答，并提示待补全。页内编辑意图可以暂存，但“明确没有”必须只来自用户主动的否定选择。不能用 `provided + []` 同时表示“还没填”和“没有”。如需刷新后完整恢复中间编辑意图，交E3定义持久化语义；这不阻塞先修“不写成没有”的错误。

**验收：** 有经验未填、输入无效年数、填完后删除、换职业、返回/刷新、撤销都不产生未经选择的否定。明确没有仍按正式空表保存，填足有效年数后仍由E3判断资格，前端不授予资格。经验待补全时审阅如实显示；不靠隐藏输入让确认继续。

### E5-R2：迁移内容变化后，旧同意未作废

**复现：** 旧草稿有一条待清空要求，勾选同意；在另一请求中增加第二条要求；原页面迁移收到修订冲突，再点重新读取。新清单已出现，但同意框仍勾选。定位 `MigrationPanel.tsx` 的consent状态与 `DraftRoute.tsx` 的重读复用。

**修复：** 同意只适用于当前草稿ID、服务端修订和此次明确展示的迁移影响。上述任一变化后清除同意，按钮重新等待用户选择；提交继续携带正式expected_revision。不要以缓存旧勾选替代新授权。

**与v3.5关系：** 删除旧硬要求/属性偏好的同意，和旧分配改成新原始评分的选择，是不同语义。按E3正式迁移结构展示；可以同页，但必须让用户知道清除什么、保留什么、评分要重新回答什么。既有迁移同意不能自动授权“把旧百分比当评分”，也不能把已确认画像或已开始运行送进草稿迁移。

**验收：** 正常迁移通过，未同意无请求；待移除项增删改后重读必须重新同意；旧分配可先查看，再明确选择重新评分或同等重视。未选择时不生成新评分；无关事实保留，旧确认不能充当新问卷授权。

正常迁移的浏览器测试现在就能补：现有 `tests/product_service/test_input_closeout.py::_old_draft` 展示了通过保存接口构造待迁移草稿的方法。本方法可测试迁移交互，**不能**证明真正旧画像的身份兼容；后者必须使用旧版本实际产出的JSON与运行。

### E5-R3：按中文原文查译文，丢失字段身份

**复现：** 在同一正式形状的显示信封内，两个位置都叫“文员”。第一项provided英文为Office clerk，第二项为missing/binding_unverified；当前 `buildScope/lookupText` 会让第二项借第一项英文。两项有不同英文又会一起变成歧义。内层unavailable还可能借外层当前能力清单。定位 `web/src/display/scope.tsx` 的byOriginal索引；原页面调用几乎不传pointer。

**修复：** 用明确业务对象、字段位置及来源快照定位服务文字，保留实体/目录身份。优先消费同一个DisplayEnvelope里的source与fields；若保留独立业务查询，按正式来源身份核对后才能组合。字段位置必须相对于正确的source，不在多个作用域按相同pointer或中文串碰运气。

- 缺失字段按自己的原因显示原文，不借同名实体、当前能力或最新资源。
- 不把组合后的英文句子再当中文全文查译文；先解析业务片段，再用UI模板组合。
- 换语言、对象修订、身份与资源版本时隔离缓存；旧异步回复不覆盖新对象。
- 未知、损坏或不匹配的附层不修改原业务对象，不跳过业务校验，不重签画像身份。
- 缺译统计对应实际呈现的字段，不能只因服务计数为0就掩盖前端漏接/错误关联。

**验收：** 同名不同实体各取自身英文；一项缺译不影响另一项且不借译；嵌套历史正文不由外层当前文字覆盖；source不匹配不套文字；数组重排仍按实际字段/身份关联。补组件与真实页面覆盖，不只保留纯函数测试。

**与E3兼容修复的边界：** E3旧画像加载后产生binding_stale是另一根因，不能靠E5猜译文消除。E5先修本节关联方式，等后端修复后再验证真正旧画像的18段英文及旧审阅。不要把前端假回退作为后端兼容测试通过。

### E5-R4：历史版本为空仍读取当前地图

**复现：** 结果显示信封resource_version为空，页面显示“没有绑定的历史版本”，但 `ResultsPages.tsx` 仍调用 `useGeography(pack, null)`。后端不带版本即当前清单。独立探针 `runs/e5r34/extra/boundaries.spec.ts` 已记录该请求；`unbound-display.json` 通过公共模型校验并有匹配的source指纹。

**修复：** 区分当前输入与历史结果。当前输入可读当前清单；历史结果必须有明确绑定才请求对应版本。null、尚未读取、显示失败分别呈现状态，但都不得用当前城市锚点兜底。保留底图、列表、表格与可读取事实，不伪造位置。

**E3C配合：** 将“版本为空不传”和“不回退当前版本”的矛盾写清：历史页面应停止该地理读取，而不是发出一个代表当前版本的请求。前端调用保护可以立即修，不需要等待新字段；真正旧对象绑定读取则等兼容修复联验。

**验收：** 正常结果传精确版本；旧版本404/损坏明确缺失；空版本及显示失败没有无版本地理请求、没有当前城市点。先看新结果再看旧结果也不能借缓存。当前选城地图仍可用，两种外观行为一致。

### E5-R5：独立鼠标手势被合并撤销

**复现：** 同一滑块第一次调到20并松手，第二次调到40并松手，撤销一次却回到未答。定位 `Allocator.tsx` 的endSlide、pointer结束事件和 `draft/reducer.ts` 的points/move合并键。

**修复：** 明确指针手势边界，一次按下—移动—结束只提交一次；下一次独立手势新建一条记录。连续方向键可按同一编辑序列合并，失焦/换项目/新的独立操作结束合并。取消手势、失焦与pointerup的组合不重复提交。

**与新评分关系：** 在可复用的控件/历史层修，再让ratings控件复用；不必为旧转移器单独重做整套UI。恢复的是原始评分和答案状态，不能用舍入后的饼图权重作撤销快照。

**验收：** 未答→20→40，两次独立手势撤销依次回20、未答；重做反向恢复。一次拖动的许多input事件只一条记录；连续方向键按约定合并；鼠标、触摸模拟、键盘与数字精调可用。明确输入0能区别于未答，即使滑块初始视觉位置就在0。松手保存，不每个像素触发审阅。

### 4.1 真实旧画像与旧运行

E3审核确认：真实旧JSON由 `a851db3` 生成，新版加载补入qualifications/catalog字段后改变身份；原暂停运行恢复后变成service_reference_stale，旧画像18段英文变binding_stale。次数未重复扣除不等于恢复成功。

- 旧草稿按新问卷显式迁移，需要用户重新回答/确认；

- 已开始的旧运行继续使用原画像、设置、run_id、归档及显示资源，按allowed_actions明确恢复；
- 历史结果继续可读，不被新评分或新启动UI强制迁移。

使用真正旧版产出的JSON和暂停运行。把新版对象改版本号、重算指纹，只能作为特定控件测试数据，不能作为升级兼容证据。已存模型回复不重发、额度总共使用一次、数据库只读不改写等核心证据由E3提供；E5补浏览器打开、展示、明确恢复及结果可达的联验，不冒称重跑了所有后端探针。

### 4.2 新评分契约与旧分配迁移

等E3实际提供schema、转换版本、原始答案路径、审阅原始合计/精确权重、确认来源和迁移样例后再接。前端可按公开规则精确预览，正式校验和确认仍由E3负责。

验收必须包括：未答与明确0分开；全零报错、不自动均分；“同等重视”主动将原始评分设50；尚未答完只显示明确标注的临时预览，不能把未答画成已经确认的0权重。暂不确定、无所谓不转数值。原始精调最多两位小数，派生权重可为精确分数，显示舍入不回写。

物质父项为0时四维不适用，草稿中的四维原始答案仍保留；父项恢复正数后找回，不能清零、均分或参与父项为0时的评分。旧manual/equal_split的百分比按原义展示，用户明确选重新评分或同等重视后才进入新模式；已确认对象与运行不改。

新字段加入后，真实v3.3旧画像兼容验收必须再次通过；另覆盖v3.4对象，不能只验证最新新建用户。

### 4.3 一次开始与进度摘要

以E3最终OpenAPI为准接设置预览和带授权的意图创建，不把建议路由或字段名自行实现为公共API。

- 预览展示有效城市/人数/年数、停机费用上限、模型种类、范围与必要知悉项；不声称预算上限是预计费用。设置改变后旧预览/同意失效，获取新版并重新确认；语言切换不能改变授权含义。
- 用户一次“确认并开始”提交 `start_when_ready`。同一次操作保留同一业务幂等身份，连点、响应丢失、刷新或重开后通过E3正式查询/幂等重试找回同一意图与run。没有拿到intent_id时也必须有找回路径，不能猜“列表里最新一项”，不能生成新键另起运行。
- 后台完成检查后自动衔接的是已持久化授权。前端轮询永远只读，不发现ready后自行submit/confirm/resume。关闭浏览器后仍运行。
- 新流程没有第二个正常开始按钮；无预授权的旧意图保留原正式流程。失败、预算停止、发送不确定或旧暂停运行不自动恢复，不自动新开一次。
- 授权条件变化或阻断时按E3说明停止，展示修改/重新确认入口；不把普通已说明资料缺口再次变成正常流程的重复授权。
- 消费progress_summary的phase、当前句子、更新时间、进度模式与权威年度计数。检查/排队/整理为不定长；模拟展示已结算分身年度数，不用调用数、时钟或页面计数估计。
- 提前出局/中断未经历的年份不补进分子。只在结果实际可读时显示全流程完成；即使流程完成，年度数也不能强填计划总数，C/E/M照公开结果分别呈现。
- 断网保留最后已知状态和更新时间，说明暂时不能刷新；不能当成已完成或一直假装实时增长。错误/needs_attention展示原因与allowed_actions，不被永久转圈遮盖。
- 只替换当前一句状态，不累积普通用户的执行历史。保留“查看本次输入与设置”“离开稍后查看”，不增加没有后端支持的暂停动作。

| 故事 | 验收标准与证据 |

| 新评分状态边界 | 未答、明确0、全零、无所谓、暂不确定分别正确；不完整预览有标记；父项0→正数找回原四维 |
| 手势历史 | 两次独立操作两次撤销；一次拖动一条；键盘连续输入按约定合并；明确0可以撤回未答；原始其它项不变 |
| 一次开始与回执丢失 | 浏览器→真实本地服务→worker→LangGraph→E1 mock；只有一次开始授权；已受理但回复丢失后找回同一意图/run；一次额度 |
| 离开后后台继续 | 开始后关闭页面/浏览器上下文，后台完成检查与启动；重新登录找回同一运行，不能靠原页面偷偷提交 |
| 授权变化与失败 | 改城市/规模/预算需新预览/同意；后端报告资料/报价/知悉条件变化不能自动接受；付费关闭、检查失败、预算停止各有正确解释 |
| 真实进度 | 检查、排队、模拟、整理、完成、needs_attention及终态都有样例；出局/缺失的年度不补齐；完成且有M不会说全部成功 |
| 单次取消/恢复/删除 | 在有实际运行的身份中测试具体动作；首次排队取消与恢复排队不同；恢复是明确动作；删除该run后旧结果和display不可读、缓存不复活 |
| 历史与英文 | 真正旧画像/旧审阅/旧暂停运行按原身份可读并恢复；原译文/地图固定，缺资源不借当前；新增字段后再测一次 |
| 新旧意图并存 | 新授权意图没有第二次正常确认；旧未授权意图仍按原allowed_actions交互；不自动给旧意图补授权 |
| 全程键盘与手机 | 从选城、目录、评分、同意、开始、等待、详情到单次删除确认均可键盘完成；焦点正确，无遮挡；360×740及桌面、中英×双外观实测 |

单次删除测试不能用“另一身份只有一份草稿时删除全部内容”替代。正常版本号看起来像 `e3-display-res-*` 不能证明历史资源升级后不变，必须测试明确旧版、null、缺失/损坏与切换缓存。

保留现有退出失败、首页草稿、多标签冲突、跨身份隔离、邀请秘密清除、C/E/M空值、范围几何、月份事实、地图点选/地球拖动与WebGL回退等回归；记录各项实际测试层级，不把组件覆盖写成真实浏览器已验证。新的授权仍须保护预检查、费用、发送不确定、删除、到期和归属规则。

结果回归仍明确展示C/E/M、原计划人数和均值分母；C=0不补成0分，模拟缺失不解释为生活出局，缺失范围不叫置信区间。保留L/V/J的既定解释，V不承诺未来幸福；等待页或美术调整不能删掉这些含义。地图、图表和表格均消费同一公开结果，不另算评分或缺失范围。

浏览器可以在隔离服务中注入断网/回复丢失、创建受控暂停与缺资源场景。真实主链不能全部替换成stub；后端崩溃/升级证据若由E3C提供，应标明归属，不能冒称自己跑过。纯组件夹具也必须满足正式契约和来源身份。

手机视口和触摸模拟不等于真机；有真机则测试拖转/滑动/页面滚动竞争，无设备则明确保留该项未验收。axe不能替代全程键盘、遮挡和读屏文案检查。后续美术反馈改动后复核这些行为。
