E1-4B：上一年满足感对下一年月度精力额度的有界反馈
一、目标、范围与授权
在通过审核的 E1-4A r2 上实现：
根据一个分身上一年实际生活的完整满足感评分，确定下一年每个月可承受的活动负担额度。
本轮完成一个零 LLM 调用、可手算、可关闭反馈、可重放的合成机制，并打通：
年度结算 → 实际生活评分 → 下一年精力额度 → 下一年真实资源检查。
不是只写一个计算函数，也不是给状态手工填入新额度后宣称接线完成。
本轮授权新增必要的 econ 反馈纯函数模块和薄层年度编排接口，并修改相关 common、ledger、agentlayer 契约与接线。此授权覆盖本轮必要的 `src/econ/` 修改，不需再次为同一范围请求确认。
边界：

* 不修改旧静态经济内核、P8/P9/P10 或历史研究判定。
* 不改变 E1-3 的评分公式、偏好权重和缺失处理规则。
* 不改 E1-4A 的月度记账、分别往返、家务替代或出局下限机制。
* 不实现即时回血、月度疲劳累积、疾病、培训收益、折现、期末价值、城市排名。
* 不实现 LLM 适配器、重试系统或通用 runner；完整闭环仍属于 E1-7。
* 不接真实资料，不宣称反馈参数经过现实标定。
* 不提交、不推送、不执行 `git add`。
* 所有说明、演示与最终报告使用中文。

三、本轮探索规则
1. 反馈分数
使用现有 E1-3 评分器对本次实际结算结果产生的完整年度平均满足感：

```
S_y = 第 y 年 12 个月满足感的平均值
```

要求：

* 12 个月都已完整评分；
* 分数有限且在 [0, 1]；
* 属于同一个人、分身、城市和年份；
* 对应本次账目、评分规格和偏好来源。

不使用：

* LLM 自报幸福度；
* 行动理由或计划中的预期幸福；
* 单独某个有利维度；
* 部分月份的平均；
* 覆盖率；
* 现金、收入或剩余时间直接换出的分数。

产品路径用用户明确陈述的数值偏好；研究路径用内部合成真值。不能在产品缺偏好时借用研究真值。
硬要求继续按已有方式独立报告。本轮不把它们变成新的满意度扣分或精力公式。
2. 反馈公式
本探索版采用：

```
E_raw(y+1) = E_base × (1 + α × S_y)
```

其中：

* E_base：个人固定的基础月度精力额度，不含满足感加成；
* S_y：上一年完整年度满足感；
* α：最大加成比例。

本版允许 0 ≤ α ≤ 0.10：

* 新合成主样例显式设 α = 0.10；
* 对照取 α = 0；
* 小型敏感性比较取 α = 0.05。

这些是预先声明的合成参数，不是经验结论。不得看完结果后调参数，使某个城市、计划或假设得到期待的结果。
性质：

* 第一年从基础额度开始，没有虚构的第零年满意度。
* 第 y 年的满意度只影响第 y+1 年。
* 下一年的 12 个标准月使用同一个更新后的额度。
* 时间预算不变。
* 每次从固定 E_base 计算，不从上一年的加成后额度继续乘。
* 不累积所有历史满意度，只用上一年。
* 满意度降低可以使加成减少，但本版不低于基础额度。
* 未安排时间不自动变成休息或恢复。
* 精力加成不直接加进满足感评分。

手算例子：基础额度 250，α = 0.10。

* S = 0：下一年 250。
* S = 0.6：下一年 265。
* S = 0.8：下一年 270。
* S = 1：下一年 275。

连续两年 S = 0.8，后续额度仍是 270，不会从 270 再增加 8%。
3. 数值口径
现有资源输入只接受两位小数，反馈结果必须能合法进入下一年资源检查。
本轮约定：

* 评分器保持已有的数值实现，不重写它的浮点算法。
* 反馈读取评分器输出的数值，按明确的十进制表示进入确定性计算。
* 先保存未量化的 E_raw，再向下保留到 0.01 负担点，得到实际使用额度。
* 记录量化前后数值与规则。
* 不使用偷偷添加 epsilon 的方式跨过边界。
* 量化后的额度仍不得低于基础额度或超过声明上限。
* 月度资源比较继续精确进行，不添加容差。

把“量化规则”和“测试容差”分开：账目与已量化资源仍精确比较；已有评分测试的数值口径不因本轮放宽。
四、基础额度、当前额度与状态流转
区分：

1. 固定的个人基础额度；
2. 当前行动年的实际月度额度；
3. 产生本次更新的年份、政策版本与内部依据。

可以继续让 `energy.level` 承载当前实际额度，但不能因此丢掉固定基础额度，也不能下一年把更新后的 level 当作新的基础。
同一个人的对照分身：

* 初始基础额度和时间预算相同；
* 第一年当前额度等于基础额度；
* 之后可以因各城市实际生活的满足感不同，产生不同的当前额度。

调整相关跨对象检查时，不要把“同一个人跨城基础一致”的约束删掉，也不要让它错误地禁止第二年以后合理的额度差异。
内部记录至少能追到：

* 人、分身、城市；
* 来源年与目标年；
* 反馈政策与评分版本；
* 基础额度、原当前额度、新额度；
* 分数来源、反馈强度、未量化值、量化规则；
* 更新、关闭、无法计算或无需更新的原因。

完整内部依据不进入代理观察。
重复调用同一年度交接不得叠加加成。重放应得到同一结果；不能把第 1 年的分数拿去更新第 3 年，或把另一座城的分数用于当前分身。
五、关闭、缺失、失败与终态
1. 关闭反馈
反馈模式必须显式配置，新 B 协议不能因漏字段而静默关闭。旧 A 协议继续固定额度。

* 明确关闭，或有效强度 α = 0：额度使用固定基础值。
* 关闭分支不需要完整满意度即可继续结算。
* 可以另行生成评分报告，但缺评分不能阻断本来可行的关闭对照。
* 不把上一轮开启反馈产生的加成当作关闭对照的初始条件。
* 实验臂从相同初始状态分别运行，主演示不在中途切换政策。

在相同初始状态与相同计划下，关闭反馈的业务结果应复现 E1-4A r2。若 B 新增元数据导致结构不同，预先列出允许不同的字段，其余账目、活动、资源和状态逐项精确核对。
2. 评分不完整
开启反馈、存在下一行动年、但缺少完整评分时：

* 不补零；
* 不用已知月份平均替代；
* 不重新归一化偏好；
* 不擅自维持旧加成或恢复基础额度并称反馈已完成；
* 返回明确的“反馈信息不足”，列出原因。

当年已完成的真实结算保留。这是下一年反馈更新无法完成，不是当年计划不可行，不回滚当年的生活。
编排接口不能把一个尚未确定精力额度的候选状态，当作可直接开始下一年的正式状态返回。区分已结算结果与可继续执行的下一年状态。
3. 结算失败、出局与终态

* `plan_infeasible`、`input_error`、`data_error`：不产生生活满意度反馈，不推进状态。
* 已出局：不更新精力、不复活；当年出局信息保留。
* 正常结束第 N 年：进入 N+1 终态，不再为不存在的下一行动年计算加成。
* N 保持可配置，至少验证 N=1 与 N=3。
* 最后一年仍可以正常评分和记录；是否有下一年反馈与最终评分是否完整是不同问题。

六、接线方式与信息边界
接线原则
建议分为：

1. common：反馈政策、基础额度与结果记录的必要契约；
2. econ 反馈纯函数模块，例如 `life_feedback.py`；
3. 一个很薄的年度交接/编排接口；
4. ledger：加载与一致性检查；
5. agentlayer：公开额度与安全事实投影。

具体文件名可按仓库结构调整，职责不得混合。
保持：

* `settle_year` 不读取评分或偏好真值；
* `score_year` 只读当年的年初状态与实际结果，不修改账目；
* 编排层在结算之后调用现有评分器，再更新下一年额度；
* 下一年的结算器实际使用更新后的额度。

不要另造评分器或复制资源算法。
评分要使用第 y 年年初状态，不能误传已经推进到第 y+1 年的状态。优先在编排接口内对本次结果调用评分器，避免随手传入一个同名但来自另一份账目的分数。若复用缓存，必须核对相应输入指纹。
本轮只需用固定结构化计划完成多年度离线演示，不实现 LLM 规划和通用运行平台。
信息边界与研究条件
标准产品分身继续看到：

* 当前年度实际月度精力额度与单位；
* 时间预算；
* 活动的公开时间、负担及执行事实。

不直接发送内部年度分数、隐藏偏好、评分参数、完整反馈计算记录或它们的序列化字典。
同时必须明确：
不直接发送分数，不等于没有间接透露评价。额度随满足感变化，本身就是反馈通道；若基础额度和公式已知，甚至可以反推分数。
分别记录：

* 反馈政策是否开启、有效强度是否为零；
* 精力额度是否可见；
* 这是静态文字理解条件，还是含生活反馈的动态条件。

不要仅用已有 `dynamic_feedback_channel` 一个布尔值，代替“E1-4B 是否实际开启”的判断。
原来用于测量文字偏好理解的无反馈条件应保持独立。即使隐藏精力数值，变化后的行动可行性也可能透露信息，不能宣称简单关显示就消除了反馈。
新增内部类型及原样序列化结构要按现有隔离机制处理，不只拦对象、不拦字典。不要扩大通用保留键名单，误拦正常生活事实。
七、合成样例与实际演示
新增 B 专用生活配置、匹配的探索评分配置和反馈政策。旧 A、旧 E1-3 配置不改写。
新样例需通过已有单位、来源、功能供给与比较组检查。不要为打通演示绕过 E1-3 的资料校验。
至少演示：
A. 真正的年度交接

* 从实际年度结算生成完整探索评分；
* 用该评分产生下一年额度；
* 下一年读取上一年的现金、物品和新额度；
* 再结算和评分；
* 三年后进入终态。

主闭环选用当前评分器支持的生活安排，例如明确的一份线下工作。不要为本轮扩展远程、多岗位或家务满足感公式，也不能偷偷删除已有正权重来制造完整评分。
B. 开关对照
相同起点、相同目录和相同预先声明的年度计划，分别运行反馈关闭与开启。
至少一个例子显示：

* 第一年生活结果相同；
* 下一年额度开始不同；
* 某个钱和时间都够、负担位于两种额度之间的计划，一边可行、一边不可行。

它只验证接线，不证明开启反馈使产品更准确。
关闭分支若停止，不补出之后的生活结果；也不只比较继续存活的一边而宣称效果更好。
C. 机制检查

* 连续高满意度不造成额度复利增长；
* 满意度下降后加成减少；
* α=0、0.05、0.10 的小规模对照；
* 缺少完整评分时明确阻断下一年反馈更新；
* 同一缺失情形下，关闭反馈的资源执行仍可继续。

纯函数手算测试可以直接输入 S=0.6。端到端演示必须实际调用评分器，不能用手填 S 代替接线。
八、验收要求
至少覆盖：

1. 第一年基础额度、年度滞后、下一年 12 个月使用同一额度。
2. 固定基础、不复利、上下界、单调性及精确量化。
3. 时间预算不变；未安排时间不回血、不加分。
4. 分数身份、年份、城市、协议及对应账目错误被拒绝。
5. 评分来源正确：产品不借研究真值。
6. 12 个月完整才更新；缺分不补零、不重归一化。
7. 已结算生活与反馈失败分开；不把反馈失败写成计划失败。
8. 失败计划、出局、终态不发生非法更新；N=1 不虚构下一行动年。
9. 重放一致，重复调用不叠加，输入与既有账目不被修改。
10. 关闭分支及 α=0 不依赖完整评分，复现 A 的固定额度行为。
11. 新额度确实被下一年的 `settle_year` 使用。
12. 跨城基础一致，后续当前额度可以合理不同。
13. 可见权限与内部对象、序列化结构的隔离有效。
14. E1-4A r2 的出局下限、多岗位、精确预算等回归继续通过。

先跑针对性测试，再跑全量离线回归和改动文件检查。不得放宽旧数值容差或更新历史结果来掩盖行为变化。
少量有针对性的变异检查应验证关键保障，例如：

* 用上一年当前额度替代固定基础；
* 提前把本年评分用于本年；
* 把缺失评分补零；
* 关闭反馈仍要求评分；
* 算出新额度但下一年继续使用旧额度；
* 允许错误年份或另一分身的分数进入更新。

变异在临时副本运行，并核对工作区未受污染。
九、版本、文档与证据
B 有独立的协议/反馈政策身份，不让 A 的历史输入被静默赋予新行为。
无需重写月度资源规则，但要明确资源执行修订、评分版本、反馈政策与信息条件如何共同标识一次运行。
新反馈参数与配置必须明确，缺配置不猜默认。新机制完成后仍是合成探索，不把整个生活协议标成 formal，不为解锁演示把其他未决政策改成 decided。
按既有文档分工更新：

* README：说明新增能力与关键限制，保持篇幅克制。
* PLAN：A 已审核完成，B 已实现待审核，其余 E1 阶段状态准确。
* E1-4 技术说明：完整记录本轮公式、数据流、取整、失败状态、信息通道、例子、代码与测试落点。
* 新 ADR：使用当前可用编号，明确旧建议未采用、本轮采用什么及原因。
* CLAUDE：必要导航与约束更新。
* 设计索引与 prompt 归档。

省略表继续采用“省略什么—影响谁—以后如何扩展”的结构。明确反馈方向和幅度尚无经验标定，当前机制不模拟临床疲劳、疾病或休息恢复。
证据写入新的运行目录，拒绝覆盖。包括：

* 命令、配置副本、版本与源码指纹；
* 每年实际账目、评分、基础额度、更新前后额度；
* 反馈开关与可见条件；
* 手算核对、对照、缺失和停止原因；
* 测试结果及未来提交依赖清单。

十、最终报告与审核点
最终报告全中文，按以下顺序：

1. 实现了什么、仍不能做什么；
2. 一个三年生活例子，逐年解释“今年如何生活，为什么明年额度改变”；
3. 开关对照：相同与不同分别发生在哪里；
4. 缺分、出局、失败、终态怎么处理；
5. 分身能看到什么，以及仍存在什么间接评价信息；
6. 文件、依赖图、兼容性与版本；
7. 实际测试结果、发现的问题和修复；
8. 合成假设、受影响人群、未解决事项；
9. 待审核项与证据位置。

公式旁边写生活含义。金额、小时、负担点和满足感不得混用单位。不要用大段 JSON 或“全部通过”代替解释，也不要把原理示例说成真实运行结果。
完成后停在架构审核点，不进入 E1-5，不提交、不推送。
