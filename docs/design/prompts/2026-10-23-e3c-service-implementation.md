## 一、目标与边界

完成后，E5 应当能够通过正式 HTTP 接口实现：

> 用户打开专属链接 → 填写与审阅 → 确认画像 → 查看运行前说明 → 确认开始 → 后台模拟 → 查询结果 → 删除。

用户关闭网页、刷新、换设备或服务重启，都不应因此生成另一批分身或重复扣次数。

已确定的产品规则：

| 内容 | 本轮规则 |
|---|---|
| 访问 | 每人一个专属链接，不注册、不收集邮箱 |
| 使用次数 | 每人总共 3 次，不自动重置 |
| 模拟规模 | 六个都会区、每城 4 个分身、每个分身 3 年 |
| 每次费用保护 | 应用侧按报价控制在 10 元人民币以内，不自动加预算 |
| 结果保存 | 从运行首次结束起保存 30 天，查看不续期 |
| 主动删除 | 支持；运行中删除会停止批准后续模型请求 |
| 产品模型 | 复用仓库的 `product_planner` 角色及现有传输层 |
| 本轮验收 | 离线 mock、假传输层、故障注入；真实调用为零 |

“3 次”是 **3 次启动模拟的机会**，不是保证取得 3 份所有分身都完整的结果。资料不足、部分模拟缺失和预算耗尽仍须如实报告。

保留现有六维偏好、独立健康回答、物质四项、口味与爱好、标准初态和所有信息隔离规则。偏好表示用户在意哪些改善，不是固定消费比例。

**不属于本轮：**

- E3B 的住房、通勤、安全等映射返工和数据补齐；
- 活动日历、年龄资格等生活功能扩建；
- LLM 访谈；
- E5 页面布局和视觉设计；
- 多机调度、自动扩容、支付、注册系统、管理员网页；
- 修改工资、税、疾病、评分、反馈、L/V/J、C/E/M 的数学。

## 三、架构固定如下

采用：

- **FastAPI**：认证、业务请求、查询。
- **SQLite**：邀请身份、会话、草稿、额度事件、提交与任务记录、公开状态。
- **一个独立 worker 进程**：串行推进用户的模拟。
- **现有 LangGraph**：负责预检查、确认、提交、启动或恢复、结果交付。
- **现有 E1**：负责分身生活、规划修订、费用账本和归档。
- **持久磁盘**：保存每次模拟独立的工作目录。

同一时刻只运行一个用户的模拟；这一批内部继续使用现有分身并行能力，最多 16 个工作线程。不要把分身重新改成完全串行。

长任务不能放进 HTTP 请求或 FastAPI 的进程内 `BackgroundTasks`；重启后的恢复由持久任务记录和原流程负责。这也符合 [FastAPI 对较重后台工作的说明](https://fastapi.tiangolo.com/tutorial/background-tasks/)。

责任关系：

```text
E5 浏览器
    ↓ 同源 HTTP
E3C：身份、次数、业务请求、公开查询
    ↓ 持久任务
单个 worker
    ↓
现有 LangGraph
    ↓
E3 编译 / 预检查 / 投影 ↔ 现有 E1
```

队列只负责“哪个工作什么时候执行”，不能再另写一套确认、规划和恢复流程。

建议模块位置固定为：

- `src/product/service/`：HTTP、认证、存储、任务、留存与公开视图；
- `src/product/execution.py`：构造正式运行设置，供服务和脚本复用；
- `src/product/workspace.py`：生产使用的工作目录准备；
- `scripts/product_service.py`：启动 API、worker 和管理员操作；
- `configs/product/service.yaml`：不含秘密的服务配置；
- `tests/product_service/`：服务验收。

若现有工作目录准备逻辑位于 `fixtures`，提取成正式模块后让测试复用。生产服务不依赖合成人物、测试脚本或 monkeypatch 来构造真实用户。

HTTP 进程不得调用 `chdir`。需要现有工作目录上下文的编译与运行都交给 worker。

## 四、专属链接、身份与权限

### 1. 链接不是用户名，而是一把钥匙

邀请链接采用：

```text
https://<站点>/invite#token=<随机秘密>
```

秘密由密码学随机源生成，使用 32 字节随机值；服务端只保存摘要。创建时向管理员显示一次完整链接，不能把它写进普通日志。

E5 读取 fragment 后，通过 JSON 请求交换会话，再从地址栏移除秘密。不要将邀请秘密放在查询参数、路径、localStorage 或模型请求中。

浏览器会话同样使用随机秘密，服务端保存摘要。正式环境使用：

- `Secure`、`HttpOnly`、`SameSite=Strict` 的 host-only Cookie；
- 会话固定有效期 7 天，不因查询自动延长；
- 会话到期后可以重新打开原邀请链接；
- 邀请链接本身持续有效，直到管理员撤销或重发。

这些是本项目选定的具体实现参数；安全 Cookie 与会话管理原则参考 [OWASP 会话管理说明](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)。

重发链接必须沿用原来的身份和次数，并使旧链接及旧会话失效。转发链接意味着别人也能进入同一空间，不能宣称验证了现实身份。

### 2. 服务身份与模拟人物分开

每个邀请对应服务端生成的 `principal_id`。

`person_ref`、`confirmed_id`、`run_id` 或内容指纹都不能充当访问凭证。不能接受浏览器提交一个 `user_id` 就取得其数据。

所有草稿、确认、运行、查询、恢复、删除都检查归属。访问别人的编号统一返回不存在，避免泄露他人是否有该运行。

### 3. HTTP 保护

- 正式环境同源 HTTPS；关闭任意来源的 CORS。
- 修改操作同时检查 Origin 与会话绑定的 CSRF token。
- 邀请交换限定同源 JSON 请求。
- 请求体上限 256 KiB。
- 邀请交换按来源地址限速，默认每分钟 10 次；其他写操作按身份默认每分钟 60 次，超限返回 429。
- 生产环境不公开交互式 API 文档。
- 不记录 Cookie、邀请秘密、CSRF token、完整请求体或原始校验异常。
- 本地 HTTP 模式必须显式开启且只绑定回环地址，不能静默降低生产安全设置。

管理员只通过本机 CLI 创建、撤销、重发邀请，查看待处理任务和修正误扣次数。不增加管理员网页。

## 五、输入、确认与最终运行身份

保留两次独立确认：

1. **确认画像**：“系统这样理解我，是对的。”
2. **确认运行**：“我知道这次范围、限制和费用保护，使用一次机会开始。”

具体规则：

- 草稿编号由服务器分配；保存使用 `expected_revision`。
- 两个标签页修改同一版草稿，后到的旧版本返回冲突，不能覆盖新答案。
- 审阅绑定草稿编号、版本、内容和所用资料包。
- 确认请求只提交草稿／审阅引用及知悉项；服务器重新校验并调用 `confirm_profile`。
- 不接受浏览器自行构造完整 `ConfirmedProfile` 并宣布它已确认。
- 后续修改草稿不能改变已经确认运行的输入。

新增服务端内部 `ExecutionSpec`，保存固定规模、规划器设置、模型角色、报价、费用及调用上限等。它由服务器配置产生，不是前端可编辑表单。

**必须先编译最终运行设置，再生成 ProductPreflight。** 不允许用户确认 mock 预检查后，后台偷偷换成真实模型。

最终身份至少绑定：

- 确认画像；
- 冻结资料包及其引用文件的实际内容身份；
- 六城 × 四分身 × 三年的规模；
- 协议、评分、评价、提示模板及信息许可；
- 真实规划器、有效调用设置、报价版本；
- 规划调用、服务请求、费用上限。

仅凭清单声称的哈希不够，应复用已有内容核验。

生产入口显式配置 E3B 资料包，不得回退到合成资料包。六城有不满足的必要条件时说明阻断原因，不偷偷删城、减分身或补资格。

新资料包影响尚未确认运行的预检查；**已确认并排队的运行也绑定当时那份快照**。后续更新不能替换它。快照缺失或被改坏时停止，不用新资料冒充旧资料恢复。

本轮可以使用当前包做离线接线，但不能代替另一会话宣告 E3B 的映射返工已验收。

## 六、次数、提交与排队

### 1. 次数如何变化

| 用户行为或运行状态 | 次数处理 |
|---|---|
| 填写、审阅、确认画像、预检查 | 不扣 |
| 确认开始并成功入队 | 预留 1 次 |
| 最终核验通过，准备首次启动 E1 | 预留转为已使用 |
| 开始前取消，或启动前检查失败 | 释放预留 |
| 刷新、查询、恢复原运行 | 不另扣 |
| 开始后出现部分结果、预算耗尽或用户删除 | 不退次数 |
| 删除结果、换设备、重发邀请 | 不重置次数 |

公开返回 `total=3`、`used`、`reserved`、`available`。

次数以不可重复的事件记账；管理员修正误扣也追加记录，不直接改掉历史。不因为出现 M 就自动退款。

### 2. 一次确认只能产生一次运行

引入服务端生成的 `RunIntent`，表示“准备进行的这一次模拟”。

- 同一身份最多有一个尚未结束的运行意图。
- 重复创建同样的待处理意图，返回原意图；想修改正在处理的条件，返回明确冲突。
- 同一意图重复确认，即使前端换了幂等键，也只能对应一个运行。
- 同一个幂等键配了不同内容，返回冲突。
- 再跑一次必须显式创建新意图、重新确认。
- 已删除意图保留最小墓碑记录，旧请求不能使它复活。

接受确认、预留次数、保存稳定运行编号、创建队列任务必须在一个 SQLite 短事务内完成。使用唯一约束及 `BEGIN IMMEDIATE` 等方式保证并发提交不能突破额度；不要持有数据库事务等待网络。SQLite 的写事务行为以[官方事务说明](https://www.sqlite.org/lang_transaction.html)为准。

稳定运行编号在接受提交时即可确定，必须与 LangGraph 后续登记使用的编号一致。内部幂等键包含服务身份和意图身份，不能由浏览器控制跨用户命名空间。

服务端 SQLite 是托管提交与次数的权威存储。提取、复用原 `bridge.submit` 的校验逻辑；不能同时维护一套线上 SQLite 登记和另一套同样权威的 JSON 登记。

### 3. worker 与重启

- 使用跨平台进程文件锁，建议 `portalocker`，整个 worker 生命周期持锁。
- 第二个 worker 必须拒绝启动；不能仅凭“心跳过期”抢占仍在工作的进程。
- 预检查也由 worker 执行，可能等待正在运行的模拟；页面显示“排队检查”，不扣次数。
- 每次模拟使用独立工作目录、LangGraph checkpoint 和费用账本。
- SQLite 使用短事务、连接独立管理；不支持网络共享盘或多机共用。

发生崩溃后，先检查记录：

- 提交已登记但图未记下：找回原运行；
- 已启动：交给 E1 原有恢复核验；
- 回复可靠落盘：复用；
- E1 已完成但产品结果未保存：重新投影；
- 发送状态不确定、身份冲突、账本不一致：停止等待维护者。

不得通过重置次数、账本、规划重试计数或新建运行目录“解决”恢复问题。

## 七、真实规划器、费用与公开进度

复用 `LlmPlanner`、`make_transport`、`RoundBudget` 和现有归档机制，不另写模型调用器。

固定规模下：

- 72 个分身年度；
- 每年一次正常规划、最多两次修订；
- 最多 216 份规划候选；
- 每份候选最多一次服务重试，因此最多 432 次服务尝试；
- 每次运行费用上限 10 CNY；
- 模型、输入长度、输出长度等沿用现有产品配置，不自行扩大。

**每次运行新建自己的账本。** 不得复用配置中的历史 `ledgers/qwen-flash-convenience` 账本；恢复必须继续读原账本。

所有服务用户的账本和内容放在服务数据目录中，不进入 git。

服务配置默认：

```yaml
live_calls_enabled: false
```

本轮实现真实调用通路，但不得打开付费开关或试跑。缺凭证或开关未开启时，明确报告；不能悄悄换成 mock。

修正费用投影：

- mock 才能标为零费用；
- 真实规划器标为按报价估算；
- 区分已结算费用、用量不确定的保留费用、在途预留；
- 显示 CNY、报价版本及 10 元应用侧上限；
- 调用候选数与实际服务尝试数不要混为一个计数；
- 不宣称应用侧估算就是供应商最终账单。

进度由 worker 从权威进度和账本生成白名单快照。运行期间可用 worker 内的监测线程按绝对路径读取并更新；该线程不能切换工作目录或推进图。

HTTP 查询只读公开快照，**不能因为轮询而恢复运行、调用规划器或重放全部历史**。

## 八、公共接口与 E5 对接

公共结构继续统一维护在 `src/common/product_contracts.py`。

在当前 v3.1 基础上增加服务消息，目标为 `e3a-product-schema-v3.2`，导出仍在 `contracts/product/v3/`。不新建第二套公共定义，不改变问卷的含义。

保留并复用：

`UserInputDraft`、`ProfileReview`、`ConfirmedProfile`、`ProductPreflight`、`RunSubmission`、`RunReceipt`、`RunProgress`、`ProductResult`。

增加：

- 会话与次数摘要；
- 草稿保存、审阅引用、画像确认请求与回复；
- 运行意图与正式工作流公开视图；
- 删除回执；
- 统一安全错误；
- `RunReceipt.service="hosted_service"`。

工作流公开阶段固定为：

```text
checking
awaiting_confirmation
blocked
queued
running
needs_attention
finished
cancelled
deleting
deleted
expired
```

这是网页流程状态，不能拿它替代 E1 的 C/E/M。

公开视图包含：

- 公共意图编号、运行编号；
- 阶段及中文说明；
- 当前预检查、确认身份、可用进度；
- 是否有结果；
- `allowed_actions`；
- 等用户还是等维护者；
- 更新时间、到期时间、删除状态；
- 安全解释及支持编号。

不透传原型的整个状态字典，不公开 LangGraph thread ID、checkpoint、文件路径、堆栈或内部诊断正文。

`finished` 表示本次服务流程结束，不表示所有分身都是 C。预算耗尽有现成报告就展示，没有就明确说没有。

HTTP 路径采用：

| 接口 | 用途 |
|---|---|
| `POST /api/v1/session` | 邀请秘密交换会话 |
| `GET /api/v1/session` | 会话、额度、服务规则 |
| `DELETE /api/v1/session` | 退出当前会话 |
| `GET /api/v1/capabilities` | 正式能力清单 |
| `POST /api/v1/drafts` | 创建草稿 |
| `GET/PUT/DELETE /api/v1/drafts/{id}` | 读取、带版本保存、删除 |
| `POST /api/v1/drafts/{id}/review` | 审阅已保存版本 |
| `POST /api/v1/profiles/confirm` | 确认服务端审阅过的画像 |
| `POST /api/v1/run-intents` | 创建意图并排队预检查 |
| `GET /api/v1/run-intents/{id}` | 查询流程 |
| `POST /api/v1/run-intents/{id}/submit` | 明确确认、预留次数、入队 |
| `POST /api/v1/run-intents/{id}/cancel` | 只允许开始前取消 |
| `GET /api/v1/runs` | 本人的运行列表 |
| `GET /api/v1/runs/{id}/progress` | 进度快照 |
| `GET /api/v1/runs/{id}/result` | 白名单结果 |
| `POST /api/v1/runs/{id}/resume` | 仅执行服务端允许的安全恢复 |
| `DELETE /api/v1/runs/{id}` | 删除一次运行 |
| `DELETE /api/v1/me/data` | 删除本人全部业务内容，保留次数记录 |

长操作返回 202；用户通过查询获取状态。本轮使用轮询，不增加 WebSocket。

恢复按钮只在服务端确认 E1 允许、预算和尝试次数仍合法时出现。发送不确定、身份冲突不能通过普通用户“再试一次”绕过。

错误至少区分认证失败、归属不存在、旧版本冲突、预检查失效、次数不足、重复键冲突、不可恢复、删除中、已删除、资料包不可用、付费关闭、限流和内部错误。

解释采用“发生了什么—影响是什么—下一步怎么做”的中文。不要直接返回 Pydantic 原始错误，它可能包含用户输入或内部对象。

## 九、运行中删除与 30 天清理

### 1. 删除的准确含义

删除一次运行：

- 立即撤销它的查询可见性；
- 标记 `deleting`；
- 阻止新的规划发送许可；
- 已进入发送流程的请求可以完成并记账；
- 等运行线程与在途记录安全收尾后，清理内容；
- 最后标为 `deleted`。

不能承诺撤回已经发出去的请求。

仅增加一个窄的内部运行控制接口，例如 `RunControl`：

- E1 运行器在安全边界检查停止；
- `LlmPlanner` 在**每一次服务尝试，包括重试**之前检查发送许可；
- 许可与删除标记在同一服务数据库中串行裁决；
- 删除之前已取得许可的尝试算在途；删除之后不得再批准；
- 不预先批量批准后续年度的调用。

用户删除必须使用独立停止原因，不能伪装成预算耗尽、计划非法或生活出局。不要改 `src/econ/`，不要中途破坏年度原子提交。

删除和完成同时发生时，删除优先于对外发布；监测线程、结果缓存或重启恢复不能把内容重新写回来。

### 2. 清理哪些内容

每次运行独立目录覆盖：

- 该运行的画像副本、编译输入；
- 模型请求与回复；
- 生活归档、结果及缓存；
- LangGraph checkpoint、内部诊断；
- 该运行的详细费用记录。

删除前保存最低限度的次数与费用摘要；发送不确定的金额不能改成零。随后不得恢复此运行。

删除一份运行不删除另一份运行，也不自动删除用户独立保存的当前草稿。“删除全部数据”才覆盖所有草稿、确认、意图和运行。

保留的最小记录只包括不透明身份、次数事件、必要费用摘要、删除时间与防重墓碑，不含答案、模型正文或生活故事。它们用于保证删除不重置三次额度。

共享城市资料包不属于个人内容，不能跟着删除。

### 3. 时间规则

- 结果：首次结束时间 + 30 × 24 小时。
- 草稿：最后一次编辑 + 30 天。
- 等待确认、阻断或需要人工处理的意图：最后一次有效业务操作后 30 天。
- 轮询、查看和进程心跳不续期。
- 服务停机跨过到期时间后，重启先检查过期，不能先恢复并付费。

API 访问时检查到期时间，不能等清理任务跑过才隐藏。worker 维护线程定期清理非活动目录；活动删除通过上述停止机制收尾。所有文件操作使用固定根目录与已登记路径，拒绝路径穿越和越界链接。

SQLite 中的个人正文也必须删除；处理 WAL 与空闲页残留，不把“删掉一行”描述成磁盘安全擦除。

第一版不为个人运行内容建立长期备份。服务数据目录、日志与账本全部 git-ignore。说明 30 天是本服务的保存规则，不宣称替模型供应商删除其记录。

## 十一、验收标准

至少覆盖以下独立场景，避免只测试“自己调用了自己”：

1. **身份隔离**：两个邀请；修改编号也不能读取、恢复或删除对方对象。重发链接后旧会话失效，次数不变。
2. **草稿冲突**：两个标签页提交同一旧版本，只有一次更新成功。
3. **确认不可伪造**：修改画像、知悉项、资料包引用或运行设置，服务器拒绝。
4. **次数原子性**：并发提交、换幂等键、响应丢失后重发，都不突破 3 次，也不重复启动。
5. **预留释放**：开始前取消或最终检查失败释放；开始后删除不退款。
6. **固定规模**：实际名单为 24 个分身、3 年；浏览器不能改变城市数、年份、模型、预算或工作路径。
7. **身份一致**：预检查、实际规划器、账本、归档相符；改动快照后拒绝继续。
8. **重启恢复**：在提交后、启动附近、回复落盘后、E1 完成而投影未保存时分别中断；恢复不多扣次数、不重复请求已有回复。
9. **不确定发送**：保留不确定费用，不自动重发，不给用户误导性的普通重试入口。
10. **费用保护**：并行请求仍遵守原预算预留；达到上限停止；查询和恢复不建立新账本。
11. **查询无副作用**：连续查询不会调用 planner、推进 graph 或重复生成结果。
12. **worker 排他**：第二个进程不能执行任务；原进程退出后，接任先核查归档。
13. **删除竞态**：排队时、请求发送前、请求在途、服务重试前、结果写入时删除，均符合约定。
14. **过期**：使用可注入时钟测试；查看不续期，停机后重启不复活过期任务。
15. **清理范围**：正文、归档、checkpoint、缓存均清掉；共享资料和其他用户不受影响；旧幂等请求不能恢复已删除内容。
16. **信息隔离**：认证秘密、内部诊断、评分参数不进入代理请求；HTTP 错误不泄露路径、输入正文或密钥。
17. **结果语义**：C/E/M、未知、部分结果、预算停止继续沿用 E1；不得把所有 HTTP 成功响应解释为模拟成功。
18. **离线闭环**：正式 HTTP → 真实业务函数 → LangGraph → E1 → 产品结果完整跑通。假 LLM 样例明确标注为测试传输，不能冒充真实模型表现。

测试必须使用临时数据目录和假秘密；默认阻断外网，防止误调用。

完成相应功能后执行仓库规定的全量测试与 lint：

```text
uv run pytest -n auto
uv run ruff check src tests scripts
uv run ruff format --check src tests scripts
uv run python scripts/product_e3a.py check-schema
```

新增功能不能靠扩大 skip 或放宽断言通过。现有跳过项说明原因，不宣称 E5 已完成升级。
