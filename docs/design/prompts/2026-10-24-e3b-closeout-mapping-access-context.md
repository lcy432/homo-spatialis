本文件是给 coding agent 的实施 prompt，也是供所有者核查的设计说明。基线为 `44ca6f8`、`2bf006a`、`9e58b7f` 后的当前工作区。本轮在现有实现上修缺口，不重新搭建 E3B。

你负责工程实现，不负责重新选择统计方法、评分设计或产品架构。下文给出的规则直接执行；如果现有接口确实无法表达，报告具体冲突，不自行换规则来获得全部通过的结果。

**并行实施补充（2026-10-24）：** 所有者将就业覆盖门槛确定为 60%，本文已同步。E3C 正在并行修复服务接口，因此本轮 E3B 负责资料、参考住房、请求压缩，以及无副作用的请求渲染/长度检查函数；`src/product/preflight.py`、`src/workflows/service_worker.py` 和次数/HTTP 接线由 E3C 窗口修改。第 6 节关于正式预检查和扣次的要求仍是联合验收要求，E3B 提供函数与测试样例，E3C 完成调用接线，双方不要同时修改这些文件。

## 1. 目标、范围与先读材料

目标有三项：

1. 不再把 ACS 中每月几美元、但普通租客能否获得尚不明确的住房，直接当成人人可租的最低住房。
2. 参考生活的住房要兼顾全城就业选择面和这份模板的实际工作，不再要求一套房用同一种方式到达全部就业片区。
3. 保留丰富机会，修好 A 报价更新、旧 B 岗位入口、紧凑请求和正式预检查，形成可以继续联调的基线。

先检查工作区，阅读 `CLAUDE.md`、README 的产品愿景、`docs/INDEX.md`、ADR0044、`docs/design/e3b-mapping-and-daily-support.md`、`docs/design/prompts/2026-10-23-e3b-mapping-and-daily-support.md`，以及现有 E3C 预检查、执行和额度接线。其他窗口的 README、E5 文档和 prompt 不覆盖、不带入提交。

继续遵守：E3 定义资料与业务；E1 执行生活、结算和评价；LangGraph 组织流程；E5 消费公共结构。本轮不改网页、不加城市、不抓取新报价、不调用任何真实或订阅模型，不改模型配置、费用预算、服务重试或正式服务的分身数量。

不改工资税、疾病、时间精力、食品与消费篮子、日常支持、兴趣加成、L/V/J 或 C/E/M 的数学。允许窄改 E1 的参考住房绑定、契约校验与观察序列化；不得增加参考模板或降低模板中的生活要求。运行不了就说明原因，不改规则凑出全部 C。

## 2. 普通住房池：保留原始低价记录，暂不假定人人能获得

生活含义：4 美元的实际租金可以是一条真实调查记录，但不代表一个普通新来租客能用这个价格租到同类住房。本轮采用明确的保守代理，不声称识别出了补贴房或真实挂牌房。

规则名称采用 `ordinary_rental_access_p10_v1`，六城完全相同：

1. 从当前住房 B 完整池的前置合格记录出发：税务居住范围合法、价格已观测或按登记方法插补且未删失、厨卫完整，沿用现有其他资格条件。
2. 按“都会区 × 卧室组（0、1、2、3及以上）”计算毛租金的**加权阶梯 P10**。先按租金升序累计权重，第一次达到总权重 10% 的观测租金就是门槛；不用插值。
3. 权重沿用 B 的目标格质量：`目标格权重 × 支持点权重 / 支持表总权重`。门槛计算使用精确分数，不能按扩增候选个数计数，也不能用已经四舍五入的占比。独立样本数按来源记录 ID 去重；回退借来的同一条记录不能重复增加样本数。
4. 每个卧室组至少有 30 条独立来源记录。不足则回退到同城全部卧室的同一前置合格池；仍不足则报告无法形成该组的普通租赁代理，阻断受影响城市的资料包冻结，不能借别城、补任意金额或静默删除该正权重组后继续构建。
5. 租金严格低于门槛的，退出普通可执行池，原因 `access_unverified_low_tail`；等于门槛的保留。原始租金、来源和权重仍存于资料层。不得把低价记录抬价到 P10，不得标成假房、已识别补贴房或确定不可租。
6. 门槛在过滤前一次算定，不能反复截尾；既有住房质量等级也不因过滤重算。门槛不依赖用户现金、菜单种子或运行结果。
7. 普通目录、年度菜单、最低住房、参考住房统一应用这条资格规则。最低住房仍是过滤后合格池中最便宜的一套，沿用既有年度菜单外自动加入最低住房的机制；不再额外从原始最低 10% 抽一套，也不放回被排除的低价记录。

报告每城每组的门槛、样本数、回退层次、排除的原始权重比例、过滤前后最低租金。并列保留原始质量分母与执行池分母，不能将排除后重新归一化的比例说成现实市场比例。使用“普通租赁市场的保守模型代理”文案；ACS 不能证明保留住房正在挂牌或对所有用户开放。

## 3. 参考住房：60% 就业覆盖，加上实际工作通勤检查

所有者要求既不能只顾某一个实际岗位，也不能要求覆盖所有岗位。采用下面两道检查，阈值由所有者确定为 **3/5**，不根据六城结果调整。

### 3.1 全城就业选择面

对一个居住片区 h：

`覆盖率(h) = 有已知可执行线路通达的就业片区权重之和 / 全部支持就业片区权重之和`。

- 就业片区全集来自当前完整岗位池及开局岗位所使用的片区，与年度抽样无关。
- 权重读取冻结通勤资料 `diagnostics.work_areas.areas[].inbound_weight`，即现有 ACS 流入就业权重。不能用岗位候选数量、职业模板数量或已经取整的 share。
- 对分子，允许任一当前已支持、线路和必要费用已知的交通方式。此处只测住所的潜在地理适用面，不给用户免费车辆，也不另加一个全城统一的 60 分钟条件。
- 所有支持片区都留在分母；缺线路不算已知覆盖，不能删掉未知片区后重新归一化。正权重缺失或分母为零时报告资料不足，不默认等权。
- 覆盖率至少 60% 才能进入参考住房候选。它不表示 60% 工作在一小时内、不表示实际招聘概率，也不表示不用车就能覆盖这些工作。

### 3.2 这份参考生活实际怎样上班

通过上面的检查后，还必须核对该模板实际使用的全部岗位：

- 延续现职的模板读取真实终态岗位；换岗模板读取它指定的目标岗位；多岗逐一检查，完全居家工作的岗位沿用现有零通勤语义。
- 只使用该模板实际获得的交通能力。无车模板不能借用开车线路；用车模板照常支付用车权和油费。沿用 E1 现有交通方式选择与费用规则，不能另写一套“更有利”的路线选择器。
- 实际通勤必须满足用户的硬要求；每月时间、精力与现金继续由 E1 检查。覆盖率达标不能豁免实际岗位，实际岗位位于未覆盖部分时也不能蒙混执行。
- 在符合条件的候选中，基本档按“月租、稳定编号”升序选一套；较舒适档仍限定一卧、中档质量，按“到实际非居家岗位的最大往返分钟、月租、稳定编号”升序选一套。没有非居家岗位时，通勤比较值为 0。
- 不按隐藏评分、期末财富或模拟 J 排序；不为让模板可行而删掉健身、消费或工作小时。选定住房后照原流程评价，所有模板确实资源不足时仍如实报告估值不完整。

### 3.3 接口改动限定

现有“每城四个固定住房编号”不足以表达终态岗位差异，允许增加一种**内部的住房槽位选择器**，不扩建生活引擎：

- E3 从完整、按第 2 节合格的池生成参考候选，保存规则 ID、阈值、就业权重、通勤资料身份、候选身份及选择依据。
- 参考候选可以无损缩成每个居住片区两项：当地最便宜的基本房、当地最便宜的一卧中档房；同价按编号。这对上述选择规则是精确简化，因为同片区使用同一通勤关系。不可按效用或用户财富继续裁剪。该压缩只对当前参考排序与通勤硬要求成立；未来增加面积、楼型等住房硬要求时必须重新核对，不能直接沿用。
- 这些候选作为内部评价资料进入现有目录和评价内容身份。住房槽位在实例化每份参考模板、岗位已经确定后解析；其他槽位继续使用现有绑定。
- common 定义内部契约，ledger 校验，E3 编译候选，E1 参考模板实例化处执行确定性绑定。不得让 econ 反向导入 product 业务模块，也不得在 LangGraph 节点中选择住房。
- 正常年度行动仍只允许年度菜单、最低住房与合法延续项。参考专用候选不能因这次接线泄漏给 agent；同一编号若本来就是当年菜单项则正常可见。
- 绑定记录包含实际岗位片区、覆盖分子与分母、允许方式、选中住房及失败原因，并进入评价证据。目录缺信息与已知不符合条件分开，不能一律记为确定没有。线路缺失且无明确不可达证据时算未知；已知覆盖不足 60% 而加上未知片区可能达到 60% 时，资格为未知。所有候选都已知不满足才记确定没有；不能把含未知候选的失败说成已证明不可行。
- 保持现有 12 个模板及 V 的计算与选择公式。评价内容身份应随新绑定规则改变，评分数学身份不应无故改变。

已知反例：西雅图一套月租 1,650 的一卧中档，到实际 Pierce 岗位步行/骑车往返 20 分钟，到 King 开车 70 分钟，到 Snohomish 开车 40 分钟。它在“60 分钟内”只覆盖约 33.59% 就业权重，但有线路的潜在覆盖为 100%。本轮按后者判断选择面，再按实际 20 分钟检查无车模板。不能把这段说明改成“60% 工作均可一小时内到达”，也不能承诺修完所有分身必然 C。

## 4. 修好 A 的城市报价更新与宽带回退

对应独立审核的 R1、R2、R3；不重新设计共轭更新公式。

### 4.1 后验必须进入执行价

当前 `family_update` 只汇总更新状态，编译出的机会价格仍是基础价。修成一条单向链：

`基础成本预测 → 同规格直接报价校验/去重 → 既有零售修正公式 → 最终价格 → E1 机会 → 结算`。

- 在现有构建输入中增加一份明确的本地报价清单，当前六城为空；它及来源内容摘要进入构建身份。无需本轮搜集新报价。
- 每条报价至少含城市、稳定 quote_id、供应商、规格键、金额、币种、时期/基年、单位、税费/捆绑口径、来源及原始定位。仅完全同规格和同口径的报价参与同一次更新；不登记的新换算不能自动发生。
- 先按城市与 quote_id 去重。同 ID 同内容只算一次，同 ID 不同内容拒绝；同一供应商不同的真实报价按现有规则汇成一个供应商观测。重复抓取同一报价不能改变均值、方差或执行价。
- 沿用 `retail_correction_lognormal_v1` 的先验、方差、后验中位数和现有金额舍入。不更改 A 的效果、寿命、可得性或数量分布。
- 每个规格保存基础价、合格报价、先验/后验、最终执行价和未更新原因，再汇总到方案族。最终价只应用一次，不能报告一套价格、E1 执行另一套。
- 原本就是直接报价的机会（如公园整期项目）原样保留；零价格沿用独立处理，不取对数。负价格拒绝。无合格报价时结果应与原基础价一致。

验收必须包括完整构建接线：手机基础价 61.08、同规格一家报价 91.62，现有公式给出约 74.81，冻结机会与 E1 账目必须使用最终价；不能只测孤立的 `retail_update`。

### 4.2 宽带缺资料时文案也必须回退

- FCC 原始资料未获取或明确不可得时，允许使用现有 CE 一人通信支出回退，明确“预算代理”，不能仍宣称 FCC 100–199 Mbps、上行 20、无限流量的同档报价。
- FCC 2023 价进 2024 的路径仍须有登记的 CPI；CE 已是 2024 口径时不重复换算。
- 已存在文件的指纹错误、损坏或错误格式应拒绝构建，不能伪装成“资料缺失”触发回退。
- 公共事实、来源标签与 agent 文字均从实际采用的分支生成。

## 5. 清理旧 B 岗位入口，补上菜单诊断

对应 R4、R6。新的 E1 岗位池已经使用“20 个工资支持点 × 工时/就业片区联合分布”，保留它；不改 MCMC、不减少支持点、不动开局岗位的现行众数选择规则。

- 删除活动构建入口中旧的 p25/median/p75 三档岗位候选生成及旧岗位菜单。当前 intake 的旧 `job_opening_candidate` 不再生成或对外冒充现行机会。
- OEWS、PUMS、学历与职业要求仍作为来源事实保留。先把 `life_inputs` 对旧候选内学历/资格的依赖迁到权威来源事实，再删除旧生成器。
- intake 的通用查询可以继续展示这些原始事实；对已废弃的旧岗位候选/menu 查询给出明确迁移提示，指向现有生活资料包的新 B 池与菜单。不要再复制一套新 B 生成器到 intake。
- 活动代码和测试只维护现行路径，不同时保留新旧两套实现。历史归档不改写；确实不兼容的旧格式显式拒绝，不能悄悄按新语义解读。

保留年度住房和岗位各 60 项、现有同城同年同环境重复共享菜单机制，以及 30/60/120 的诊断。补齐以下诊断，不用它自动筛选机会或调整菜单大小：

- 对六城、三年、现有四个环境重复，列出各尺寸的价格分位、片区覆盖和可用质量。抽样菜单与额外最低住房/延续项分别计数。
- 使用现有 u501 的能力与每城标准开局岗位作为统一诊断人物；往返上限固定 60 分钟，初始现金分别 0、1,000、3,000 USD_2024_LOCAL。这是诊断夹具，不改变产品默认值。
- 住房诊断：给定其标准开局岗位，列出能通勤且首月能支付最低食品、住房与必要交通的选项数量，以及是否至少有一套。税后收入、付费时点、车月费及油费沿用 E1 的检查，未知费用不当零；不要另写近似预算公式。
- 岗位诊断：按同一能力列出可就任岗位数，及其中有至少一套本次菜单住房能在 60 分钟内通勤的岗位数。它只诊断资格与空间匹配，不声称三年生活一定可行。
- 完整合格池给出相同定义的基准；结果标明是首月/空间诊断，不是长期成功率。可缓存重复候选组合检查，不能改变判定语义。

## 6. 请求压缩与正式预检查：保留选择，省掉重复

对应上下文阻塞与 R5。当前芝加哥首年约 48 万是项目保守估计 token，不是服务商实测；其中大量内容是 327 个食品方案的重复字段。

本轮选定**一次年度规划、按板块表达、可逆的结构压缩**：不减少 60 项菜单，不拆成多个模型决定，不新增查询回合，不由隐藏评分筛选“好选项”。

具体格式：

1. 住房、岗位、食品、服务、设备、活动、地区、通勤分别使用自己的公共字段与行表，不能把所有异质机会摊成同一张一百多列的大表。
2. 食品按现有生成关系因子化：36 个基础组合（三个篮子 × 四种非全自炊餐数 × 三种外食方式）、9 个菜系及其证据、3 个全自炊方案。合法组合仍精确展开为现有 327 项。
3. 共享的数值和文案模板只写一次；菜系标签、来源差异、缺失状态与任何例外逐项保存。ID 从冻结的组合键确定，给 agent 清楚的合法编号写法；返回编号仍由普通权威行动校验检查，模型不负责算价格或生成环境数值。
4. 以后某个组合被本地报价单独更新时，将最终价作为该组合的例外覆盖，不能因因子化吞掉它。没有完整笛卡尔积的板块显式存合法组合，不补出不存在的选项。
5. 共用重复字符串和嵌套对象可以确定性引用去重，但必须保持可阅读的字段/组合说明，不使用仅程序能解码的二进制或压缩包。
6. 对**完整公开观察对象**验证 `decode(encode(x))` 类型敏感、逐字段相同，包括缺键与 null、0 与未知、价格、时间、资格、效果、合法 ID 和文字。解码器是离线校验工具，不能要求模型实际调用它；提示必须足以按表理解选项。
7. 不删除上一年的必要反馈，不把内部评分权重、系数、评价模板、参考专用住房或隐含推荐混进压缩字典。不把数据映射公式发给模型代算。

沿用目前配置的上下文护栏和估计器，不通过调低估计或提高上限把测试做绿。首年目标控制在 96,000 估计输入 token 内，为后续反馈留余量；真实六城首年与离线运行中第二、三年、修订、最大已支持记忆的请求必须分别测量，并低于它们实际绑定配置的上限。更小上下文的模型放不下就预检查拒绝，不静默删内容。96k 是工程余量目标，不是对未来任何输入的保证；若可逆压缩仍达不到，报告剩余体积分解，等待设计处理。

正式预检查接线：

- 抽出与真实发送共用的纯函数：构造公开观察、规范渲染、估计输入、检查预算上限；它不调用模型、不扣额度。
- `ProductPreflight` 在可确认之前，对本次配置绑定的全部首年请求执行这项检查。过大时输出可读的阻断码、影响与下一步，不泄露内部提示或评分参数。
- 提交/worker 在扣运行额度之前再核对该预检查身份和请求上限，避免旧预检查或配置变化绕过。已知首年超限应为零服务调用、零额度消耗；重复请求不能多扣或多退。
- 运行中后续年份仍保留发送前护栏；如果新反馈使其超限，按现有失败/暂停语义如实处理，不能将已执行运行伪装成从未开始。
- 保留 LangGraph 的确认、幂等、恢复和 E1 账本分工，不加第二套调度器。
