E1-5C：疾病、应急与恢复——医疗影响真实生活，健康风险倾向指导代理选择
一、目标、授权与边界
实现 V1 最小疾病闭环：
年度计划声明应急安排 → 月初发生或延续疾病 → 执行实际工作、生活与治疗 → 结算收入、支出、时间和负担 → 更新学习、储蓄目标与健康状态 → 根据实际生活评分 → 跨月、跨年延续。
本轮最重要的所有者裁决：

1. 医疗重视程度不再表示“城市医疗条件越好，健康时越快乐”。
2. 它在新生活协议中表达健康风险应对倾向，供代理作计划。
3. 同等病情的直接痛苦采用全组共同规则，不乘个人医疗权重。
4. 城市医疗条件通过治疗费用、就医时间及服务可得性影响生活。
5. 不把“愿意冒险”直接写成更强壮、更低患病概率或更能忍受疼痛。
6. 不根据个人医疗输入自动替代理选择治疗。
7. 保持 V1 简单，不追求完整医学真实性。

授权必要的 common、ledger、econ、agentlayer、配置、测试、演示和文档修改，包括实现上述机制所需的 `src/econ/` 修改。开工说明具体落点后继续，不必重复询问硬规则 3 的授权。
保护范围：

* 不改旧静态内核 `kernel.py`、`utility.py`、`core.py`，不改 P8/P9/P10。
* 不覆盖旧协议、旧配置与历史证据。
* 不新增保险、带薪病假、借贷、死亡、永久伤残、多病叠加或疾病名称。
* 不新增月度 LLM 调用、真实医疗资料抓取、产品前端或正式调度系统。
* 不制定 E1-6 的终值、缺失插补或总体排名规则。
* 不提交、不推送、不执行 `git add`。
* 所有参数和结果明确标为合成探索，协议不因此成为正式城市评价工具。

三、新协议中的偏好与评分语义
3.1 健康风险应对倾向
旧 `healthcare` 输入不能无声明地改义。
新协议须显式声明：该输入在本协议表达健康风险应对倾向，作为代理规划信息，不是疾病痛苦权重，也不是患病概率。
可以复用既有字段和七项输入形状以减少迁移，但必须：

* 保存用户原始点数；
* 标明新语义与版本；
* 拒绝把未声明新语义的旧画像静默迁入；
* 对产品输入给出清楚的问题说明；
* 不从年龄、财富或旧医疗便利回答推断其自信程度、主观概率或风险厌恶系数。

该输入可以进入许可范围内的观察。结算不得读取它来自动治疗、减少痛苦或改变风险。
本轮不构建完整主观风险模型。不同健康倾向的演示使用明确编写的不同应急计划；不能把手写计划称为 LLM 的理解成果。
3.2 六维日常生活与共同健康项
仅在新评分版本中：
\[ \widetilde w_k=\frac{w_k}{\sum_{j\ne healthcare}w_j}, \qquad B_m=\sum_{k\ne healthcare}\widetilde w_k s_{k,m} \]\[ S_m=(1-\gamma)B_m+\gamma H(q_m) \]
要求：

* 六维现有分项公式保留，包括物质、成长和广义交通。
* 医疗城市背景分不再直接进入本协议满足感。
* \(\gamma\) 和 \(H\) 全组共用，不因人或城市改变。
* 主演示可用 \(\gamma=0.2\)，健康/小病/大病的 \(H=1/0.5/0\)；明确为合成设定，并提供 \(\gamma=0\) 的评分对照。
* 同样日常生活与病情，仅改变健康风险应对输入，不能改变得分。
* 医疗付款本身不计分；治疗通过后续健康状态发挥作用。
* 不再额外扣一份“医疗未满足惩罚”，避免与病情延长重复设置同类奖励或惩罚。
* 六维正权重项缺数据仍阻断完整评分，不补零、不按城市改变权重。
* 六维点数合计为零时明确报输入不足，不自动等权。
* 输出能核对：原始输入、有效六维权重、日常生活分、健康项及总分。
* 不把新结果伪装成旧七维加权结果；不要制造医疗维权重为零却声称含义完全不变。

新增评分内容进入内容指纹和年度绑定。旧额度不得跨入新评分臂；对照从共同初始状态重跑。
四、最小疾病与治疗模型
4.1 状态与过程
只支持健康、小病、大病，一次一场疾病。

* 健康月份才判定新事件。
* 患病月份延续现有事件，不叠加新病。
* 月初状态确定本月工作限制与健康评分。
* 当月治疗影响月末恢复转移及下一月，不追回本月工资或学习进度。
* 小病增加明确的恢复时间和负担，不自动整月停工。
* 大病整月停工，暂停学习及政策指定的主动活动。
* 不改变 E1-4B 年度精力公式；本轮不再乘一个疾病精力系数。
* 恢复是明确记录的过程，未安排时间不自动回血。
* 未治疗允许按声明规则自然恢复；不自动进入永久患病。

采用少量整数月的合成恢复表即可。例如大病未经治疗影响两个月，及时治疗后下月恢复。明确月份计数，禁止恢复后仍重复计病或多收治疗费。
一次疾病成功接受治疗至多收费一次。若之后已无治疗收益，不能机械重复购买。延期接受治疗、自然恢复和跨年延续的实际规则须写成可手算表。
4.2 城市医疗目录
各城统一声明小病、大病两类服务的：

* 可得 / 确定不可得 / 资料未知；
* 当地基年价格；
* 就医时间与负担；
* 来源与对应需求。

同类治疗的恢复效果先全组共用。不要从现有城市医疗背景值自动推导价格、疗效或候诊时间。
比较组要求相同需求定义与颗粒度。未知不能当免费或确定缺货；缺记录不能默认资料完整。
本轮受支持的闭环使用资料明确的城市。未知资料返回独立的数据或支持缺口，不当作现实中治不起病，也不因此连带终止其他独立分身。
五、年度应急安排与月度执行
5.1 应急安排
为年度计划增加小型、明确的应急结构，不建立通用规则语言。
至少能表达：

* 对小病、大病：条件允许时接受治疗，或明确暂不接受；
* 患病时允许暂停的学习、主动休闲及尚未执行的可选购买；
* 必要时用于决定暂停顺序的明确列表。

不能由健康风险倾向字段自动生成执行政策。
无应急声明的新协议输入不得静默补成“总是治疗”。演示可以提供完整预设计划，但须标明这是代理计划。
优先复用既有住房、食品和兜底规则：

1. 保留最低生活门槛，门槛检查不重复扣钱；
2. 结算声明的住房和食品及合法兜底；
3. 在剩余资金和资源允许时执行声明的治疗；
4. 再执行应急规则允许保留的其他活动。

不得为了治疗自动降级到未声明住房、借钱或取用未来工资。
5.2 执行顺序及不撤销历史
在月初确定健康事件及本月活动限制，再计算实际工资、税、生活与医疗支出、其他活动、资源和恢复。
明确区分：

* 年初就无效或不可行的计划；
* 原计划可行，但事件使实际生活改变；
* 事件后应急规则不足，模拟无法继续；
* 最低生活资金不足导致生活出局；
* 数据缺口与程序错误。

后四类不能统一退回“全年从未发生”。
允许对当前月做未提交的试算，但必须说明提交边界：

* 已执行的此前月份保留；
* 当前月只保留真正发生的阶段；
* 未实际工作的工资不得保留；
* 随机事件不因失败或重试重新抽取；
* 无法完成的月份不伪装为完整可评分月份。

若应急安排仍不能满足时间或负担约束，停止该分身并保存已发生轨迹和具体原因。不要自动删除未授权的活动，也不要把这种支持边界直接称为现实中活不下去。
正式重试与批次异常隔离仍归 E1-7。
六、与既有模块的衔接

1. 工资与税： 按实际执行月份计工资，复用累计税。无带薪病假，不补发停工工资。
2. 岗位： 病假不等于辞职。区分劳动关系、实际工作、领薪月份；不能借此让从未实际开始的岗位自动授予雇主身份。
3. 通勤： 按实际到岗次数计算时间与负担；广义交通读取同一事实。停工不产生工作通勤。
4. 学习： 疾病暂停月不增加参加进度或成长；已付学费、已有进度与能力保留，恢复后按规则继续。疾病造成的执行中断不等于新增“任意分段课程”功能。
5. 持有物与服务： 寿命照常流逝。已付款不等于当月实际参加了健身等主动活动；避免一边暂停活动，一边照算参与收益。
6. 储蓄： 医疗支出直接减少原现金余额。目标到期、未兑现、实际兑现继续由 B 判断，不设专款、不自动延期、不新增安心奖励。
7. 精力反馈： 完整年度评分才按原公式更新下一年额度；不在年内即时反馈。新分数尺度会改变额度，这是声明过的效果。
8. 跨年与终态： 未恢复疾病、治疗状态及工作负担历史能跨年；终态保存事实，不自动治愈、不继续行动。终态健康如何评价留给 E1-6。
9. 年度绑定： 健康事件、实际执行、治疗、恢复及相应状态在封存前完成。不能把甲次试算的治疗结果拼进乙次现金状态。

七、风险生成与信息边界
先完成指定事件，再接随机抽样；两者共用同一疾病处理器。
7.1 最小风险规则
采用年龄段与上一月实际工作相对负担的合成概率表即可。

* 月概率明确标为月概率；
* 小病、大病概率非负，合计不超过 1；
* 读取上月已完成的实际工作负担与额度，不能使用本月患病后的工作量反推自身发生概率；
* 首月无历史时使用声明的基准条件；
* 年龄采用明确输入，给出简单年度推进规则，不从自然语言猜；
* 健康风险应对输入不直接改变概率；
* 相同年龄、历史工作与随机数，仅改变该输入，事件不变。

7.2 配对与重放
随机流绑定实验配对身份、种子、人物、重复分身序号、绝对月份和事件类别。

* 跨城同序号分身共享随机数，风险不同允许事件不同。
* 不因遍历顺序、增减其他分身、重试而重抽。
* 对照臂需要共享随机数时，不把变化的评分或风险参数指纹塞进随机键，意外破坏配对。
* 不使用进程随机化的 Python `hash()` 作为稳定种子。
* 记录实际风险规则身份、随机来源和事件；内部日志不得进入代理观察。
* 修改风险或恢复规则后，旧中间状态不得无声明续跑。

7.3 代理可见内容
公开经过投影的生活事实：当前病情、活动限制、实际经历、可得治疗与费用、时间成本、已声明的应急安排。
默认不披露模拟器的疾病—工作负担关系，包括定性方向、概率表、系数和未来事件。活动时间与负担成本仍公开。
隐藏健康评分参数、完整内部对象及其原样字典。不能把当前健康事实也一起屏蔽。
本轮只实现默认信息条件；其他风险告知、主观概率和经验学习机制登记为未来工作，不顺带实现。
八、实现落点、兼容与参数登记
按既有职责分层：

* common：契约、局部约束、身份；
* ledger：加载、跨对象和单位检查；
* econ：纯疾病转移、实际月度执行、资源与评分；
* agentlayer：可见事实投影；
* scripts/tests：指定事件、随机重放与生活演示。

可以新增小型健康模块，不复制工资、税、资源、学习或储蓄算法；不要把经济运算搬进 ledger。
使用新协议、新评分版本和必要的执行修订。
兼容验证区分：

* 旧协议： 业务结果及约定输出保持不变。
* 新协议无疾病对照： 账目、实际活动与资源应与对应无事件生活一致；新评分按本轮定义变化，不要求假装旧分数不变。
* 新协议疾病路径： 差异必须能对应事件、执行或评分规则。

参数目录登记并区分：

* 世界规则：概率表、历史窗口、恢复期、活动限制、就医与恢复负担；
* 评价规则：共同健康权重及状态映射；
* 用户输入：健康风险应对倾向；
* 代理行动：治疗与暂停安排；
* 城市事实：服务可得性、费用、时间及来源；
* 实验设置：随机配对、种子、信息条件；
* 固定会计关系：收支守恒，不列为待学习参数。

没有参数得到现实标定。记录每项省略影响哪些人。新研究中该输入已不是旧静态医疗效用权重，不能直接沿用旧七维回收结论。
九、必须通过的行为验收
至少覆盖：

1. 健康且无事件时，改变医疗价格、可得性或旧医疗背景分，不直接改变满足感。
2. 同样生活与病情，仅改变健康风险应对输入，不改变疾病痛苦、环境概率或现金。
3. 同等病情的直接扣分在不同用户之间相同；医疗付款不直接加分。
4. 六维权重转换可核对；纯医疗点数输入明确要求补充，不自动等权；缺数据不重新加权。
5. 小病治疗、拒绝治疗、买不起治疗，以及大病停工、治疗后恢复均有手算例子。
6. 疾病停工正确减少工资、税、工时和到岗次数；两份工作全部处理。
7. 年底病假保留正确劳动关系；真正离职仍与之不同。
8. 学习暂停不增长、不重复收费；已有能力保留，恢复后的进度正确。
9. 医疗支出影响储蓄目标；“有钱”“付款”“兑现”“恢复”“获得分数”分别记录。
10. 第五月发生意外，前四个月不被撤销；出局月和应急受阻月的保留范围清楚。
11. 当月额外就医时间、负担不能绕过资源上限；恰好达到上限按原精确规则通过。
12. 未治疗自然恢复、跨年患病、终态未恢复不出现重复收费或自动治愈。
13. 当前月患病不反过来修改其触发概率；随机配对、顺序无关、重试不重抽。
14. 同一实际生活重放一致；不同试算不能交换健康结果、评分或候选状态。
15. 代理能看到所需健康事实，但看不到风险映射、评分参数或未来事件。
16. 单个分身生活出局或支持受阻，演示中的其他独立分身可以继续；不报告完成者平均代表全体。
17. 旧协议回归和评分内容绑定回归通过。

新增测试应检查实际行为，不只检查字段存在。金额和资源沿用精确比较，不放宽容差使测试通过。
做少量针对性变异，例如：漏扣医疗费、停工仍发薪、病假误判离职、暂停仍涨学习进度、重试重抽事件、医疗输入降低痛苦、漏算就医时间、撤销前月历史。仅在临时副本运行并保留结果。
