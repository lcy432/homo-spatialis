# E1-7A：代理规划、事实记忆与合成城市闭环

## 一、本轮目标与授权

请实现 E1-7A，完成后停在独立审核点，不进入 E1-7B。

我们的产品直觉是：

> 把按照同一位用户的信息构造的分身放进不同城市。分身理解自己的需求，在当地条件下安排生活；环境负责算账、执行约束和记录结果。分身根据实际经历调整下一年的计划，最后由独立评价模块汇总生活表现。

本轮要接通：

用户陈述与角色信息
→ 当前处境与事实记忆
→ 对当年需求的理解
→ 结构化年度计划
→ 执行前检查与有限修订
→ 环境按月执行
→ 事实反馈与下一年规划
→ E1-6 的单分身评价和城市汇总。

**本轮用可控的 mock 代理，不调用真实 LLM。** 它用于检验接口、状态传递、错误处理和信息隔离，不能作为模型行为能力的证据。

继续保持：

- 分身固定在各自城市，默认生活三个行动年。
- 一年制定一份计划，环境按月执行。
- 同一用户的原始偏好固定，消费与工作选择可以随城市、余额和经历变化。
- 金额、时间、精力、疾病、成长、满足感和期末估值由现有代码计算。
- 真实模型接线与付费试跑归 E1-7B；真实资料接入归 E3；前端归 E5。
- 本轮不新增需求满足公式、心理状态模型、社交、迁移或环境 LLM。

允许为本轮接线修改 common、ledger、agentlayer，新增必要的编排模块、配置、测试、演示和文档。

若现有入口不足以区分“执行前计划问题”和“实际生活中的事件”，允许对 `econ/life_settlement.py`、`econ/life_year.py` 及评价交接接口做最小的接口提取或元数据补充。理由是避免错误重试和丢失轨迹；不改变已有经济、资源、疾病、评分、反馈和聚合数学。

不修改旧 `kernel.py`、`utility.py`、`core.py`，不改变或重跑 P8/P9/P10 的主规模实验。保留现有未提交工作，不执行 git add、提交或推送。

## 三、城市事实、代理输入与未来真实资料必须对齐

这是本轮的基础工作。

目前部分城市背景事实与隐藏评分参数仍混在 `CityScoringConditions` 中。不能为了让代理了解城市，直接把这个内部对象开放出去。

### 3.1 明确两种信息

**代理可以看到的生活事实：**

- 当地可选住房、食品、工作、课程、物品和治疗方案；
- 价格、币种与基年、服务期限、数量和单位；
- 公开的时间与负担成本；
- 岗位资格要求、课程能授予的能力；
- 当前疾病、已经发生的事件、公开的病程和治疗规则；
- 支持代理比较生活条件的城市背景事实。

**独立评价使用的信息：**

- 隐藏偏好真值；
- 满足感映射参数、内部评分对象；
- 期末估值结果与最优参考分支；
- 默认隐藏的患病概率、工作强度与风险的对应关系；
- 尚未发生的随机事件。

### 3.2 做最小的事实契约和来源分离

复用已有机会目录、单位、来源和可得状态，不重新建立一套平行目录。

对尚无安全出口的城市背景事实，增加必要的结构，至少能表达：

- 这是什么事实及其含义；
- 数值或类别、单位；
- 已知、确定不存在、资料未知；
- 城市范围、时间口径和来源性质。

合成事实明确标为合成。未来 E3 应能按同一结构提供真实资料，不需要重写规划器。

内部记录这些事实怎样对应现有评分输入，并把“事实的来源”和“转换或评分假设的来源”分开。不能把隐藏的 b、c、η 换个字段名直接发给代理，也不能编造真实观测替合成设定背书。

本轮只覆盖闭环实际需要的内容，不建设通用数据平台，不引入新的评分公式。转换有假设就登记到参数目录。

### 3.3 防止两套城市描述各说各话

运行前检查并记录可见事实、机会目录与内部执行/评分配置之间的对应关系和内容身份。

例如：代理看到房租 1,000，执行不能悄悄按 1,400 扣款；看到的是另一份城市资料，也不能继续沿用旧配置的身份。

各城市使用相同的字段定义、单位与选择粒度。允许价格不同、供给不同；资料未知不能补零，也不能把资料较少的城市自动套上另一种简化模式。

## 四、代理的职责：理解需求并提出可执行计划

建立稳定的规划接口，供 mock 和未来真实模型共用。

输入只包括：

- 经过许可投影的观察；
- 本分身获准看到的事实记忆；
- 当前允许公开的规则和行动格式；
- 若处于修订阶段，上一份计划的安全诊断；
- 分身、城市、年份和请求编号等必要元数据。

代理实现不应接收整个内部运行 bundle、研究真值、原始评分配置或完整内部状态，再自行决定忽略哪些字段。

建议输出包含三部分，名称可以结合现有契约调整：

1. **当年需求摘要**：根据用户陈述和当前处境，简短说明今年关注什么。
2. **计划理由**：简短说明取舍。
3. **年度行动**：能解析为现有 `YearAction` 的结构化变量。

例如：

> “我仍然重视职业发展，但今年现金不够支付课程费用，先维持工作并积累学费。”

这句话可以解释计划，却不能直接增加存款、学习进度或满足感。

要求：

- 需求摘要不改写用户的原始点数、硬要求和研究真值。
- 角色信息和用户文本作为输入资料处理，不能覆盖环境规则。
- 金额、资格、完成状态、病情和评分只能由环境生成。
- 不执行模型输出的任意代码。
- 只改摘要或理由、行动完全相同，生活结果必须相同。
- 不额外增加一个“推断需求模型”或“反思模型”；未来真实模型可在同一次规划响应中提供摘要和行动。
- 不把最优方案、评价模板或评分结果作为规划提示。

mock 可以使用确定性规则或受控脚本，但必须实际读取收到的观察或反馈。至少一个案例要证明：年初余额、资格或实际经历改变后，下一年输出确实随输入变化，而非只是盲目播放三份预写计划。

## 五、记忆：保留发生过的生活，不让自述变成事实

V1 采用简单的分身独立记忆：

- 用户原始陈述；
- 当前真实状态；
- 上一年必要的事实反馈；
- 按既定规则保留的经历摘要；
- 上一年的简短需求摘要和理由，明确标为代理自述。

不引入向量数据库或另一个总结 LLM。

必须区分：

- **事实**：“第 7 月学费支付成功，课程完成 6/12。”
- **自述**：“我希望明年转做会计。”

自述不能让资格提前生效。

完整轨迹保存在审计记录中；规划上下文可以有明确的长度限制。限制和选择规则应固定、可解释，并写入参数目录。

不得因截断而静默丢掉用户的正权重偏好或硬要求。不得混入其他分身、其他城市、未来年份的记忆。所有摘要、修订诊断和历史响应，最终仍须服从当前信息许可。

产品条件和研究条件分别验证。研究条件隐藏精力额度时，不能从诊断或记忆中直接泄漏该数值；公开活动负担仍可能支持推断，应如实注明这个已有边界。

## 六、年度执行和有限修订

### 6.1 每年一次正常规划，最多两次修订

默认每个分身每年最多：

- 1 次正常规划；
- 2 次因可修改问题而产生的计划修订。

即最多接收三份候选计划。次数可配置，开跑前固定并记录。

模型服务的网络重试与计划修订是不同概念，接口和计数预留区分。本轮不实现真实服务重试，也不伪造真实 token 用量或费用。

不能在修订耗尽后：

- 自动替代理选一个最便宜的方案；
- 暗中换模型；
- 删除某项偏好；
- 补分；
- 换一个新分身顶替。

### 6.2 哪些可以修订

典型可修改问题：

- 输出格式错误；
- 引用了不存在的选择；
- 年初资格不足；
- 违反当前支持的组合规则；
- 执行前可以确定的资金、时间或精力问题。

诊断只提供获准公开且有助于纠错的信息，例如：

> “第 1 月安排了 273 负担点，公开额度是 250。”

不得返回内部评分、隐藏参数、未来事件或“换成某方案分数最高”。

### 6.3 哪些不能通过重试重来

真实疾病发生之后、实际生活已经出局或受阻之后，不能重新问一次代理，再从年初重跑以躲过事件。

沿用现有月度提交规则：

- 已提交的月份保留；
- 停止月如何保留或不提交，服从现有引擎；
- 不改写已经发生的生活，不重抽随机事件；
- 反馈不足时保留当年实际结果，不擅自关闭反馈继续。

**特别注意现有入口：**健康协议有“没有新事件”的执行前试算，而其中某些结果也可能叫 `stopped`。不能仅凭一个状态字符串决定是否允许修订。

请用明确的执行阶段和诊断来源，区分：

1. 执行前检查发现的问题；
2. 实际事件路径中的停止；
3. 内部配置或程序错误。

复用现有判断。必要时提取最小公共接口或增加阶段元数据，不复制一套结算器，不通过观察真实未来事件来帮助计划修订。

## 七、运行前声明与多分身调度

### 7.1 先检查，再运行

入口先输出一份简洁的支持范围说明：

- 固定城市、年度规划、月度结算、模拟年数；
- 合成数据与参数；
- 支持的选择和组合限制；
- 用户偏好和城市资料覆盖情况；
- 可能出现的生活出局、模拟缺失和技术错误；
- 本轮使用 mock，不代表真实 LLM 的能力。

复用 E1-6 的标准开局检查、冻结名单及跨城检查。不要随机生成家具、疾病史或初始培训进度，也不要因城市不同给同一个人不同的个人初始条件。

如果比较组在冻结前就不合法，明确拒绝启动并报告原因；不得偷偷删城市后继续声称执行了原比较。

### 7.2 限制选择应依据公开规则

告诉代理当前支持哪些行动及组合。暂时不能执行的方案可以标明原因；将来学习后才可申请的岗位，仍应能了解其资格要求。

不要依据隐藏评分，替代理筛掉“看起来分数较差”的合法选择。不能通过菜单过滤抹去未覆盖需求，然后声称覆盖完整。

### 7.3 一个分身失败不等于整场失败

先实现顺序调度，暂不引入分布式或并发框架。

保留原始全部名单，并区分：

| 情况 | 本轮处理 |
|---|---|
| 正常完成 | 交给 E1-6 评价 |
| 真实生活出局 | 保留实际事件链，停止本分身，其他人继续 |
| 修订耗尽、反馈不足等个体预期停止 | 保留已有轨迹及原因，其他人继续 |
| 可定位的城市资料问题 | 标明影响范围，不自动扩散为所有城市失败 |
| 共享配置错误、未知程序错误 | 显式暂停受影响批次，未运行者保留为未运行 |

不要用一个宽泛异常捕获，把所有错误都当成普通个体缺分后继续。

记录运行顺序、每人每年的尝试次数以及全局调用上限。全局预算耗尽后，尚未运行的人仍在原名单中，不补新样本，不缩小分母。

## 八、接入 E1-6，保持评价口径不变

复用现有评价与聚合接口，不在 runner 中重写 L、V、J、城市平均或缺失范围。

必须做到：

- 完整者的均值明确标为完整者均值。
- 生活出局不计入该均值，报告实际事件链。
- 模拟问题按 E1-6 已定规则进入缺失范围。
- 缺失范围不是置信区间。
- 各类人数与原计划名单对得上。
- 硬要求的满足情况单独展示。
- 不能因进入 E1-7 就把合成探索标成正式现实推荐。

如果一个分身第 1 年已经生活完成，第 2 年规划失败，不得用一个空的错误对象替掉其第 1 年轨迹。保留实际记录，并让 E1-6 使用已有信息。

如现有失败对象不能表达“规划阶段失败但已有部分轨迹”，可以做最小契约扩展；分类与聚合公式不变。

期末参考估值仍由已有代码执行，不是再让代理选择一次“第 4 年人生”。估值结果和参考分支不返回给生活中的代理。

## 九、记录、重放与年度边界恢复

保存能够核对同一次运行的记录：

- 冻结名单、初态和信息条件；
- 配置、事实目录、规则、评分、评价及提示模板的内容身份；
- 环境随机种子或事件来源；
- 每次可见请求、响应、解析结果、安全诊断及修订次数；
- 接受的年度行动；
- 实际执行结果、停止原因和评价结果。

密钥不写入日志。mock 的身份和用量与真实模型记录分开。

### 重放

读取已接受的行动，从同一初态重新调用现有执行路径，验证生活与评价结果。

不能重新问 LLM 来“复现”旧轨迹。不能反序列化后自行设置私有封存标记，伪装成已经执行过的年度结果。

当前年度绑定包含不序列化的私有信息，因此请沿用真实执行入口重新产生绑定。

### 最小恢复

支持从已提交的年度边界恢复：

- 根据归档行动重建并核对已完成的前缀；
- 从下一个尚未接受行动的年度继续；
- 不重复调用代理生成已接受的年度计划；
- 不重复计算为新的正式交易；
- 尝试次数与预算记录不能因恢复而清零。

不承诺任意月内恢复，不建设通用任务平台。配置或内容身份不一致时，明确拒绝继续旧运行。

## 十一、验收：必须证明闭环行为，不只证明结构能解析

请先整理验收映射，再实现测试。至少覆盖：

1. mock 从正常入口完成三个行动年，并产生 E1-6 报告。
2. 第二年读到第一年的真实余额、物品、能力、病情和获准反馈。
3. mock 的后续选择确实响应输入变化。
4. 同一行动只改理由，生活数值与评价不变。
5. 可见事实与实际执行配置冲突时被拒绝。
6. 完整请求中的规则、记忆、诊断和历史响应均遵守信息许可。
7. 格式错误和资格不足可以修订，修订上限严格生效。
8. 执行前不可行不留下现金流、物品或进度。
9. 实际疾病不能触发年初重试或重新抽签；已提交月份保留。
10. 单个分身的预期失败不阻断其他分身，原名单不缩小。
11. 未知程序错误显式停止受影响批次，未运行者没有消失。
12. 第 2 年规划失败时，第 1 年轨迹仍进入后续报告。
13. runner 接入的 E1-6 结果，与相同行动直接调用已有入口的结果一致。
14. 归档行动重放与年度边界恢复结果一致，不重复调用已完成年度的代理。
15. 改动规则、事实、初态或许可后，不能冒充原运行继续。
16. 即使环境里存在 API 密钥，A 的执行也没有网络调用。

至少展示三个能手算或逐项核对的生活故事：

- **成长后调整计划**：第一年学习，第二年根据真实资格选择岗位。
- **修订与生活不幸的区别**：超出预算的计划可修；疾病发生后的生活不能重来。
- **同批不同结局**：有人完成、有人生活出局、有人规划失败，报告保留所有人。

对修订上限、实际事件不回滚、信息隔离、部分轨迹保留、重放身份至少做针对性破坏检查，在临时副本上运行，不能改坏工作区或历史证据。

运行适合本轮的测试、全量离线回归和代码检查。已有业务数值应精确比较，不通过放宽容差掩盖接线差异。时间戳、运行目录等元数据差异事先单列。

不因本轮范围广而重跑昂贵拟合或在线测试。

## 十三、交付反馈要求

最终报告使用中文，面向大四统计本科生。先讲生活含义，再解释必要技术细节。

按以下结构反馈：

1. **实现了什么、仍不能做什么。** 明确 A 完成不等于真实 LLM 已会生活。
2. **一张完整流程图。** 标出用户信息、需求解释、计划、环境、记忆和 E1-6 的位置。
3. **三个实际运行的生活故事。** 给出输入、行动、执行结果和下一年变化；标明合成数字。
4. **分身实际看到了什么。** 展示一份简化请求和一次安全修订诊断。
5. **失败怎样处理。** 列出生活出局、计划失败、资料问题、程序错误如何影响本人与整批。
6. **文件与依赖。** 说明复用了什么，以及对已有接口做了哪些最小修改。
7. **验证与兼容。** 区分实际运行证据、读代码判断、尚未验证；报告精确比较结果。
8. **本地实现选择与限制。** 说明你自行决定的内容及其影响，不把它们写成科学结论。
9. **E1-7B 交接。** 列出接入真实模型还缺什么、需要哪些预算决定；本轮不得提前调用。

过程中发现的问题，分开记为实现缺陷、测试预期错误、接口适配和设计限制。

不要仅以测试数量证明正确，也不要自行宣布通过独立审核。完成后停在“已实现、自测通过，待独立复核”，不进入 E1-7B。
