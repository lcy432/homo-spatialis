任务：E1-6A——单分身跨期评价与最小期末估值

一、项目目标与本轮范围

我们要回答：
同一个用户的分身，在一座城市实际生活三年后，过去过得怎样，留下的资源还能支持怎样的生活？

原始产品逻辑保持：
- LLM 根据用户偏好决定行动。
- 环境负责结算收入、支出、时间、精力、物品、学习和疾病后果。
- 评分器评价实际获得的生活。
- 钱通过消费、学习和应对冲击发挥作用，不直接等于幸福。
- 不增加独立的“储蓄让我安心”奖励。
- V1 使用简单、公开、可审计的合成规则，不追求最大程度还原现实。

E1-6 分为两轮，本轮只做 A：
A：单个分身的实际生活汇总、期末估值、两部分合成，以及供下一轮使用的状态和证据。
B：同城多分身平均、生活出局事件链、模拟缺失范围、城市比较及整体验证。

本轮不实现城市排名，不进入 E1-7，不调用 LLM，不接真实数据，不训练或标定参数。

二、所有者已经确认的评价口径

以下是本轮必须遵循、并需要同步文档的决定：

1. 确认生活出局的分身：
   - 不进入城市平均分。
   - 不作为未知分数放入缺失范围。
   - 保留全部已发生生活及实际事件链，第二轮独立报告。
   - 出局人数占比使用原计划人数作分母。

2. 因模拟问题未完成计算的分身：
   - 与生活出局分开。
   - 资料缺失、评分不支持、反馈受阻、程序错误等，不能解释为生活差。
   - 第二轮纳入不确定性范围分析，不默认补零。

3. 部分分身停止不取消其他分身的有效结果。
   城市平均的含义是完成且评分完整的分身平均，不宣称代表全部可能人生。

4. 现有 stopped 不自动改称生活出局。
   尤其是疾病之后应急安排不足、资源执行受阻或资料缺口，必须保留实际状态与原因。
   有疾病事件，不等于已经证明“生活出局”。

本轮实现单分身分类与证据接口，并更新上述口径；城市层面的统计计算留给 B。

五、实际生活评分：逐月汇总，不重新发明评分器

1. 评价对象

实际模拟长度为 N 年，T = 12N。
默认演示 N=3，但不得把代码中的实际生活期限写死为 36 个月。

使用同一次实际生活产生、经过验证的逐月满足感 S_m。
保持原有评分范围 [0,1]。

不要：
- 使用 LLM 自报幸福；
- 用现金或工资直接替代满足感；
- 对城市分别做 z-score；
- 取最后一年代替全部生活；
- 对已经递减映射过的月度总分再默认取对数。

2. 时间权重

评价规格显式声明 monthly_discount_factor δ：
0 < δ ≤ 1。

本轮主设定 δ=1，表示每个月同等重要。
另做一个显式非 1 的小型对照，验证折现机制；该数值只是演示，不宣称已标定。

定义：
w_m = δ^(m-1)
W_actual = Σ(m=1..T) w_m
L_actual = Σ(w_m × S_m) / W_actual

δ 是报告的时间评价参数，不自动改写用户的未来偏好或 agent 的行为。

3. 精度

- 金额继续使用整数最小单位。
- 资源可行性继续使用原有精确比较。
- 新聚合层可将现有浮点评分的最短十进制表示转换为精确分数，复用已有转换约定。
- δ 以明确的十进制值参与确定性计算。
- 保留计算值与显示值；显示时四舍五入不参与判断。
- 不增加 epsilon，不靠放宽容差通过守恒、身份和边界测试。
- 不修改旧评分器来追求另一种浮点求和顺序。
- 新汇总以逐月分数为依据，不要求它与“先对旧年度浮点均值再平均”的末位一定一致；如有这种差异，要解释原因。

4. 不完整轨迹

只有 T 个实际月份均有合法评分，才提供 L_actual。
缺月、重复月、年份断档、评分缺失都不能用已有月份平均冒充完整生活。

保留：
- 已知月份、分数及加权贡献；
- 缺失位置和原因；
- 实际已发生月份与未继续模拟月份；
- 原始状态、出局或停止记录；
- 硬要求逐月状态。

本轮不补分，不计算城市范围。

六、期末估值：小规模、确定性的参考生活方案

1. 估值含义

估值回答：
“从这个真实终态出发，按预先声明的少量参考方案，资源能够支持怎样的未来生活？”

它不是：
- LLM 第四年的真实行动；
- 对现实未来的预测；
- 对全部可能行动求出的全局最优值。

本轮只对正常结束实际模拟的终态进行估值。
出局、停止、反馈待定的状态不能被估值器复活。

2. 期限和权重

本轮采用 H=12 个月的估值期。
H 必须作为显式规格字段和参数目录条目出现。
为控制范围，本轮可以只支持 H=12；其他长度应明确拒绝，不能静默改成 12。

不递归估值：
估值期结束后，不再给估值期剩余资产追加第二次终值。

明确记录局限：
这仍是有限期估值，会低估更长远的收益，不等于解决了完整生命周期问题。

3. 参考方案集合

用配置声明一个小型、固定的参考方案集合，每个终态最多评估 6 个方案。
不调用 LLM，不遍历目录的全部组合，不训练策略。

方案应能表达少量有意义的取舍，例如：
- 延续工作与基本生活；
- 延续工作与较舒适的消费；
- 已具资格的相关岗位与基本生活；
- 已具资格的相关岗位与较舒适消费。

示例不是要求硬编码职业名称。
岗位、住房、食品和服务均引用实际目录里的合法机会。

要求：
- 候选集合及生成/绑定规则在看结果前冻结。
- 同一比较组采用相同的方案类别、选择规则与资料要求。
- 城市价格与实际供给可以不同，不能给某座城额外增加更有利的方案类别。
- 确定没有机会、资格不足、已知资源不足，与资料未知分开。
- 不按城市名、期望排名或事后结果挑方案。
- 记录每个方案的实际动作、适用性、执行结果、评分及未被选中的原因。
- 并列最高分使用稳定的方案 ID 决定展示顺序，不影响数值。

年度动作、报价、资源和资格检查尽量复用现有结构。
不要另建一个通用规划器。

4. 选择规则

对能够完整执行且完整评分的参考方案 p，计算：

V_p = Σ(k=1..H) δ^(k-1) × S_future[p,k]
      / Σ(k=1..H) δ^(k-1)

V_reference = max(V_p)

这里选择的是参考集合内的最高可实现评分。
报告必须明确这一点，不能称为“预测明年幸福度”或“全局最优生活”。

已知资格不符、确定不可得、确定资金或资源不足的方案可以判为不可行，并记录依据。

资料缺失、评分不支持或程序错误不能悄悄当成不可行后丢弃：
- 对可能适用但无法评价的候选，本轮不给出完整的 V_reference。
- 可以另存“已知方案中的最好结果”作诊断，不能冒充整个参考集合的确定估值。
- 所有方案都无法完成时，返回清楚的估值未完成状态，不默认填 0。

不得因为估值失败，把实际完成三年的人重新标为生活出局。

5. 钱、物品、资格与疾病怎样起作用

现金：
- 来自真实终态的同一笔余额。
- 未来工资、税、支出仍由现有账本结算。
- 不建立额外可花的钱，不将余额直接换成加分。
- 多留现金可以支持原本负担不起的参考方案；所有方案已充分满足时，更多现金可能不再提高有限期估值，要如实说明。

物品：
- 保留数量和真实剩余服务月。
- 不重置寿命，不重复付款。
- 只有实际提供的未来服务进入评分。
- 不同时加上这件物品的全部转售价值。
- 持有物与参考方案中的购买冲突应按明确规则处理；不允许既免费保留旧物品又重复取得新物品。
- 任何条件购买规则都要写入方案规格，不能临时藏在演示脚本中。

资格与职业：
- 使用真实终态里已经获得、在估值起始年生效的能力。
- 可以支持参考方案里的相关岗位。
- 继续核对职业、雇主和知识作用域。
- 未完成课程不能按已取得资格处理。
- 不因有资格直接增加工资；只有参考方案实际执行对应岗位才有该工资、税、工时和负担。
- 不默认选择最高工资岗位；选择依据是参考生活的完整评分及可行性。
- 本轮不新开课程，也不继续未完成课程；保留并报告这部分尚未估值的潜力与已付学费，不退款、不补能力。
- 资格本身不重复获得成长满足感。

疾病：
- 保留真实终态中的延续疾病、已病月数和治疗历史。
- 沿用同一套病程、治疗、病假和恢复资源规则。
- 估值期采用显式“没有新发疾病”的确定性条件。
- 这不是把患病概率改为 0，更不是保证现实中不会生病。
- 参考方案要显式声明治疗和应急选择，不由医疗点数自动生成。
- 未恢复疾病必须实际影响估值期生活，不能在估值入口自动痊愈。

价格与环境：
- 使用冻结的合成目录、税绑定、城市评分条件与评分规格。
- 不预测涨薪、通胀或房价。
- 仍使用当地基年价格口径，不把未来名义价格混进来。
- 缺少估值所需资料时明确报告，不能补默认城市条件。

储蓄目标：
- 不按目标名称、目标金额或是否“完成目标”额外加分。
- 目标本身不自动触发购买。
- 参考方案中的实际购买照常产生服务。
- 估值中的购买不回写真实目标历史。

6. 时间与精力

估值仍受月度时间和精力约束，不能只算钱。

注意现有代码：
真实第 N 年结束后进入终态，不会计算第 N+1 年的行动额度。
因此不能直接把终态保存的旧额度当成估值期额度。

本轮估值期起始额度：
- 沿用实际运行的反馈开关、α、固定基础和量化规则。
- 开反馈时，用实际第 N 年完整年度满足感，调用已有额度计算函数得到估值期额度。
- 关闭时用基础额度。
- 额度只存在于估值上下文，不改真实终态。
- 估值期内不再滚动更新额度。
- 不使用三年总分、期末估值或合成总分计算这份额度。

七、实际终态与估值上下文必须隔离

现有终态禁止继续行动，这条约束保留。

可以新增专用估值入口及必要的内部适配器：
- 从已经验证的真实终态构造独立的估值上下文；
- 明确标注来源、估值身份和字段转换；
- 复用现有结算、资源、疾病与评分算法。

禁止：
- 让普通 settle_year 开始接受真实 terminal 状态；
- 在外部脚本用 model_copy 把终态随便改成 active；
- 清空疾病、持有物、资格或政策身份来通过检查；
- 把真实年份整体重置成第一年，导致能力生效、物品寿命或病程错位；
- 将估值状态接回实际生活；
- 将参考方案结果当成新的一年真实年度记录；
- 为了估值重新运行或改写前三年的生活。

如复用需要内部扩展行动期限或派生“无新事件”来源，应：
- 只在估值入口创建；
- 保留来源身份及明确的转换记录；
- 继续校验疾病规则和评分内容；
- 保证普通生活入口的保护没有放松。

不要复制一套工资、税、资源、病程或评分数学。
优先增加薄的编排与适配层；必要的公共函数提取必须证明旧路径行为不变。

八、合成单分身评价

对实际生活和期末估值都完整的分身：

W_future = Σ(k=1..H) δ^(T+k-1)

J = [Σ(m=1..T) δ^(m-1) S_m
     + Σ(k=1..H) δ^(T+k-1) S_future[selected,k]]
    / (W_actual + W_future)

主设定 N=3、H=12、δ=1 时：

J = 0.75 × L_actual + 0.25 × V_reference

必须同时输出：
- 三年实际生活分 L_actual；
- 参考未来生活分 V_reference；
- 合成分 J；
- 实际部分与估值部分各占多少权重；
- 被选中的参考方案和选择原因；
- 实际生活的硬要求状态；
- 估值方案的硬要求状态；
- 尚未估值的内容、合成假设及受影响人群。

J 保持 [0,1]，不是货币，也不是现实幸福百分比。
不要把 0.75 解释为“75% 的真实幸福”。

硬要求不得被总分掩盖：
本轮保留清晰的单独状态；参考方案若明确违反已声明的硬要求，不作为满足该用户要求的可选方案。
硬要求资料未知不能当成满足。
实际生活中的硬要求失败不自动改成出局，最终推荐规则留给 B。

实际分完整但估值不完整：
保留 L_actual，V_reference 和 J 为空，并给出原因。
不要把 J 临时改成 L_actual，也不要重新归一化权重。

九、完整性、来源与防止混用

本轮不能只接收一组人名、城市名和分数后直接平均。

验证至少覆盖：
- 同一个人、分身、城市；
- 年份和月份连续，无重复、无遗漏；
- 上一年正式交接状态与下一年年初状态相接；
- 分数来自对应的同一次结算；
- 最终终态来自最后一次真实交接；
- 评分内容、偏好来源、城市条件和目录来源可追踪；
- 产品陈述与研究真值不混用；
- 估值使用的输入与实际轨迹的来源关系清楚。

优先复用现有 ScoredYear 封存和年度交接验证。
只凭几个相同的字符串 ID 或外部提供的哈希，不足以证明配对正确。

本轮可以先支持受控运行中生成的验证对象。
若旧 JSON 无法证明这些关系，应明确报告不支持直接导入，必要时从保存的原始输入重放。
不要为此扩建全项目通用检查点或防伪系统。

新增评价规格要有独立内容身份：
包括时间权重、估值长度、候选方案及选择规则、估值事件条件、合成公式和相关执行修订。

十一、验收与生活例子

请至少覆盖以下行为，不以测试数量代替覆盖说明：

1. 完整轨迹逐月汇总正确；N=1 与 N=3 均工作。
2. δ=1 下的合成权重可手算，非 1 对照的时间权重正确。
3. 缺月、重复月、跨人、跨城、跨试算或错终态被拒绝或明确标为不完整。
4. 部分轨迹不会变成“剩余月份的平均就是完整分”。
5. 实际生活完全相同、只改评价参数，真实账目、月度分数和精力历史完全不变。
6. 原生 terminal 仍被普通行动入口拒绝；估值结束后原终态指纹不变。
7. 多留现金能支持一个此前负担不起的参考方案；展示实际购买或服务如何提高估值。
8. 对同一终态只增加现金，固定参考集合内的最好估值不会下降；允许饱和后不变。
9. 物品数量、剩余寿命正确；不重置、不重复付款、不重复奖励残值。
10. 第 N 年刚取得且在 N+1 生效的资格可支持相关参考岗位；无资格、错职业或错雇主不能通过。
11. 未完成课程不产生资格或未来工资，限制明确报告。
12. 期末患病继续影响病假、费用、资源与评分；不产生新的随机疾病。
13. 估值额度来自最后一个实际年度的评分及原反馈规则，不错误沿用旧额度，不使用 J。
14. 候选方案已知不可行与资料未知分开；未知方案不被静默删除。
15. 所有候选均失败、估值缺分、硬要求未知等不被填成确定的零，也不把实际分身改成出局。
16. 估值失败的试算不污染其他候选、真实现金、目标或健康状态。
17. 同样输入可以精确重放；同名配置改内容能被识别。
18. 评价内部对象不进入代理观察。
19. 已有默认演示与旧协议业务结果保持兼容。
20. 保留并运行交通—健康反例，分别展示实际分、现金、健康和估值；不得要求估值必然逆转原排序。

至少提供四个便于人类阅读的故事：
- 两人前三年体验相同，但期末现金不同。
- 留下可继续使用的物品，和物品已经到期。
- 第三年学成相关资格，与没有学成。
- 健康结束与带病结束；另展示一个估值所需资料缺失的情况。

每个故事说明：
原有状态 → 参考方案 → 实际发生的估值期收支/服务 → 分数 → 仍依赖什么假设。

测试要求：
- 跑本轮针对性测试、生活模块回归、全量离线回归及适用静态检查。
- 不调用在线 LLM 测试。
- 对关键保证做少量针对性变异检查，例如：
  终态污染、寿命重置、重复给余额加分、越过资格、错误使用旧精力、丢弃未知候选、跨试算混配。
- 变异只在临时副本进行，不修改历史证据。
- 每个失败区分实现缺陷、测试预期错误、接口适配与设计限制。
