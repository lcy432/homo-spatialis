## 一、目标：让分身面对更丰富、但有来源和边界的生活选择

本轮解决四件事：

1. B 方法不再把已有分布过度压成三个价格、一个工时和一个工作地点。
2. A 方法具有共同方案空间、参数先验、城市更新规则和代表性检查。
3. 日常便利除洗衣、打扫外，增加个人通信、居家联网和家用日耗品。
4. 个人消费与享受改为一个抽象的“个人消费篮子”，不再用几种按摩代表整个板块。

保留现有 E1、E3 与 LangGraph 分工：

- E3 管资料、统计映射、候选池、菜单、画像与公共结果。
- E1 管合法行动、实际结算、实际获得的服务和评分。
- LangGraph 继续组织既有构建、冻结、预检查、确认、运行与恢复流程。
- 不把国家判断、价格换算或评分公式搬进图节点。
- E5 本轮只交付接口和样例说明，不修改另一窗口的网页代码。

不调用任何真实模型，包括订阅调用；不改变模型、预算或调用次数。允许有针对性地获取下文指定的免费公开数据，不注册、不付费、不绕过访问限制。

不得仅把旧模板复制改名，也不得把普通商品按人口购买频率随机隐藏。

每个 A 板块统一保存：

- 参数含义、单位、支持范围；
- 共同先验及来源或假设；

### 4.1 价格更新的共同规则

价格分两层：

1. 基础成本预测：食材价、人工工资、场地或商品价格依据。
2. 同规格零售价相对基础成本的修正。

没有直接本地报价时，保留基础成本预测和共同修正先验，标为估计；不能把它称为本地观测价。

对正价格的零售价修正采用对数正态模型：

- 既有成本公式给出基础预测价格 `P_base`。
- `δ = log(P_actual / P_base)`。
- 共同先验 `δ ~ N(0, log(1.5)²)`，这是登记的探索先验。
- 同规格直接报价先按供应商去重；每家供应商对同一方案族提供一个对数比值，不能靠重复抓取增加证据量。
- 本地均值观测的方差为 `max(s²/n, log(1.1)²)`；只有一家时使用 `log(1.5)²`。
- 按正态共轭公式更新，默认执行价格用后验中位数，即 `P_base × exp(后验均值)`。
- 直接报价本身另存，不被预测值覆盖。
- 零价格单独处理，不取对数。
- 不同规格、捆绑、税费或时期无法统一的报价不得强行合并。

这些方差是模型设定，不宣称从现有报价估计出来。用留出报价检查预测；没有合格报价时报告“未发生本地报价更新”。

工资、RPP 只更新对应成本预测，不更新服务效果。没有效果资料的参数沿用明确共同设定，可以是点质量先验，不随机生成高效果商品。

默认运行冻结一套中心参数；后验不确定性只进入独立的敏感性情景，同城共用。不能让分身从我们的估计误差中挑到“特别便宜又特别有效”的假商品。

### 5.1 数据与费用

- 解析现有 ACS 的接入字段，严格按官方字典处理抑制、不适用和缺失。

- 不能把全部家庭的通信总支出直接称为单人套餐价格。
- 预算代理不是观测单价；字段、文案和报告必须保持这一差别。

### 5.2 执行与评分

新增项目复用现有按月服务结算。只在付费成功、实际获得的月份提供功能；未知不当已获得。

三种功能各按“未获得=0、已获得=1”计量。重复买两份同功能不叠加。更贵、更快但已超过本轮基本功能定义的套餐不额外加分。

保留原家务分：

`S_chore = min(0.9, q / (q + 8))`

新增支持分：

`S_support = 0.9 × (通信覆盖 + 居家联网覆盖 + 日耗品覆盖) / 3`

新的日常支持与便利分：

`S_daily = 0.5 × S_chore + 0.5 × S_support`

0.5、三项等权及二元功能都是本轮共同探索设定，写入评分配置和参数目录，不由城市数据拟合，不向代理暴露。

不把通信功能伪造为节省家务小时；不因此修改时间账。未安排的空闲时间仍无额外休闲分。

本轮不扩张最低生活出局条件：断网或未买日耗品不直接触发生存出局、患病或工资损失。工作与培训所需资源继续遵守现有安排；个人网络不得悄悄成为新的职业门槛。

## 六、个人消费与享受改为一个抽象消费篮子

用户含义：

“在其他生活开支之外，获得衣着、个人护理等个人消费的满足。”

它是消费服务流的抽象，不是一次买下若干资产，也不是让分身按收入比例花钱。

### 6.1 固定消费边界

篮子纳入：

- 成人衣着、鞋履与个人配饰；
- 非医疗的个人护理产品和服务。

排除：

- 房租、水电、食品；
- 通信网络、家用清洁日耗品；
- 洗衣、打扫、家务设备；
- 交通、医疗、培训；
- 爱好课程、门票、活动材料与装备；
- 储蓄、赠与、赌博、税费。

服装服务中属于洗衣、干洗的部分必须排除。不能用 CE 的整个 Entertainment 大类作为篮子，否则会与爱好重复。

使用官方详细分类建立明确的叶子项白名单及排除表；分类边界按上述规定，不能自行扩大。源表无法拆开的类别单列缺口。

### 6.2 篮子尺度与价格

- 从全国一人消费单位资料得到共同月度参照。
- 细分类不足时，用全国详细表的类别构成分配一人大类支出，标为估计。
- 得到共同参考支出向量 `e_j`，所有城市和用户使用同一个向量。
- 商品项使用商品 RPP，个人护理服务使用其他服务 RPP，形成城市标准篮子价格：

`P_c = Σ e_j × 对应城市价格系数`

这是固定构成的粗粒度成本模型，不是从城市居民支出识别出的零售价。各城市 CE 消费均值只做外部对照，不用于修改个人偏好或制造城市享受优势。

直接匹配报价出现时，只更新对应价格参数；没有报价时保留当前代理与不确定性。

一个标准篮子的消费量记作 `u=1`。提供月度档位：

`u = 0、0.25、0.5、1、1.5、2、3、4`

其中 0 是不购买，不生成收费机会。其他档位费用为 `u × P_c`，按现有整数分结算。

这些档位是共同覆盖网格，不是居民购买比例，也不按用户收入自动确定。

### 6.3 计分与跨期

采用现有享受项的服务量机制，当前唯一有效功能为 `personal_consumption`：

`z = 3 × 当月实际获得的标准篮子量`

`S_enjoyment = min(0.9, z / (z + 3))`

因此一个标准篮子对应 0.5，半个对应约 0.333；这是共同量级设定，不是 CE 测量出的幸福函数。

必须保证：

- 评分读取实际消费量，不读取付款金额。
- 同样篮子涨价，直接享受分不变。
- 固定钱数在昂贵城市买到更少篮子，可以间接降低满足。
- 买不起时消费量为 0，用户的偏好权重不变。
- 不增加休闲参与小时，不获得兴趣匹配奖励。
- 这是当月消费服务流，不产生可转卖资产或装备能力。
- 期末参考生活按当期篮子价格购买后续消费流，不把历史花费算作财富。

移除当前产品链独立按摩、居家舒适用品的享受计分与对应模板，避免与抽象篮子并存重复计分。原始报价可留在资料层作为价格证据，但不再作为第二套有效享受机制。

爱好装备、家务设备及其寿命、同月购买使用和期末能力规则继续保留。

## 七、第三步：统一接线、清理旧路径、重新冻结

- 更新或删除与已删除行为绑定的测试；不可删除现金守恒、隔离、恢复和评价核心测试来凑通过。

菜单扩大如需压缩提示，使用可逆的共同字段＋行表表示。必须满足：

`decode(encode(public_payload)) == public_payload`

保留缺失键和 null 的区别。不得用内部评分筛选选择，不增加模型查询回合，不自动缩减共同菜单。超过现有上下文预算时明确报告。

同时处理已明确的参考住房约束：有一条过慢的无车路线，不能导致合法用车参考生活被提前禁用。是否可行应由现有通勤、现金和硬要求检查判定，不为这项修复扩展模板上限。

## 八、验收：工程正确、分布代表性与现实有效性分开报告

至少完成以下验收。

### 数据与分布

- 六城使用同一方法、参数表、回退、删失与缺失规则。
- 住房完整经验分布与源记录的权重、分位及关键交叉关系一致；插补部分单列。
- 工时与工作片区来自同记录关系；工资拼接假设、未知尾部明确。
- 重复候选合并不改变概率质量，不靠复制名字提高覆盖。
- A 的每个城市更新只触及获准参数；没有证据时后验保持先验。
- 本地报价修改不直接改变服务效果或评分参数。
- ACS 未接入不被解释为买不到；空值、抑制和不适用不当 0。
- 家用日耗品、个人消费及其他板块的分类不存在交叉收费范围。
- 全国、地区、都会区及实际居住范围分别标明，不把地区估计写成本地观测。

### 生活执行与评分

- 通信等服务付费成功后才获得功能，重复购买不重复得分。
- 同一组合中的家务减负仍取现有有效残余时间规则。
- 通信和日耗品不制造节省小时、活动小时或健康效果。
- 消费篮子只扣一次费用、只进入享受项，不进入爱好或资产。
- 同样数量只改价格，直接分项不变；偏好不因未消费被重写。
- 固定行动时，未改动分项、健康、税、时间和现金规则保持一致。
- 期末估值与实际生活使用同一费用、功能和单位。
- 新增一条不可用或过慢路线，不得消灭原有合法参考生活。
- 评分、参数先验及后验内容不出现在任何实际模型请求中。

### 规模、运行与代码卫生

- 30／60／120 菜单诊断单独报告，不拿它替代候选分布验收。
- 检查完整目录是否实际进入代理可见表示，不能只扩大数据库。
- 无损编码往返测试覆盖嵌套值、缺失、null、金额和机会编号。
- 六城、现有分身规模、三年 mock 跑通，报告每城 C/E/M 和原因；不为全 C 调整模型。
- LangGraph 中断恢复、幂等、零调用重放、冻结确定性通过。
- 全量离线测试、lint、格式和共享结构检查通过；所有跳过项目逐项说明。
- 检查所有活动入口，不残留旧生成器、旧享受计分或未更新样例引用。
- 无真实模型调用、无推送、不带入其他窗口文件。
