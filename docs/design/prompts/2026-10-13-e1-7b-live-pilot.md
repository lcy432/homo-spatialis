## 四、先补齐分身的“生活说明书”

### 4.1 公开实际使用的合成税制

生活含义：不能让分身拿税前工资安排支出，却不知道环境怎么扣税。

要求：

- 公开当前城市实际绑定的合成税规则、金额口径、年度税档、同年多岗位收入合并和月度预扣时序。
- 从环境使用的同一份声明投影，不能手写另一份税表或复制计税公式。
- 输入说明和实际税绑定不一致时，调用前拒绝。
- 明确这些是合成规则，不是真实美国税表。
- 税规则属于公开生活成本，不能因此把完整内部对象或评分参数暴露出去。

### 4.2 补全年度行动与储蓄目标格式

当前示例只把 `savings_goal` 展示为 null，不能充分指导真实模型。

补齐支持的字段、单位、月份含义和少量合法的局部示例，至少覆盖：

- 持续行动和一次性购买的月份写法；
- 住房、食品、工作、培训和服务的数量限制；
- 最低生活兜底；
- 学习参加、生效年份与岗位资格；
- 建立、保留、取消、替换或改时点的资金目标；
- 实际购买通过 `goal_id` 关联目标；
- 生病时暂停活动与取消一次性耐用品购买的区别；
- 到期未兑现不会自动购买、自动延期或自动出局。

特别提醒：“钱够报价”“付了钱”“学会了”“获得服务”是不同的事。

示例只解释语法和规则，不给出一份隐藏评分最优的完整年度答案。不能把 mock 的策略当作所有真实分身应该照抄的计划。

### 4.3 保持资料未知与个人选择的区别

必须分别表达：

- 治疗资料已知且可得；
- 治疗确定不可得；
- 治疗资料未知；
- 分身明确选择不治疗。

禁止在适配器、解析器或运行器中，把资料未知自动改成不治疗，或把错误行动替换成一份默认可行计划。

模型可以在获知缺口后明确作出自己的选择；原始回复、修订理由与最终行动都要留档。资料问题导致停止时，仍按模拟问题报告，不说成用户主动拒绝治疗。

### 4.4 核查机会说明与记忆

- 移除或隔离“只用于资格测试”等开发者备注。
- 保留价格、单位、条件、资格、时间负担、可得状态和来源性质。
- 保留“合成资料”的标识。
- 沿用有长度上限的事实记忆；代理自述与实际经历分开。
- 继续准确表达病假导致的领薪月份缺口。
- 不添加新的 LLM 总结调用。

### 4.5 完成最终请求的隔离检查

真实适配器只接收现有安全投影产生的规划请求，不接收完整运行 bundle 再自行忽略字段。

最终真正发给供应商的请求也要接受检查，确保新增税说明、示例、修订诊断没有带入：

- 研究真值与隐藏偏好；
- 评分参数、分数及期末评价答案；
- 患病概率、工作负担到疾病的隐藏映射；
- 未来随机事件；
- 凭证或内部运行对象。

用户陈述是规划资料，不能覆盖系统规则。需求摘要与理由保持简短，不要求长篇内部推理过程。

请求压缩只做可审计的格式与冗余清理，不静默删掉影响生活选择的事实。

## 五、真实模型适配、调用记录与预算

### 5.1 复用已有接口

新增一个真实模型规划器，实现现有 `plan()` 与 `effective_spec()` 约定。

- 复用现有凭证加载及 OpenAI-compatible SDK。
- 散文生成客户端可参考，但它不是年度规划器；不要直接沿用其短输出上限等设置。
- 模型、服务商、端点、温度、思考开关、输出格式、输出上限和相关运行政策都要显式登记。
- 实际设置与运行配置不一致时，在调用前拒绝。
- 保留 mock 和测试替身入口。

- 不给分身浏览、执行代码或调用外部工具的权限。

结构化输出只帮助保证 JSON 形状；资格、资金、时间和精力仍由原来的检查器判断。

### 5.2 分清三类失败

1. **模型交了不合法计划**：进入已有的有限修订流程。
2. **服务请求失败**：按网络政策处理，不冒充一次生活失败。
3. **程序或共享配置错误**：明确暂停，保留已有结果。

建议处置：

- 超时、临时连接错误、可重试的限流或服务端错误：最多重试一次，采用有上限的等待。
- 凭证错误、账户额度不足、请求配置不支持：暂停批次并报告，不连续消耗请求。
- 临时服务错误重试耗尽：保存现场并暂停本次付费批次，未执行部分明确标记；不换模型，不伪造默认计划。
- 回复被截断、为空或格式不合法：记录实际原因，进入受限的输出修订路径；不接受半截行动。
- 未预料到的程序错误：沿用保守暂停规则。

服务重试不能修改生活计划、重新抽疾病或消耗一个“修订机会”；计划修订不能偷偷获得额外的服务重试额度。

### 5.3 一个规划记录对应若干实际请求

现有 E1-7A 归档与 `common.runlog` 都使用过 `calls.jsonl` 名称。不要把两种结构写进同一个文件。

保留已有年度规划记录，另以独立文件保存供应商请求明细，通过请求编号与服务尝试序号关联。复用已有日志数据形状，必要时最小扩展。

至少记录：

- 运行、分身、年度、候选与服务尝试编号；
- 实际模型设置、供应商返回的模型名称；
- 经过隔离检查的请求、原始回复；
- 完成原因、实际输入输出 token、耗时；
- 安全的错误类型、状态码；
- 报价版本、费用估计，以及用量未知的情况。

mock 不伪造 token 或费用。不要把真实运行报告继续写成“mock”。

日志不保存密钥、鉴权头、完整环境变量或包含凭证的配置对象。异常信息采用安全字段，不直接倾倒原始 SDK 异常和 HTTP 调试日志。

### 5.4 预算先预留，返回后核对

- 全轮先导、主试跑、诊断和网络重试共用同一份费用与请求次数记录。
- 发送前检查次数，并按输入的保守上界和最大输出预留费用。
- 返回实际 usage 后核对；不能把实际 usage 与本地估计混写。
- 超时、断连或缺少 usage 时保留“费用尚不确定”及保守预留，不能直接记零。
- 恢复运行不得清零预算，也不得重复累计已有记录。
- 预算不够发送下一次请求时保存现场并暂停，不清空名单，不改变 C/E/M 的定义。
- 不能通过新建子目录、重启进程或改 run_id 自动获得新的本轮额度。

预算保护是按已记录报价执行的应用侧控制；服务商实际账单可能受计量差异影响，不能宣称已经实现供应商级的绝对账单上限。

## 七、离线验收：通过后才进入付费阶段

所有故障注入都使用离线替身，不用真实付费接口故意制造错误。

至少验证以下行为：

1. 税说明与实际绑定一致；故意错配时调用前拒绝。
2. 储蓄目标及 `goal_id` 的合法局部示例可解析，兑现仍只认实际付款。
3. 治疗资料未知不会自动变成不治疗；开发者备注不进入最终请求。
4. 最终 API 请求通过信息隔离检查；伪造用户指令不能改变环境规则。
5. 模型、温度、思考开关等实际设置与声明错配时，零调用拒绝。
6. 合法 JSON 能进入原检查器；空回复、截断、散文、多 JSON、额外结果字段和不存在的机会编号正确处理。
7. 一次临时服务失败后成功，正确记录两次实际请求；没有 SDK 与应用层叠加重试。
8. 网络重试、计划修订各有上限，计数不混淆。
9. 凭证／账户错误暂停；预算不足时零新增请求；服务失败不被写成生活出局。
10. 费用计算、预留、实际用量和未知费用各自正确；恢复不清零、不双计。
11. 已保存回复在恢复时不重复调用；不确定发送状态不能无记录地自动重发。
12. 篡改响应、检查、接受行动或模型设置后，恢复拒绝且原归档不变。
13. 零网络重放不需要真实密钥；归档配置足以恢复输入，不依赖后来改过的原配置。
14. 单个分身的规划停止保留前几年生活；真实疾病发生后不回到年初重选。
15. 新调用记录不污染原规划日志；日志和异常不泄露凭证。
16. E1-7A mock 演示与相关旧回归保持约定结果。

运行全量离线测试及相关格式检查，使用明确可写的新临时目录。旧的在线测试不因本轮而批量开启。

做少量有针对性的变异检查，至少破坏预算前置检查、重试上限、有效设置核对和恢复后防重复调用，确认对应行为测试失败。只在临时副本操作。

记录离线门槛结果。未通过不开始付费；通过后按下一节执行。

## 八、小规模真实试跑

### 8.1 调用前冻结试跑设计

本轮是合成环境中的工程试跑。

先确定两种有区别且在当前评分范围内的画像，例如偏职业发展、偏物质生活／交通；两座城市使用一致的行动类别和数据细化程度，价格与条件可以不同。

优先复用既有样例和加载工具。若需要两座资料完整的试跑城市，可以建立明确标为合成的新样例；不能把原样例里的“未知”静默补成已知，也不能修改旧证据。

完整保存派生关系和参数。正式请求发出后，不根据模型表现再挑选“更容易成功”的画像、城市或事件。

事件安排保持简单：可使用现有指定事件机制，在运行前安排用于检验跨年状态和应急的情景，同一画像、重复序号在跨城比较时配对。未来事件不告诉分身。随机机制继续通过离线测试覆盖，不额外增加付费实验臂。

### 8.2 第一步：一个分身，一个年度

使用三年生活协议，在第一个年度完成后暂停观察，不为了先导把模拟长度改成一年、提前生成终态。

最多一份正常计划和两次修订，所有网络重试计入本轮总预算。

检查：

- 真正发送的输入长度和实际 token；
- JSON 能否解析；
- 计划检查结果与修订过程；
- 第一年的实际账目、资源和记忆；
- 每次请求费用；
- 归档能否零调用重放。

允许在年度边界增加最小的受控暂停入口，复用现有运行器，不复制一套先导生活循环。

若候选耗尽、出现配置或服务阻塞，保存结果并停止扩展试跑。不能换成 mock 计划冒充成功，也不能反复抽到一份好计划再只展示那一次。

### 8.3 第二步：两个画像 × 两座城 × 每组合两个分身 × 三年

共 8 个分身，正常规划最多 24 次；用满修订时最多 72 份候选；每份候选最多两次实际请求。

先导最多 6 次实际请求，加上主试跑最多 144 次，合计受 150 次和 50 元双重上限约束。任何额外真实诊断也占用这份总额度。

要求：

- 每个画像跨城开局满足已有标准开局检查。
- 名单、顺序、事件、提示与设置先冻结。
- mock 使用同一份主试跑名单和输入作离线对照，比较处置分布，不要求其与 LLM 得分相同，也不把 mock 当人类或最优策略。
- 分身生活出局或修订耗尽，不取消其他分身的有效结果。
- 服务、程序或预算造成的暂停与生活出局分开。
- 调用预算不足时如实报告未完成部分，不缩小原计划分母。
- 正常完成后交给既有 E1-6，不另写城市均值或缺失处理公式。

不要求模型一定培训、储蓄或选择某种消费，也不要求两个重复分身必须作出不同决定。报告实际行为及解释是否与用户陈述相符，不预先宣称偏好理解正确。

### 8.4 真实试跑的收尾

- 对已保存响应做零调用重放，精确核对生活与评价结果。
- 用已保存响应构造离线恢复测试，不再次付费抽样来“证明重现”。
- 核对每个实际请求都进入预算记录。
- 报告成功、修订、服务重试、规划停止、生活出局、模拟问题、未运行的人数及次数。
- 模型计划不好可以是试跑发现；不要为了提高完成率改变评分、放松资源约束或替模型修改行动。

## 九、文档、参数目录与未来产品接口

文档各司其职：

- README：只补当前能力、限制与入口。
- PLAN：登记 B 的完成情况、阻塞和后续任务。
- E1-7 技术说明：解释真实调用、公开输入、预算、失败处理和恢复。
- 新 ADR：记录本轮确定的工程选择及理由。
- 参数与假设目录：登记模型快照、温度、思考开关、提示与信息条件、修订次数、请求上限和试跑设计；区分模型行为设置、实验条件与工程保护。
- 本 prompt 原文归档，标题说明与正文分开。

网页版与本地版继续共用生活引擎。本轮只保留模型适配、运行身份、结构化进度和结果边界；网页、账户、任务队列、用户配额及部署放到后续产品阶段。

凭证只用于调用配置，不进入生活状态。开源不意味着公开个人输入、真实调用日志或密钥。

保存本轮配置副本、请求响应、测试、兼容比较、费用记录、变异结果和提交依赖清单。历史证据保持只读；`.gitignore` 仅精确放行必要的合成证据。

## 十、最终反馈格式：中文、生活例子、证据与判断分开

请用大四统计本科生能读懂的中文反馈，不只罗列类名、函数名和测试数量。

按以下顺序：

### 1. 结论

分别说明：

- 接线是否实现；
- 离线验收是否通过；
- 真实先导和三年试跑各运行到哪里；
- 是否有阻塞；
- 哪些仍待独立复核。

不能把“接口成功”“计划可执行”“分身完成三年”“评分完整”混为一谈。

### 2. 两到三个真实发生的生活故事

从本轮实际记录挑选，例如：

- 分身为什么选择培训或推迟购买；
- 哪份计划超出精力，怎样修订；
- 生病后实际发生什么，下一年记忆如何表达；
- 同一画像在两座城作出了什么不同选择。

每个故事说明：模型看到了什么、选择了什么、环境怎么算、结果怎样。给可手算的金额或小时数。没有发生的故事不编造，用离线测试说明覆盖即可。

### 3. 花了多少钱，调用了多少次

表格分开列：

- 正常规划；
- 计划修订；
- 网络重试；
- 成功与失败请求；
- 实际输入／输出 token；
- 已知用量的费用估计；
- 用量不确定的保守预留；
- 剩余预算。

没有供应商账单时，写“按报价估算”，不要写成已核实扣款。

### 4. 与项目愿景的贴合程度

说明分身是否真正根据用户陈述与往年事实规划，环境是否保持独立结算。

清楚区分：

- 工程闭环已跑通；
- 当前模型在这些例子中的规划表现；
- 尚未验证的现实有效性和研究结论。

### 5. 文件、依赖与兼容

解释各模块为什么要改；哪些业务数值不变，哪些提示、身份或日志字段按计划变化。提供路径，不只贴 diff 行数。

### 6. 实际验证和过程问题

分别列出：

- 真正执行过的检查；
- 只靠读代码得到的判断；
- 没有验证的部分；
- 实现缺陷；
- 测试预期错误；
- 接口适配；
- 环境或服务错误；
- 已知边界。

第一次失败与后续重跑分别记录，不改写成一次通过。

### 7. 下一步建议与审核入口

列出最值得独立核查的具体结果、证据位置和未来提交清单。

完成后停在审核点，不进入真实城市接入、大规模研究或产品部署；不自行宣称 E1 全部通过独立审核。
