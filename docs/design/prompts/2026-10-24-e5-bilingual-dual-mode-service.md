## 二、产品目标与完整用户故事

用户不需要下载代码、提供 API Key、理解 LangGraph 或职业编号，便能填写条件、确认模拟、比较结果。开源本地运行仍保留，配置与服务端密钥不进入网页表单。

用以下故事贯穿实现与验收：

> 小林打开专属链接，看到一张稿纸上的世界地图。美国点亮，其他尚不支持的国家只有轮廓。小林看到默认选中的受支持都会区，保留西雅图与芝加哥，并可从列表增减。点击国家只筛选或展开城市，不悄悄改变已选集合。
>
> 小林描述工作、填写年龄和可动用现金，按需要回答资格问题；分配六维偏好，并在物质内部表达四项取舍。小林写“喜欢音乐和川菜”，审阅 E3 给出的候选与未识别部分，亲自确认哪些表达符合原意。
>
> 填到一半切英文，再切地球模式，拖动地球找到城市；回到稿纸后，答案、精确点数和城市选择完全相同。切换显示不等于保存新画像或启动模拟。
>
> 小林审阅“系统怎样理解我”，再选择服务允许的分身数与停机预算，阅读这次运行的范围、资料缺口和模型说明，明确确认开始。断线后重新打开页面，找到原来的运行，不再次扣机会。
>
> 结果先回答“这一轮有哪些可比较的结果、哪些仍缺失”，再进入一座城市，最后查看某个分身逐年怎样生活。小林能分清生活出局、服务或资料造成的模拟缺失，以及实际记录和模型计划。

本轮同时交付：输入、审阅、运行前说明、进度、结果总览、单城详情、分身生活汇报、我的运行与删除。页面数量可适当合并，减少重复填写。

## 三、技术方案与代码组织

沿用 **React + TypeScript + Vite、React Router、TanStack Query、Ajv、fraction.js**。保留能复用的输入、错误说明、精确分配、撤销、焦点管理和 C/E/M 组件，修复旧数据流，不全面重写。

| 部分 | 本轮选择与理由 |
|---|---|
| 契约 | 从 E3 的 JSON Schema/OpenAPI 生成类型，Ajv 做边界校验；不手写另一套 Zod 业务 schema |
| 精确数值 | 复用 fraction.js 与现有 reducer；显示格式与精确值分离 |
| 双语 | i18next + react-i18next；前端界面字典与 E3 的业务显示资源分开管理 |
| 平面地图与小图表 | React 管理 SVG，使用必要的 D3 地理投影、路径和比例尺子包；不为几个图引入庞大 BI 框架 |
| 地球 | 优先 react-globe.gl，使用其 Three/WebGL 能力；按需加载。不同时再维护一套 React Three Fiber 地球 |
| 稿纸质感 | CSS 变量、轻量纹理、SVG 笔触；Rough.js 仅在确有必要时用于装饰，不能扰动数据位置 |
| 表单 | 优先沿用现有受控组件和 reducer，不额外引入第二套答案状态；普通表单库不是本轮必要条件 |

具体依赖版本由实现时核对兼容性并锁定，保留锁文件与资源许可。不要迁到 Next.js、加 Redux、另起微服务或第二套队列来实现这两个视觉模式。

建议分为：契约与 HTTP adapter、服务查询/缓存、草稿编辑状态、纯展示模型、国际化、主题、地图/地球、页面与共享业务组件。可以调整目录命名，但边界必须清楚。

- **一套业务状态，两种外观。** 地图、地球、城市列表消费同一城市选择与详情状态；主题不拥有独立草稿、意图或运行。
- TanStack Query 管服务快照；reducer 管尚未保存的编辑与撤销；服务端修订号不当本地编辑计数。
- 展示模型可以组织公共事实，不能算新的业务分数、缺失范围、资格或恢复条件。
- 正常产品入口使用 HTTP adapter；公共样例另设明确的开发/演示入口。HTTP 失败不能静默切到样例，更不能显示“模拟完成”。
- Ajv 不开启自动填默认、类型强转或删未知字段；发现协议不匹配时保留安全错误，不把错误数据“修成能用”。

## 四、双语与双模式视觉

### 4.1 双语

顶层始终可切中文/English。第一次进入可按浏览器语言选择中文或英文，之后记住用户选择；**视觉模式第一次默认稿纸**，可记住用户主动切换的偏好。

覆盖导航、表单、帮助、状态、地图/图表图例、表格、错误、预检查、结果解释、生活汇报、无障碍名称和日期/数字单位。不做“只有导航是英文”的双语。

- 用户自由文字保持原文；界面语言不自动改变职业描述的语言字段、候选选择、偏好、币种或规划器语言。
- E3 提供的题干、健康选项、资格解释、动态错误、范围与结果说明，接入 E3 维护的双语资源/投影，不由前端另写语义或用在线翻译补全。
- E3 尚无英文资源的部分显式显示原文和“英文说明尚未提供”，登记为未完成依赖；不能把这种回退算完整双语验收。
- 业务原始响应和指纹保持完整；不要改写 `*_zh` 后继续沿用原指纹。显示资源用独立语言与版本缓存。
- 输入解析遵守契约。金额/分数的千分位、显示舍入不回写原始答案；不要把 `1,000` 错读为 `1`。单位与计价口径不能被语言切换改变。

### 4.2 默认稿纸模式

暖白旧式算术稿纸、很淡的方格、石墨色主线、少量克制的彩铅强调色。正文、数据和表格用清晰的中英字体；手写感留给标题、页码、注释和装饰，避免大段难读手写字。

地图轮廓、坐标、图表轴与数据点必须准确。纸纹、铅笔粗糙感不能改变面积关系、地理位置、坐标值、柱长或月历标记；不能靠线条抖动掩盖小差异。

输入使用世界地图＋国家筛选＋城市列表。国家点亮只说明其有当前可选的模拟地区，不表示全国都支持。国家点击展开城市，不隐式全选；明确的“选择全部可用城市/清除”另作按钮。新草稿初始城市以服务器给的选择为准，其余答案保持未答。

结果按国家展示本轮城市；多国并列，手机顺序排列或切换分组，全部国家可达。多国布局可用独立展示测试验证，但不在正式能力清单里伪造尚未支持的国家。

### 4.3 写实地球模式

采用真实地球纹理、正确经纬度与轮廓，配简洁的现代技术面板。深蓝灰或其他克制配色均可；禁止用大量霓虹、镜头运动和装饰读数压过内容。

- **真实可交互**：鼠标拖动旋转、合理缩放、点击城市；触屏可旋转，提供“回到所选地区/重置视角”。区分拖动结束与点击，不让转动误改城市选择。
- 输入点击可用城市增减选择；输出点击本轮城市打开同一单城详情。不支持的城市不能因为纹理上存在就可运行。
- 无自动持续旋转；尊重 reduced-motion。自动定位城市可短暂平滑过渡，减少动效时即时定位。
- 标签避让可以移动文字或引线，不能挪动城市锚点。遮挡在地球背面的点不误选。
- 先加载可填写的页面与城市列表，再按需加载地球。WebGL 不可用、纹理加载失败或性能不足时，清楚说明并保留列表/平面地图，不阻断填写和结果。
- 列表是完整等价操作入口。键盘用户无需操作 3D 场景即可完成所有业务；地球工具栏与详情面板可用键盘，退出面板后焦点返回触发处。

地图底图采用可追溯、许可清楚的地理资源。普通国家底图可由 E5 管理；**城市显示锚点、都会区身份和实际支持范围由 E3 供给**。显示锚点不是模拟住宅、工作地址或都会区边界。真实六城采用 MSA/CBSA2023 口径，不能把旧金山画成整个湾区、把纽约或芝加哥的限制范围说成整片都会区。

不使用生成式图像充当地理真值；合成城市不附会现实坐标。没有坐标的城市仍可从列表进入，地图明确缺少定位信息。E3 已找到六城 Gazetteer 原始代表点，但原始大地基准仍待核实；E5 不直接读内部原始缓存，也不把其数值自行标成 WGS84，等待正式地理显示清单。

## 五、输入、审阅与运行前说明

按“支持范围 → 生活事实 → 偏好与可选表达 → 确认理解 → 运行前说明”组织，允许返回修改和撤销。

1. **生活事实**：自然语言职业、必要的职责候选确认、年龄、初始可动用现金及币种；相关时展开资格。只提供当前支持的国家、币种、语言和职业体系，不让用户填职业编号。标准开局说明清楚：重新开始的一段生活，不自动带入全部家具、病史与家庭资产，不收集暂时用不上的详细病历。
2. **六维 100 分**：初始不预填；均分是主动操作；满分后由用户决定从哪项挪分。未答、明确零、无明显倾向、不确定分开保存；精确均分不能被显示舍入覆盖。修订和撤销不能意外改变其它答案状态。
3. **物质四项**：使用当前 capabilities 的居住条件、食品生活、日常支持与便利、个人消费与享受等正式标签、定义和说明，不硬编码旧三项文案。点数是重视程度，不是花钱比例、愿付金额或购买指令。不要再出现按摩椅、靠垫等旧例子。
4. **健康**：独立问题，完全使用 E3 的题干与选项；不是第七维，不解释成体质、患病概率、意志力或道德评价。
5. **兴趣与口味**：保留原文、E3 候选、歧义/未识别说明；用户主动选定，不预勾。兴趣与口味的状态集合不同，按各自 schema 实现。品牌等当前只保留的表达要说明用途，不能暗中改权重、现金或硬要求。
6. **审阅**：展示“我填的”与“系统将采用的理解”，给出字段定位修改入口。旧问卷/词表确认失效时，引导阅读新含义后重新确认；不只是把版本号覆盖成新版本。
7. **运行选项**：读取 `SessionView.rules.options`，显示 `RunIntentView.settings` 的最终有效设置。城市来自已确认画像，准备运行请求不另传一份城市。服务目前默认六城×每城4个×3年、20元，仅供理解；页面不能写死这些值或允许范围。
8. **运行前说明**：已确认条件、城市与年数/分身数、执行/评分/精力更新支持、资料缺口与未支持项、模型、停机上限、机会规则、保存规则，并明确确认范围后才提交。相关输入修改后，旧审阅、确认和运行前说明不能继续作为新输入的授权。

精确展示三个不同概念：用户的模拟现金、服务的模型调用停机上限、剩余启动机会。20 元之类的上限不能写成“预计费用”或“保证只花这些”。

## 六、E3C 接线与状态管理

以下路径以当前 OpenAPI 为准，客户端同时校验 HTTP 与业务状态；HTTP 200、202 都不表示模拟全部完成。退出会话的204没有响应体，不解析 JSON、不做消息 schema 校验；其余2xx按各自响应形状与业务状态处理。

| 步骤 | 现有业务入口 |
|---|---|
| 邀请/会话/退出 | `POST /api/v1/session`、`GET /api/v1/session`、`DELETE /api/v1/session` |
| 能力 | `GET /api/v1/capabilities` |
| 草稿 | `POST /api/v1/drafts`；`GET/PUT/DELETE /api/v1/drafts/{id}` |
| 审阅与画像确认 | `POST /api/v1/drafts/{id}/review`；`POST /api/v1/profiles/confirm` |
| 准备/查看意图 | `POST /api/v1/run-intents`；`GET /api/v1/run-intents/{id}` |
| 明确开始/开始前取消 | `POST /api/v1/run-intents/{id}/submit`、`.../cancel` |
| 运行列表与结果 | `GET /api/v1/runs`；`GET /api/v1/runs/{run_id}/progress`、`.../result` |
| 恢复与删除 | `POST /api/v1/runs/{run_id}/resume`；`DELETE /api/v1/runs/{run_id}`；`DELETE /api/v1/me/data` |

### 6.1 会话与草稿

- 从 `/invite#token=…` 读取秘密后立刻从地址栏/历史移除，再同源 JSON 换会话。秘密不进查询串、存储、分析事件、日志、截图或模型请求。
- Cookie 由服务端 HttpOnly 管理；CSRF 只放内存，刷新后 GET session 重取。除首次会话交换外，修改请求带 `X-CSRF-Token`，同源发送。没有自建登录、用户编号输入或前端 API Key。
- 会话固定期限、不因查询续期；401 提示重新打开专属链接，同时停止私有轮询、清除 CSRF 并锁住或清理私有视图。换邀请身份、退出、删除全部时取消在途查询，清理私有缓存、编辑状态和面板；旧会话的迟到响应不得写回缓存。重新认证后再加载服务内容，防止另一人的旧资料短暂闪现。
- 服务端分配 draft_id/revision；PUT 用 expected_revision。保存与响应处理防止旧响应覆盖新编辑；审阅必须针对已经保存的修订。
- 409 revision_conflict 展示冲突，保留当前未保存编辑供用户比较/重新应用，重新读取服务端；不能静默覆盖或自动最后写入者获胜。
- 服务草稿是跨设备来源。本地持久化只默认保存语言/主题等非私密偏好，不把全量私有响应长期放 localStorage。旧样例缓存不自动并入邀请身份；旧真实答案如需迁移，必须有清楚来源并重新审阅，不能仅改版本头。

### 6.2 提交、刷新与恢复

- 当前一人只有一个未结束意图。输入/设置改变时处理原意图，未启动的按允许动作取消后重新准备；已开始运行保持原输入与设置。
- 用户一次明确确认产生一个幂等键，绑定该意图、`confirm_with` 与请求内容。双击、超时重发复用同一键和内容；新预检查的 `confirm_with` 需要重新阅读、再次明确确认和新键。
- 刷新或响应丢失时先 GET session/open_intent、意图或运行列表找回原运行；刷新不自动重发 submit，不自动 resume，不创建新模拟。前端不为“修复断线”改变请求身份。
- 按 `allowed_actions` 呈现业务按钮、按 `waiting_for` 说明在等用户、服务还是维护者。前端可以展示“请求发送中”，不能自行发明恢复资格、扣次数或取消权限。
- `checking/queued/running/deleting` 阶段每2–5秒只读轮询；其它阶段停止自动轮询。429 遵守服务等待时间，断线退避并提示最后更新时间；给显式刷新入口。避免后台标签高频请求。
- submit/resume/cancel/delete 不套用通用自动 mutation 重试。发生超时时先查询确认状态，再由用户选择安全的后续动作。
- submit/resume/取消/删除及服务状态变化后正确刷新相关缓存；结果从未生成到生成、从部分到新结果时能够更新。不能沿用旧结果查询 `staleTime: Infinity` 而永远显示旧内容。
- 已知服务动作/期限问题见配套单；由 E3C 修正，E5 不根据浏览器历史造“是否曾启动”的判断。动作冲突未修时阻塞相应动作验收，不停止本地 mock 主闭环与无关页面；期限缺失暂显示正式保存规则，精确截止日期保持未验收。

### 6.3 进度、机会与删除

- 进度区分别显示：当前执行/等待原因、已完成部分、可否恢复及服务给的原因。阶段结束不写“所有分身成功生活三年”。无可靠总进度时不伪造百分比或 ETA。
- 3 次是启动机会，读取 quota 的 total/used/reserved/available。提交预留、首次启动消耗；开始后部分结果、预算停止或删除不退回；查询、刷新、恢复不另扣。用服务实际值，不在浏览器推算账本。
- 费用按公共字段区分已核算、用量不确定、在途预留，保留报价估算说明；缺项不当零，不把候选规划数和服务尝试数混成一项。
- 保存日期只用服务投影的实际时间。未给精确到期时间时只显示正式规则，不能按浏览器收到时间、updated_at 或查询次数推算。
- 删除一次运行/全部内容需要清楚、简短的范围确认。202 表示正在删除，不声称已物理清空所有账本；立即隐藏已不可读内容并清缓存，后续只查看删除状态。说明在途请求可能已经产生费用，删除不返还已用机会。
- 错误保留“发生什么 → 影响什么 → 下一步”的结构和支持编号；不透出原始异常。拒绝确认、资料不支持、版本过时、限流、会话失效、结果暂不可取各有准确界面。

## 七、结果呈现逻辑

### 7.1 第一层：本轮城市比较

页面开头显示本轮有效设置、资料性质、结果生成状态与必要限制。主区域是地图/地球与同一份城市比较列表；地图颜色只是一种入口，不能成为唯一结论。

- 默认着色指标是 E3 返回的 **`mean_j`：完成且评价完整分身的平均组合评价**。E3 AB 与 C 已确认当前有效值域为 **[0,1]**；同一结果内所有国家和两种模式共用该固定连续色阶与数值图例，不按各城/各国 min-max 拉伸。超域值报契约异常，不偷偷截断或重新归一化。未来正式显示元数据交付后按其版本读取；当前确认仅适用于本轮受支持的比较组，不推广为不同用户、不同轮次或未来国家间的可比性，0.7 不表示现实幸福70%。
- 有有效 mean_j 的城市显示颜色和数值；C=0、未生成、缺少评价用中性独立符号和文字。含 M 但仍有有效均值的城市保留该均值颜色，另加缺失标记与人数，不把整城误画成“最差”。
- 不用红绿二分暗示适合/不适合，不写“最佳城市”“推荐搬去”。保持服务城市顺序或用户选择顺序，不自建排行榜。
- 每城同时给 planned、C、E、M、均值及 mean_denominator。例：“计划10个，7个完成且可评价，2个生活出局，1个模拟缺失；0.60 是前7个的平均。”这只是解释故事，真实页面按返回数据渲染。
- 建议比较图以城市为行：一行显示完整者均值点，另一条明确标注“模拟缺失范围”的带及其分母 C+M。**它不是均值的误差条或置信区间，不能画成保证包含该均值的统计区间。** 均值、范围均直接取公共值。
- 配一张可访问表格，列出 J、L、V、C/E/M、两个分母、缺失原因入口。城市两两关系使用 `comparisons` 的方向与说明；`undetermined/not_available` 不升级成结论。
- C/E/M 可用带人数和文字的组成条；没有评价时不从进度自行补成 C/E/M。`evaluation_status=not_generated` 显示原因，保留可看的事实，不输出猜测分数。

### 7.2 第二层：单城详情

地图/列表点击打开同一详情区域或路由。包含：

1. **评价怎么读**：并排展示 J、L、V，解释 L 是实际生活评价，V 是期末资源在既定参考生活中的未来使用价值，估值期仍有工作收入，J 是组合。不要把 V 写成保证下一年幸福；不使用 L+V=J 的堆叠图。
2. **这城有多少可用信息**：原计划与 C/E/M、缺失原因、硬要求核验（未核验不等于满足）、服务给的比较与限制。
3. **资料从哪里来**：`data_nature`、`option_coverage`、scope notes 与来源分层展开。scope notes 取本运行绑定的预检查，不是 ProductResult 自带字段；无法取得对应版本时明确缺失，不用当前能力或另一份预检查替换。观察、推导、估计、合成设定分别说明；来源条数不是“真实性百分比”。目录覆盖、评分完整性与服务运行状态是三个不同问题。
4. **分身入口**：每个分身的类别、已生活年/月与摘要；E 和 M 用不同文字/图标。服务失败不能写成“在这城生活不下去”。

真实都会区数据不再一律贴“合成城市”；但仍有合成设定、估计参数和 mock 规划器时必须保留其性质。样例 envelope 的出处说明也要保留，受控计划和测试传输不冒充真实模型能力。

### 7.3 第三层：分身年度生活汇报

默认是一份简洁的年度生活记录，按年展开，支持月份条带、事实卡和短段落；稿纸与地球面板都使用同一公开事实。允许 coding agent 在布局、插画点缀和信息密度上发挥。

| 公共事实 | 可以怎样展示 | 不得推断 |
|---|---|---|
| 年初/年末现金、年度已支付总额 | 年度端点或表格，清楚写年与计价口径 | 月度现金曲线、完整收入/税/支出分项；年度总额不是月度流水 |
| 工作、住房、食品、培训 | 公开名称、发生月份、已有说明 | 未提供的面积、每餐细节、做饭时间、工资或因果解释 |
| goods/devices/services、没买成的购买 | goods 按已提供字段显示购入、在用、到期与剩余寿命；devices 显示在用月份；services 显示计划/实际获得/未获得月份；未成交购买使用公开原因 | 未提供的购入/到期信息；买了就一定参加爱好；没买成就一定没钱 |
| activities | 完成/暂停/未完成月份，年度总次数与小时 | 把全年次数平均摊成每月，或编造活动恢复精力的具体数值 |
| homes/commute/car_access | 住所片区与实际通勤分别展示；分组月份与“每月费用”标清 | 把片区典型通勤当个人实际通勤，或把每月费用误当整组总额 |
| support | 通信、居家联网、家用日耗品的计划/实际获得/未获得月份 | 缺少服务必然失业、生病、出局，或自动节省时间 |
| consumption | 12个月标准消费篮子，精确数与状态 | `"0"` 与 `"—"` 等同；当月消费变成期末可售资产 |
| health、event_chain、requirements | 公共已发生事件与核验结果 | 私自生成病史、心理原因、实际不存在的事件 |
| valuation_scope | 期末装备哪些用途被参考模板考虑、哪些未纳入 | 没被模板纳入就等于装备毫无价值 |

金额仅在相同计价口径下比较；不同币种或基年的金额不隐式换算、不共用可比金额轴。正文使用可审查的双语事实模板，能追到公共字段。可以写“这一年买到吉他，但没有实际练习记录”；不能写“我终于找到了人生方向”“因为压力大所以买吉他”等没有来源的心理活动。

**本轮不新增 LLM 写报告调用。** 当前没有公开的规划理由时不伪造 agent 自述；将来有安全投影再以独立的“模型计划/解释”栏目接入，并与实际生活记录分开。六维评分雷达、物质得分分解、完整月度现金/税/时间精力图也不在本轮范围，不能读取 E1 内部文件来补。

## 八、本轮实施顺序与完成边界

1. **协议与主链**：迁移 v3.3，接通真实本地 E3C HTTP→worker→mock E1。修旧草稿版本覆盖、固定样例匹配、结果永不刷新等问题。四份草稿夹具重新统一到页面实际 schema/reducer，不能保留绕开页面的测试捷径。
2. **稿纸与双语**：完成输入/审阅、运行前说明、进度、比较与年度报告；前端字典完整，接 E3 业务显示层。
3. **地图与地球**：接可信显示元数据，两种输入/输出模式共用业务状态；完成拖转、点选、回退与移动布局。
4. **用户故事验收**：故障、缓存、精确值、语义与视觉一起核验，交付可重复的本地启动说明。

这些是实施顺序，不是把地球、英文或服务接线无限后推的分期。上游未补齐时可以交付明确的部分成果，但必须列出缺口和受影响验收，不能标注整轮完成。

本轮不做：公网部署、支付/注册/管理员平台、更多国家的数据生产、重新训练/更换规划器、修改评分、自动生成建议城市排名、实时模型访谈、完整明细账新投影。地球场景、底图、已具备字段的图表不能拿静态截图或永久 placeholder 代替实现。
