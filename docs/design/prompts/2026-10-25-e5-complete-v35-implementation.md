## 3. 两套独立评分控件：直接接 v3.5

### 3.1 输入与数据

六维一组、物质四维一组，各自归一。维度键、名称、规则来自能力清单，物质按当前四维呈现，不恢复旧三维版本。

读取 `capabilities.points.ratings`：`method`、`minimum`、`maximum`、`slider_step`、`max_decimals`、`equal_weight_rating`、`rules`。当前规则是每项 0–100，滑条步长 1，数字精调最多两位小数，主动同等重视设为 50。

草稿 `six_dimensions` 与 `material` 均使用正式 `AllocationAnswer`：

```json
{
  "mode": "ratings_normalized_v1",
  "entries": {
    "material": {"state": "provided", "value_text": "80"},
    "safety": {"state": "provided", "value_text": "40"}
  }
}
```

以上只是六维中两项的形状示意，完整数据用正式维度键与样例。`value_text` 写原始十进制评分，不写归一百分比或 `50/3` 这样的派生分数。不要只向后端提交前端算出的权重。

拖动只改变当前滑条的原始评分，其他原始评分完全不动。删除来源选择、未分配池、凑满 100、“还差几分”、两维转移和“其余设为 0”等旧入口及隐藏提交逻辑。

### 3.2 饼图与审阅

复用精确十进制/分数工具按公开规则作即时临时预览：`权重 = 100 × 当前评分 ÷ 本组原始合计`。这只是页面预览，正式校验与确认由 E3 完成。交接单“不要自己换算权重”指不能另造业务真值或用旧百分比冒充评分，不禁止第 16 节明确允许的临时预览。

饼图旁说明：“分数表示相对重视程度，系统按比例换算；不是收入分配比例。”英文表达同义。

- 未答完：标为“已填部分的临时预览”，显式列出未答项，不能宣称它们权重为 0。
- 已答值合计为 0：没有可用比例，不画看似有效的均分饼图。全零时显示服务同义提示：“至少有一项大于 0，或主动选择同等重视。”
- 回到审阅：原始评分取 `lines[].rating_exact/rating_display`，原始合计取 `rating_total`；正式权重取 `lines[].exact/display`，权重合计取 `total`。两类数值分清，未生成权重时不补 0。
- 确认画像的 `ratings`、`rating_total`、`rule` 与既有 `points` 由服务返回；E5 不自己构造或重签确认画像。E1 仍只消费原有 `points`。
- 显示舍入不回写输入、预览计算、撤销记录或保存请求。

必须对照：80/40/40/20/10/10 → 40/20/20/10/5/5；8/4/4/2/1/1 相同；六项 50 → 每项精确 `50/3`；物质四项 50 → 每项 25。

### 3.3 状态、操作与自动保存

- 初始不预填。滑条视觉停在 0 时仍可为“未答”；用户明确输入/选择 0 才成为 `provided` 的 0。提供键盘和触摸都可完成的明确回答 0 的办法。
- `unanswered`、`provided` 的 0、`indifferent`、`unsure` 保留差别；无所谓/暂不确定不转换为数值。现有 E3 规则下这些未给评分的状态会阻止确认，如实解释，不判用户偏好“答错”。
- “同等重视”是用户主动操作，把本组每项原始评分设 50；已有答案会被替换时说明影响，可撤销。没有新的 equal 模式，也不自动均分。
- 物质父项明确为 0 时折叠四项，标为不适用；保留草稿中的四项答案。恢复正数后原样找回，不清零、不自动均分；父项未答不等同于父项 0。
- 一次指针拖动是一条撤销记录，松手保存；第二次独立拖动是新记录。连续方向键可以按同一编辑序列合并，失焦/换项结束合并。数字精调同样可撤销。
- 拖动期间即时更新本地临时预览，不每个像素保存或请求审阅；pointerup、blur、pointercancel 不重复提交。无效数值不悄悄截断、取绝对值或变成 0，保留可修正提示。
- 保存失败、冲突、审阅失败要可见；不能显示“已保存/已确认”而丢失最新答案。未完成保存不得把旧修订当当前答案确认。刷新与恢复后原始值、状态和精度一致。

健康问题继续独立使用 E3 题干和选项，不加入饼图作为第七维；兴趣口味继续用现有目录面板，不重新添加已经删除的硬要求、属性偏好或自由文本输入。

## 5. 本次设置与一次“确认并开始”

### 5.1 轻量设置预览

已确认画像之后调用正式 `POST /api/v1/run-start-preview`，请求为 `confirmed_id` 加可选 `clones_per_city`、`years`、`max_cost_cny`。城市来自确认画像，不另造 city_ids 运行参数；修改城市须回输入并重新审阅确认。

最终确认区展示：画像摘要、城市/分身数/年数、停机费用上限、规划器/模型说明、范围说明与必要知悉项。读取：

- `settings`：本次有效设置；`planner`：模型与费用说明。
- `scope_zh`：范围、后台检查和资料限制；`acknowledgements[].ack_id/text_zh`：必要知悉项，不自动勾选。
- `start_allowed/start_refusal`、`quota`：现在能否开始及原因。
- `consent_fingerprint`：服务给出的授权条件身份。
- `display`：这份即时回复的双语附层，不假设预览有可另行 GET 的持久对象。

预览是轻量只读，既不排队、不占次数也不调用模型。页面可在最终确认区显示短暂加载，不为它再开“检查资料”等待页。它不编译完整生活输入，不假装已列出检查阶段才能发现的每一项资料缺口。

设置变化使旧预览和同意失效，获取新预览；异步旧回复不能覆盖新设置。语言切换只更新文字，相同 `consent_fingerprint` 的授权含义不变，不因换语言要求重复同意。冻结用户确认时的有效选项，重试不能重新套用变化后的默认值。

费用称“停机上限”，不能称预计消费；`start_allowed = false` 时不得出现可执行的开始按钮，显示正式原因和下一步。

### 5.2 已交付的一次开始请求

用户看过并勾选全部知悉项，点一次“确认并开始”，调用 `POST /api/v1/run-intents`：

```text
{
  confirmed_id,
  clones_per_city, years, max_cost_cny,  // 使用用户确认的有效选项，值与类型按正式 schema
  start: {
    mode: "start_when_ready",
    consent_fingerprint,               // 原预览给出的身份，前端不计算
    acknowledged: [已明确同意的全部 ack_id],
    accept: true,
    idempotency_key                    // 本次开始操作的稳定键
  }
}
```

这是请求形状示意，实际请求对照 165 号公共样例。新建返回 202，幂等找回返回 200，都是 `RunIntentView`；开始时可能没有 `run_id`，以 `intent_id` 进入同一个等待页。

- **发送前**保存本次操作的稳定键及原始请求，按当前用户身份隔离。只存找回所需信息，不存邀请秘密或服务端密钥；退出/删除后清理对应缓存。
- 双击、网络重试、已受理但回复丢失、刷新或重开，属于同一次操作。拿到 ID 后查询原意图；尚未拿到 ID 时，重发**同一请求、同一键**，服务找回同一个意图，即使它已结束、取消或删除。
- 不猜“运行列表最新一项”，不因超时生成新键。同键不同请求的 `idempotency_conflict` 必须显示冲突，不自动换键绕过。
- 重发已明确授权的原请求是丢失回执的恢复，不是后台轮询提交。普通轮询只 GET，不发送 submit、confirm、resume 或新的 start 请求。
- 正常检查通过后由服务自动开始，浏览器关闭不影响；新流程绝不出现第二个正常开始按钮，不发 `/submit`（服务会返回 `start_already_authorized`）。

### 5.3 授权变化、旧意图与额度

直接处理现有 `start.state`：`pending` 等服务、`used` 已按授权开始、`void` 已作废；原因用 `void_reason` 与 `explanation`。带授权意图短暂处于底层 `awaiting_confirmation` 也不能据此画第二个开始按钮。

- `start_consent_stale`：重新取预览，让用户看过变更后重新授权；`start_acknowledgement_missing`：要求补充必要同意；付费关闭、额度耗尽、意图冲突等如实呈现。
- `allowed_actions` 含 `start_again` 时，重新取预览，用户明确确认后使用新键。服务等待维护者时不自动恢复授权；重新开启付费也不是新的用户同意。
- 一次真正结束后用户主动再跑，也要新预览、新明确操作和新键；断线恢复不是再跑。
- `start = null` 的旧意图保留正式旧流程：只在允许 `submit` 时由用户明确确认；不能静默给旧意图补预授权。
- 预览与检查不扣次，检查通过才按服务事务预留，首次进入 E1 才使用。前端只展示 `quota`，不自己扣减或回填。
- 自动开始不等于自动恢复失败、自动重发不确定的付费请求或失败后新建模拟。取消、恢复、删除始终遵守服务动作许可。

## 6. 等待页：进度条与当前一句话

直接消费 `RunIntentView.progress_summary`；检查阶段没有 `run_id` 也有摘要，不能等拿到运行编号才显示等待页。

| 字段 | 页面行为 |
|---|---|
| `phase` | checking / queued / simulating / assembling_result / finished / needs_attention / cancelled / deleted / expired |
| `sentence_zh` | 当前一句话；英文取此对象显示附层的 `/progress_summary/sentence_zh`，新句替换旧句 |
| `updated_at` | 最后已知状态时间；断网时据此说明 |
| `mode = indeterminate` | 执行中的检查、排队、整理或没有计数时用不定长条 |
| `mode = clone_years` | 按 `settled_clone_years / planned_clone_years` 展示，例如“已结算 18/72 个分身年度” |
| `mode = finished` | 结果实际可读，进入完成/结果展示；不把已结算数强行补到计划数 |

具体要求：

- 检查和模拟在同一页自然衔接，当前文字不累积成执行历史列表。不显示 checkpoint、内部路径、凭证或评分参数。
- 自动只读轮询，刷新按钮不是主要交互；保留“查看本次输入与设置”和“离开，稍后回来查看”。离开不取消后台任务。
- 年度结算才更新数值，不能拿调用次数、耗时或页面动画伪造百分比/倒计时；旧快照没有计数时不猜。
- `needs_attention` 或取消/删除/过期时停止“仍在忙”的动画，即使摘要 mode 是 indeterminate；显示原因、影响、下一步。可保留停止前年度数，不能用转圈掩盖错误。
- 取消/恢复/删除/重新开始仅按 `allowed_actions`；已有运行恢复排队可能不可取消，不能套首次启动排队的按钮规则。没有后端支持的暂停按钮不要新增。
- `deletion.state` 区分删除中和已删除，不能只看 phase=deleted 就宣称清理完成。清理对象缓存，后退不能复活旧内容。
- 断线显示最后已知状态和时间，重连查询同一个意图；失败重试有节制，不伪称后台已停或已完成。
- 只有结果实际可读才进入结果页；结果请求暂时失败要有读取错误/重试，不能空白或补出数据。底层 stage=finished 不足以证明结果可读。
- 提前出局、中断后没经历的年份不计入已结算；全流程完成可以仍小于计划，C/E/M 继续分别解释。

## 7. 七项独立核查问题：复现与必须通过的修复

以下编号是 E5 本轮核查编号，不是 E3 的旧画像 R1。旧代码定位用于理解根因，按当前组件实际结构修改。新的评分控件与这些修复是一套实现，不先完整修一套即将删除的旧控件。

### E5-R1：未完成经验被保存成“没有经验”

**复现：** 目录选餐厅厨师 → 点“有相关经验”但不填年数 → 等保存 → 刷新，旧页面变为“没有相关经验”。`pages/draft/Steps.tsx` 的 ExperienceQuestion 把 has 派发为 none，仅用局部 wantsEntries 维持外观。

**修复与验收：** 未填足形成答案的内容时保持未答/待补全，不用 `provided + []` 表示未完成；只有用户主动选择没有才产生明确空表。页内可保留编辑意图，但不自造服务字段。未填、无效、删除年数、换职业、返回、刷新、撤销都不暗中变成否定；审阅如实要求补全，资格由 E3 判断。若刷新后无法保留更细的编辑中状态，回到“未答”可接受，回到“没有”不可接受。

### E5-R2：迁移清单变化后沿用旧同意

**复现：** 旧草稿显示一项待清除，勾选同意 → 另一请求增加待清除项 → 原页迁移冲突 → 重新读取，旧同意仍勾选。涉及 MigrationPanel 状态与 DraftRoute 复用。

**修复与验收：** 实施第 4 节的修订/影响绑定；新增、删除、修改清除项后必须重新同意，未同意不发送迁移。新加入的评分迁移选择也按当前影响作废，不能被旧清除同意替代。正常迁移、冲突重读、英文说明、无关事实保留均走浏览器测试。现有真实旧夹具和测试 helper 已可用，不再以“服务造不出旧稿”为阻塞。

### E5-R3：按中文字符串借译文，丢失字段身份

**复现：** 同一信封两个字段都叫“文员”，第一个 provided=Office clerk，第二个 missing/binding_unverified；`display/scope.tsx` 的 byOriginal/lookupText 把第二个也译为 Office clerk。两个合法不同译文又被合成歧义；内层 unavailable 还能借外层当前能力文字。

**修复与验收：** 以正确业务对象、字段 pointer、显示 key/实体身份和来源快照定位，优先同一 DisplayEnvelope 的 source+fields；独立查询拼接必须验证正式来源匹配。页面调用必须传到正确位置，不能只改索引函数却继续用原文兜底。

同名字段各取自身译文，缺译不借另一个字段；内层失败不借外层当前资源；数组重排仍关联正确；新旧异步结果与缓存隔离；显示失败不改业务对象。缺译提示对应实际展示字段，不因服务缺失数为 0 就掩盖前端漏接。补真实页面覆盖，不只测纯函数。E3 兼容已修，不用前端改绑定或重算身份来“修”历史英文。

### E5-R4：历史版本为空却读取当前地图

**复现：** 结果显示 resource_version=null，页面写没有历史版本，却调用 `useGeography(pack, null)`，后端省略版本即当前版本。

**修复与验收：** E3 第 19 节已明确规则，无需等澄清：历史结果有绑定才请求对应版本；null、显示读取失败、指定资源缺失/损坏都不得请求无版本清单或回退当前锚点。保留底图、列表、表格和可读事实。当前选城可以读取当前版本。正常传精确版本、空版无请求、旧版缺失、先看新结果再看旧结果的缓存隔离，在两种外观都验证。

### E5-R5：两个独立拖动被合并撤销

**复现：** 同一滑条未答→20松手→40松手，撤销一次直接回未答。旧 Allocator 的结束事件未结束 reducer 历史合并。

**修复与验收：** 新评分组件必须按手势分组；撤销依次回 20、未答，重做反向恢复。一次拖动许多 input 事件仍一条记录；连续方向键按约定合并，独立手势不合并。历史保存原始值和状态，不保存舍入权重。鼠标、触摸模拟、键盘、数字精调、取消/失焦/松手组合均不重复提交。

### E5-R6：旧减少去向与文案矛盾，以独立评分替换解决

**旧复现：** 六维均分，选休闲作来源，安全减 1，页面说退回池，实际休闲变为 53/3。

**本轮要求：** 不再实现“退回池”的旧交互；按第 3 节删除来源、池和转移逻辑。增加或减少一个原始评分，其他原始评分逐项不变，只有派生比例会随合计变化。旧分配仅在迁移/历史中按原义读取，不保留有矛盾的新用户编辑入口。新控件真实接通并验收后，将本项记为“按新交互替换解决”。

### E5-R7：已有英文未接到原生控件和迁移页

**复现：** 英文口味分组仍中文，移除按钮读屏名称为 Remove 中餐；迁移已有服务英文却显示中文和未翻译。涉及 ChoicePanel 的 option/aria-label、CatalogPicker 手机下拉、经验插值、DraftRoute 迁移作用域。

**修复与验收：** 在 R3 正确字段绑定之上覆盖 option、aria-label、标题/提示和组合文案；迁移读自己的 draft 显示信封，新预览读即时 display，进度读意图自己的信封。先翻译业务片段再用 UI 模板组句，不把拼好的句子再按中文串查找。中英×桌面/手机检查分组、移除、经验、资格、迁移、授权失效与进度；用户原文保留，真正缺译明确标记，不猜英文。

同时修复 ReviewStep 资格块 `<p>` 包 `<ul>` 的 React 结构警告，复核标题层级、焦点和读屏结构；不把控制台警告当作“测试已通过所以无问题”。

## 8. 结果与历史显示的保留要求

- 保留城市比较 → 单城详情 → 分身年度记录，地图、图表、表格消费同一公开结果。
- 同时展示 C（完成且可评价）、E（生活出局）、M（模拟问题造成不完整评价）、原计划人数、均值分母和缺失范围。例：“计划 10 个，7 个完成可评价，2 个出局，1 个模拟缺失；0.60 是前 7 个的平均。”
- C=0 不显示 0 分；服务错误不是这座城市生活不下去；缺失范围不是置信区间，不自行重算范围或另造排名。色阶沿用已确定的 ADR 0045 和显示规格，不借本轮重新设计。
- L 是实际生活评价，V 是既定参考方案中期末资源的未来使用价值，估值期仍含工作收入；V 不保证未来幸福，J 按正式组合解释。
- 环境实际账目与模型理由分开；模型写错税或工资不改变事实。没有公开的计划理由不自造。
- 原始资料、合成假设、离线 mock 的用途按服务来源标记，不把本地工程验证宣传成真实城市推荐，也不要把含真实资料的整包一概改称纯合成。
- 历史文字与地图依其绑定资源；缺译/缺版本如实说明。UI 导航可以使用当前字典，不能因此覆盖历史业务解释。

## 9. 实施顺序与 E3C 边界

现在即可完整推进，建议分四个功能提交：

1. 契约类型、显示绑定与经验状态修复，补原生控件英文和历史地图保护。
2. 独立评分、手势撤销、审阅原始值/权重、迁移同意与迁移选择；更新前端草稿夹具和跨语言测试。
3. 设置预览、一次开始、持久化幂等找回、统一等待页与进度摘要；保留旧意图的正式入口。
4. 浏览器故障场景、历史兼容联验、手机/键盘/双语双外观收尾及文档。

按代码内在依赖可调整组合，不为了分工重写两遍同一控件。不要单独修好旧定和分配器再将它删掉。

**无需再向 E3C 索要的内容：** 独立评分结构、迁移两种选择、预览/授权请求、同键找回、progress_summary、历史 null 地图规则、真实旧对象夹具均已交付。

**只有实际发现后端缺陷时才交 E3C：** 公共回复与 schema 不一致；来源身份/绑定无法匹配；授权、额度或恢复行为违反正式规则；缺少业务必需的公开语义。提供页面故事、实际提交号、最小请求/响应、期望/实际及测试证据。先完成不受影响部分，不修改 E3 规则、关闭校验或在前端推断替代字段。不要把新后台功能当作本任务默认扩展。

`assembling_result` 阶段很短，当前没有独立的完整意图公共样例；可依正式 ProgressSummary/schema 与 `test_progress_summary.py` 构造受控组件/浏览器夹具，明确其层级，不为等待新样例停工，也不声称实际长时间观察到该阶段。

| 授权变化 | 选项变更旧预览失效；服务条件改变停下；start_again 重新预览/同意用新键；付费关闭不开始、不自动恢复授权 |
| 进度与部分结果 | 所有 phase/mode 可正确呈现；提前出局/缺失不补年度；needs_attention 不永久转圈；结果不可读不算完成；C/E/M 与空值正确 |
| 单次取消/恢复/删除 | 用实际有运行的身份测试；首次排队与恢复排队动作不同；恢复需用户操作；删除后该 run 的结果/display 不可读，后退缓存不复活 |
| 真正旧对象 | v3.3/v3.4 原身份、旧英文与旧运行恢复可用；新问卷不强制改写旧运行；原回复不重发、次数不新增的证据注明来自哪个验证 |
| 新旧意图 | 新授权意图无第二确认；旧 start=null 只在允许时明确 submit；不自动迁移授权 |
| 键盘、手机和两种外观 | 全程键盘完成选城/目录/评分/同意/开始/等待/详情/删除；焦点正确，无底栏遮挡；桌面和 360×740，中英×稿纸/地球可用 |

浏览器正常主链至少一次用真实本地服务，规模取服务允许的最小值，不为页面改动无故跑六城大规模。多个城市、部分结果、预算停止和短暂阶段可使用符合契约的公共样例或受控测试传输，分别标明；不能用全部 stub 的页面流程冒充 HTTP→worker→E1 主链。

旧对象升级、后台崩溃与自动提交竞争已有 E3 测试与证据；可以引用并复跑相应定向测试，不必为每个页面重复造一套后台升级器。若自己没有实际执行，就不声称自己独立验证了后台全过程。

单次运行删除不能用“另一身份只有草稿时删除全部”替代。版本属性形如 `e3-display-res-*` 不能替代缺失/升级/缓存场景。axe 通过不能替代完整键盘与人工检查。手机视口/触摸模拟不等于真机；有真机再测拖转、滑条和页面滚动竞争，无设备则如实保留该限制。

保留现有目录搜索与资格、兴趣口味互斥、跨身份隔离、邀请秘密清除、退出失败/首页草稿、多标签冲突、地球拖动/WebGL 回退和结果语义回归。记录各自实际验证层级。
