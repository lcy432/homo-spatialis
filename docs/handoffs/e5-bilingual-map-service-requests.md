# E5 → E3：双语、地图与服务边界补齐

日期：2026-10-24。配套 [E5 工程 prompt](../design/prompts/2026-10-24-e5-bilingual-dual-mode-service.md)。本单根据当前代码核对提出要求，**不是已交付 API，也不授权 E5 修改公共业务契约**。开工时复核是否已有后续修复。

所有者已确认：中英双语、默认稿纸模式、可切换且可拖动的写实地球；输入与结果都支持地图、地球与等价城市列表。

公共结构仍由 E3 唯一维护：`src/common/product_contracts.py` → `contracts/product/v3/`；E3C 同步 OpenAPI、样例与交接。以下字段名称若用于例子，只表达需要的语义，最终形状与路线由 E3 决定，不在前端先宣布为正式协议。

## 1. 已有接口，不需要再建一套

E3C 已提供会话/CSRF、能力、草稿、审阅、确认画像、运行选项与意图、提交、查询、恢复、删除、机会与费用状态。E5 直接接这些 HTTP 接口。LangGraph checkpoint、E1 文件、队列和执行者继续只在后端，不需要新增一个“给地球模式用”的后端。

公共结果已提供 C/E/M、L/V/J、分母、模拟缺失范围、比较、资料性质、覆盖与年度生活事实；本轮不请求完整月度账本、六维得分分解或模型思维过程。

## 2. 必需：双语业务显示资源

**场景**：小林把界面切为 English，运行前说明仍必须准确解释纽约支持范围、职业资格不足、费用停止与模拟缺失，不能只翻译按钮。

**目前**：大量 `*_zh` 和单语 label/definition；没有正式的英文投影/显示资源协议。职业输入 `language` 不代表 UI locale。

**责任**：E3-A/B 维护题干、选项、业务事实与说明的中英语义；E3C 维护公开承载方式、鉴权与版本。E5 维护导航、按钮、纯展示布局字典。

建议使用**独立显示资源层**，按稳定业务标识、对象/字段与必要参数关联，不改写现有业务响应后复用旧指纹。不强制新增某个具体路由；可以使用 E3 导出的版本化资源或公开显示接口，只要能覆盖动态对象并正确隔离私有内容。

最小交付：

- 中英两套题干、健康选项、物质四项标签/定义/说明、职业/资格与兴趣候选的公开名称和限制。
- 预检查问题、scope notes、服务错误三段说明、等待/恢复解释、费用/额度/保存规则、结果阅读指南、限制、缺失原因、比较说明。
- 地区、机会名称和年度事实描述、期末估值范围说明；无法结构化的动态中文要有官方英文对应或明确语言缺失状态。
- 稳定关联键、语言、显示资源版本、插值参数约束与回退规则。业务内容版本变化仍按原确认失效机制处理，显示翻译修正不能无故改变画像。
- UI locale 的改变不改变原文、输入语种、权重、画像/结果指纹或规划器语言。自由文本保留用户原文；不要求后端把原文翻译成英文再存储。
- 英文版覆盖关键业务状态的公共样例和校验，避免前端根据任意中文字符串反查翻译。

**请求/响应语义例**（示意，不是正式字段）：

```text
请求：显示语言=en；显示对象=某份预检查中 code=planning_request_too_large 的问题；
      绑定该问题的稳定标识/内容身份及 E3 已给的参数。
响应：同一问题的英文“发生什么 / 影响什么 / 下一步”，标明显示版本；
      原预检查内容、指纹、确认令牌保持不变。
```

该问题的英文必须保留“没有发送模型请求、没有使用启动机会、不能由前端删减菜单绕过检查”的含义。私有显示内容不进入公开 CDN 或跨用户缓存。

**未补齐时**：E5 可以完成 UI 字典与显示适配接口，必要时显示带提示的中文原文；不能验收为全链双语完成。

## 3. 必需：可信地理显示信息与范围说明

**场景**：稿纸美国地图与地球上的 Seattle 指向同一个模拟都会区；用户理解它是支持地区的代表位置，不是自己的住宅。切换地图不能把 San Francisco 错画成整个 Bay Area。

**目前**：`CityOption` 有 city_ref、country、scheme、code、label、geography_version、data_status、selectable、note；没有经纬度、锚点性质、双语名或正式地理显示资源。

**责任**：E3-A/B 提供身份、范围、命名与可溯源的显示锚点；E3C/common 定义共享形状、验证与出口；E5 提供可靠国家底图、投影、纹理与交互。

最小交付可为按 `city_ref` 绑定的版本化地理显示清单，不必新增地图服务：

- 国家标准标识及中英名；都会区正式中英名、必要短显示名，保持 MSA/CBSA2023 身份与 code。
- WGS84 显示经纬度、明确的轴顺序、锚点类型（如代表城市中心）、来源和版本。无可靠位置可为空并说明，不填猜测坐标。
- 模拟支持范围的中英短说明及稳定引用；明确都会区、实际居住/工作支持范围和资料覆盖范围不一定相同。
- 对旧运行仍能按其资料/地理版本解析，不能拿更新后的当前 label/范围静默解释历史结果。
- 合成城市与真实地区明确区分；能力与规则仍决定可选性，显示资源有某个点不授予运行资格。

**请求/响应语义例**：

```text
请求：显示运行 settings 中的城市集合，携带对应资料/地理版本。
响应：每个 city_ref 对应的国家、中英名称、可信锚点、来源、范围说明；
      缺少锚点的城市明确缺失，仍可由城市列表访问。
```

必须解释的现有范围包括：纽约限制到 NYC 五区的居住范围及 NY 州支持工作区域；芝加哥仅支持 IL 部分；旧金山 MSA 不包含 San Jose。完整模拟范围由资料定义，不能用显示中心或国家底图外推。

**本轮不必提供**：每套住所地址、街道、楼房、全部 PUMA 多边形或精细都会区边界。E5 以国家底图＋城市代表点＋范围文字即可交付首版；若以后画模拟覆盖区，再要求真实支持范围 geometry。国家底图本身由 E5 选用可靠授权资源。

**未补齐时**：可以完成地球拖转与标准底图、以孤立展示夹具测试标签和多国布局；正式业务仍使用列表，不给真实城市附猜测位置，真实城市地图验收保持未完成。

## 4. 必修：付费开关与公开动作一致

**现状**：`src/product/service/views.py` 的 allowed_actions 只判断阶段/机会；`actions.submit()` 才拒绝付费关闭的提交。于是用户可能看到“开始”，点击后才发现服务不接受。

**要求**：对需要真实调用的规划器，在 live_calls_enabled=false 时，不公开 submit，并给正式的不可操作原因/下一步；本地 mock 不受该付费开关误伤。直接 POST 仍必须服务端拒绝，不能只藏按钮。

**交付例**：同一份待确认意图，关闭付费时只有允许的查看/取消等动作及关闭原因；开启付费后的动作由后端重新决定。E5 只读 allowed_actions，不复制一套授权逻辑，不替用户改开关。

**验收**：两种界面都不误导用户能够开始；直接提交仍守住后端边界。此问题尚未在本次核对中修复，不能混同此前 R3/R4 收尾。

## 5. 必修：首次启动排队与恢复排队的取消权限

**现状**：resume 后同样 stage=queued；views 给所有 queued 提供 cancel，store.cancel 也只按阶段接受，未排除已消耗启动机会的运行。

**要求**：服务端依据真实启动/机会消费记录区分两种 queued。首次启动前按规则允许取消并退预留；曾开始的运行恢复排队时不得出现“开始前取消”或清掉既有进度/暗示返还机会。删除仍按既有规则处理。

公开状态可以继续使用 queued，但须提供准确动作与中英解释；如确需新的结构字段，由 E3 统一设计。前端不根据本地是否见过 running 来猜，也不因为刷新丢历史改变按钮。

**验收例**：先暂停一个已开始运行，再恢复，刷新或换设备，取消均不可用；直接调用 cancel 被拒绝，已有结果与机会记录不被破坏。

## 6. 必补：意图与确认画像的实际到期时间

**现状**：RunIntentView.expires_at 只取 result_expires_at，待确认/暂停的内部截止时间未完整投影；ProfileConfirmReply 只含确认结果，没有数据库已有的首次确认/到期时间。

**要求**：

- RunIntentView 对当前适用的保存期限给出真实 expires_at，并说明期限类型/触发规则；不能把无结果理解成永不过期。
- 确认画像返回首次确认时间与有效截止时间，并提供刷新/重连后可读取的确认摘要。仅在首次确认响应加日期不足以支持换设备。
- 重复确认、查询不重置期限；服务端业务动作仍校验到期。
- 说明“画像到期不能新建意图”和“已建意图自己的期限”是不同规则，不能使用户误以为已有运行随画像一起消失。

**验收例**：小林过几天回来，看到同一份画像与意图各自准确截止日期；不断刷新不延长。到期后的动作收到410，页面不再次提交。

**未补齐时**：E5 仅显示服务给的保存规则，无精确倒计时；不能从 updated_at、浏览器收到时间或默认30天生成伪日期。

## 7. 规范补齐：OpenAPI 重复成功返回

当前创建意图、submit、delete 的重复/已处理成功路径可能返回200，而导出接口主要列202。请使 OpenAPI 包含实际成功码及其响应结构，连同重复提交、重复删除样例一起更新。

E5 同时处理2xx与业务 status，不能只接受202；这不替代 E3 修正公开文档的一致性。

## 8. 确认即可：地图评价口径与颜色尺度

E5 本轮默认使用现有 `mean_j`，不请求新综合分、不排名。请确认当前 J 的公开数值域与同一运行内可比较条件；将其作为公共文档/显示元数据的承诺，并为未来评价版本或跨国不适用保留明确限制。

所有国家共用同一尺度；不能每国单独归一化。C=0/未评价不着最低分颜色；C>0但有M仍可显示完整者均值，旁边必须标缺失。

该确认只为正确画图，不要求公开评分系数或内部参考住房。E5 依据现有 comparisons 呈现比较结论，范围不重算、不解释成置信区间。

## 9. 上游交付与 E5 完成条件

每项完成时，提供：权威结构/代码改动、导出 schema 或显示资源、OpenAPI（如涉及HTTP）、中英公共样例、相关回归测试、简短迁移说明。共享版本是否变更由 E3 统一决定。

双语和可信坐标是完整产品展示的依赖；动作不一致是服务接线的正确性缺口；期限投影影响准确的保存说明。E5 可以并行完成其它页面，最终报告必须逐项列出已接通与未交付内容，不使用前端临时字典、猜测日期或坐标宣布完成。

这张交接单不要求 E3 再建队列、生成新业务报告、暴露内部归档或部署服务。真实调用和公网部署仍需所有者另行安排。

1. **原业务消息保持原样。** 新增只读 `GET /api/v1/display?kind=…&id=…&locale=zh|en` 返回 `DisplayEnvelope`：原公共 `source`、其显示绑定指纹、语言/资源版本、按 JSON Pointer 与稳定 key 关联的文字附层及缺失状态。source 与附层同次返回，避免错配。E5 adapter 将 source 送入原业务状态，仅用附层呈现文字；不翻译原正文后沿用旧指纹。

## 12. E5 接线时发现的问题与新增需求（2026-10-24）

E5 按 v3.3 主链接通本地 E3C（HTTP → worker → LangGraph → E1 离线 mock）时发现。逐条写现象、影响与建议；**都不由 E5 在前端绕过或修补业务**。

1. **数据目录太深时，检查阶段报“服务出现了内部问题”（已查清：不是服务逻辑的缺陷）。** 现象：数据目录放在很深的临时目录下时，运行前检查停在 `blocked`，worker 诊断是 `FileNotFoundError: workflow\preflights\<64 位指纹>.json.tmp`。原因是 Windows 的 260 字符路径上限（这台机器没开长路径，`LongPathsEnabled = 0`）：失败的两次完整路径是 272 与 261 个字符，成功的是 256；放在仓库的 `runs/` 下只有约 168。E5 的浏览器测试已把隔离服务的数据目录固定在仓库的 `runs/web-e2e/service`。**建议（可选）**：服务启动时检查数据目录的深度，或者在写文件失败时给出“路径过长”的明确诊断，免得维护者看到的只是内部错误。
2. **审阅说明露出内部键名。** 口味写“喜欢川菜”时，`taste.message_zh` 是“口味与菜系：待选中——候选 ['chinese']，有歧义 []，没认出 []”。请改成显示名称（“中餐”），不要出现 Python 列表写法。
3. **知悉项只有编号。** `pending_confirmations` 只给 `ack:standard_start`、`ack:retained:<ref>`、`ack:interests_not_personalized` 这样的编号，正式文字只在服务内部（`answers._ack_text`）。E5 现在用公开内容拼说明（能力清单的 `start_scenario`、审阅里的陈述原文、兴趣与口味的审阅说明）。请在审阅消息里直接给出每一项的中英文说明。
4. **兴趣与口味的作答说明是按顺序排的字符串。** `interests.leisure_states_zh`、`taste_states_zh` 是“名称：含义”的列表，顺序靠与枚举对齐。请改成带键的结构（`state`、名称、含义，中英文），E5 不再靠顺序与冒号拆分。
5. **模型输入 / 输出语言（所有者 2026-10-24 新定）。** 所有者要求“显示语言”和“模型输入与输出语言”都是用户开局可调的选项，不维护半中半英的组合。现在契约里只有 `occupation.language`（职业匹配本身不看它）；规划模型用什么语言，没有任何字段能指定，提示模板也只有中文。E5 已做好开局选项：选择写进 `occupation.language`，选英文时页面说明“规划模型的提示与输出暂时只有中文”。**需要 E3**：能力清单声明支持的规划语言；草稿 / 确认画像 / 运行意图里有正式的“模型语言”字段并进入运行身份；英文提示模板与英文的分身可见事实。
6. **共享工作区里的半成品。** E3C 正在实现的 `profile_summary`、`expiry_basis`、显示出口等已经改了工作区里的 schema 与服务代码（还没提交）。E5 只按已提交的结构接线与测试：浏览器测试可以用 `E5_SERVICE_REPO` / `E5_CONTRACTS_DIR` 指向只含已提交代码的工作树。E3C 提交新结构之后，E5 的 `contract:check` 会按设计失败，再重新生成类型并接上新字段。
7. **结果色阶的口径要对齐（需要所有者裁定）。** 工作区里 E3 正在做的显示附层（参数目录 PI-61 草稿、`MetricDisplaySpec`）把 `mean_j` 的色阶写成固定 [0, 1]、不按城市重新拉伸。所有者 2026-10-24 给 E5 的决定是“城市差距很小时适度放大，但不画成第一名满分、最后一名零分”（[ADR 0045](../../DECISIONS/0045-e5-web-dual-mode-bilingual.md) 第 4 条）：同一结果共用一个窗口，宽 = min(1, max(0.02, 2 × (最高 − 最低)))，落在 [0, 1] 之内，图例写明窗口两端。手算（本地 mock 主闭环，合成设定）：西雅图 0.5602、芝加哥 0.5643，固定 [0, 1] 时两城在色阶的 56.0% 与 56.4%，是同一个颜色；适度放大后窗口宽 0.02、中心 0.56225，即 [0.55225, 0.57225]，两城在 (0.5602 − 0.55225) / 0.02 = 39.75% 与 60.25%。建议 `MetricDisplaySpec` 只声明值域 [0, 1] 与分母，窗口怎么取由界面按所有者的决定做；如果 E3 认为必须固定 [0, 1]，请所有者裁定，E5 照改。
