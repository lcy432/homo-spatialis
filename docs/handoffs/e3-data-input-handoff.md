# E3 交接：用户输入处理与美国真实城市资料

更新：2026-10-17。供新的 E3 讨论与 coding agent 会话读取。

**任务：把用户确认的生活取舍和美国真实资料，转换成 E1 能执行、能解释来源的输入。** E3 包含用户输入处理，不只是抓数据。E5 负责如何呈现表单和结果；不要让 E5 自己解释职业、分配权重或生成初始状态。

本文是分阶段交接，不是已经实现的 API，也不自动批准付费调用、修改经济公式或扩大研究实验。产品上线优先，E4/R 线研究可以后置。

**2026-10-18 补记（E3-A）：** 第 5 节的 E3-A 已实现、离线自测通过，**待独立审核**（[ADR0034](../../DECISIONS/0034-e3a-product-input-contract.md)、[技术说明](../design/e3a-product-input.md)、[证据](../../runs/2026-10-18-e3-a-input/README.md)）。交付：唯一权威结构 `src/common/product_contracts.py` 与导出的 [contracts/product/v1/](../../contracts/product/v1/README.md)（13 份 schema、35 份合成样例）；原始答案 → 审阅 → 确认画像；六维＋独立健康接入 E1（新画像类型与偏好来源，不补医疗占位分，与旧七维在同比例下严格等价）；标准开局复用 E1 检查；便利资料的来源事实 → 候选 → 合法机会与选项目录覆盖；离线预检查、本地提交与幂等、mock 三年闭环与白名单结果。第 6 节验收 1–4、6–10 在合成范围内有离线证据（3 里的“网页与本地相同”要等网页入口；8 只走了 mock 路径，没有付费预算），5 里的同口径入账与“未知不是免费”已实现，真实税的计算与公开说明同源留 E3-C。第 8 节的建议：六维均分表示定为规范分数 `50/3`；健康题给出三道暂定题；美国资料的来源与缺口只做了盘点（技术说明第 8 节）；首发人群、真实税最小覆盖与城市集合仍待所有者决定。下一步：E3-B 真实资料（产出 `SourceFact` 与 `OpportunityCandidate`，经同一编译器进入 E1），E3-C 运行服务与 E5 联调。

**2026-10-18 收尾补记：** 独立审核（[runs/2026-10-18-e3a-independent-review](../../runs/2026-10-18-e3a-independent-review/README.md)）发现的 F1–F5 已修复，离线自测通过，**待独立复核**（[ADR0034 第九节](../../DECISIONS/0034-e3a-product-input-contract.md)、[证据](../../runs/2026-10-18-e3a-closeout/README.md)）。对 E3-B 数据入口的要求因此更明确：每个用到的已知字段都要引用记录这个字段、单位对得上的 `SourceFact`（报价按资料包的当地基年价口径，寿命按年，效果与本人参与按 小时/月），单个数值要有事实支持或写明换算；缺来源、缺计价单位、非法数值逐候选拒绝；供给、资料与编译状态分开。这些规则不需要 E3-B 改编译器，只需要按它们整理资料。共享结构已是 `contracts/product/v2/`。

### 两项必须先设计的适配

**六维＋独立健康输入。** 当前 `StatedLifeProfile` 是七维合计 100；健康版评分再移出医疗项、归一化其余六维。新问卷不能直接塞进去。新增明确版本，独立保存健康回答、六维分配及确认来源，并接到规划观察和评分偏好构造。旧问卷和研究真值保持旧语义。不能偷偷放一个医疗占位分，或者让 E5 先压缩六维来适应旧结构。

**真实数据与税。** 当前运行配置仍限 `exploratory_synthetic`，运行器绑定合成税，规划说明也由该合成税生成。真实资料接入需要分清：真实生活事实、估计映射、未标定的模型规则。工资、税、价格口径要一致；真实税绑定和公开说明必须同源。保留探索评价标签，不能仅删掉“synthetic”就宣称模型已验证。

## 3. 用户输入怎样编译成一个人

### 3.1 职业：用户说人话，系统维护映射

例：“我在餐厅做店员，有时收银，有时做饮品。”

1. 保留这句话和语言信息。
2. 用职业词表和别名给出少量可读候选，例如“主要负责收银”或“主要制作饮品”；只在工资映射有实质歧义时追问。
3. 保存用户确认的职责与职业概念，再关联美国分类体系、版本和代码。
4. 从本地岗位机会获得工资与资格要求；不能由 LLM 凭常识发明报价。

美国代码不出现在用户输入口，也不是用户的永久身份。当前 `OccupationId` 只有 `scheme + code`；新增的产品层还需保留国家上下文、分类版本、匹配方法与歧义。V2 可从同一个职业陈述分别映射中国、加拿大等分类；行业均薪与职业工资不可直接当成同一口径。

V1 优先用词表、搜索和明确规则，不要求为职业匹配另开 LLM 访谈。匹配失败给可理解原因，不自动改成“普通白领”。初始证书/技能按相关岗位条件收集并确认，不从职位称呼自动授予全部资格。

### 3.2 偏好、钱与硬要求分别处理

- 六维定和，物质内部另分配；同一用户跨城保持同一权重。父项为 0 可跳过其细分；为正时必须有明确、受支持的细分方案。
- 可用资金、币种、年龄是事实。不能从“重视物质”推出更富有，也不能从消费较少推出不喜欢。
- 风险应对倾向作为独立陈述供规划参考，不改变客观概率或共同病痛项。不确定可以保留，不填中间值。
- 自由文本不自动覆盖结构字段。旧 [elicitation.py](../../src/worlds/elicitation.py) 的文本调分、旧固定消费篮子逻辑不是新产品默认处理器，不能直接接上。
- 硬要求只开放已有明确语义与资料支持的项目；普通愿望留作软偏好。不能识别的要求应说明未支持，不能承诺已满足。

### 3.3 标准初态不是随机人设生成器

同一个人开局现金、年龄、能力、时间和精力条件在各城市及重复分身中一致。遵守 E1 的健康、无旧物、无历史进度/经历开局。不要因为要生成十个分身，就随机给三人洗衣机、两人慢性病。

将来不同币种的“相同财富”、不同国家职业身份的等价，需显式升级现有严格一致性核对；V1 只保存扩展所需的语义和来源。时间/精力的示例数值是模型设定，给用户可读说明，不让用户填写负担点数来冒充测量。

## 4. 美国资料：统一口径，尽量用全已有覆盖

### 4.1 获取与转换流程

```mermaid
flowchart LR
    A[全国性来源及使用条件] --> B[原始快照：时期、地理、单位]
    B --> C[可审计映射与派生]
    C --> D[城市事实和少量生活选择]
    D --> E[全城市相同检查、代表城市手工核对]
    E --> F[版本化资料包与覆盖报告]
```

不人为只采三座城市。先查全国性资料的实际覆盖，批量导入，再用代表性城市核对含义和边界。可发布城市应通过相同口径与共同选择类型的检查；不齐全的城市显示缺口，而不是用隐形默认值补成高颗粒度。

来源选择时核实许可、地理边界、年份、抽样对象与定义。原始值、固定单位换算、估计模型、合成设定分层保存；追溯应能回答“这 1,200 美元租金究竟来自哪条资料，经过了什么转换”。

### 4.2 七类生活信息怎么接现有 E1

| 内容 | 最小接线 | 不能从统计量直接推出来的东西 |
|---|---|---|
| 物质与住房 | 可付费的住房/食品/服务方案、可测规格、报价、供应状态 | 价格指数不是商品单价；平均消费不是本人偏好；房租不能自动购买安全 |
| 安全 | 统一空间尺度的背景事实与明确映射 | 街区细节、花钱改善安全的效率，资料不足就不建 |
| 发展 | 城市背景与岗位/培训关系；相关技能只解锁相应机会 | 均薪不是保证录用；会计证不能提升开发岗位资格 |
| 休闲 | 抽象休闲机会、费用与本人时间 | 具体爱好与地理匹配留 V2，不从游客数自动推所有人的快乐 |
| 环境 | 环境背景；自然景观与户外吸引力可单列来源 | 购物或古迹旅游热度不自动等于环境好 |
| 交通 | 住房方案绑定的出行事实、到岗安排与广义交通映射 | 不能自由拼“远处租金＋近处通勤”；广义交通中间量不是实际时间账 |
| 医疗 | 小病/大病的可得性、费用、治疗时间及来源 | 实际平均医疗支出不等于同等治疗的价格或效率；现实疾病与保险复杂性不能假装已覆盖 |

最后一行不是要求首轮造出完整医学模型。若真实资料不足，必须明确哪些是代理场景/估计/合成，约束产品说法；由所有者裁决是否能以探索版本上线。取得真实租金不意味着疾病概率、负担系数和满足感参数也获得了现实标定。

金额沿用当地基年不变价，记录币种、基年、资料时期及必要转换。不要重复空间平减。真实税表要核对税辖区、适用年份、收入定义和累计预扣，不能把旧空间平减美元的税表换标签使用。

## 5. 最小工程阶段与交付

| 阶段 | 交付与审核点 | E5 可以并行做什么 |
|---|---|---|
| **E3-A 输入与共享契约** | 一份结构定义、版本规则、能力清单、确认画像/标准初态适配、公开结果投影、公共样例；先离线 | 页面草图、组件；冻结后按同一结构接样例 |
| **E3-B 美国资料管线** | 来源清单、批量获取/映射、职业与金额/税接线、统一覆盖报告；冻结资料包 | 表单状态、进度与结果页，仍用公共样例 |
| **E3-C E1 联调** | 从确认画像到真实资料运行输入；预检查、冻结、幂等提交与现有运行器衔接；离线及批准的小试跑 | 接服务、联查拒绝/暂停/部分完成，再做发布准备 |

这不是要求每阶段只用一次对话。首轮先把 E3-A 做成可审核结果，不同时重构所有模块。若 E1 需要窄范围扩展，先列出接口和影响；不能绕过保护，让真实资料看起来能运行就算通过。

服务层归 E3 的业务部分包括：校验、确认身份、输入编译、运行前检查、调用已有运行器、结果投影。E5 可以负责 HTTP/页面部署，但不在其中复制业务判断。新增依赖、框架和文件路径由首轮结合仓库现状选择，并通知 E5。

## 6. 验收要证明什么

1. 用户从自然职业文字到明确映射，歧义/未知都有可读状态，浏览器不用职业代码。
2. 六维与健康真正分离；仅改变健康陈述，在固定行动和事件下不改变评分或疾病；它可以影响今后 LLM 的计划。
3. 网页与本地相同确认输入生成相同初态；两座城只改变城市条件，不改变个人起点。非法旧物/病史开局被拒。
4. 未答、明确 0、无所谓、未支持不同；文本不会自动改分、工资和资格。
5. 同单位与计价才可入账；未知不是免费；真实税的计算与给分身看的说明同源。
6. 新城市经过同样覆盖和颗粒度检查；不能按城市删除用户正权重再重新归一化。
7. 品牌/饮食属性可以保留并报告未评分，不能伪称已实现商品异质性评价。
8. 冻结输入、预算身份、模型身份、重放保护仍有效；同一个提交不会重复付费。
9. 公开结果与 E1 的 C/E/M、L/V/J、分母和空值精确一致；不泄露研究真值、隐藏参数或服务密钥。
10. 相关旧协议回归通过。涉及运行器/经济核时再跑适当全量离线检查；不为了文档或界面微调机械重跑全部大计算。

先用离线模型替身和公共样例。真实试跑需要新的明确预算、运行 ID 与证据目录；历史 Flash 的三次/一元额度不是本阶段持续授权。

## 7. 交付给人的反馈格式

每轮报告用中文，按以下顺序：

1. **结论与范围**：实现了什么、还不能做什么，区分自测与独立审核。
2. **一个生活例子**：用户写了什么，系统如何理解，进入哪些 E1 字段，钱和行动怎样变化。
3. **数据例子**：原始资料 → 单位/口径转换 → 城市机会；注明观测、派生、估计或合成。
4. **E1/E5 影响**：改了哪些共享字段、是否需要 E5同步、新旧版本怎样区分。
5. **实际证据**：测试与运行结果；未跑的不能写通过，推断不能写成实测。
6. **限制与待裁决**：影响哪些用户；给出一个简单建议，不把所有技术细节都交给用户猜。

必须维护共享约定、PLAN、参数目录和对应技术说明。题干、默认值、锚点、工资/税/价格映射都有版本；用户陈述不是可为了提高模型分数而训练掉的噪声。

## 8. 首轮需形成的具体建议

- 首发支持哪些职业与生活情境；哪些输入可默认、默认依据和用户确认方式。
- 六维改善锚点与物质首批功能；独立健康题的中性题干与选项；六维精确均分的内部表示与显示舍入，不能暗中偏爱排列在前的维度。
- 美国资料的统一地理范围、年份、真实税最小覆盖和仍需估计的项目。
- 新产品契约怎样显式衔接旧七维 E1；共享结构与样例的实际文件位置。

不用在这些问题全定之前等待：可以先盘点代码、资料与词表，并给出可审核的样例。不要擅自开放跨国比较、家庭模拟、真实医疗预测或品牌评分。
