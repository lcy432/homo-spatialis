## 2. 页面要让用户完成什么

建议用短步骤、可返回修改和渐进展开；不在一个页面要求用户填完几十项。具体页数可以调整，语义顺序保持清楚。

### 第一步：选择比较范围，说明这是怎样的模拟

用短句说明：分身在各城固定生活三年；每年做计划、按月执行；世界中有现实资料，也有尚未标定的模型设定。先展示当前支持的生活情境与城市范围，避免用户填完才发现职业或国家完全不支持。

城市选项来自 E3。没有“三城上限”的产品约定；资料覆盖与运行费用决定可选范围。中国、加拿大等未来支持的国家不能放进可点击的正式运行选项。

### 第二步：几项生活事实

- 职业用自然语言或搜索，并展示职责说明帮助确认。**不要求、不展示职业编号。** 前端可持有不透明选项 ID，但不能让人填写美国 SOC 等代码。
- 年龄和开始时可用现金；现金明确币种和含义。不是总资产、信用额度，也不是每月工资。
- 只有相关岗位需要时才展开资格问题。
- 时间/精力用生活语言说明当前默认情景，不要求用户算自己有多少“负担点”。

初态说明可写：“本次模拟从健康、尚未购买生活物品的新生活开始；现实中的旧家具和病史暂未纳入。”这是假设，不是对用户现实健康的判断。不能要求用户上传病历来使用当前模型。

### 第三步：表达生活取舍

六个维度分配 100 分，采用 E3 提供的统一定义和改善情境。初始不预填数值；显示未分配点数，辅助计算。分满后由用户自己指定减少哪项，再增加另一项；不要自动从所有其它项等比例扣分。

“平均分配”可作为主动操作，不能预选。示例放帮助中，不默认给“事业型”“享乐型”等人格套餐。用户可明确给 0 分，未回答保持未回答；控件步长不解释成测量精度。

六维均分采用 E3 冻结的内部表示和显示规则；不要自行取整成不均匀分配。预检查通过也不承诺全部分身活完三年，后续计划与事件仍由环境逐次处理。

先分六维，再展开物质内部。物质父权重为 0 可跳过细分；为正时让用户完成当前可支持的细分。页面解释：“这里分的是重要性，不是规定每月怎样花钱。”

品牌、菜系、档次等不要做成几十道必答题。当前若保留这类补充，应明确显示“本版是否用于规划、是否进入评分”。未支持时不能画出暗示已影响排名的匹配度。

### 第四步：独立健康回答和可选补充

健康风险应对单独展示，不挤占六维 100 分。使用 E3 审核的中性题干；不把冒险、体质自信、不治疗、能忍痛混成一个人格标签。允许“暂不确定”，不自动给中间值。

提供可选文本，不要求额外多轮聊天。显示长度限制，不静默截断。结构化硬要求只展示 E3 说能核验的选项；从文本发现可能的硬要求时先请用户确认，不能直接替用户勾选。

可用少量具体生活取舍检查帮助理解，但不判“回答错误”，不自动改分。这不是测验通过才能使用产品。

### 第五步：确认理解、范围与费用，然后运行

展示一张易读摘要：职业解释、资金口径、六维及物质取舍、健康陈述、默认开局、未支持的偏好。允许从摘要回到对应字段。

再展示 E3 运行前检查的三种能力：能执行、能完整评分、能更新精力。输入结构合法不代表这三件事都成立。预算由服务端给出：城市数、每城分身数、行动年数、模型、调用/金额上限。用户修改任何相关内容都应重新检查与确认。

一次点击只提交一个幂等运行。等待时查询已有运行，不因刷新、断线或重复点击重新生成一批分身。

## 3. 结果怎样让人看懂

### 3.1 主页面

每座城同时展示：

- 完成且可评价的分身平均分，以及参与计算的人数。
- 原计划人数、生活出局人数、模拟问题人数；不要只展示一个成功率。
- 缺失范围与解释：它是未知结果可能改变均值的范围，不是置信区间。
- 一两条代表性的实际事件链和年度现金/生活摘要；可展开查看全部分身。
- 资料覆盖、模型设定、未考虑的偏好，以及硬要求通过/不通过/无法核验的人数。

例如：“原计划 10 个分身，7 个完成并可评价，2 个生活出局，1 个因资料缺失无法评价。0.60 是前 7 个的平均。”出局不进入该平均，但始终可见；不能因此暗示退出的人不会改变用户对城市的判断。

若 C=0，显示“没有可用于平均的完整结果”，不显示 0 分或排最后。M 的服务错误、模型规划停止、资料问题、未运行应有各自原因，不能写成“当地生活太难”。

### 3.2 展开说明

L 是实际几年过得怎样；V 是期末资源在参考方案中的未来使用价值；J 是两者的组合。V 的估值期仍有工作收入，采用既定模板与治疗分支，不是又问 LLM 任意规划一年，也不保证全局最优。

不要写“这座城市让你幸福的概率是 65%”。分数是当前模型下、按用户确认的陈述偏好计算的结果。不要把小数末位差异包装成可靠排名；比较状态、范围重叠与证据不足由 E3 返回，E5不能自己加胜负判定。

生活事件依据环境记录；LLM 理由里的错误算术不能当作真实账单。既保留“模型认为预算紧张”这种主张的归属，也展示环境实际计算结果，不能让模型重写事实美化结果。

## 4. 对接方式与开发顺序

| 阶段 | 交付 | 对 E3 的依赖 |
|---|---|---|
| **E5-A 离线界面** | 表单、确认、典型错误、进度与报告的可用原型；明确合成样例标记 | 可先依共享约定画草图；数据接线使用 E3-A 的同一结构和公共样例 |
| **E5-B 运行接线** | 调用输入校验/预检查/提交/进度/结果接口；幂等、断线恢复、暂停和部分结果展示 | E3-C 服务入口；不旁路 E1 运行器 |
| **E5-C 轻量上线** | 串行任务队列、服务端密钥、费用保护、访问与数据留存/删除、部署说明 | E3 真实资料和全链路验收；付费试跑另有批准预算 |

框架不在本交接里指定。选择能尽快实现和维护的轻量方案，不为第一版先建复杂的微服务、多供应商或多进程调度。`src/ui/` 可作为现有入口参考，实际目录在首轮决定。

E3 主责共享结构与业务服务；E5主责展示和部署。共用接口名见共享约定第 7 节。不要在前端再实现职业映射、六维到旧七维转换、税、汇率、初态、覆盖率或 C/E/M 算法。前端的即时校验可以帮助填写，但正式确认仍由服务端做。

模型供应商密钥在托管版只留服务端，不让用户填写自己的密钥才能试用。开源本地版另提供自己的配置方式；业务语义保持一致。当前串行预算账本不能多进程共写，初版用单个执行工作者排队即可。

接口与部署还需做到：一个用户不能通过猜运行 ID 读取另一个人的资料；浏览器不收到内部路径、隐藏评分参数或研究真值。真实用户文本和模型回复不能沿用“合成人设可进仓库”的归档发布方式。初版是否需要账号、保留多久，由首轮给出简单可行建议，不默认为永久公开保存。

## 5. 最少要验收的界面行为

1. 职业歧义能用人话确认；国家分类代码不进入用户题目。
2. 未答、明确 0、平均分配、不确定、未支持状态能被区分，刷新草稿不会悄悄改答案。
3. 分数不会自动从其它维度扣走；物质细分不会改变物质父权重；有撤销和返回修改。
4. 六维、独立健康、自由文本各守用途；前端不偷偷做旧协议转换。
5. 数据未知时不显示免费、不可得或 0 分；缺少正权重项不能只弹一个小提示就给完整比较。
6. 标准开局、默认值、产品省略和品牌/饮食未评分状态在运行前可见。
7. 修改输入后旧预检查失效；双击提交与断线重试不造成重复付费。
8. 服务端额度不足、服务失败、部分完成、C=0、全 E、硬要求未知都能正确展示。
9. 城市结果和底层 E1 报告的数字、分母、空值与事件链一致，不以格式化规则改变结论。
10. 手机和键盘操作可用；文字清楚，有少量真实使用者的理解检查。记录实际耗时与困惑，不宣称某种界面天然无偏。

涉及付费前必须完成离线联调；不要自动运行旧 `pilot`/`main` 命令。使用新批准的预算与目录，费用估算和供应商实际账单分开。

## 6. 怎样反馈给所有者和 E3

每轮中文反馈至少包含：

1. 用户现在从哪一步走到哪一步，哪些页面还只是样例。
2. 一个具体用户的填写 → 确认 → 运行 → 结果故事；附实际界面证据。
3. 哪些信息来自 E3/E1，哪些只是展示；遇到接口缺口时给出请求/回复示例。
4. 实际跑过的交互、契约和回归检查；没验证的内容单列。
5. 未支持的用户和偏好；需要所有者决定的少数产品选择。

共享字段有变更时先协调 E3，再更新结构、样例与两边测试。不要在 E5 临时加字段后让 E3 猜含义。根目录文档只补当前入口与阶段，不改写历史证据。

**首轮优先交付：** 一套可交互的离线填写与结果原型，重点检验用户是否理解“权重不是预算”“风险不是痛苦偏好”“完成者均值不代表全体”。真实数据和托管运行接线随后推进，不用等待后置研究全部做完。
