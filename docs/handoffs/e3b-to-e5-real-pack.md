## 3. 资料性质（`CityDataNature`）怎么读

* `summary_zh`：一句话，直接显示。
* `opportunities` / `totals`：目录里各类机会（住房、岗位、食品、服务、设备、活动、培训）按来源性质的条数——观测、派生、估计、合成设定，四种都列，没有的写 0。真实资料包里大多数是“估计”（例如住房租金是同格租金分位的估计），不要显示成“实测”。
* `named_assumptions`：登记的模型设定（例如设备的类别价格与寿命、爱好装备、模型活动），带原文、条数与几个例子。它们是设定，不是某个商品或场所的报价。
* `common_priors`：比较组各城共用的背景设定（安全与休闲），没有可比资料时登记的共同先验，不制造城市差异。**不显示数值**，也不显示它换算到评分的规则。
* `treatment_assumptions_zh`：治疗价格是六城共同假设（没有真实医疗价格资料）。
* `model_plan_activities`：按模型活动设定写的活动（网球、在家练吉他、参观博物馆等）。
* `home_areas` / `work_areas`、`commute_modes`：片区数与三种通勤方式在这座城的关系表里有没有、有几条线、使用条件（与给分身看的同一份公开说明）。
* `menus`：住房与岗位的年度菜单（几年、几个环境重复、每份几项）。
* `tax`：税规则编号、状态、支持的居住与工作地、规则名称、官方说明没有的税、没有建模的部分（逐条显示 `not_modeled_zh`，它们让结果与真实税单有差别）。
* `build_status` / `build`：冻结资料包构建报告里的计数（片区、通勤线、住房候选与排除原因、放进目录的住房与岗位、菜单）。`not_available` 表示报告读不到或与生活输入对不上：计数未知，不是 0。

## 4. 展示时要守的口径

* 片区是资料的地理单位（PUMA 或按县划的就业片区），不是街区或楼栋；片区本身不加分。
* `area_typical_roundtrip_minutes` 为空是未知，不是 0 分钟。`commute` 的 `unknown_no_housing`（出局当月没有住房）也是未知，不是 0；`no_onsite_work` 才是确定为零。
* 通勤每个月在可用方式里取往返最少的一种：分钟与方式是执行结果，不是用户选择，也不是路线模拟。缺的方式不当 0 分钟、不当免费。
* 没买用车权就不能开车；用车权是一项普通的按月付费机会。
* 设备故障只显示事实与替换结果：**不显示**故障概率、抽签随机数或键（消息里也没有）。坏了之后剩余寿命作废；买不起替换就是没买成，不顺延。
* 年度菜单是接触机会，不是成交或录用；现住的房子可以续租、现在的岗位可以延续。
* 结果不排序真实城市，也不是现实推荐；资料性质与范围说明要和分数放在一起显示，不能只显示分数。

## 5. 仍然不支持（照实告诉用户）

* 职业：只支持资料包里的 40 种（受控词表，每种对应一个 SOC 2018 职业）。词表外的职业在审阅时被拒绝并说明原因，不换成别的职业；某座城没有对应岗位时那座城报错，不自动换岗。开局岗位要求的学历、证书或经验只认用户在资格一栏明确确认的（样例 54），职称与自由文字不授予。
* 税：只支持单身、只有工资收入、按标准扣除；纽约只支持纽约市五区居民、工作地在纽约州；芝加哥只支持伊利诺伊州部分；三年都按 2024 年规则。抵免、税前扣除、逐项扣除、非工资收入与跨州组合没有建模。
* 资料包的 `unsupported` 清单（在 `scope_notes` 里原样列出）：多人家庭、非工资收入、家庭共同资产、买房与贷款；停车费与按距离计的公交票价；旧金山的公交票价（官方网站拒绝访问，所以旧金山的关系表没有公共交通）；芝加哥公园管理局的真实活动（需要日期窗口、整期报名与年龄资格，引擎暂不支持，没有放进目录）；品牌、制作方式、档次、服务质量与上门顾虑的评分；访谈式输入。
* 设备故障：真实资料包里的设备与装备都写的是“模拟期内不随机坏”（`none_within_horizon`），所以真实运行里不会出现故障记录；`device_failures` 的形状由合成样例上的受控年份测试（`tests/product/test_e3b_public_facts.py`），没有公共样例。
* 用车权：mock 规划器不买用车权，所以样例里都是 `not_bought`；买了的形状同样由受控年份测试。

## 6. 发现的问题（不在本轮范围，没有改）

* 旧金山的 mock 分身（合成文员 u501，带 60 分钟通勤上限）三年生活正常、评分完整，但期末估值不完整（`valuation_incomplete`，E1 的原因是 `no_feasible_plan`：参考集合里没有能完整执行、完整评分并满足硬要求的分支），所以是 M 而不是 C；休斯敦、西雅图是 C。旧金山没有公共交通可能与此有关，没有核实。原因与修法属于引擎与评价配置，需要另外处理；界面照 `explanation` 与 `missing_reason_zh` 原样显示即可。
* 网页迁移到 v3.1 之前，`test_web_drafts.py` 仍跳过；迁移时要把网页草稿改成 v3.1 的结构版本。
