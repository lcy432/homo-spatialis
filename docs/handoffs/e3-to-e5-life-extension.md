日期：2026-10-22。规则见 [ADR0041](../../DECISIONS/0041-life-extension-food-enjoyment-hobbies.md)，机制见 [生活扩展技术说明](../design/e1-8-life-extension.md)。本轮只提供接口与样例，**没有改 E5 页面**。

## 1. 结构升级

共享结构从 `contracts/product/v2/` 升到 [`contracts/product/v3/`](../../contracts/product/v3/README.md)（`e3a-product-schema-v3`）。唯一权威结构仍是 `src/common/product_contracts.py`；不要在前端临时加字段。`tests/product/test_web_drafts.py` 在网页草稿还写着 v2 时跳过（4 条），网页改读 v3 后它会恢复检查。

## 3. 展示时要守的口径

* 物质点数是相对重要程度，不是开支比例；兴趣不是“必须买”的指令。
* 买到、在用、实际参加是三件事：吉他在用不等于练了琴（样例 45）。
* 没成交的购买没有扣款；没能进行的活动没有收费、没有小时。
* “没认出”的兴趣原文与品牌只留存、本版不评分，要原样显示给用户，不能写成“已支持”。
* 匹配系数是公开登记的模型假设，不是对用户的测量；不显示任何评分参数。

## 4. 旧确认怎样处理

旧版本（v2）的确认画像不能补 0 或重新分配后沿用：结构版本不同，直接拒绝。界面应引导用户重新回答物质四项与兴趣、口味，重新审阅并确认（`tests/product/test_interests.py` 有这条检查）。

## 5. 没有做的

真实资料里的食品方案与活动还不能编进 E1（缺做饭时间、新鲜餐数、活动参与时间；活动带日期与年龄限制）；编译检查现在只有受控样例。期末参考生活只覆盖音乐练习这一种装备活动。
