# Development guide

English · [简体中文](DEVELOPMENT.md)

Find the relevant module in the [project index](INDEX.en.md), then read its design. The [architecture guide](ARCHITECTURE.en.md) explains module relationships; the [contribution guide](../CONTRIBUTING.md) explains submissions. Coding agents also follow [CLAUDE.md (Chinese)](../CLAUDE.md).

## Environment

From the repository root:

~~~sh
uv sync --locked
~~~

[.python-version](../.python-version) specifies Python, and [uv.lock](../uv.lock) pins dependencies. Applications run from source; entry scripts load `src/` through `scripts/_bootstrap.py`. See the [reproduction guide](REPRODUCING.en.md) for the smallest example and its outputs.

The web app uses Node.js 22. Run `npm ci` in `web/`; the [web guide](../web/README.en.md) covers the service, worker, and browser app.

## Automated checks

The usual offline Python suite and style checks are:

~~~sh
uv run --frozen pytest -n auto
uv run --frozen ruff check src tests scripts
uv run --frozen ruff format --check src tests scripts
~~~

The default suite excludes `live` and `slow`. Run research tests separately with `uv run --frozen pytest -m slow`. Tests marked `live` may use network services or model quota. [pyproject.toml](../pyproject.toml) and [tests/conftest.py](../tests/conftest.py) define the scope. Runtime depends on hardware, concurrency, and data packs.

For a specific issue, target its test file:

~~~sh
uv run --frozen pytest tests/life/test_settlement.py
~~~

Run web checks from `web/`:

~~~sh
npm test
npm run typecheck
npm run build
~~~

Browser end-to-end requirements are in [web testing](../web/README.en.md#testing). Record the checks actually run and their results. Distinguish local verification, CI, and earlier reports.

## Contracts and generated files

Python message definitions live in [product_contracts.py](../src/common/product_contracts.py). JSON Schema and public samples are in [contracts/product/v3/](../contracts/product/v3/). Change the authoritative definitions first, then export the schema and frontend types. Export commands are in the [contract guide (Chinese)](../contracts/product/v3/README.md).

Frontend types under `src/contract/generated/` are generated by `npm run contract:gen`. Both `npm test` and `npm run build` check that generated files match the schema. New states also need display text and appropriate input or result examples.

## Documentation maintenance

- READMEs introduce the project, quick start, scope, direction, and a short methods overview. Keep facts and roadmap aligned across languages.
- Put code responsibilities in [architecture](ARCHITECTURE.en.md), and formulas and mapping details in [technical designs](design/README.en.md).
- Maintain module status and default entry points in the [project index](INDEX.en.md), and version direction in the [roadmap](../PLAN.en.md).
- Record literature in [references](REFERENCES.en.md), and design decisions in [DECISIONS (Chinese)](../DECISIONS/README.md).
- Use relative links. After a rename or move, check entry points, fragments, and incoming links. The [history guide (Chinese)](history/README.md) resolves old section numbers.
- English pages should link to English counterparts when available; Chinese pages should link to Chinese counterparts. Mark untranslated destinations explicitly. Keep language switches reciprocal.

When multiple sessions share the checkout, inspect existing changes and commit only your own work. Commit and push conventions are in [CLAUDE.md (Chinese)](../CLAUDE.md).
