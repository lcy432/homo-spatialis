## 一、要回答的问题

已有结算已经能留存现金、跨年攒钱、购买物品和支付培训。缺的是：分身想为未来的一笔购买或学费攒钱时，这件事在环境里
**有没有记录、进展怎样、最后有没有兑现、凭什么说兑现了**。本轮只新增结构化目标、进展与兑现依据；储蓄账户、利息、
支付系统都不另写——钱仍只在原来那一本现金账里，按原来的月度顺序流动。

## 二、目标是什么

| 字段 | 说明 |
|---|---|
| `goal_id` | 年度计划给出，同一分身全史唯一（取消或替换后也不能重用） |
| `kind` | `durable_purchase`（一次性计价的耐用品）或 `training_tuition`（一次性计价的课程） |
| `opportunity_id`、`quantity` | 本城目录里的机会与数量（课程数量必须是 1） |
| `target_year`、`target_month` | 希望实现的年月，限定在本年到第 N 年 |
| `note` | 说明文字：只存储与展示，不参与任何计算 |
| `quote` | 建立时的报价依据：一次性单价 × 数量、口径、读到它的年份、来源类型——**当时的资料，不是价格预测** |
| `status` | `active` 进行中 / `overdue` 已到期未兑现 / `realized` 已兑现 / `cancelled` 已取消 / `replaced` 已被替换 |
| `events` | 建立、保留、改时点、取消、替换、到期未兑现、兑现，每条带年月与说明 |
| `realization` | 兑现依据：年月、计划第几项、实付金额、`durable_purchase_executed` 或 `tuition_paid_in_full`、是否按时 |

建立目标时按现有可购买性规则拒绝不成立的目标并说明原因：机会不存在、确定缺货、报价未知（不补零）、不是一次性计价的耐用品
或课程、报价口径与账户不同、总额为 0（零学费的课程照常可以报名，但没有要攒的钱）、耐用品**仍在持有**（现行规则持有期间
不能再买；旧的那次购买也不能冒充新目标的成果）、课程学费已结清或已学完。这些与"已有未结束的目标还要再设一个""指令指向的
不是现有目标""目标 ID 用过""关联对不上"一样，都是**输入错误**：整份计划退回、什么都不提交（E1-7 可修改重试）。

## 三、目标是软约束：同一本现金账

目标不创建资产、不转移现金、不扣款、不锁定资金。记录器 `econ.life_savings` 拿不到现金，只读结算已经算出的月末余额与已经
发生的支出——结构上就动不了钱。分身把钱花在别处，差距照实变大；环境不替它节俭，也不阻止任何实际支付。

每个完整过完的月份月末（以及年初指令之后、任何交易之前）记一行进展：实际余额、目录**当前**报价 × 数量、还差多少
（max(0, 报价 − 余额)）、余额是否不少于报价。当前报价每年按目录重新读取；目录没有可用报价（未知或确定缺货）时报价与差距
都记为未知，不补零。兑现那个月只记余额与状态，不再拿付款之后的余额去比报价。

## 四、兑现必须由环境事实决定

* 关联：年度行动里最多一条写 `goal_id`，必须指向年初指令之后的那个未结束目标，机会、数量与角色（耐用品 / 培训）必须对得上。
  代理不能写"已完成"——兑现只由结算判断。
* 依据：这一条在某个月实际执行、付出的钱等于"数量 × 当前单价"（原结算付一次性购买与学费用的就是这一个算法）。耐用品
  记 `durable_purchase_executed`，什么时候开始提供服务照原物品规则；课程记 `tuition_paid_in_full`，**这不表示学完或取得资格**，
  学习进度、完成与能力生效照原规则。
* 不兑现：付不起（原规则下一次性购买不顺延）、缺货、未知、计划被拒、余额只是够了、买了目标的东西却没写 `goal_id`（照常
  执行与付钱，记一条说明）。
* 时点：兑现不晚于当时的目标年月记"按时"，否则"晚于目标时点"；逾期的目标之后仍可由关联购买兑现，也可以改时点或取消。
* 一笔交易最多兑现一个目标；重复交接被年度绑定拒绝，不会重复扣款或重复记事件；"这次试算的现金 + 另一次试算的兑现记录"
  由现有年度绑定拒绝（候选状态与实际结果的指纹覆盖目标）。

## 五、不重复计分

评分器不读目标。储蓄的价值只通过实际生活结果体现：买到的物品按原服务期与功能规则评分（演示里洗烘一体机让洗衣分项从
无到有），付学费后的学习按原参加、成长与资格规则产生结果；功能去重与物品数量规则照旧。付款金额、目标金额、目标状态都不
另加一遍分；期末未花现金、未兑现目标与物品残值留给 E1-6。**实测**：同一份行动、只改目标（没有目标、只改说明、只改时点、
换成学费目标），现金流、逐月分数与下一年额度逐项相同，只有目标记录与包含它们的指纹不同。

## 六、为应急留下的最小接口

储蓄不锁成专款。将来已声明的实际费用（例如 E1-5C 的医疗）从同一本现金账支付，余额下降后差距在月末自然更新——这就是
本轮建立的全部接线（"根据真实余额与已执行交易更新目标"）。没有疾病结算器，不预设事件发生时回滚全年。演示与测试用一笔
**计划内的普通开支**（探亲往返 1,500）证明目标既挡不住实际支付、也不会复制或藏起一笔钱；**它不是随机疾病机制**。

## 七、状态、版本与信息边界

1. 目标与事件在结算收尾时写进下一年候选状态与结算结果，在年度绑定封存之前完成。
2. 反馈受阻：已经发生的现金与目标事实保留在结算结果里，不返回可直接继续的状态。
3. 出局：此前的事实保留（含年初指令），出局当月及以后不再更新；终态保存目标与余额，不再安排购买；整份试算失败什么都不留。
4. 新协议的状态必须写 `savings_goals`（没有目标写空列表）；旧协议的状态写了就报错；旧文字目标原样保留。
5. 代理可见自己的目标、实际余额、建立时与当前的报价、差距、是否到期、事件、兑现依据、未兑现原因与七条规则说明
   （`AgentObservation.savings`、`VisibleFeedback.savings`）；目标储蓄规则、目标与它的报价依据、事件、兑现依据、这一年的目标
   记录都是内部类型，登记在禁止类型清单里。隐藏评分参数与研究真值照旧不进 payload。
6. 单个目标未兑现不停止任何分身；执行、评分、反馈能力仍分别报告；原计划分身与停止原因照旧保留，不为 E1-6 提前决定补零、
   剔除或完成者平均。

## 九、本轮的局部实现选择（prompt 没有写死，请所有者复核）

1. 年度计划不写目标指令 = 已有目标原样延续，不记事件；明确写 `keep` 才记一条"保留"。
2. 目标 ID 由计划给出（全史唯一），而不是环境生成：同一年设定并购买时，行动可以直接引用它。
3. 兑现只认写了 `goal_id` 的行动；同一机会的购买没写就不算兑现（钱照付、东西照买，记一条说明）。
4. 逾期目标之后仍可由关联购买兑现（记"晚于目标时点"）；`reschedule` 让它回到进行中，原到期记录保留。
5. 耐用品仍在持有时不能为同一件设目标——即使它会在目标时点前到期（要替换快到期的物品，等它到期移除后再设）。
6. 设目标时不检查资格（课程或岗位相关的资格在购买那一年按年初状态判断）。
7. 出局当月不记"到期未兑现"，也不再更新进展（出局记录说明这个月）。
8. 每年按目录重新读取当前报价；目录未知或缺货时差距记为未知。V1 的目录不随年份变，所以当前报价与建立时相同。
9. 指令或关联不成立按整份计划退回处理（输入错误），不是丢掉目标、照常执行其余行动。
10. 演示样例用 0 税档（年收入 40,000 以内 0%）让每个月的现金流能直接手算；与以前样例的税档不同，只是测试替身。

## 十、仍不能做；进入 E1-5C 前要讨论的

* 多个目标之间的资金争抢、自动优先级、分期或部分付款、利息、投资、借贷、多个账户（都没有实现）。
* SV-02 里"缺钱时是否推迟目标按**事先声明**处理"：没有实现事先声明的推迟规则；现在只能下一年明确改时点或取消。
* 应急事件插在月度顺序的哪一步、是否允许应急时动用原定的购买资金（现在目标本来就不圈钱）、应急后是否需要自动暂停目标
  （现在没有任何自动行为）——留给 E1-5C 与所有者。
* 期末未花现金、未兑现目标、物品残值的评价（E1-6）；代理是否会因"钱够了"而误以为目标完成（要在 E1-7 的真实调用里观察）。
