# 0048 E3C 一次开始：设置预览与检查前的开始授权（`start_when_ready`）

日期：2026-10-25。层：托管服务（E3C）。任务原文见所有者 2026-10-25 的“E3 输入与服务体验调整”第二节；交接见
[E3C → E5](../docs/handoffs/e3c-to-e5-service.md) 第 17 节。

## 背景

原来的流程要用户点两次：准备一次模拟（排队检查）之后，等检查通过、回到页面再点“确认开始”。检查可能要等，用户关掉页面就停在
“等你确认”；页面为了省事又容易自己轮询、一看到通过就替用户提交。所有者确定：用户在检查之前看过设置预览、点一次“确认并开始”，
授权“检查通过就按这些设置开始，只开始一次”；之后的检查与开始都在后台，等待页只读。

## 决定

1. **设置预览只读**（`POST /api/v1/run-start-preview`）：确认画像 + 运行选项 → 这次的有效设置、规划器与模型种类、费用上限、范围说明、
   必要知悉项与同意身份（`consent_fingerprint`），以及此刻能不能开始。不编译生活输入、不排队、不预留次数、不调用模型、不写库。
2. **同意身份**绑定确认画像（编号与内容身份）、资料包、有效设置（`ExecutionSpec` 的身份：城市、规模、年数、规划器、模型、报价、费用
   上限与调用上限）、范围说明的业务版本（`START_SCOPE_VERSION`）与知悉项编号。不含任何文字，换语言不改它；说明的含义变了才换版本。
3. **一次开始**：`POST /api/v1/run-intents` 带 `start = {mode: "start_when_ready", consent_fingerprint, acknowledged, accept, idempotency_key}`。
   服务端按当前的预览重新核对同意身份与知悉项、付费开关，把授权保存在意图上（服务库 v4 的 `start_authorization`）。同一个键的重试先
   找回原来的意图（即使已经结束、取消或删除），同一个键配不同请求是冲突；新的键遇到尚未结束的同一份准备只附上授权或记下键——一次
   开始和它的重试只对应一个意图、一次运行。没有 `start` 的意图照旧：检查之后由用户确认开始（`submit`）。
4. **后台衔接**：检查通过之后，worker 在同一个检查任务里按授权开始（`actions.start_authorized`）：与用户点“确认开始”同一套核对
   （按保存的选项与现在的政策重算有效设置、按现在的知悉规则重算同意身份、付费开关、预检查是不是授权的那一份设置、提交核对），
   预留 1 次、写运行编号、排队与把授权标为已用在服务库的**同一个短事务**里；次数到第一次进入 E1 才转为已使用。LangGraph 的确认节点
   照旧，确认记录写明来源（`source = start_authorization`，附同意身份与授权时间），不写成用户在检查之后又点了一次。带授权的意图不接受
   `submit`（`start_already_authorized`）。
5. **授权作废，不替用户接受**：设置、资料包、报价或知悉规则变了（重新检查）、选项不再允许、付费调用关了、次数不够、检查没有通过、
   检查结果与授权的设置对不上、开始时出了程序问题、用户取消——授权作废（`void_reason`），停下说明；用户看过新的说明后重新取预览、
   再确认一次（`start_again`）。已经说明过的普通资料缺口（检查通过但某些城市缺评分资料）不需要再确认。
6. **崩溃与重启**：检查结果写下之后、自动开始之前进程退出——检查任务留在进行中就随重启退回待办；任务已经结束只剩授权的，重启时
   兜底重新排队（`requeue_pending_starts`）。再开始之前照样按授权与当时的条件核对；提交本身对同一意图幂等，只开始一次。
7. **自动开始 ≠ 自动恢复 ≠ 失败后自动重开**：授权只用一次；停下之后的恢复照旧由用户点，失败或结束之后再模拟要新的开始。
8. **版本**：服务 API v1.4（与 [0047](0047-e3-independent-ratings.md) 同一轮）；服务库 v3 → v4 就地升级（只加一列，已有意图没有授权、
   照旧流程；v2 先升到 v3）；LangGraph 的流程版本不变（确认记录多一个字段，旧检查点照常恢复）。

## 后果

* 页面只有一个正常的开始按钮；等待页轮询只读，不再自己提交确认或恢复。关闭浏览器不影响已经授权的开始。
* 授权作废之后要用户重新确认（新的幂等键）；同一份准备不会因为条件后来恢复了就悄悄开始（例如付费调用重新开启）。
* 预览不编译生活输入，所以检查才会发现的资料缺口不在预览里逐条列出；预览说明这类普通缺口不再要求确认，阻断与授权以外的变化照样停下。
