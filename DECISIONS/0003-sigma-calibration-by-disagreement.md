# 0003 地板臂的 σ 用分歧率二分标定，跑在重复子集自己那批 scenario 上

**状态**：已采纳（v0.9 迁移期，细化 MIGRATION C10.2）
**落点**：`src/eval/`（M5）｜**对应硬规则** 25

## 决定

```
target := 重复子集实测的分歧率
          = 重复对里选出不同城市的比例
          （150 人设 × 3 次 → 每人 C(3,2)=3 个无序对，全体池化）

求 σ 使得地板臂模拟数据在**同一批 (世界, 人设) 交叉点**上的分歧率 = target
分歧率对 σ 单调递增，二分即可

护栏：若 target > 1 − 1/n，无解 → 报错，不要外推
```

## 为什么写成过程而不是一句话

MIGRATION C10.2 原文是"把地板臂生成数据时的 σ 标定到**人内重复一致性**与重复
子集实测相同"，并且它自己在同一段里写着"将来任何一次简化最可能改错的就是
这里"。

"一致性"有方向歧义。可观测量是**分歧率**，而地板臂的分歧率完全由 σ 决定，σ 越大
分歧越多。若有人把"一致性"实现成"一致的比例"再去匹配，方向就反了——而反了
之后代码跑得完全正常，只是 λ 系统性偏到另一边，然后门二的判定跟着错。

所以文档里一律用 **disagreement rate（分歧率）**，不用"一致性"。

## 为什么必须在同一批 scenario 上标定

**分歧率依赖选择集。** 备选城市之间效用越接近，同样的 σ 给出越高的分歧率。拿
另一批世界去标定，标出来的 σ 会系统性偏一边，偏多少取决于两批世界的福利离散度
差多少——一个没人会去检查的量。

C10.2 只说了要"同构"。这里收紧成**就是同一批**：重复子集的 (世界, 人设) 交叉点
是现成的，而地板臂本来就是用真值 `w_i` 经 softmax 生成选择，完全可以跑在那批
scenario 上。这比"找一批相似的世界"精确，也省掉"多像才算同构"这个说不清的判断。

## 为什么上界是 1 − 1/n 而不是 1

n 座备选城市下，完全随机选择的分歧率是 `1 − 1/n`（12 座城市时 0.917），不是 1。
若实测 target 超过它，**没有 σ 解得出来**，而那本身是个信号：说明重复对里混进了
不同条件（世界不同、prompt 不同、备选顺序没固定住）。二分之前先查这一条，
不要把它当成"σ 要取很大"然后外推。

## 保留 C10.2 的那条限定

重复子集测的是**同人设同世界跨次运行的分歧**，logit 的 σ 测的是**备选项间的特异
误差**，两者相关但不同一。这是**校准启发式，不是恒等式**。代码注释里要写明，
不要因为"看起来应该相等"就改成解析换算。
