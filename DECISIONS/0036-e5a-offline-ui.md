> **当前规则一览**
>
> * **技术路线**：React + TypeScript + Vite 的静态单页，放在 `web/`；React Router、TanStack Query、Ajv（2020-12 版本类）、fraction.js；Radix 只在需要时按组件引入（本轮没有用到）；
>   不用 React Hook Form、全局状态框架、CSS 框架、组件库或图表库。Node 只用于开发与构建。
> * **契约只有一份**：TypeScript 类型由 `contracts/product/v2/*.schema.json` 生成（不手改）；`contract:check` 核对每份 schema 的 SHA-256 与 `index.json`、并确认生成的类型是最新的，
>   在 `build` 与 `test` 之前自动执行。Ajv 只检查不改数据（不开 `useDefaults`、`coerceTypes`、`removeAdditional`）。
> * **页面只依赖业务访问层 `ProductApi`**：E5-A 用 `SampleAdapter`（按场景原样返回 E3 公共样例，不做任何业务判断，只模拟网络条件）；E5-B 换成 `HttpAdapter`（接 E3-C）。
> * **E5-A 不对任意修改后的输入给出新的模拟结果**：自由填写只做回显与草稿导出；系统审阅、确认、预检查、运行与结果只能用配套样例演示，页面写明。
> * **草稿只存在当前标签页**（sessionStorage）：刷新还在，关掉就不保留；有“清空我的答案”。版本变了提示重新核对，不静默迁移。
> * **答案状态**：草稿就是 `UserInputDraft` 的形状，一个状态更新函数维护它；未答 = 没有这一项，明确 0 = provided "0"，无所谓 = indifferent，暂不确定 = unsure；用户写的文字原样保存。
> * **提交**：幂等键在发送之前生成并存进本标签页；提交返回之前不触发新的提交；断网与回执丢失后的重试用同一个键；查询可以重试，提交从不自动重试。
> * **结果**：数字一律取 E3 的显示值，不在前端计算 J、均值、比例或范围；空值写成文字（“没有可用于平均的完整结果”“没有范围”），不显示 0；不排序、不加胜负徽章。

## 二、采用的规则

### 2.1 契约消费

* `npm run contract:gen` 把 13 份 schema 合成一份再生成类型：同名的 `$defs` 必须逐字相同（来自同一个 pydantic 类），不一致就报错、不挑一个用。唯一的预处理是去掉嵌套字段上的
  `title`（注释性关键字，不影响校验；保留它会生成 State1、State2 之类的类型名）。
* `npm run contract:check`：哈希与 `index.json` 一致、目录里没有未登记的 schema、重新生成的类型与仓库里的逐字相同。测试在临时副本上验证了两种失败：改一个字节；schema 与 `index.json`
  都更新了但类型没有重新生成。
* 运行时用 Ajv 的 2020 版本类编译全部 13 份 schema（导出的 schema 没写 `$schema`、引用是 `#/$defs/…`）；样例 22 是 `YearFacts` 片段，用 `ProductResult` 里的 `#/$defs/YearFacts` 校验。
  适配器的每份输入（草稿、提交）与每份回复都过校验。

### 2.2 样例适配器的边界

* 场景表（`web/src/api/scenarios.ts`）写明每个场景用哪几份样例；只有“正常闭环”与“答案改过之后提交”能从第 1 步走到运行，其余场景直接打开对应页面（审阅、预检查、
  确认画像的单条样例用确认页的同一组件展示）。
* 不匹配职业、不换算金额、不审阅、不判定合计、不算 C / E / M；样例里没有的情况返回“样例里没有这种情况”，不编造回复。改过的草稿拿不到样例审阅或确认。
* 适配器模拟的是服务端，所以提交登记（第一个幂等键与收到过的提交）存在本标签页里，刷新页面之后同一个键再提交照样得到“重复提交、同一个运行”（样例 08）。
* 只模拟网络：延迟、断网（含浏览器真的离线）、“提交已送达但回执丢失”。断线之后再查进度返回 E3 标明为契约示例的那一份（32），内容与平时相同。

### 2.3 填写与答案状态

* 草稿 = `UserInputDraft`；另外只多记年龄输入框里的原文（契约里年龄是整数）、下一个属性偏好编号、撤销记录。撤销以“一次操作”为一步（同一输入框里连续打字合成一步）。
* `revision` 只增不减（撤销也换新编号）：同一个草稿编号下不会出现两份内容不同、编号相同的草稿；收到的审阅如果对应的不是当前版本，就当作过时丢掉。载入的样例答案一改，
  草稿换成本标签页自己的编号。
* 分配器：不预填；超过 100 不拦输入、不自动扣减，由用户点选从哪一项减；分满后按＋先问从哪一项挪 5 分；“平均分配”要主动点并确认，之后改一项先问要不要改成手动分配
  （其余各项保留精确的 50/3）；按钮与挪分算出的值能写成两位以内小数就写小数，否则写规范分数；写法不对的项原样保留、不计入合计。合计用精确分数，只是填写辅助。
* 打开硬要求时不替用户填数字；属性偏好的 `need` 让用户从物质细项里选（与 E3 样例 17 一致，需求 A10）。

### 2.4 确认、预检查与提交

* 确认画像与预检查记下它们对应的草稿版本；之后改了答案就标“已失效（你在确认后改了答案）”，运行按钮不再出现。
* 运行按钮在 E5-A 写“查看样例运行”：只有预检查 `ready` 且确认与预检查都没失效才出现。

### 2.5 进度与结果

* 进度：排队或运行中时每 3 秒重查，其余阶段不自动重查（有“刷新状态”按钮）；分身状态逐个显示；没有恢复按钮（“由维护者处理；你不需要重新填写”），等 E3 给出“由谁处理”（需求 B2、B3）。
* 结果：城市卡按 E3 的顺序；C / E / M 用字母方块与文字（不只靠颜色）；均值必带分母那句话；缺失范围画在 0–1 刻度上、标“不是置信区间”与分母；`not_generated` 时不显示任何城市分类。
  E3 给的中文原样显示。分身故事页的“分身自己的说法”是占位（需求 B7），不放任何模拟内容。
* 结果里只有英文键的字段（健康月份、年度状态、硬要求、参考方案、家务任务）先用 `web/src/contract/pending-labels.ts` 的临时文字：每条注明转写自仓库里的哪一处，没登记的键如实显示代码（需求 A1）。

## 三、没有做的（占位或留给后续轮次）

真正的审阅、确认、预检查与运行（E3-C）；HTTP 适配器（只有空壳）；恢复按钮；“排队”“运行到一半”的真实样例（页面已做好、由组件测试覆盖）；登录、“我的运行”、删除与分享；
模型理由的展示；资格题的自动展开（先放在折叠区）；长期保存草稿；部署。

## 四、本地实现选择（任务原文没有写死，请所有者复核）

1. 第 1 步合并了“支持范围”与“生活事实”；“开始填写”的两个入口是“从空白开始”与“载入样例用户 u501 的答案”。
2. 分配器的“说不准？”用原生下拉菜单（无所谓 / 暂不确定）；−/＋ 每次 5 分；还没分满时＋直接加 5 分，已经分满或超出时才问从哪一项挪；剩余点数的状态条在
   滚动时固定在顶部（可见高度不到 520 像素时不固定，免得放大或横屏时挡住屏幕）。
3. “用样例继续看后面的流程”会用样例答案替换本标签页里的答案，所以先问要不要导出自己的答案。
4. 双击运行按钮：第二次点击在提交返回之前被拦下，只发一次请求；“重复提交”由回到确认页再点一次来演示（同一个键、回执 08、同一个运行）。
5. 年龄输入框写不成整数时，草稿里年龄记为未答，原文留在界面上并提示“写成整数”（需求 A12）。
6. 生产构建是一个约 0.9 MB 的包（39 份样例与 13 份 schema 都打进去了）；原型阶段不做拆包。

## 六、限制
