>
> * 发展维 z_m = b + η_growth × g_m，s = min(c, z/(z + τ))；月度总分仍由原有七维加权函数计算。b 是城市的发展条件（背景），

> * 能力 a 的进度 p_a：年初已有 = 1；否则取授予它的课程里最高的"实际累计参加月数 / 要求月数"（0–1）。g_m = Σ_a (p_a,m − p_a,m−1)。
>   只用本月及之前真实参加的记录；不读理由、学费、工资或课程名称；没付成学费、没参加、被拒绝的课程不长；已有或已学完的能力

> * 通勤维（人话：交通便捷程度及出行对生活的影响）：k_m = ρ + (1 − ρ)·D_m / D_ref，T_eq = k_m·T_m，S = τ_T / (τ_T + T_eq)。
>   T 是实际所住住房（含兜底）的往返分钟，D 是资源账的当月累计到岗次数。ρ = 0.25、D_ref = 20、τ_T = 60 分钟（合成）。
> * 无工作、纯远程（D = 0，k = ρ）、混合、兼职与多岗位在资料齐全时都能评；住房分钟或资源账缺失报未知、不补 0。

> * 证书本身、换岗、职位名称与涨薪不另加分；钱仍通过实际生活服务产生满足感。

## 一、要回答的问题

E1-5A 让学习改变了下一年能做的工作，但学习的月份本身在评分里什么也没有——一个看重发展的人，花一年学会计，那一年的
满足感与不学的人一模一样（CA-06 当时登记为未实现）。另一方面，E1-3 增补的方案级通勤只评"恰好一份固定线下工作"的月份：
不上班专心学习、纯远程、混合办公或兼两份工作的月份，通勤一律报"不支持"，反馈开着时整年额度定不下来。

本轮用**已有的维度与数学形式**补上这两处：发展维加实际成长，通勤维扩展成广义交通。不新增第八维，不另造一份"成长偏好"，
不把旧 M2 的对数效用接入生活评分。

## 二、成长满足感：使用已有的发展维

### 2.1 公式与字段

    z_m = b_opportunity + η_growth × g_m        s_opportunity,m = min(cap, z_m / (z_m + τ))

* 规格：`ScoringComponent.growth = GrowthSpec(eta, progress_rule = ability_progress_increment_v1, unit = 能力进度/月, definition)`，
  只能挂在发展维、不再挂物品来源；η 全组共用，只写在评分规格里（不能按城市调）。
* 城市条件：发展维仍写 `known` 的 b 与上限 c（例值 b = 2、c = 0.9、τ = 2）。b 是城市的发展条件，**不由本人的学习结果回填**——
  背景与个人成长分开登记。
* 结果：`ComponentMonth.growth = GrowthTerm(g, eta, contribution, steps)`，`steps` 列出这个月有进步的能力（之前、之后、增量、
  这个月实际参加的授予课程）。
* 产品评分读用户明确陈述的发展权重，研究路径读研究内部偏好，沿用原有隔离规则，不互借。

### 2.2 怎样计算实际成长

`econ.life_scoring.growth_by_month(protocol, catalog, state, outcome)`：

1. 年初已有的能力（`state.abilities`），进度视为 1；
2. 未有的能力，看所有**明确授予它**的课程（目录里的 `grants`）：课程的进度 = （年初进度 + 本月及之前实际参加的月数）/ 要求月数，
   最多 1。年初进度读年初状态（包括这一年没有安排、暂停中的课程），这一年只因同一次结算写出的实际参加月份
   （`EnvironmentOutcome.career.learning.months_attended`）增加；
3. 多门课程授予同一能力，取最高进度——不把两门各学一半的课拼成一项完成的资格；
4. g_m = Σ_a (p_a,m − p_a,m−1)，按精确分数计算。

学习记录的年初进度与年初状态对不上（例如把别次试算的学习记录配到这一次的状态上），直接报错，不评。一门课明确授予两项
能力，按词表里的两项能力算，每月就是两份进度：**能力拆分粒度会影响成长量**，这是登记在 CA-06 的合成假设；词表由环境配置
决定，代理不能自创能力或成果。

### 2.3 生活含义与例值

一门 12 个月的课，每参加一个月新增进度 1/12。b = 2、τ = 2、c = 0.9、η_growth = 12：

    不学习：2 / (2 + 2) = 0.5        实际学习的月份：(2 + 12 × 1/12) / (2 + 1 + 2) = 3/5 = 0.6

发展权重 0.2 的人，其他结果固定时，这个月总分多 0.2 × 0.1 = 0.02；发展权重 0 的人照样学、照样长能力，总分不变。12 是探索
参数，不是心理规律或固定单位换算；η = 0 是关闭对照。

成长分只随当月实际进步出现：学完以后能力继续保留，但证书本身不会每个月自动加分；涨薪不直接加分，钱仍通过实际生活服务
产生效用。本版用学习形成的能力进步代表可测的职业成长，**不**凭换岗、职位名称或涨薪推断额外成就感。

## 三、广义交通评分

### 3.1 含义与公式

维度键沿用 `commute`，人话含义改写为"交通便捷程度及出行对生活的影响"；上班通勤是其中最常见的部分。

    k_m = ρ + (1 − ρ) × D_m / D_ref        T_eq,m = k_m × T_m        S_m = τ_T / (τ_T + T_eq,m)

* T_m：这个月实际所住住房（含兜底，降级后读实际住房）的往返分钟——与资源账计通勤用的是同一个住房字段
  （`resource_rules.commute_minutes_key`，加载器核对）；
* D_m：这个月实际累计到岗次数，读资源账的 `MonthResources.onsite_visits`（多岗位相加，没执行的岗位不在里面）；
* ρ：不因上班消失的交通影响；D_ref：参考到岗次数；τ_T：沿用交通映射锚点。

规格：`ScoringComponent.transport = TransportSpec(minutes_key, rho, reference_visits, unit, visits_unit, definition)`，只能挂在
通勤维，不与旧的方案级通勤并存；结果 `ComponentMonth.transport = TransportTerm(住房, T, D, D_ref, ρ, k, T_eq, τ_T)`。S 不再被城市
上限截顶（与方案级通勤相同）。

### 3.2 支持的情况（T = 30 分钟，ρ = 0.25，D_ref = 20，τ_T = 60）

| 安排 | D | k | T_eq | S |
|---|---|---|---|---|
| 无工作、纯远程 | 0 | ρ = 0.25 | 7.5 | 8/9 |
| 混合办公 | 10 | 0.625 | 18.75 | 16/21 |
| 一份工作天天到岗 | 20 | 1 | 30 | 2/3（与旧的方案级通勤相同） |
| 两份兼职各到岗 10 次 | 20 | 1 | 30 | 2/3 |
| 两份工作各到岗 20 次 | 40 | 1.75 | 52.5 | 8/15 |

D 不在 D_ref 处截断。实际记录或住房分钟缺失仍报未知，不补 0；资源账与评分读到的住房或分钟对不上是记录错误，直接拒绝；
生活出局的月份仍按现有评分边界单列，不因公式扩展而补成完整月份。

### 3.3 不改变时间账

T_eq 是评分中间量，不是实际出行分钟。工作通勤的时间与负担仍是 Σ（实际住房往返分钟 × 各岗位实际到岗次数）/ 60 与对应负担，
不乘 ρ 或 k，不重复扣时间或精力。本版**没有**细化非工作出行时间：不能声称它已经在资源账里核算，也不能说已经从时间预算
中扣除。用住房到就业中心的往返分钟代理广义出行条件是合成映射假设，不能完整反映购物、社交、就医与公共交通可及性；以后有
共同粒度的资料时可以替换，本版不建 GIS 或出行网络模型。

### 3.4 "评分不读资源账"的一个窄例外

ADR0020 规定评分不读资源账。广义交通只读其中**一个计数**——到岗次数 `onsite_visits`，也就是时间账用的同一个数，不另写一套
到岗统计、不按 `onsite/remote` 字样或岗位数量去猜；小时、负担、额度、剩余与检查结论一律不读。ADR0020 原处已加指针。

### 3.5 参数与对照

ρ = 0.25、D_ref = 20 次/月、τ_T = 60 分钟都是合成设定（性质、单位与依据见参数目录 SC-10），不是由真实数据估计的。演示提供
ρ = 0、0.25、0.5 的对照：远程的人 S 分别是 1、8/9、4/5；天天到岗 k = 1，与 ρ 无关。组内所有城市用同一套 ρ、D_ref、τ_T，不能按
城市是否缺数据临时换口径。

## 四、版本、反馈、覆盖与信息隔离

1. 成长项与广义交通只属于 `GROWTH_TRANSPORT_VERSIONS = {e1-5a-growth-transport-v1}`：旧版本声明它们直接拒绝，新版本必须两项
   都声明（η = 0、ρ 等对照用另起的规格编号）。加载器还核对协议里真的有它们要读的事实：成长要职业规则，交通要月度资源规则
   与同一个住房分钟字段；评分器在计算前复用同一份检查。
2. 新评分规格与版本进入反馈政策（内容指纹覆盖评分规格编号与版本）、比较组与年度绑定（评分输入指纹）。旧评分产生的中间
   状态不能拿来继续新评分实验：E1-5A 协议下的第 2 年状态放到新协议里结算，按政策内容不一致拒绝；新实验从共同初始状态重跑。

   > ⚠ 第 1 条"对照用另起的规格编号"与第 2 条"内容指纹覆盖评分规格编号与版本"已被 DECISIONS/0025 加强：反馈政策必须声明评分规格的**内容**身份，加载、年度交接与下一年开始前都核对；编号版本相同、参数不同的规格是另一个实验身份。见该记录。
3. 成长与交通只读同一次年度结算写出的记录，在 `settle_and_score` 的年度绑定里评分；不能用别次试算的进度或通勤搭配本次现金。
4. 覆盖报告（coverage-v2）同步：广义交通的实际行动可评分性是"任何安排"，城市资料核对每个可得住房的往返分钟与每份可得工作
   的岗位方案；发展维有行动机制，读课程授予作为事实来源。评分器与覆盖报告用同一套事实，不会一边说支持、另一边报不支持。
5. "没有成长"（g = 0，已知）、"没有到岗"（D = 0，已知）与"相关资料缺失"（未知）分开。
6. 代理照旧看得到学习进度、岗位要求、工作安排（到岗次数）、实际住房的往返分钟与时间负担；η_growth、ρ、D_ref、k、T_eq、
   内部评分与研究真值不进 payload。新增的内部类型（`GrowthSpec`、`TransportSpec`、`GrowthTerm`、`AbilityProgressStep`、
   `TransportTerm`）登记在 `internal_scoring_models()`，新增保留键 `progress_rule`、`rho`、`reference_visits`、`visit_factor`、
   `equivalent_minutes` 不与可见字段重名。
7. 新评分会改变下一年精力与计划可行性，这是预期行为：例如远程客服在原规则下第 1 年通勤不支持、反馈受阻；新规则下第 1 年
   S = 0.590277…，第 2 年额度 264.75，一份每月负担 260.5 的第二年计划因此可行（关闭反馈的 250 额度下不可行）。

## 五、边界订正（不新增功能）

* 跨年度暂停学习、保留进度、恢复后不重复收学费**已经支持**（独立审核 `runs/2026-10-09-e1-5a-review/audit.json` 的探针，以及本轮
  的暂停样例）；ADR0023 与技术说明里"没有中断后恢复"的说法过宽，原处已订正。
* 同一年里同一门课拆成几段不连续的时间，目前**不支持**（计划的一项只有一段起止月份）。
* 课程长度是 `completion_years × 12` 个有效参加月，`completion_years` 是正整数：**不支持短课程**，课程长度都是 12 个月的整数倍。
* 培训代表主动的额外成长投入，不包含正常履职或普通入职培训；岗位的正常工时不能重复当作额外学习。
* 当前职业信息公开策略保留（能力、学习进度与资格提示对所有观察条件公开，没有新增许可开关）。
* `qualification_missing` 保持可识别的问题代码；E1-7 把它登记为**可修改、可重试**的计划拒绝，与资料损坏、程序错误和生活出局区分
  （PLAN §3.0.1 的 E1-7 行）。
