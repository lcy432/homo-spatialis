# 0046 E3 输入体验收敛：输入目录、结构化资格答案、面板多选与去掉的板块

日期：2026-10-25。层：接入层（intake-05 收尾）。交接见 [E3C → E5](../docs/handoffs/e3c-to-e5-service.md) 第 14 节，任务原文见所有者
2026-10-25 的“E3 输入体验收敛与 E3C 最小收尾”。

## 背景

独立核查（`runs/e3c-closeout-recheck-20261025/`，本机）发现：职业只能写自然语言再靠别名猜（“我是程序员”认不出，软件开发工程师明明在
范围里）；资格页把学历、证书与经验混成一组逐题问；兴趣与口味要先写文字再选；硬要求与“品牌、菜系等属性偏好”在新流程里只留存、却仍会改变
模拟。所有者确定的方向：受控目录直接选、最高学历单选、证书多选、必要时才问经验、定和分配用饼图与滑块、兴趣与口味面板多选，E3 定义
映射与语义，E5 只呈现。

## 决定

1. **输入目录是独立的小配置**（`configs/product/input_catalog/<pack_id>.yaml`，代码 `product.input_catalog`），只引用资料包里已有的职业、
   资格与兴趣 / 菜系的键；加载时逐项核对（每个职业恰好一个主分组、全部可浏览，引用不存在就报错），不改资料包、不新增职业 / 资格 /
   活动 / 评分类别或系数。它带内容身份（配置 + 资料包身份），按目录选职业的草稿带着它；目录换了，旧选择算过期。
2. **搜索是公开规则，不是服务**（`catalog_search_nfkc_casefold_all_terms_v1`）：NFKC、casefold、去首尾空白，空格分开的词全部命中；只筛
   已发布条目，空查询给出分组的全部、顺序固定。搜索词是明确维护的数据（名称、资料包别名、目录补充的中英叫法），E5 在完整的小目录里
   筛选，服务端只认提交的编号，搜索词不保存、不进画像。
3. **职业的目录模式**：`OccupationAnswer.mode = catalog` 只提交概念编号与目录身份，不需要文字；未知编号、过期目录、目录模式带文字都拒绝，
   不替换职业。文字匹配保留为兼容路径，不是新页面的必经入口。
4. **资格用结构化答案，规则不变**：最高学历（7 项单选）、职业证书（多选，空列表 = 明确没有）、相关经验（只在选中的职业需要时问，记录
   职业与年数），由 `product.qualifications` 换成 `ConfirmedProfile.abilities`——与 E3B 编译时的 `Scope.from_confirmed`
   （`confirmed_experience_mapping_v1`）是同一条规则，测试按冻结资料逐项核对。职业、自由文字与搜索词不授予资格；未答与暂不确定不授予；
   新答案与旧的逐项资格确认同时存在而结果不同就拒绝，不取并集。
5. **兴趣与口味面板多选**：新增作答状态 `selected`（至少一个类别、不带文字），确认画像里就是 `confirmed`；跳过 = 未答；“暂不确定”“没有
   固定爱好 / 没有口味偏好”“随当地体验”仍分开保存。只用已支持的类别：川菜搜到的是“中餐”并说明本版不区分地方菜，徒步、游戏本版没有、
   不会算成健身（待办）。文字解释保留为兼容路径。
6. **新问卷不再收集硬要求与属性偏好**：新草稿两者为空；草稿里还有就阻断（旧值会改变模拟，不悄悄沿用也不悄悄丢掉）。旧草稿给迁移说明，
   用户明确同意后才清空并换成当前版本（`POST /api/v1/drafts/{id}/migrate`），之后重新审阅。E1 内部的硬要求机制、已有运行与历史结果
   不变；测试与两份样例用标明的“历史画像”受控夹具核验那套机制。
7. **版本**：共享结构 v3.4（仍导出到 `contracts/product/v3/`，`ProductMeta` 同时接受 v3.3 以读回历史对象）、问卷 v0.4-draft、词表 v5、
   转换 v3、服务 API v1.3；显示附层仍是 v2，冻结新的资源版本、旧版本保留；健康问卷、E1 协议与评分版本不变。
8. **F3 遗留**：同一份运行前说明身份的显示绑定只在第一次检查时写；确认开始前的再次核对与恢复不重绑，进度、结果与历史地图继承这次运行
   确认过的版本；绑定缺了、坏了或旧资源没了就照实缺失，不拿当前资源补。
9. **旧对象按原版本序列化**（2026-10-25 独立复核 R1 之后补上）：v3.3 的草稿、审阅与确认画像没有 v3.4 新增的字段——读回时这些字段
   只能是默认值（未答 / 空，用了 v3.4 才有的状态也拒绝），写出时照原样不写（`product_contracts._legacy_dump`）。所以旧对象的 JSON、
   内容身份、草稿指纹与显示绑定的消息摘要都与当初相同：不跳过校验、不重签、不改写旧绑定、不用最新译文替换历史解释。已经开始的旧运行
   照旧用自己保存的画像、设置、归档与显示资源恢复；旧画像仍不能直接准备新模拟。新版本的对象照常写出全部字段；公共结构的 JSON Schema 不变。

## 后果

* 去掉用户硬要求会改变新流程的模拟结果（mock 不再按 60 分钟通勤上限挑住处），不再以 22 C / 2 M 为准；按固定旧输入核对过显示修复本身
  不改生活结果。
* 旧版本的确认画像能读回，但不能直接准备新模拟（新确认必须用新问卷）；旧草稿要先迁移。
* 输入目录的分组、搜索词与经验问题是人工维护的数据，与资料包一起审阅；资料包换了要同步核对（加载时报错，不会悄悄失效）。
