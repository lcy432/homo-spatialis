# 0042 E3B：六城真实生活资料包与最小引擎适配

日期：2026-10-23（所有者批准的 E3B 范围：真实资料的补全、标准化、映射、编译与冻结；居住条件；按住处片区的安全与环境；住处—岗位—出行方式的通勤关系；有限设备故障与预先登记的替换规则；菜单、资格、标准起点、真实税与期末资料的接线）。六维加独立健康、用户权重、饮食与兴趣的评分原则、健康项、疾病、精力反馈、L/V/J、C/E/M、年度规划与修订次数、预算与归档保护都不改；不碰研究线。

## 背景

intake-02（[0040](0040-intake-02-real-data-database.md)）把六个都会区（CBSA 2023 的 MSA：纽约 35620、洛杉矶 31080、旧金山 41860、芝加哥 16980、休斯敦 26420、西雅图 42660）的公开资料冻结成机会数据库，但 E1 还跑不了它：住房只有卧室数与租金、没有面积；通勤是每处住房的一个固定分钟数；税只有合成的测试替身；整份目录都给分身看，没有菜单；设备从不坏；期末估值读的是合成样例的价格。

## 决定

1. **片区**：目录声明城市内部的片区（`CityLifeCatalog.areas`，居住 / 就业 / 两用），住房与岗位写自己所在的片区（`LifeOpportunity.area`）。片区是资料的地理单位（ACS 的 PUMA、按工作地 PUMA 合成的就业片区），不是街区或楼栋，本身不加分。
2. **地区条件按住处片区读**：评分条件可以写按片区的基础量（`CityComponentCondition.area_bases` 与依据说明），写了就**取代**城市背景 b，不在城市值上再叠一次；这个月读实际住处所在片区的值。住处没有片区、或片区不在表里，这一项这个月未知（不沿用城市值、不当 0）；只有城市级证据时各片区写同一个值，不捏造片区差异。比较组检查要求每处可得住房的片区都有值。
3. **居住条件取代居住空间**（词表 `e3a-vocabulary-v3`）：只看房子本身，z = η_空间 × 空间等级 + η_档次 × 条件档次，s = min(c, z/(z + τ))。空间等级由卧室数推断（单人：开间 1、一卧 2、两卧 3、三卧及以上 4），卧室数本身不再单独加分；条件档次是同片区同户型里的档次（1–3），是含误差的估计，所以 η_档次 = 0.5、η_空间 = 1.0；τ = 3、c = 0.9。新的合并规则 `sum_of_source_max`：每个来源只取最好的一项，不同来源相加——两处住房不叠加，空间与档次平滑互补，没有一票否决。楼型、楼层与租金都不是评分输入：只改租金不改分数，跨城的绝对租金不是质量。旧确认里的“居住空间（只看面积）”含义不同，要重新审阅。
4. **通勤是一张片区关系表，每月一份执行记录**：目录的 `CommuteRelation` 写方式的条件与月度封顶（例如开车要有在用的“用车权”，公交月票封顶）与片区之间的往返（住处片区 × 就业片区 × 方式 → 往返分钟、每次往返的花费、来源性质）。住房规格不再写通勤分钟。每个月，结算按实际住处、实际到岗的岗位与在用的功能，用 `fastest_available_v1`（可用方式里往返最少；相同取花费低的）定方式，写出唯一的 `MonthCommute`：通勤费按它付（在每月的购买之后结清，付不起是计划不可行），时间账按它记小时，交通评分读它的分钟与到岗次数（公式不变；没有到岗时 T 读住处片区的居民平时往返分钟），通勤上限读它最长的一趟往返（没有到岗是 0）。到岗岗位从住处没有可用方式是计划不可行，不当 0 分钟；片区缺失是资料错误。公交时间与开车时间各是各的格；用车权是一项按月付费的普通机会，不买就不能开车。

## 后果

- 新数值都是探索设定（参数目录 SC-26、SC-27），在看任何 mock 结果之前写定；不能据此排序真实城市。
- 合成样例两处住房都是一卧中档：z = 3，s = 0.5，与旧版本分数相同；评分规格的内容身份变了，资料包与反馈政策里钉住的身份一起更新。
- 代理看得到住房规格里的卧室数、空间等级与条件档次（房子本身的事实），看不到 η、τ、c 与分数。
- 代理看得到片区、通勤关系表（方式条件、封顶、每格的分钟、花费与来源性质）和自己每月实际的通勤（方式、分钟、次数、付的钱）；选择规则写在行动说明书里。提示模板改为 `e3b-product-prompt-v1`。
- 合成样例改成两个居住片区与一个就业中心、只有公共交通且票价为 0：分钟与旧住房规格相同，所以旧的手算值不变。
