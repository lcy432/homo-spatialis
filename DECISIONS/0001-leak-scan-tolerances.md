# 0001 泄漏扫描的两个容差必须分开

**状态**：已采纳（v0.9 迁移期）｜**落点**：`src/common/leakcheck.py`

## 决定

```
单值扫描   DEFAULT_RTOL      = 1e-3
向量指纹   FINGERPRINT_RTOL  = 4e-2
```

不得统一。

## 为什么

迁移文档 A4 只给了 `rtol ≈ 1e-3`。实测下来这个容差**抓不到整数百分数形态的泄漏**，
而按 §6.3，那正是最可能的一种：

| 权重 0.1768 的呈现 | 相对误差 | 1e-3 能抓到吗 |
|---|---|---|
| `0.1768` | 0 | 能 |
| `17.68`（两位小数百分数） | 0 | 能 |
| `17.7`（一位小数） | 1.13e-3 | **刚好越线，抓不到** |
| `18`（整数） | 1.8e-2 | **抓不到** |

§6.3 明写"人会给 10、20、30"——整数锚定是真实用户的行为，也就是散文里最可能
出现的形态。

## 为什么指纹可以用松得多的容差

证据强度不同。单个数匹配上是弱证据，容差必须紧，否则误报淹没一切然后被人关掉。
而**七个数同时匹配、且作为多重集与真值权重对上**，即使每个只匹配到百分之二，
随机文本凑出这样一组的概率可以忽略。松容差在这里不是妥协，是让指纹能抓到它
最该抓的那一类。

有一条测试固定这个性质：`test_the_loose_fingerprint_tolerance_does_not_fire_on_unrelated_numbers`。

## 反向提醒

将来任何一次"统一容差"的重构都会把这条改回去，而改回去之后扫描仍然通过、
指纹仍然报告"未发现"，只是它瞎了。这是本文件存在的全部理由。
