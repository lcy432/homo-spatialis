# 0005 `CityRecord` 校验 rpp 量级

**状态**：已采纳（v0.9 迁移期，补 MIGRATION A2 的缺口）｜**落点**：`src/econ/types.py`

## 决定

`CityRecord.__post_init__` 校验三个 rpp 分项落在 `[0.3, 3.0]`。

## 为什么

A2 要求"在 ledger 层把 RPP 归一到全美等于 1"。`src/ledger/normalization.py` 的
`normalize_rpp` 已经实现，但 **`CityRecord` 只校验键名，不校验量级**——没有任何
东西强制它被调用。

M1 接真实 BEA 数据时，谁忘了调，`ln P` 就落在 4.6 而不是 0 附近。后果是 logit
数值条件变差、系数不好解释，而且**不会报错**。100 制的值（典型 85–130）会立刻
撞上 3.0 的上界，一行断言就挡住了。

区间取 `[0.3, 3.0]` 而不是更紧：合成世界的 `ln_rent_sd = 0.20` 给出的 rpp 大约在
0.6–1.6，加上第三档难度求解器可能把某一维推到边缘，留出余量。它守的是"口径
搞错了"这种量级错误，不是"数值有点偏"。
