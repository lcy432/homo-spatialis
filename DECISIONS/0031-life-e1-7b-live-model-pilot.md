## 二、采用的规则

### 2.1 公开输入

* **税**（`agentlayer.life_planning.visible_tax_rules`）：由环境实际用的 `SyntheticTaxPolicy` 投影——状态（合成测试替身）、金额口径、地区、年度、累计预扣、
  税档，以及五句规则（应税收入只有岗位工资、同年多岗位合并、累进只对超出部分、每月预扣 = 累计应纳 − 已扣、第一步扣税然后付住房食品）。不手写另一份
  税表、不复制计税公式。运行器在每次发送前比较 `visible_tax_rules(绑定的税表) == 请求里的 tax`，不同就停下（`request_check`）。
* **行动说明书**（`action_guide`）：按协议启用的部分生成，六节：时间字段与数量、最低生活兜底、工作与学习、资金目标（set / keep / cancel / replace /
  reschedule 与 `goal_id` 关联）、生病与应急（四种治疗状态、`pause_order` 与 `cancel_purchases_when_ill` 的区别）、"钱够报价 ≠ 付了钱 ≠ 学会了 ≠
  获得服务"。示例都是局部片段，编号不存在，不是一份完整的年度计划，更不是"最好"的计划。
* **资料未知 ≠ 选择不治**：说明书写明四种情况；适配器、解析器与运行器都不把未知改成不治，也不替换计划。计划要治而遇到未知，照旧是 E1-5C 的资料缺口
  停止（模拟问题），不写成用户拒绝治疗。
* **开发者备注**：新样例的每条说明都是写给分身的话；真实模型运行在开跑前扫描城市目录与事实表（`ledger.life_run_config.developer_note_hits`），发送前
  再扫一遍最终请求的城市部分。标记词登记在 `common.life_planning_contracts.DEVELOPER_NOTE_MARKERS`。
* **最终请求的隔离检查**（`agentlayer.life_llm.final_request_problems`）：请求体只能是这份安全投影渲染的两条消息；载荷通过原有的保留键与内部对象扫描；
  没有开发者说明；不含评分与评价规格的编号、说明与内容身份、疾病事件来源的设置与指定事件说明；不含像凭证的内容。用户陈述原样作为资料出现，系统提示
  第 2 条说明它不是指令。
* **紧凑渲染**：提示里的 JSON 不缩进（只省空白，可以原样还原载荷）；样例里最大的一份请求约 49 KB。

### 2.2 真实模型规划器与传输

* `QwenPlanner(settings, transport=…, budget=…)`：身份 `llm.qwen.base_b` / `e1-7b-llm-v1` / 模型快照；`effective_spec()` 报出 `PlannerSpec(identity, llm=settings)`，
  运行器在建归档与第一次调用之前比较行为指纹（`llm` 设定去掉说明后进入行为内容）。
* 传输层可替换：真实运行用 `OpenAICompatibleTransport`（OpenAI SDK，`max_retries=0`，显式超时，`extra_body={"enable_thinking": false}`，
  `response_format={"type": "json_object"}`，`max_tokens=4096`，`temperature=0.2`）；离线测试用替身。密钥只在传输层，发送前确认请求体里没有它。
* SDK 异常换成安全字段（`classify_sdk_error`）：超时、断连、429 限流、5xx → 可重试；401 / 403 → 凭证；带欠费或额度用完错误码 → 账户；其他 4xx → 请求配置。
  原始异常不串联、不写日志。
* 输入估计：ASCII 字符 × 1 + 非 ASCII 字符 × 2 + 每条消息 16 + 请求 16（`ascii1_nonascii2_v1`）。ASCII 部分是字节级 BPE 的严格上界；汉字部分**不是**严格上界
  （罕见字可能多于 2 个 token）。它是估计，不是实际 token；超过 64,000 就在本地拒绝，不删减请求里的任何事实。实际 token 只认返回的用量，两者分开记。

### 2.3 失败与停下

| 情况 | 处置 | 计数 |
|---|---|---|
| 回复为空、不是 JSON、多个 JSON、多写结果字段、引用不存在的编号、资格不够、资源超限 | 已有的有限修订（每年 1 + 2 份候选） | 修订 |
| 回复被截断（`finish_reason` 不是 stop） | 即使能解析也不接受；按格式问题 `format_incomplete` 修订 | 修订 |
| 超时、断连、限流、服务端错误 | 同一份请求原样再发 1 次（等 5 秒）；仍失败 → 停下 `service_unavailable` | 服务重试 |
| 凭证（401/403）、账户（欠费、额度）、请求配置（其他 4xx） | 不重试，停下 `credentials` / `account` / `bad_request` | — |
| 预算不够发送下一次 | 不发送，停下 `budget` | — |
| 输入估计超过上限 | 不发送，停下 `input_limit` | — |
| 请求检查不过（税、隔离、开发者说明） | 不发送，停下 `request_check` | — |
| 返回的模型名与设定不同 | 不用这份回复，停下 `model_mismatch`（恢复时不复用这份回复） | — |
| 上一次请求只有发送记录、没有结果 | 不自动重发，停下 `uncertain_send`，预留保留 | — |
| 意外程序错误 | 沿用 E1-7A：这个分身记程序错误，批次暂停 | — |

停下的批次：进度 `status = halted` 与 `halt_kind`，正在规划的那一份候选记为待续（`pending_*`），不是任何分身的生活结果；没轮到的分身保留原名单。
恢复（`resume_run`）允许从 `halted` 继续；服务尝试次数按请求明细累计，不清零。

### 2.4 付费预算账本（`orchestration.life_budget.RoundBudget`）

* 位置由运行配置 `paid_budget.ledger_dir` 给出，在运行目录之外；头文件 `budget.json` 记额度与报价，第一次建立之后不改（配置不同就拒绝打开）。
* 每次服务请求先预留：次数 + 1；费用 = 输入估计 × 12 + 4,096 × 36（元 / 百万 token），向上取到 0.000001 元。已占用（已核算的按核算值，没核算或不确定的
  按预留值）加这次预留超过 50 元、或次数超过 150，就不发送。
* 返回之后按实际 `prompt_tokens`、`completion_tokens` 核算；没有用量保留预留并记 `uncertain`。每次预留之前重新读账，不缓存；只支持串行。
* 同一次服务尝试的键（`run_id/请求编号#s序号`）重复预留 → 按"发送状态不确定"停下。

### 2.5 归档、重放与恢复

* 运行清单新增身份：`input_files`（各用途输入文件的内容指纹，路径写法不参与）与新增关键代码（`agentlayer/life_llm.py`、`orchestration/life_budget.py`、
  `orchestration/life_archive.py`）。
* `inputs/`：第一次规划调用之前，运行读到的全部配置（运行配置、名单、生活输入、评分、事实、评价、模型角色声明）按原相对路径复制并核对内容；
  `preflight_from_snapshot` 只用这里重建运行世界（不需要密钥，不读工作区里后来改过的配置）。真实模型运行的输入必须是仓库内的相对路径。
* 服务请求明细 `provider_calls.jsonl`：每次请求发送前写 intent（完整的已检查请求、输入估计、预留），返回或失败后写 outcome（原始回复或安全的错误字段、
  实际用量、费用与状态），都立即落盘。恢复时：这份候选已有成功回复 → 直接用、不重发；只有 intent 没有 outcome → 停下 `uncertain_send`。
* 规划记录 `calls.jsonl` 每行新增 `finish_reason`、`transport_attempts`、`usage`；恢复与重放核对每份原始回复都是请求明细里那一次成功请求的原文（E1-7A
  的三项防线不变）。
* 先导用 `stop_after_commits`：提交指定个年度之后在年度边界停下（`interrupted`）；`replay_run` 对没有结束的运行只重放已提交的年份、核对绑定，不评价。

## 四、本地实现选择（prompt 没有写死，请所有者复核）

1. **输入估计规则**用"ASCII × 1、非 ASCII × 2"而不是字节数：字节数会把每份请求估成 ~6 万（汉字 3 字节），超过 64,000 的上限；本规则对 ASCII 是严格上界，
   对汉字不是。用实际返回的用量核对（第七节）。
2. **紧凑 JSON 渲染**：同一份载荷，省掉缩进的空白；不删字段。
3. **服务重试等 5 秒**、只重试一次；`model_mismatch` 恢复时不复用那份回复。
4. **停下而不是记成程序错误**：服务、预算与请求检查的问题让整个批次停下（可恢复），而不是把正在规划的分身记成程序错误——它们不说明这个分身的生活
   或计划有问题。
5. **重用 run_id 会撞账本的键**：键里含 run_id；同一本账里重用 run_id 的第一次请求按"发送状态不确定"停下（测试覆盖）。
6. **归档原子替换的有限重试**：Windows 上刚写好的临时文件可能被杀毒或索引程序短暂占用（第一次跑 E1-7A 演示时遇到 `PermissionError`），`os.replace`
   只对这个错误最多重试 8 次、每次 0.25 秒，仍失败照常抛出。
7. **新样例**（第五节）：两座资料完整的新合成城与两位新合成用户，而不是改旧样例里的"未知"。

### 8.1 F1：服务回复只能用来规划它真正对应的那一次请求

* **一份检查** `agentlayer.life_llm.service_history`：一个请求编号的全部服务记录——请求编号属于这个运行、拆得出分身 / 年份 / 候选，每条记录的这些身份
  相同；服务商、模型角色、模型快照与设定指纹等于当前设定；报价版本等于当前预算；发送意图与结果按顺序配对（结果必须有意图、上一次有结果才有下一次、
  同一次不重复、成功之后不再发、次数不超过 1 + 服务重试）；每次意图的请求正文**逐字节等于**这份候选按当前设定渲染出的请求体（渲染函数只有一份
  `expected_provider_body`）；输入估计与正文相符；成功的结果有原文与返回模型，失败的结果有错误种类。结论：可用的回复（返回模型 = 设定）、被拒的回复
  （返回模型不同）、发送不确定的尝试，或问题清单。
* **谁调用它**：规划器在缓存命中前与每次新回复写进明细之后（同一份判断决定能不能用）；恢复与重放共用的归档核对 `load_archive_records`——每份规划记录
  按它存下的载荷重新渲染请求体比较；**还没有规划记录的服务历史**（回复已落盘、规划记录还没写；发送不确定；服务失败或被拒而停下）只在允许中断时存在、
  最多一份，请求正文里取回的载荷必须就是这份候选。
* **服务成功 ≠ 可以用来规划**：结果记录新增 `usable_for_planning`；返回模型不同的回复原文、模型名、用量与费用都保留，首次运行、缓存与恢复都停在
  `model_mismatch`（不重试、不换模型、不新增年度）。
* **对不上就在写任何东西之前拒绝**：归档核对在恢复构造运行器之前；缓存命中时与重建请求不一致，运行器把 `ServiceRecordMismatchError` 变成
  `RunRefusedError`，不写调用记录、不执行生活（以前会被当成规划器异常写进记录）。
* 这是工程一致性检查，不防有人把全部记录与指纹一起重写的伪造。

### 8.2 F2：实际预算就是声明的那一本，花过的钱不能从账上消失

* **身份**（`orchestration.life_budget.budget_identity_problems`，开跑与恢复在第一次调用之前）：规划器实际持有的预算的请求次数上限、费用上限、报价全文、
  **解析后的账本绝对路径**与磁盘上的头文件都等于运行声明；不只比名字或报价版本。
* **历史**（`ledger_history_problems`，恢复之前）：按"运行 / 请求编号 / 服务尝试"的完整键核对本运行的服务明细与共享账本：每次发送意图都有预留（运行、
  请求、序号、输入估计、预留金额、报价版本相同），每个结果都有核算（有用量的 settle 用量与金额相同；没有用量的 uncertain 等于预留）；缺预留、缺核算、
  金额矛盾 → 拒绝恢复，不当作空白预算、不猜测补回。共享账本里其他运行的条目照常存在、不删除；额度仍按整本账算。
* **只读对账**（`read_ledger`、运行器的 `budget_reconciliation`）：不创建、不写账本；驱动脚本的 `replay` 把"生活重放"与"付费对账"分开报告。
* 仍只支持串行；不是供应商级账单上限。

### 8.3 合法中断的处理（按实际的写盘顺序：预留 → 发送意图 → 发送 → 核算 → 结果 → 规划记录 → 检查记录 → 年度执行）

| 停在哪里 | 磁盘上有什么 | 恢复时 |
|---|---|---|
| 已预留，发送意图还没落盘 | 账本预留；明细里没有这次尝试 | **确定没有发出**：沿用那份预留继续（不重复预留、不重复计数） |
| 已写发送意图，没有可靠回复 | 预留 + 意图 | 可能已发出、结果不明：停下 `uncertain_send`，预留保留，等所有者 |
| 费用已核算，回复没落盘 | 预留 + 核算 + 意图 | 发出过、回复丢了：停下 `uncertain_send`，已核算的费用保留，等所有者 |
| 合法回复已落盘，规划记录还没写 | + 结果（可用） | 一致性检查通过就零新增请求复用，只执行一次 |
| 被拒回复已落盘 | + 结果（`usable_for_planning = false`） | 停下 `model_mismatch`，不重试、不换模型，等所有者 |
| 服务失败、次数用完 | 结果（错误） | 停下；服务尝试次数按明细累计，不清零 |
| 规划记录已写，检查或年度执行还没完成 | 规划记录（+ 检查记录） | E1-7A 已有规则：用原响应重新检查、执行，与归档比较 |
| 归档对不上（正文、设定、所属分身、缺意图、重复、别的运行的记录、缺费用历史、错账本） | — | 在写任何东西之前拒绝，原文件不变 |
