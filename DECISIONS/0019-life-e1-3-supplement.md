## 一、与 ADR0018 的关系

核心函数不变：分项仍是 z = b + Σηx、s = min(c, z/(z+τ))，物质维线性加权、月度七维加权、十二个月
都可评分才有年均；缺失传播、出局状态、硬要求语义与信息隔离都不变。本记录**新增**的规则只在新评分
版本里启用：

| 新规则 | 在哪里启用 | 旧版本 |
|---|---|---|
| 持有服务数量由结算写出、评分直接读取 | 所有新写出的记录 | 旧评分版本读旧记录时保留顺序推断（第二节） |
| 功能来源（`functions` 过滤、`present` 取值） | 只在评分规格用到时 | 旧规格不用，行为不变 |
| 自然景观加分 | 环境分项声明了 `landscape` 才启用 | 旧规格没有，环境照旧 |
| 方案级通勤 | 通勤分项声明了 `plan_commute` 才启用 | 旧规格照旧用城市基础 |
| 比较组与覆盖报告 | 评分配置声明了比较组 | 旧配置没有，照旧可运行 |

"固定的是人的偏好，而不是替他固定消费结果"：同一个人的权重与起点对齐规则跨城不变，价格、机会和
历史状态可以改变实际安排；不把跨城的实际选择当成独立同分布，也不用固定消费份额替代理人做决定。

## 二、持有服务数量直接记录

`HoldingService.quantity` 由结算写出（每条持有服务记录的数量就是那件持有物的数量），评分直接读取。
**新记录不再依赖"年初持有在前、本年新买在后"去猜数量**：同一机会跨年续购、到期后再买、记录顺序被
重排，都不影响评分。寿命按月、跨年延续、当年/次年生效、到期移除、可配置 N 全部保留。

**旧记录兼容。** 本轮之前写出的结果没有这个字段（`quantity` 为空）：

* 只有旧评分版本 `e1-3-explore-v1` 接受这种记录，沿用 ADR0018 的推断（信息来源：年初状态的数量 +
  本年成交数量 + 结算写出顺序）；对不上就报错，**不默认为 1**。评分结果写明 `holding_quantity_source`。
* 新评分版本拒绝缺数量的记录，提示重新结算或改用旧版本；部分有、部分没有的记录一律拒绝。
* 历史输出不回写。

## 三、功能、方案属性与城市报价

| 层 | 例子 | 在哪里 |
|---|---|---|
| 需求功能 | 居住、饮食、通信、工作设备、洗衣、储物、工作空间 | `LifeOpportunity.functions`（词表在生活输入里声明） |
| 方案属性 | 品牌、档次、菜系、准备方式 | `LifeOpportunity.attributes`：**只存储，本轮不评价** |
| 城市供给 | 当地报价、资格、可得性 | 已有的 `price`、`eligibility`、`availability`、`source` |
| 个人偏好 | 各评分叶子的权重 | 研究真值或用户明确给出的点数 |

**计分规则（复用 any/max/sum）：**

* **存在型功能用 `any`**：通信、工作设备、洗衣、工作空间各是一个评分叶子；这个月有一件在用的、声明了
  该功能的物品，就满足一次。第二部手机、更贵的手机都不再加分。
* **容量型功能只按声明的数量语义相加**：只有读取明确容量规格（如储物 `storage_liters`）的来源才可以
  `sum`；两个柜子＝容量加倍，收益照样递减。
* **不能按件刷分**：用功能过滤、只取"存在"（`present`）或数量的来源，不允许 `sum`——加载时就拒绝。
  没声明功能的物品不是任何来源（例如装饰小玩意），报告会列为"在用但没带来计入的改善"。
* **功能分类不自动拆偏好**：原来的 `durables` 叶子在新样例里拆成通信/工作设备/洗衣/储物，新样例为每个
  叶子**明确给了点数**；不把旧权重均分，也不按价格分配。旧样例保留原叶子不动。
* **住房**：评分用面积；独占、基本设施、房间数作为结构化事实，供最低生活声明与硬要求检验；不做购房融资。
* **食品**：鲜食分（每周新鲜餐数）；准备方式是属性、准备时间是时间事实——**不另给一份"省时幸福"**，
  时间约束留 E1-4。
* **工作空间**：住宅工作间与外部工位互为替代（any）；新样例不设城市基础值——没有依据时不虚构免费的
  私人办公室。
* **便利服务**（如保洁）：只记录功能与时间事实；对应需求本轮没有评分分项，列入"未支持的需求"。
* **属性未启用**：在用物品带有属性时，评分结果列出"已记录、未评价"的属性；**不从高价格推断高品质
  偏好**，不写死品牌×国家的价格规律。品牌/菜系/档次匹配在 V2 裁决。

价格从不进入评分：同样的实际功能条件，标价更高不会得分更高；预算差异由结算产生。

## 四、来源类型

`SourceRecord.kind` 扩为四类：

| kind | 要求 |
|---|---|
| `observed` | 直接观测，必须带 `provenance`；不能写换算规则 |
| `derived` | 可审计派生（确定性换算）：必须列出输入 `inputs` 与规则 `rule`，能据此重算 |
| `estimated` | 统计估计：必须列出输入与方法（`rule`） |
| `synthetic` | 合成设定：必须写 `synthetic_note`，不能带观测溯源 |

有网址不等于实测：派生与估计结果不能标成 `observed`。检查挡得住"缺输入、缺规则、合成冒充观测"，
挡不住"把别城数字抄来并标成同类来源"——那要靠 `inputs`/`rule` 的人工审计，这一点写明。

## 五、比较组：共同粒度

评分配置可以声明一个比较组：城市清单、地理粒度、时间基准（币种、基年）、行动类型、规格键与单位、
允许的来源类型、通勤粒度、评分版本。加载检查：

* 组内每座城的目录用同一币种与基年（不混币，不重复空间平减）；
* 组内目录项目与评分条件的来源都用声明的地理粒度、属于允许的来源类型——**不能某城细化、某城用别的
  粒度或默认值填**；
* 每座城对每类声明的行动都要有明确记录：可得、确定不可得、或未知。**真正不可得是合法事实**（例如这座
  城确实没有共享办公），不要求每城机会数量相同；完全没有声明则报错；
* 评分规格用到的规格键都在单位表里；
* 通勤粒度：`plan_level` 要求全组每个可得的合格住房都写明往返分钟、每份可得工作都写明工作方式，否则
  拒绝；`background` 则通勤只用城市背景，不读住房分钟。

## 六、覆盖报告（只报告，不解锁）

覆盖算到偏好叶子：非物质维的叶子权重 a = w_k；物质细项 a = w_material × m_j。J 是全部候选城市都
支持的叶子（评分规格有分项、且每座城的条件都已知；景观启用时还要景观数据已知），

    C_i = Σ_{ℓ∈J} a_iℓ

报告逐叶子写出：支持 / 某城未知 / 没有评分分项，证据类别（直接观测或派生、估计、仅合成），是否有
行动改善机制（背景已知不代表行动效果也建模了），以及受影响的需求。全部输入都是合成时标为"合成契约
覆盖"，不说真实覆盖率。

**不新增任何百分比阈值**：50% 或其他比例都不解锁完整总分；正权重未知时总分照旧为空，不补零、不按城
重加权。账务资料与硬要求单独检查，不被覆盖比例豁免。有限区间与排名属于 E1-6。

## 七、自然景观与户外环境加分

所有者已确定：自然景观/户外环境吸引力进入环境维；购物、历史古迹等旅游吸引力不混入。

    S_env = min(c_env, S_physical + β × A_nature)

* `S_physical`：显式合成的基础环境，按原规则 b/(b+τ) 得到（不声称已接真实空气、气候）；
* `A_nature` ∈ [0, 1]：共同定义的自然景观指标，必须有来源或显式合成说明；不按城市名、游客数或收入猜；
* β：评分规格里声明、全组共用、非负、上限 0.5（探索上限）；演示 0.1，β = 0 是关闭对照；
* β > 0 时，每座城都必须写明景观数据（已知或未知）——缺失不当零；景观未知 → 环境分项未知；基础环境
  未知 → 不被景观加分补成已知；
* 城市条件若声明基础环境**已经包含**同一景观，再启用 β > 0 是重复计分，加载时拒绝；
* 输出保留基础分、景观贡献（β、A、来源类型）与是否截顶。

## 八、简化的租金—通勤组合

不做地图。少量显式住房方案把住房条件、月租与**每工作日往返分钟**作为同一方案的事实（规格键在评分
规格里声明）。允许"远一点、便宜一点"，不要求所有城市存在统一斜率。

    S_commute(T) = τ_T / (τ_T + T)，T ≥ 0 为往返分钟，τ_T 全组共用（演示 60）

* T 从这个月**实际住的**住房读取（含兜底降级那一处），不从计划或理由读；远处租金不能配近处通勤；
  降级时住房、服务月份与通勤一起切换。
* 还要核对这个月**实际执行的线下工作**：恰好一份已执行、工作方式为固定线下（`onsite`）的工作，才评通勤。

> ⚠ 本条已被 DECISIONS/0024 推翻（只在评分版本 `e1-5a-growth-transport-v1`：广义交通按实际住房往返分钟与资源账的到岗次数评分，无工作、远程、混合、多岗位都能评；本版本 `e1-3-supplement-v1` 照旧），见该记录。
  无工作、远程、多岗位、工作方式没写、住房分钟没写——都报"方案级通勤评分不支持/信息不足"（分项未知），
  不给最高分，也不照扣通勤分；正权重时该月总分不完整。
* 长通勤降分（映射单调递减），它是对实际条件的映射，不是把分钟当作正改善叠加在旧城市分上。
* 住房不自动改善安全或室外环境。
* 比较组的通勤粒度统一：全组方案级检查通过才启用；否则全组用背景级。
* 乘工作日数变成月度时间占用、远程比例、与其他活动竞争时间——留 E1-4；本轮只记录事实与单位，不宣称
  完整生活可行，也不把同一通勤负担在两个分项里重复扣。

## 九、其他维度与登记（不实现）

* 安全：统一城市背景，不造"房租买安全"系数。
* 医疗：背景 + 情景设计；E1-5 再做年龄与相对工作精力强度相关的无病/小病/大病情景（时间单位、历史窗口、
  初始条件、病程/费用/工作中断与恢复规则、配对随机数），本轮不建疾病执行器。
* 机会：E1-5 实现培训 → 完成 → 资格 → 岗位申请/获得 → 收入与工时；资格不暗含必然录用或涨薪。
* 休闲：V1 抽象易得性与实际使用；E1-4 管时间；V2 做爱好占比与城市匹配。
* V2：品牌/菜系/档次/细商品、多国真实资料、爱好—地理、更细的寿命/维修/故障/替换/二手/折旧；已有按月
  寿命保留，E1-6 的期末现金/物品评价按原阶段推进。

**实施时的选择（前文没写死、这里补明）：**

1. 方案级通勤多了一条加载检查：住房的往返分钟键不能被列成可选安排（`arrangement_options`）——分钟是住房方案的事实，能单独选就是"远处租金配近处通勤"的拆配。
2. 城市的通勤条件写成 `unknown` 时，方案级通勤报"城市条件未知"（与其他分项一致），不报"不支持"。
3. 覆盖报告对方案级通勤的叶子加注：城市资料齐全不等于每个人的安排都能评（远程、无工作的月份仍报不支持）。
4. β = 0 对照不另存一份配置：演示从主配置派生（只改 β 与规格 ID，城市条件的 spec_id 跟着改），派生结果原样存进运行目录。
5. E1-2 的结算规则不允许在还持有同一件持续物品时再买一批（不同剩余期限不叠成一件）。所以"同一年里同一机会、旧的与新的数量不同"只出现在年付服务到期后续买；数量与重排的测试用年卡续购（1 张 → 2 张），持续物品的续购测试放在旧的那批到期之后的年份。本轮没有改这条结算规则。

**仍然开放：** `score_mapping` 与 `material_preference_aggregation` 仍是 undecided，协议 `scoring_ready = false`；β、τ_T、A_nature 与各项 b、η、c 都是合成探索设定。剩余现金本轮不计分（期末价值属 E1-6），所以租金—通勤取舍在分数上偏向近处——这是省略，不是结论（2026-10-08 订正了这句的说法，见第十二节第 6 条）。E1-4（时间占用、远程比例、家务与省时）、E1-5（疾病情景、培训—资格—岗位）与 V2（品牌/菜系/档次、爱好—地理、更细的物品生命周期）只登记，没有实现。

## 十二、2026-10-08 订正：覆盖追踪实际资料、单位、数量语义与信息隔离

**起因。** 独立审核（`runs/2026-10-07-e1-3s-review/`）用 7 条边界反例复现了四类缺口：覆盖报告只核对评分
条件有没有声明（F1）；单位表只查字段在不在（F2）；存在型功能可以经 max + 数量按同批件数刷分（F3）；
内部参数原样序列化成字典后能混进机会属性、通过观察入口（F4）。默认合法样例没有触发任何一条。本节是
对第三、五、六节与信息隔离边界的订正，所有者经
[边界修复 prompt](../docs/design/prompts/2026-10-08-e1-3s-boundary-fixes.md) 授权。

**适用范围与版本。** 只在非 ADR0018 版本里启用（契约里的 `ADR0018_SCORING_VERSIONS = {e1-3-explore-v1}`
照旧按原规则运行，单位是说明文字、来源可以不声明数量语义）。评分版本仍是 `e1-3-supplement-v1`：
修复只收紧检查，默认合法样例的结算账目、逐月评分、β = 0 对照与可行性探查和 2026-10-07 演示逐字节
相同；两份新协议配置做了**显式迁移**（只补元数据，数值改动 0 处，见
`runs/2026-10-08-e1-3s-boundary-fixes/config_migration_diff.json`）。迁移前的配置在新代码下会被拒绝——
那是有意的：不能把旧资料默认为已经核查过。覆盖报告的版本从 coverage-v1 升到 coverage-v2。

### 1. 功能供给声明（F1）

每座城对比较组评分要用的每项需求功能写 `function_supply`：`available`（目录里至少一项**可得**的机会
声明了这项功能）、`unavailable`（确定没有；目录里不能有可得或资料未知的同功能条目）、`unknown`
（资料未知或未完成采集）。加载检查与目录交叉核对；比较组检查要求评分用到的功能每城都有声明——
**目录里没有记录不等于确定没有**。评分时，按功能过滤的来源若供给没被确认（unknown 或根本没声明），
而这个月又没有在用的物品，这一项报未知，不给确定的 0。三种"没有"因此分开：

| 情形 | 评分 | 覆盖 |
|---|---|---|
| 有可得方案、只是没买 | 确定的 0（没有新增收益） | 资料齐全 |
| 确定不可得 | 按规则评价，确定的 0 | 资料齐全 |
| 资料未知 / 没声明 | 未知（不当零）；没声明时比较组在入口拒绝 | 资料缺口 |

any 替代的语义保留：一个替代方案的供给资料有缺口时，实际安排用了另一个资料完整的替代，这个月照样可评。

### 2. 覆盖报告 coverage-v2（F1）

逐叶子分三层报告：**规则覆盖**（规格有没有这项分项）、**城市资料覆盖**（每座城是否提供了规则真正读到的
事实：候选机会的规格键、功能供给、景观指标、住房往返分钟与工作方式、城市评分条件本身）、**实际行动
可评分性**（方案级通勤只评恰好一份线下工作的月份）。候选怎样认、规格怎样读，与评分器共用
`econ.life_scoring.source_candidate` / `source_reading`，不各自维护。一个无关字段缺失不影响别的叶子。

来源分两类报告：**生活事实**（目录、供给声明、景观、住房与工作）与**评分映射参数**（城市评分条件的 b、
c、η）。标签按两者合起来的证据：只要依赖里还有合成设定就不是 data_coverage——参数是估计，不会让合成的
住房、商品或通勤资料变成真实资料。只有城市背景的维度，背景值 b 与参数 c 同记在一条评分条件里，来源只能
一起报（拆开属于 E1-7 前的"城市可见事实与隐藏评分参数分开"任务）。

照旧只报告：不设阈值，不解锁正权重未知的总分，不逐城重新加权。旧的 coverage-v1 报告仍能读进来，但标为
`catalog_facts_checked = False`，它的 data_coverage 不代表生活资料齐全。

### 3. 单位约定（F2）

`common/life_units.py` 登记本轮用到的少量规范单位与明确别名（平方英尺、百平方英尺、升、百升、分钟、
餐/周、次/月、是/否、有/无、类别、指数；另登记立方英尺、小时，好把冲突叫出名字）。不是通用换算系统，
不按字段名猜单位，不做货币换算。

* **资料单位 = 读取单位**：比较组单位表里的单位必须与读这个键的来源是同一个规范单位。评分器从不换算
  原始资料；资料若是别的单位，先在整理时按可审计规则换算，并把来源标为 `derived`（写明输入与规则）。
  只改标签不改数值、未登记的写法、空单位，一律拒绝。
* **读取单位 → 分项单位**：同量纲才行，换算系数写进来源表（1 平方英尺 = 0.01 百平方英尺）；η 仍是
  "换算 × 效率"，含义不变。
* **锚点同单位**：方案级通勤的 τ 与往返分钟必须是同一个单位（S = τ/(τ+T) 不做换算）。

### 4. 数量语义（F3）

每个来源声明 `measure`：`presence`（有没有：取"存在"或规格是/否，件数不进入，分项只能 any 或 max）、
`capacity`（规格容量 × 件数，必须 per_unit，sum 或 max）、`level`（一项的规格水平，只能 max）、`count`
（一次体验算一次，只能 sum，只读一次体验）。按功能过滤的来源只能是 presence 或 capacity，且必须与生活
输入里 `function_kinds` 对这项功能的声明一致。由此堵住的等价绕过：max + 数量、同批多件、分批多件、换一种
商品、去掉功能过滤改按类别数件、给存在型功能编一个容量规格。容量型的合法收益保留（1/2/3 个 200 升柜子
→ 0.5 / 0.667 / 0.75）；旧版本的"按件数相加"只在旧版本里。

### 5. 信息隔离（F4）

两道检查，在**正式加载**（机会的规格、属性、安排项）、**可见投影**与**最终 payload** 三处都做：
`RESERVED_SCORING_KEYS`（beta、tau、η、a_nature、minutes_key 等明显属于评分参数的键名；不收"定义""单位"
这类通用词，也不收可见对象自己的字段名——有测试盯着两边不重叠），以及"原样序列化的内部评分对象"结构
检查（取字典里与某个内部类型字段同名的部分，必填字段齐全且能原样校验成该类型就拒绝，混在别的正常属性
里也认得出）。扫描的内部类型清单与结构检查共用 `internal_scoring_models()` 一份。

**防护边界**：这是对已知内部类型、保留键名与它们原样序列化结构的检查，不是对任意改名或自然语言隐写
的通用检测器，不作这种承诺；主防线仍是逐字段白名单构造。CityScoringConditions 不放开，"城市可见事实与
隐藏评分参数分开"仍登记为 E1-7 前的架构任务。

### 6. 保留的设计选择与一处说法订正

* 功能叶子拆分（通信、工作设备、洗衣、储物）与样例点数保留；点数只来自样例设定或用户明确输入，不推广成
  真实用户默认值，不平分旧耐用品权重，不按价格分配。
* 合成演示参数（η、τ、β、景观指标、上限）原样保留。"有功能时得 0.75"是这组参数的演示结果，不是现实
  需求满足比例，也不是硬编码常数；标定与敏感性验证属后续任务。
* 方案级通勤 τ_T/(τ_T+T) 保留，不加城市背景上限（值本身在 0–1，T = 0 是该指标的最好端点）；plan_level
  条件照旧不带 b、c、η。零分钟只在已支持的线下工作安排里按公式评价；无工作、远程、多岗位仍报不支持/信息
  不足。兼职与全职的工作日数、远程比例与时间占用留 E1-4。
* 两条规则保留并有回归测试：住房往返分钟不能列成可选安排（防拆配）；"城市资料未知"与"实际安排不受支持"
  分别报原因，都不伪装成零通勤或最高分。
* **说法订正**（第十一节"仍然开放"那句）：应写成"在其他实际消费相同、节省的现金留存到期末的当前演示中，
  节省部分尚未获得期末评价，因此分数只体现通勤劣势"。不是"省钱永远不能提高满足感"：省下的钱若用于其他
  可评分的实际服务，收益已经经那些服务体现，不再给现金节约另加一次分；留存现金的未来价值由 E1-5/E1-6 处理。
