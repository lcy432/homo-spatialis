## 一、已确认的原则（项目所有者，2026-10）

1. V1 美国国内、固定城市、三个年度周期。
2. 同一用户在各城有多个分身；**LLM 选择生活行动，环境执行、算账与评分**。
3. 主排序来自同一用户在同城的分身平均三年得分。
4. 保留七维：material、safety、healthcare、opportunity、leisure、environment、commute
   （唯一定义仍是 `worlds.dimensions`）。
5. 物质维内部增加消费偏好（住房空间、鲜食与便利食品、准备时间、耐用品……），区分
   **软偏好、硬要求与可接受替代**。
6. 核心机制是经济生活、七维满足感、时间与精力：时间是固定年度资源；精力是独立的
   活动负担约束；满足感对精力的影响有上限、滞后到下一年、并可关闭作对照；满足感来自
   实际体验、改善收益递减、各城统一尺度。
7. 经济生活含工作、消费、储蓄、培训与职业发展。余额、物品、技能、职业、目标、精力
   与有限经历跨年延续。
8. 储蓄通过未来用途产生价值；风险另有明确场景；**一次体验与持续服务必须区分**。
9. 价格、质量、可得性可以因城而异。**个人偏好稳定，实际消费安排可以变化。**
10. 现在就考虑多国家接口；真实多国数据、全面商品与品牌目录放 V2。
11. 旧静态经济核与研究协议保留。新生活模型用独立的协议标识，**不借用**旧 ln V、美元
    福利或 P8 精度结论。
12. 打听、迁移、访谈、复杂社交、最终评议 LLM 不在本轮。

**这些是方向，不是参数。** 折现率、评分曲线、精力系数、风险过程与终值算法都没有定
（第六节）。

## 二、数据、行动、状态与信息边界

### 2.1 六类对象

| 对象 | 类型 | 谁能看 |
|---|---|---|
| 用户陈述 | `StatedLifeProfile`：七维问卷分（定和 100）、软偏好（序数原话）、硬要求与替代、可选文字 | 按 `ObservationPermission` **逐项**决定 |
| 偏好真值 | `InternalPreferenceTruth`：七维权重、物质维内部细权重 | **永不可见**（评分侧） |
| 城市生活机会 | `CityLifeCatalog` / `LifeOpportunity`：稳定 ID、类别、规格、单位、质量、报价与计费周期、时间、精力负担、资格、生效与期限、可得三态、来源 | 可见（溯源与状态影响标签除外） |
| 个人年度状态 | `PersonYearState`：城市、年度、职业、现金、持有物与剩余期限、技能、时间预算、精力、目标、有限经历 | **整体不可见**；由视图逐字段投影 |
| 年度行动 | `YearAction`：引用已有机会 ID、数量、安排；可写理由 | 代理产出 |
| 结果与评分 | `EnvironmentOutcome`（实际）/ `VisibleFeedback`（可见事实）/ `InternalYearScore`（内部） | 只有 `VisibleFeedback` 可见 |

**陈述与真值是两个独立的顶层对象。** 放进同一个对象，任何一次粗心的序列化都会把
真值一起带出去。

**偏好 vs 安排。** 偏好是人的稳定属性；实际消费安排是行动，可以因城而异。旧协议的
硬规则 9（支出份额是人的字段、不随城市变）管的是旧 Cobb-Douglas 份额，**与此不冲突**：
新模型不用支出份额代替全部偏好，也不要求动态消费比例跨城固定。

### 2.2 行动的边界

- 只能引用目录里**已有**的机会 ID；安排的键与值必须在该机会声明的
  `arrangement_options` 之内（白名单）。
- **代理不能填写结果**：工资、满足感、技能提升、执行成功、余额变化等键在契约层就被
  拒绝（`RESERVED_OUTCOME_KEYS`），顶层多余字段也被拒绝。
- **理由不参与数值结算**：`YearAction.settlement_view()` 不含理由；只改理由文字，结算
  输入一字不变（有测试）。
- 请求确定缺货或数据未知的机会，结构上合法、执行时会失败；失败怎么处理是未定政策
  `failure_handling`。

### 2.3 信息边界（`agentlayer.life_views`）

**主机制是白名单构造。** `build_observation` 从显式许可出发，逐字段**复制**允许的
内容进新的 `AgentObservation`；从不整体序列化 `PersonYearState`、`EnvironmentOutcome`，
也不接受旧 `Persona` 或 `InternalPreferenceTruth`（类型检查，传错即拒）。

第二道防线 `assert_payload_clean` 扫旧答案类型（`econ.types.ANSWER_SIDE_TYPES`）、新的
内部类型与一组内部键名，嵌套到底；序列化后再扫一遍键名。**新对象安全靠的是只由列出的
字段构成，不靠"没在旧黑名单里"。**

`ObservationPermission` **每个字段都没有默认值**，`build_observation` 的 `permission`
也没有。未声明许可就构造不出观察，更不会默认落到最宽松的模式。两种信息条件：

| 条件 | 含义 | 约束 |
|---|---|---|
| `product_stated_profile` | 产品：可以告诉代理用户自己填的问卷 | 只放行许可的项，不放行整个人设 |
| `research_text_only` | 研究：从文字理解隐藏偏好 | **不得**同时给问卷分数或结构化软偏好（构造即拒） |

**一条语义边界。** 若将来可见精力受"由真实偏好导出的满足感"影响，让代理看到精力就是
一条**间接偏好反馈**——它能从"这样过一年精力变了多少"倒推自己在乎什么。所以显示精力的
观察带 `dynamic_feedback_channel = true`，**动态生活反馈实验与原静态文字理解实验不能标成
同一种信息条件**。

### 2.4 金额与跨国边界

- **实际报价与价格指数是两个类型。** `PriceQuote` 是可付的钱；`PriceIndex` 是无量纲相对
  水平，没有金额，不能当付款单价（塞进报价字段即拒）。
- **不用 `USD_2024_US100` 装当地标价**：那是 RPP 空间平减口径。生活协议的本地金额口径是
  `<币种>_<基年>_LOCAL`（`MoneyBasis`），平减口径在契约层被明确拒绝。
- 同一本账只能有一种口径：目录内报价、分身现金、结果现金流各自校验；跨口径的 `Money`
  运算沿用旧 `NumeraireMismatchError`。**不实现**自动汇率或 PPP。
- 城市身份是完整的 国家/地理体系/代码。样例里美国与虚构国家 ZZ 各有一个 `A01`，按完整
  身份区分，不撞号。
- **A/B/C 是对一次比较集合的判断**，不挂在商品或目录上（有测试）。
- 缺数据（`unknown`）不等于缺货（`unavailable`），二者都不补成零价；确定缺货的记录保留，
  不删。
- 物质维的数据支持逐项声明（`MaterialNeedCoverage`：supported / partial / unsupported）；
  有 goods 总指数**不**等于物质维全部被支持。

## 三、内部年度流程（设计，**未实现**）

与 README §8.2 一致；本轮只定义各环节的数据形状。

```
当年城市目录 + 上年实际状态 (PersonYearState)
  → 按许可投影可见观察 (AgentObservation)
  → LLM 给出行动 (YearAction)
  → 契约校验 + 目录交叉校验
  → 环境执行与算账 (EnvironmentOutcome)          ← E1-2（已实现，按月记账，见 0017）
  → 内部年度评分 (InternalYearScore)              ← E1-3/E1-4
  → 可见事实反馈 (VisibleFeedback)
  → 下一年状态 (PersonYearState, year_index + 1)
三个年度之后 → 单分身三年分数 → 同城分身平均       ← E1-6
```

## 四、旧静态协议与新生活协议

| | 旧静态协议 | 新生活协议 |
|---|---|---|
| 身份 | `econ` 的 ln V、`WelfareLevel`、`GroundTruth`、P8/P9/P10 | `PROTOCOL_FAMILY = "life_simulation"` + `LifeProtocol` 版本组 |
| 人 | `Persona` / `PersonaParams`（Cobb-Douglas 指数） | `StatedLifeProfile` / `InternalPreferenceTruth` |
| 金额 | `USD_2024_US100`（空间平减） | `<币种>_<基年>_LOCAL`（当地标价） |
| 评分 | ln V、美元等价变差 | `InternalYearScore`（映射未定） |
| 状态 | 原样保留，继续服务真值参照、合成自检与研究对照 | 本轮新增，**不复用**旧语义 |

复用的只有身份与计价的基础类型（`CityId`、`OccupationId`、`Jurisdiction`、`Money`、
`Provenance`）与七维定义。`common.life_contracts` 对 `worlds` 的唯一依赖是零 import 的
常量叶模块 `worlds.dimensions`，测试确认不会带进 M3 生成器。

**旧答案隔离照常有效。** 本轮没有修改 `src/econ/`；新视图在第二道防线里同时拦截旧答案
类型。

## 六、尚待确定的数学政策与建议

**以下"建议"不是已采纳的默认值。** 样例里出现的任何数值都标着
`synthetic_fixture_only`，不得当科学默认值使用。每条政策在 `LifeProtocol.math_policies`
里有一个槽位，定下时必须写 `decision_ref`；八条全定且协议改为 `formal` 之前，
`scoring_ready` 恒为 `false`。

| 政策 | 建议方案 | 主要取舍 | 定于 |
|---|---|---|---|
| `score_mapping` 评分映射 | 每维满足感 `s_k ∈ [0,1]`，由实际体验经**跨城共用**的凹形饱和函数得到（锚点只定一次）；年度分 `u_t = Σ_k w_k s_k`，`w` 取内部真值 | 有界、可解释、改善收益递减；但与旧模型的 Cobb-Douglas（对数）替代结构不同，跨维替代更容易——须明说"新分数不等于旧 ln V" | E1-3 |
| `material_preference_aggregation` 物质细偏好聚合 | 物质满足 `= Σ_n m_n s_n`；**硬要求作可行性约束**（未满足即记为该需求失败，先不折成数值罚分），替代按声明条件判定满足；`unsupported` 的需求不计分并**显式报告**重新归一化 | 归一化会抬高其余需求的分量；字典序硬约束比罚分更透明但不连续 | E1-3 |
| `energy_feedback` 精力反馈 | 可行性：所选项目的 `energy_burden` 之和 ≤ 当年精力（2026-10-07：可行性部分由 [0020](0020-life-monthly-time-energy.md) 改为**按月**——每月实际活动负担 ≤ 每月额度，新协议才用；反馈部分仍未定，归 E1-4B）；反馈：`E_{t+1} = E_base + clip(β·(S_t − S_ref), −cap, +cap)`，滞后一年，`β = 0` 即关闭对照 | 打开后引入间接偏好反馈通道（须标信息条件）；`β`、`cap` 没有经验锚点，只能做敏感性 | E1-4 |
| `income_payment_timing` 收付时序 | （⚠ 已被 0017 推翻）年度离散结算：一次性购买在执行时以**年初现金**检查流动性；周期费用按年内次数计；收入与费用年内轧差；税沿用 `econ` 现有税函数（经济公式只一份） | 年末一次入账会让第一年低现金分身买不起任何一次性物品；年内轧差更现实但掩盖月内现金流 | E1-2 |
| `risk_scenarios` 风险场景 | V1 首个闭环**默认确定性**；随后加一类显式、带种子的场景（如失业或医疗支出冲击），同一分身序号在各城共用随机数，使城际差异来自城市而非运气 | 确定性会低估储蓄的保险价值；随机性要求更多分身才能稳定平均 | E1-5 |
| `discounting` 折现 | V1 不折现（`δ = 1`），`δ` 作为声明参数做敏感性 | 三年期内折现影响小于其他不确定性；与终值一起决定储蓄是否被奖励 | E1-6 |
| `terminal_value` 期末价值 | 储蓄经"未来用途"计值：期末现金与持续物品残值折成一个名义未来年的消费，再用**同一评分映射**换成分数单位；残值规则另定（直线或零） | 零终值会奖励花光；直接加美元违反量纲；残值规则带入折旧假设；要防止同一笔财富既在花出时计分又在期末计分 | E1-6（依赖 E1-3） |
| `failure_handling` 失败处理 | 格式不合法：一次有限重试（带错误信息），仍失败则执行声明的"无新增自主行动"并记录；资金/时间/精力/资格不足：按声明的优先级部分执行（住房 → 食品 → 工作 → 其他）并逐项记录拒绝原因（⚠ 这一句已被 0017 推翻）；缺货与未知：拒绝并说明。**失败计入分母，不丢弃分身** | 优先级本身是价值判断；默认动作可能使结果偏向被动 | E1-2 |

> ⚠ 上表两处已被 DECISIONS/0017 推翻，见该记录：`income_payment_timing` 的“一次性购买以年初现金检查流动性”（改为按月记账，当月及此前已入账的收入可用于同年后续月份的购买），以及 `failure_handling` 的“按住房 → 食品 → 工作 → 其他的固定优先级部分执行”（改为：最低住房 + 最低食品付不起即出局；自选项付不起只拒绝该项；自选住房/食品给不了而最低仍可负担时，声明了兜底才降级，否则计划不可行）。收付时序已定；失败处理里格式错误的有限重试、重试后的默认动作与出局期间如何计分仍开放。

> ⚠ 上表 `energy_feedback` 的反馈建议 `E_{t+1} = E_base + clip(β·(S_t − S_ref), −cap, +cap)`（参考点、可正可负）没有被采纳：E1-4B 的合成探索版改用相对固定基础额度的正向加成 `E_base × (1 + α × S)`，不低于基础、不复利，见 DECISIONS/0021。`energy_feedback` 政策仍未正式定下。

> ⚠ 2026-10-11（DECISIONS/0028，E1-6A 合成探索版）：上表 `discounting`、`terminal_value` 两行的建议没有被原样采纳——折现改为评价规格显式声明月度时间权重 δ（主设定 δ = 1，非 1 对照只验证机制）；期末价值改为从真实终态出发、按预先声明的少量参考方案在 12 个月估值期里真实结算与评分（不把期末现金与残值折成一个名义消费年，也不另加残值）；二者仍未正式裁决。`failure_handling` 一行的“失败计入分母，不丢弃分身”已被更正：城市平均分排除已确认的生活出局者；原计划人数、出局比例（以原计划人数作分母）及原因的报告保留全部分身；模拟问题造成的未完成计算另作不确定性分析。见该记录。

## 七、E1-1 的实现与验收（阶段审核已通过，2026-10-05）

**实现了：** 第二节的全部数据契约；目录加载与交叉校验（引用、口径、期限、安排白名单、
陈述与真值一一对应）；按许可的可见投影与两道防线；纯合成样例（两城相对价格结构相反、
两人消费偏好相反、三种可得状态、一项持续物品、一项培训、一项一次体验、虚构第二国家
ZZ/XTS）；离线检查入口。

**不能做：** 执行行动、算账、算满足感或精力、推进到下一年、计算任何分数或城市排序、
真实调用 LLM、读取真实数据。

**验收（`tests/life/`，99 条）：** 合法样例加载并稳定往返；未知字段、非法数值、重复 ID、
缺失引用、不合理期限被明确拒绝，免费项允许零价；三种可得状态互不替代、未知不补零；
不同口径不能进同一本账、指数不能冒充报价；两城异质价格与两人不同偏好完整保留，报告里
没有得分或排序字段；一次体验与持续物品期限不同；旧答案对象、新内部评分与隐藏偏好无法
经嵌套字段进入 payload；政策未定时协议不能标为可评分；第二国家走同一加载入口、加载器
里没有国家字面量。三处关键保证做过变异测试（去掉即有测试失败）。

**选择 pydantic 的理由：** 仓库已有依赖（`common/config.py` 同样用 `frozen` +
`extra="forbid"`）；它直接复用现有的 stdlib dataclass（`CityId`、`Money` 等，实测会拒绝
嵌套多余键与缺键），并提供稳定的 JSON 往返。没有新增依赖。
