# 0047 E3 独立评分：原始评分精确归一成权重（`ratings_normalized_v1`）

日期：2026-10-25。层：接入层。任务原文见所有者 2026-10-25 的“E3 输入与服务体验调整”第一节；交接见
[E3C → E5](../docs/handoffs/e3c-to-e5-service.md) 第 16 节。

## 背景

v0.4 及以前的问卷让用户把 100 分分给六维（物质再把 100 分分给四项）：改一项就得从别处挪分，页面要维护“来源维度 / 未分配池 / 两维
转移”，E5 核查（E5-R6）显示这套操作很难做对，也很难解释。所有者确定：每项独立打 0–100 分，系统按比例精确换成权重，不另加系数。

## 决定

1. **新输入方式 `ratings_normalized_v1`**（`AllocationAnswer.mode`）。六维与物质四项各自独立换算。原始评分 r_i 在 0–100 之间，滑条
   步长 1，数字精调最多两位小数（资料包 `points.manual_max_decimals`），不必凑满 100；分数写法（“50/3”）不是评分，拒绝。
2. **换算**：要回答的项都回答了、Σr > 0 时，权重 points_i = 100 × r_i ÷ Σr，精确分数，不加任何系数，也不按职业、文字或消费能力调整
   评分。同比例放大或缩小，权重不变。显示的四舍五入只供阅读，不回到计算。
3. **状态**：未答不是 0；明确的 0 是回答；无所谓、暂不确定保留状态、不换成数值；没回答完不出权重（审阅给出已答各项的原始合计）。
   全部为 0 拒绝（`ratings_all_zero`：“至少有一项大于 0，或主动选择同等重视”），不自动均分。“同等重视”是用户主动把每项评分设为 50
   的页面动作，草稿里就是 50。
4. **物质父项为 0**：四项不适用，草稿里已有的四项答案原样留着、这一次不参与、不挡确认；父项重新大于 0 时照原样恢复，不清零、不均分。
5. **保存什么**：草稿保存原始评分；审阅给出每项的原始评分（`rating_exact` / `rating_display`）、原始合计（`rating_total`）、精确权重
   （`exact` / `display`）与换算规则（`rule`）；确认画像保存原始评分（`ratings`）、原始合计与规则，`points` 是最终权重。E1 的编译
   仍只读 `points`。
6. **旧的百分比分配**（`manual` / `equal_split`）保留原来的含义，只为读回旧对象：新问卷审阅时报 `allocation_mode_retired` 阻断确认
   （这组旧分配本身照原义审阅，合计 100 就是完整）。旧草稿迁移时照原样列出旧分配（`DraftMigration.allocations`），用户必须选择
   `rerate`（这两组改成独立评分、各项未答）或 `equal_weight`（每项 50），否则 409 `migration_choice_required`；系统不把旧百分比改读
   成评分。已确认的旧画像、已开始的运行与历史结果不改。
7. **版本**：公共结构 v3.5（仍导出到 `contracts/product/v3/`，`ProductMeta` 同时接受 v3.3、v3.4 以读回历史对象）、问卷 v0.5-draft、
   转换 v4；词表、输入目录、健康问卷、生活协议与评分版本不变；显示附层仍是 v2，冻结新的资源版本、旧版本保留。服务 API 升到 v1.4
   （迁移请求多了 `allocation_choice`；同一任务的一次开始与进度摘要也在 v1.4 里）。
8. **旧对象按原版本序列化**（推广 [0046](0046-e3-input-catalog-and-structured-answers.md) 第 9 条，取代其中的 `_legacy_dump`）：每个
   新字段登记它出现的版本（`product_contracts._Since`），比对象版本新的字段读回时只能是默认值、写出时不写；用了更新版本才有的状态
   （v3.4 的 `selected`、`catalog` 等，v3.5 的 `ratings_normalized_v1`）就拒绝。v3.3、v3.4 对象的 JSON、内容身份与显示绑定都与
   当初相同；JSON Schema 只多了 v3.5 的字段。

## 后果

* 合计正好 100 的原始评分换出的权重与原来的百分比逐项相同：测试与样例的主故事（30/20/20/10/10/10、25/25/30/20）给 E1 的输入不变。
* 只认比例：所有项都打高分与都打低分表达同一个偏好。想表达“都不在乎”的人只能选无所谓 / 暂不确定，而这两种状态挡住确认。
* 页面换成独立评分控件，“来源维度 / 未分配池 / 两维转移”不再需要。E5 现有的 v3.4 草稿样本照原样审阅（旧含义加阻断）；E5 按 v3.5
  重新生成样本之后，对应测试要换成评分的例子。
